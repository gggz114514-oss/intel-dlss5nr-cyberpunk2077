# Vulkan FP16 深度技术复盘：从算得出来到持续供给 XMX

本文展开 [完整时间线](FULL-HISTORY.md) 中的实现过程。时间线回答“每轮进步多少”，本文回答“原来多做了什么、如何改掉、为什么某些改法退化、最终怎样扩散到全网”。代码链接指向本次发布保留的最终实现；历史父版本的指标按对应阶段说明。

## 一、理解这次优化的对象

网络不是一个巨大的 GEMM，而是很多矩阵计算与非矩阵处理交替组成的图。典型 attention 链为：

```text
输入 / 残差
  → QKV 投影
  → Q/K norm 与尺度
  → QK score
  → bias、exp、den
  → P 归一化
  → PV
  → 输出投影
  → 残差 / 下一层
```

FFN 则包含 expand、激活、contract 和残差。下采样、上采样、窗口组织与最终输出还会引入额外的 gather、布局变换和投影。

最初 50.821 ms 的版本已经使用 FP16 协同矩阵和 FP32 累加。XMX 做乘加很快，但它需要收到特定布局的 A/B 片段；前一矩阵输出的累加器布局，通常与后一矩阵需要的输入布局不同。中间又夹着必须执行的 norm、激活、归约与舍入。整个优化过程主要围绕这段连接进行。

这里使用的几个词：

| 名称 | 本项目中的含义 |
|---|---|
| owner | 某段数据由哪个工作组、子组、lane 持有并负责计算 |
| fragment / 片段 | cooperative matrix 分布在各 lane 寄存器中的局部数据 |
| SLM / shared | 同一工作组共享的片上内存，用于跨子组发布和复用 |
| staging | 先复制到中间区域，再由矩阵或后续阶段读取 |
| 生命周期 | 从值被产生到最后一个消费者完成读取的区间 |
| 返回寄存器 | send 载入完成后写入的寄存器区域 |
| scratch | 寄存器分配之外的私有暂存；需要关注实际生成的读写 |
| DPAS | Intel 矩阵乘加的 native 指令 |

优化需要同时改变“数据怎样到达矩阵”和“独立工作怎样重叠”。只减少源代码行数、静态指令数或 shared 数组大小，覆盖不了这两件事。

## 二、第一轮大收益：把布局准备前移到离线，把 A 直接交给矩阵

### 原来的路径

早期多族内核先读输入，再将其整理到 shared，发布屏障后 cooperative load 才获得 A。权重也按原模型存储方式读取，再在运行时适配矩阵 B 的方向。这个路径在每个窗口、每个层重复执行。

```text
输入读取 → shared 写入 → 屏障 → shared 读取 → A 片段
原始权重 → 运行时整理 → B 片段
```

### 实际改造

对可直接寻址的输入，cooperative load 从正确的源位置生成 A，删除一层转存。对固定权重，在构建阶段重排为 tile B 的存储格式。运行时只计算 tile 地址并载入，不再重复执行固定的权重布局整理。

```text
输入 → cooperative load → A 片段
离线 tile-B 权重 → cooperative load → B 片段
```

离线重排只改变 uint16 元素位置，不重新量化，也不改变 half 位值。发布中的 `weight-transforms.json` 对每次变换记录输入和输出身份，最后核对整个 cold resource 集合。

### 结果与选择

第一轮 C64/C128/C256 expand 的 SLM 读取分别减少约 66.3%、72.8%、84.2%；C128 输出投影 shared 36,864 B→0。第一轮整网同批 48.968→41.137 ms。

C256 输出投影采用更有针对性的尾处理改造：保留 A 缓存，优化 half seed、宽化与最终写出，使 scratch 896 B→0。它比单纯删除所有 A 暂存更适合当时的复用结构。这一轮已经体现了后来的主原则：**先问暂存承担什么复用，再决定删除或保留。**

## 三、矩阵后处理：seed、激活和残差的舍入点也是数据流的一部分

矩阵链不能只画两个 MMA。比如残差 seed 可能先以 half 相乘，再宽化到 FP32 累加器；激活输出可能需要先落到 half，再进入下一矩阵。把这两步合成一次 FP32 运算，会改变结果。

我们把数值顺序和存储位置分别处理：

1. 保留 half 运算及其舍入位置。
2. 保留每个累加器的 K 遍历顺序。
3. 将完成舍入的值保留在合适片段，或直接写入下一消费者的布局。
4. 删除只用于换容器的额外宽化、复制和暂存。

这样减少的是运输，而不是用近似公式代替原计算。第二、三轮 contract、FFN、projection 的改造都围绕这个顺序展开。contract 保留成对 M 复用；split16 使用匹配的 M×N 组织；FFN 权重先离线重排，运行时减少重复 X 缓存。

数值约束在最终构建中落到了实际二进制：先验证 glslang 原始输出哈希，再恢复对应 NoContraction 装饰，最后验证最终 SPIR-V 哈希。该步骤把源码、编译器与舍入配方连在一起。

## 四、C32 为什么适合先做整链，为什么不能只统一“行列方向”

C32 的通道维较小，更多中间值能够留在寄存器或较小 SLM 区域内。这使它适合实验 norm→attention→残差→下一投影的整链 owner。

但统一方向不是让所有张量都使用 row-major。真正需要统一的是相邻两段对逻辑元素的解释：

```text
逻辑元素 (token, channel/head/key)
  ↔ subgroup
  ↔ lane
  ↔ fragment component
  ↔ 物理地址
```

生产者以某个 lane 持有值，消费者若恰好需要该 lane、该 component，便可以直接继承。若消费者要交换行列或跨子组使用，就需要 shuffle、重排或 SLM 发布。一个方向对 QK 合适，对 PV 未必合适，因此 score、den 和 PV 需要一起规划。

C32 全族按入口、body、F2 与 F20 分开核对。入口还有图像 gather 与边界处理；body 复用既有特征布局；F2 有自身融合与输出要求；F20 连接最终投影。统一方法，保留这些不同接口。

### 生命周期如何指导实现

对于一段数据，先标明产生位置、所有消费者和最后读者。值的最后一个消费者之后，原寄存器或 shared 区域才能用于下一相位。例如 Q 在 score 完成后结束生命周期，V 还要参与 PV，二者不能在同一时点回收。

早期 C32 X/P 暂存复用使 shared 37,376→29,184 B。后续 body 的直接交接、norm owner 和整链布局继续删掉运输。九个 body 的一轮寄存器交接使整网 32.482→31.431 ms。

### 为什么八个子组不自动优于四个

“八个子组执行”仍要看每个子组中有多少 lane 真正有用。四个满活跃子组的归约，拆成八个半活跃子组后，会引入跨 lane 重组和额外广播；同时更长的中间值寿命会挤压后续供料。

我们因此同时对账有效 lane、每个权重 tile 的复用次数、独立累加器数和 shuffle 数。保持八子组并行的候选还要保留 A 侧提前供料与权重共享。只修出口转置，或只减少 den 的几条指令，往往没有触及整链的主要依赖。

## 五、score→den→PV：通过 owner 改造减少中间矩阵落地

发布中的 [F10 / S22 实现](../../source/network-fp16-20261027/f10-228dee8a437d/kernel.comp) 保留了这条路径的详细注释。

父路径把 P 放在 `phase[4096]`：score 的 query/key 组织与 PV 所需的 P 转置方向不同。新的四 query-block owner 方案让一个 owner 负责 16 queries 的完整 key 范围，计算转置后的 score，再把 P 片段 join 成 PV 的 B 操作数。

```text
原路径：score → P 写 shared → 发布 → den/归一化 → 重读与转置 → PV
新组织：转置 score → 寄存器 P → 同 owner den/归一化 → join 为 B → PV
```

这里的 join 仍有成本，但它替代了更完整的 shared 交接。V 按 PV 的 A 布局消费，结果再写回规范输出地址。

实现保留：

- score 每个元素先累加 dim 0..15，再累加 16..31。
- bias 加法与一次 half 窄化的位置。
- exp 的逐元素计算。
- den 每个节点的配对和加法顺序。
- P×inv 的 half 舍入。
- PV 的 key 块顺序 0..15、16..31、32..47、48..63。

因此这里改变的是 owner 与交接，不是 softmax/attention 的数值定义。S22 改造在五热点组合阶段形成了主要收益之一；该整包同批节省 0.586 ms。

## 六、宽族迁移：C128/C256 需要控制复用范围

将 C32 的思路搬到宽族时，寄存器峰值是关键设计量。增加 M 或 N 的覆盖可以减少重复载入，但会增加同时活跃的 FP32 累加器。若扩大范围挤掉 A/B 的返回区，供料反而变慢。

[C256 attention](../../source/network-fp16-20261027/f05-236aad961967/kernel.comp) 的历史记录体现了两次具体改进。

### Q 片段在 score 循环外复用

四 query-block owner 的早期实现虽然把 P 留在寄存器，却在八个 score block 中重复读取相同 Q 的 B 片段。后续将这个常量片段外提，一次载入供八块使用；相关 score 阶段源级 SLM 读取从 48 KiB 降到 20 KiB。

这说明 owner 方案落地后，还要继续追查循环不变量：布局正确只是起点，同一个片段在多少次调用里被重新构造，同样重要。

### 两块 M8 共用权重，而不是无限扩大 tile

n05a 原来分两次 row phase 处理两块 token，每次重新载入相同权重。新实现同时持有两块 M8 的 A，让一个 B tile 依次供两次 MMA。

| 每子组、完整窗口的逻辑工作 | 父版本 | 新版本 |
|---|---:|---:|
| 权重 tile 载入 | 192 | 96 |
| A tile 载入 | 64 | 64 |
| DPAS | 192 | 192 |
| QKV 峰值矩阵累加器 | 4 | 8 |

这次复用没有增加 A 读取和 MAC，也没有改变网格与 token/head 映射。代价是多四组累加器及更长 B 寿命。最终对应单步收益 **0.521 ms**。

C64/C128 的寄存器结构不同，相同扩大方式需要不同的分段；实际以各族预算和整族计时决定实现。宽族方法因此是“有预算的局部复用”，而非无条件整核融合。

## 七、F10：从退化到 0.422 ms 的完整实现教训

生产布局改成消费者更容易读取的形状后，减少了 A 组装，但初版没有得到预期性能。分析转向 native：权重 load 是否真的提前、返回区是否与仍活跃值冲突、A 组装能否与 load 重叠、多条独立累加链是否保留。

两个看似相同的源码版本可能被编译成不同的生命周期安排。下面是设计上的区别：

```text
串行复用：
  载入 B0 → 使用 B0 → 释放返回区 → 载入 B1 → 使用 B1

独立返回区：
  发出 B0、B1、B2 的载入
  在各自依赖就绪后消费
  每块最后一次使用后再回收
```

后一种安排保留更多短期活值，换取独立供料重叠。正确的预算不是把所有权重永久缓存，而是保证正在并行的返回区不互相覆盖，在最后消费后马上复用。

最终 F10 保留生产消费布局、三块独立权重返回区及原有累加顺序，native 确认有效调度变化，无新增 scratch；16 个位置整族同批收益 **0.422 ms，95% CI [0.297, 0.547] ms**。

之后 n10 再处理地址与 slice 生命周期：四个 staging 基址随 kc 线性递推，每轮增加 1024 个 half，避免重复 tiled 地址展开；交替 slice 的下一次发布同时完成前一 slice 的退休，删除重复退休屏障。这轮保留 A/B 载入数量和三块返回区，追加 **0.094 ms** 单步收益。

F10 的经验用于后续所有候选：先检查实际机器码，再评价方向；遇到退化时分清“布局收益”与“新调度成本”，保留已正确的部分，修复占住返回区的活值。

## 八、融合之后再删镜像：D034→A1

把两个 kernel 合在一起，只是融合的第一步。生产者原先写全局中间结果，消费者独立派发时再读；合并后消费者可以直接读融合核内的数据，但原全局镜像写可能仍留着。

D034 融合删除 33 个独立 contract 派发后，下一步 A1 再检查旧 gM 的所有消费者绑定和生命周期。确认这些镜像不再供有效消费者后，删除对应写入。

```text
融合前：producer → 全局 M → 下一次 dispatch → contract
融合后：producer → 局部交接 → contract
清理后：同时移除已经失去用途的全局 M 镜像写
```

A1 单独约 0.143 ms；包含多项暂存与屏障改造的 COMBO-1 对当时父臂约 0.322 ms。该做法推广时按缓冲读写图核对，而不是根据变量名判断“看起来是 debug”就删除。

## 九、n39：32 KiB 恒等 staging 的删除

最终 [C256 输出投影](../../source/network-fp16-20261027/f06-8f592cf9576f/kernel.comp) 从 `gT` 直接读取 A。原 `shT` 是只读 `gT` tile 的逐字节复制，没有改变布局和数值。删除后仍使用同一偏移、row-major stride 和 K 顺序。

| native / 资源项 | 父版本 | n39 |
|---|---:|---:|
| `load.slm.d32x8t` | 1024 | 0 |
| `load.ugm.d32x8t` | 128 | 1152 |
| `fence.slm` | 1 | 0 |
| signal barrier | 2 | 0 |
| 静态指令 | 7087 | 6971 |
| DPAS | 256 | 256 |
| Workgroup 内存 | 32768 B | 0 B |

六组同批对照节省 **0.103768 ms，95% CI [0.092132, 0.115403] ms**，固定与反馈数值门逐字节一致。

这里减少了复制、发布和 shared 容量压力，同时增加直接 UGM 读取。GPU 的全局读取经过缓存层级，因此决策依据是整核真实供料路径和整网结果，而不是机械地认为“SLM 一定优于全局读取”。

## 十、arena 复用：少占容量不等于少读数据

n36 处理的不是复制，而是 Q/K/V 各相位的生命周期。Q 在 score 完成后死亡，V 在后续相位使用，因此可以让 V 使用已经退休的 Q 区域，保留仍活跃的 K 或其他输入。

C256 当前源码记录两 head 的三个平面改为两个平面，shared 从 24,576 B 降到 16,384 B。逻辑数据与消费者不变，减少的是峰值同时占用的 shared 容量。该轮 C256 单步 **0.117 ms**；C64/C128 成包 **0.126 ms**。

这种优化的主要目的在于让更多工作组同时驻留，为隐藏供料与计算等待提供空间。它与删除 load/store 是不同维度，成本表分别记录容量、消息数量、同步以及实际收益。

## 十一、矩阵外还有清零、地址链和小收益整族累积

### 清零

清零属于真正的 GPU 工作。若一个 buffer 在任何消费之前已经被生产者完整覆盖，原始初始化可以删除。证明对象是实际元素域、有效分支和下游读取，而不仅是 dispatch 覆盖范围。95→102 阶段已把这类改造作为重要收益来源。

### 地址依赖

整数除法、模运算和重复坐标展开会阻塞后续地址生成。F01 n18 删除 clamp 后冗余模运算，native 7168→6519，消息数量不变，单步 **0.079 ms**。n29 继续处理 ALU 地址链，单步 **0.080 ms**。

这说明矩阵外优化不一定体现在带宽。数据没有少读，但读取地址更早就绪，后续供料便能提前。

### 同族成包

同一模式覆盖多个 PASS 时，组合统一验证。ViT 16 个位置的组合收益约 **0.0096 ms**，仍按身份保留；F06 C64/C128 的小步与其他方向一起进入最终链头。

组合采用新的整体对照，而不是累加各自不同批次的数值。最终 13 步改变 120 个 PASS 行，handoff 18.724→17.450 ms，是这批改造的整包结果。

## 十二、如何读性能数据，如何复用本项目的方法

项目使用三层记录：

1. **源码映射与生命周期**：说明删了什么，增加什么，哪些消费者保留。
2. **native 与资源**：检查实际 load/store、矩阵数、调度顺序、shared 和 scratch。
3. **数值与端到端计时**：固定及反馈验证后，用同批父/候选测整网收益。

早期 profiling 的经验被收敛为明确工具用法：mode0 按基本块读取；大混合块同时包含供料、矩阵和同步；屏障密集插桩采用稀疏对照检查扰动。测量结果用于选择受控实验，最终收益以普通运行确认。

应用到新族时，先画局部生产消费图，再列下面这张账：

| 问题 | 必须写出的内容 |
|---|---|
| 映射 | 逻辑元素、owner、lane、fragment、地址的对应 |
| 算术 | 每个累加器的顺序、half 舍入、norm/den 树 |
| 读取 | A/B 重复次数、消息宽度、有效 lane |
| 并行 | 独立累加器、可重叠供料、同步位置 |
| 寿命 | 生产者、最后消费者、返回区、覆盖者 |
| 资源 | shared 峰值、寄存器活值峰值、scratch |
| 推广 | 同族位置清单、特殊变体、组合基线 |

本次最重要的可复用成果，是把这些账结合起来：**直接消费减少交接，独立返回区保留并行，生命周期复用控制峰值，整族验证把小收益转成全网收益。**
