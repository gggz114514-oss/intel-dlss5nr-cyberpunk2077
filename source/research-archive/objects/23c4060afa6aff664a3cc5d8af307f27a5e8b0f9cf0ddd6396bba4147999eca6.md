# n37-f10-arena-shrink · ANALYSIS（六问）

卡 id = `n37-f10-arena-shrink`，族 F10（16 PASS = ordinal 62/66/70/74/78/82/86/90/136/140/144/148/152/156/160/164）。
父 = **链头**（`accepted/n36-f05-arena-c64c128-20261027/plan.txt` `af6c1287…eb7c` 的 F10 16 行）
→ `cards/n10-f10-next/candidate.spv` **`228dee8a437d…`**，源 `ff2ffde6…`；本卡候选 SPV **`18c7b90dcd80…`**、
源 `b07f17ab…`、plan **`f68edee6c8bc…`**。状态 **BUILT-AWAITING-GPU**，无 GPU、无部署、无 GPU 锁。

**一句话**：F10 的 arena 声明 20480 B，但它的**同时活值峰值只有 16384 B**；多出来的 4096 B 不是活值，
是"staging 窗口 0 不得与 QKV 交接区重叠"这条**结构性约束**（第 7 片仍在被读时交接存储就要写）。
把 QKV 交接区从 4096 挪到 0、并在 kc 循环之后补**一道** workgroup barrier 退役窗口 0，
arena 就压到恰好等于活值峰值 16384 B ⇒ 驻留 3 → 4。**金帧硬门先过，计时之后再说。**

**P1 资产纪律（未违反）**：现役基线已含 F10 三块独立 B 返回区的 0.422 ms。本卡对 k-step 的
权重段**零改动**：仍是每 k-step 每 SG 三次权重读、三块互不重叠的 8-GRF 返回区、三条都早于该 k-step
的首个 DPAS，六条 DPAS 的 K 序逐字不变（`_proof.py` 的 `three_B_return_regions_untouched` 用
字符级核对兜住）。本卡不加任何 B 预取。

## 1. 映射：每个 (lane, component) 代表哪个 (token, channel/dim)，消费者要什么

### 1.1 生产者（QKV 投影，每 SG 每 slice）

每 slice（`kc = 64i`）由全部 256 线程写 4096 half，两侧都可枚举：

```
lid ∈ [0,256)     q = lid>>6 ∈ [0,4)      c0 = lid&63 ∈ [0,64)
tx,ty             窗口 tile 的 2×2 位置（WG 内一致）；w4 = p0.x/4, h4 = p0.y/4
quadrant g ∈ {0..3} → token 基址 B_g = 16*(ty*w4 + tx + dx + w4*(dy))
i' ∈ [0,4)        token t = B_g + q + 4*i'   （= 4 个 g × 16 token = 64 token 的划分）
channel c = kc + c0
SLM 落点 = abase_i + qkv_a_offset(lid + 256*i' + 1024*g)
           qkv_a_offset(e) = ((r/8)*4 + k/16)*128 + (k%16)*8 + r%8,  r = e/64, k = e%64
         ⇒ 行 r = 16g + q + 4i'，列 k = c0
```
**一一覆盖**：`(token, channel) = 64 × 64 = 4096` = 256 线程 × 16 个 STAGE，
`build/lifetime.json.candidate.staging.write_is_partition = true`（4096 个地址各写一次）。
读者侧：每 SG 读 2 个 M 块 × 4 个 k-block × 128 half = 1024 half，
`read_union_is_whole_slice = true`，且**每个地址恰好被读 2 次**（SG 对共享同一 16 token），
`read_per_address_multiplicity = {2: 4096}`。**本卡的窗口基址与这块映射一个字都没改。**

### 1.2 交接（`STORE_QKV`，循环后 6 条 coopMatStore）

| 平面 | 写者 | 逐元素地址 | 消费者要什么 |
|---|---|---|---|
| Q | **4 个偶 SG**（s=sg%2=0），各 16 token × 32 channel = 512 half | `Q_base + token*32 + channel` | score 的 B 操作数 `Q^T`：`sg<4` 每 SG **只读自己那 16 个 query** × 32 channel = 512 half |
| K | **8 个 SG**，偶数 SG 写 channel 0–15、奇数 SG 写 channel 16–31，各 16 token × 16 channel = 256 half | `K_base + token*32 + channel` | score 的 A 操作数：`sg<4` 每 SG 读**全部** 8 个 key block × 32 channel = 2048 half |
| V | **4 个奇 SG**（s=1），各 16 key × 32 dim = 512 half | `V_base + dim*64 + key` | PV 的 A 操作数 `V^T`：`sg<4` 每 SG 4 个 dim block × 4 个 key group = 2048 half |

* `handoff.write.partition = {Q:true,K:true,V:true}`：三个平面的写地址集合各恰好 2048 个、每地址写一次。
* `handoff.read.read_union_is_plane = {Q:true,K:true,V:true}`：读者并集回到同一平面（无漏读）。
* **k-step 的 A 片段**：`coopMatLoad(a0,smem,abase+((mA/8)*4+k/16)*128,8,COL)`，
  `a0` = 行 `mA..mA+7` 的 8×16 片段（`mA = 16*(sg/2)`），`a1` = `mB = mA+8` 那 8 行；
  两种 abase × 两个 M8 块 × 4 个 k-block × 128 = 16384 条地址全部回到
  `qkv_a_offset` 的同一个双射（`lifetime.json` 逐地址枚举）。**"两个 M 块共同消费"** =
  同一对 SG（p 与 s=0/1）读**完全相同的 16 token**、只在 N 方向分工。
* 尾块：channel 无尾（512 = 8×64）；token 尾由 `v_g`（WG 内一致）选 0 填充，
  三个 STAGE 宏里的 `(V)?gy[(A)]:float16_t(0.0)` 与 16 个落点**未改**。

本卡对**值**的唯一影响：三个平面整体平移同一个常量（`plane_shift = {Q:4096, K:4096, V:4096}`，
`uniform = true`），每个元素在自己的平面内落在**同一槽位**（`build/addr-audit.json` I7）。

## 3. 重叠：谁生产、谁最后消费、谁覆盖（RAW/WAR/WAW）

| 对象 | 生产者 | 首个消费者 | 最后消费者 | 覆盖者 | 父的关闭者 | 候选的关闭者 |
|---|---|---|---|---|---|---|
| staged slice `w_i`（4096 half，窗口 `b_i`） | 8 个 SG 全部（各 512 half） | slice `i` 的 publish barrier 后第一条 A 读 | 第 4 个 k-step 的 `a1` 读 | slice `i+2`（同一窗口） | slice `i+1` 的 publish barrier | **同（不变）** |
| 窗口 0 `[0,4096)` | — | — | **slice 7 的 A 读** | **Q、K 的交接存储** | 无（父不让它重叠任何平面） | **新增 barrier N** |
| 窗口 1 `[4096,8192)` | — | — | slice 6 的 A 读 | **V 的交接存储**（`[4096,6144)`） | slice 7 的 publish barrier | **同（不变）** |
| Q/K/V 平面 | `STORE_QKV` | debug echo → norm | score（Q/K）、PV（V） | norm **原地**改写 Q/K | 已有的交接后 barrier | **同（不变）** |
| A 片段 `a0/a1`（寄存器） | A `coopMatLoad` | 同 k-step 第 1 条 DPAS | 同 k-step 第 6 条 DPAS | 下一 k-step 的 A 读 | 自然重叠 | **不变** |
| 权重 `b0/b1/b2`（三块 8-GRF 返回区） | 3 条 UGM | 各自 2 条 DPAS | 各自第 2 条 DPAS | 下一 k-step | — | **不变（P1 禁改）** |
| `acc00..acc12`（6 个 8×16 F32） | DPAS 累加 | 首个 k-step | `STORE_QKV` | — | 跨 8 slice 存活 | 不变 |

逐地址统计（`build/lifetime.json`，穷举不是抽样）：

| 关系 | 父的重叠地址 | 候选的重叠地址 | 关闭者 |
|---|---|---|---|
| slice 7 A 读 → QKV 存储（**WAR**） | 0 | **4096（只撞 Q/K）** | **新增 N** |
| slice 6 A 读 → QKV 存储（**WAR**） | 4096（撞 Q/K） | **2048（撞 V）** | slice 7 的 publish barrier |
| slice 5 写 → slice 7 写（**WAW**） | 4096 | 4096 | slice 6 的 publish barrier |
| Q/K/V 存储 → 消费者（**RAW**） | 2048 / 2048 / 2048 | 2048 / 2048 / 2048 | 已有的交接后 barrier |
| norm 原地读写 Q/K | 4096 元素，读写集相同、每元素单线程 | 同 | 程序序（无跨 SG WAR） |

**为什么一道屏障就够**（源码顺序）：

```
slice 7 的 STORE → [publish barrier 7] → slice 7 的 A 读（窗口 0）→ 循环结束
                                          ↑ 此刻所有 SG 的 slice 6 读（窗口 1）早已越过 barrier 7
   → [新增 N] → STORE_QKV(Q 落窗口 0, K 落窗口 0, V 落窗口 1 前半)
```
N 之后，任何 invocation 的 Q/K 写都排在"所有 invocation 的 slice 7 A 读"之后 ⇒ 窗口 0 的 WAR 关闭；
窗口 1 的 WAR 已由 barrier 7 关闭，所以 N 只需覆盖窗口 0 一种情况。`_proof.py` 的
`barrier_between_loop_and_store` 用源码顺序正则核对这一点。

**没有把所有东西串起来**：B 的三块仍在首 DPAS 前发出，A 读位置不变，DPAS 顺序不变；
新增的同步只在**循环之后**，不在循环体内（循环体内仍是每 slice 一道 publish barrier，n10 的资产保留）。

## 5. 是否真落到 native：预测 + 判据（完整清单见 `NATIVE-PREDICTION.md`）

**顶部的硬判据（写死）**：

> **H0**：SPIR-V `shared`/`Workgroup` 总字节 **20480 → ≤16384（本卡 = 16384）**，且 plan 的 `shared`
> 字段 16 行同步为 16384。两者任一不成立 ⇒ 本卡不成立。**已在 CPU 侧核对通过**
> （`build/build.json.storage_bytes.workgroup_candidate_bytes = 16384`；`plan.json` 16 行）。

native 可观察点摘要（**这是预测，不是已证**）：

1. **P1（资产）**：三条 `load.ugm` 权重 send 仍返回到三个互不重叠的 8-GRF 区、仍都早于该 k-step
   的首个 DPAS、每 k-step 仍是 3 次权重读。若返回区交叠 / 某条落到首 DPAS 之后 / 多出第 4 次 ⇒
   **判"牺牲已接受资产"，直接否卡**。
2. **P2（同步）**：动态 `sync.bar` **+1**（每 WG 11 vs 10）是预期。**+2 以上、或 `fence.slm`
   有变化 ⇒ B 类**（副作用超出设计）。
3. **P3（消息）**：除 barrier 附带的 2 条（`signal barrier` + `fence.slm`）外，消息账不变。
4. **P4（DPAS/coopmat）**：`dpas` 38 静态不变，SLM load/store 条数不变。
5. **P5（资源）**：`max_r` 仍 255（特殊寄存器档，父也是 255），scratch **0**；occupancy 81.7% → ~86%
   （3→4 驻留）。**occupancy 不动就等于驻留机制没落地 ⇒ A 类。**
6. **P6（地址）**：Q 平面基址 4096→0、K 6144→2048、V 8192→4096；ISA 里的 SLM 立即数应整体平移
   −0x2000/−0x4000，**不应出现任何越界或"读到别的窗口"的迹象**（离线由 `_addr_audit.py` 兜住）。

## 6. 整体是否更快：测什么、怎么归因

* **臂**：`base` = 链头 plan `af6c1287…`；`cand` = 本卡 plan `f68edee6…`。两者**只有 16 行 F10 PASS 不同**
  （`plan.differing_lines = 16`，逐行核对其余 216 行与全部 BUFFER/grid 字段相同）。
* **顺序**：gates `fixed`（末帧 `1755e9c2…`）→ gates `fb2`（`--warm 0 --reps 2 --feedback --save-frames`，
  末帧 `9c3e511e…`）→ native（两臂 ISA）→ resources（两张占用率/资源表）→ **ordinary**
  （`--warm 1 --reps 30 --feedback`，末帧 `2b63d4ba…`）。
  **fb2 末帧与 ordinary 末帧不是同一个 gold，不得混用（合同 §8.1）。**
* **ordinary 设计**：两臂 6 组交替（ABABAB…），每臂每组 30 样本，共 360 样本全留；
  按组均值差做配对 t(df=5)，报 95% CI。验收 FASTER_95 6/6。
* **预期量级（诚实区间）**：本卡的机制是**驻留台阶**，不是删工作。标定只能取自本战役已有的三次裁剪：
  * F05 正向 2→4 驻留（36 PASS，3.04 ms）：**+0.116668**（C256 16 PASS）与 **+0.126122**（C64+C128 20 PASS）
    ⇒ 整个族约 **+0.243 ms ≈ 自身时间的 8%**；
  * 反向探针（F05 2→1）**−1.219 ms**、F06 2→1 **−0.364 ms**：**反向远大于正向**（强非线性）。
  * F10 是 16 PASS / **2.013 ms**，台阶是 3→4（+33%，比 F05 的翻倍小）⇒ 按"自身时间 × 台阶比例"
    折算，预期 **+0.04 ~ +0.13 ms**，扣掉一道屏障（0.001–0.012 ms）。
  * 这个量级**正好压在 L13 的地板上（0.03 ms）**，所以本卡明确写：**需要 6×30 一批 + 必要时第二批**，
    出现 INDISTINCT 时按 D 类记录、不推广成方向禁令。
* **归因边界**：只改 F10 一条 A 供料链的**地址基址 + 一道同步**，不删工作、不改数学、不改 grid。
  如果普通计时为负，先看 resources 臂的 occupancy 是否真的 3→4：
  * occupancy 没动 ⇒ **A（实现未落地）**，不是方法无效；
  * occupancy 动了但整体没快 ⇒ **C（当前身份无净收益）**，归因到"16 PASS 占 2.013 ms 的份额 + 台阶比例"；
  * sync 或 `fence.slm` 超出 +1 的预期 ⇒ **B（副作用）**，按最大增量项修一版（见 `RESUME.txt`）；
  * 金帧不过 ⇒ **E（数值失败）**，先跑 `_addr_audit.py` 与负控，再定位首差。
