# ANALYSIS — n32-f05-aluwr（六问；F05 三组 / 36 行成包）

**一句话**：F05 的 0.929 ms ALUWR 里**没有可删的贵操作**（逐条见 `ALUWR-AUDIT.md` §4），
唯一还有杠杆的是**16 条最贵算子（`math.rsqt`，30 当量/条）的延迟 100% 暴露**：父里每条的消费者
都在它后面 0–2 条指令。本卡把四个独立求和的求值提到四个开方之前，**不删、不加任何算术**，
只让开方的延迟互相掩盖。它是本战役第一次做**纯延迟隐藏型**改动。

---

## Q1 映射：每个 (lane, component) 到底代表哪个 (token, channel/head)？

**生产者（QKV 投影，`nr_norm_qk_pair` 之前）**

| 量 | 值 |
|---|---|
| 每个 WG | 256 线程 = 8 subgroup，2 个 head（`h = WGID.z*2 + sg/4`），一个 64-token 窗（`w = wy*pc.p1.x + wx`） |
| 每个 SG 的 A 片 | 8 行 × K 列，行 = token `w*64 + m0 + r`，`m0 = (sg%4)*8 + row_phase*32` |
| 六个累加器 | Q0,Q1,K0,K1,V0,V1，各 8×16 f16 累加器；Q0 = head h 的 dim 0..15，Q1 = dim 16..31（K/V 同理） |
| 每 lane 的 4 个元素 | CH 布局：`row = 2c + lane/16`（c = component 0..3），`col = lane&15` |

**消费者（同函数内的归一化 + 后续 score/PV）**

| (lane, c) 的槽位 | 代表 | 被谁读 |
|---|---|---|
| `q0[c]` | token `w*64+m0+2c+lane/16`，head h，dim `0..15` 的第 `lane&15` 列 | `nr_norm_sum` 的 `x0.x` |
| `q1[c]` | 同 token，dim `16..31` 的第 `lane&15` 列 | `nr_norm_sum` 的 `x1.x` |
| `k0[c]` / `k1[c]` | 同 token 的 K，dim `0..15` / `16..31` | `x0.y` / `x1.y` |
| 归约结果 `v.x` / `v.y` | 该 token 的 Q / K 的 **32 维平方和**（`q0²+q1²` 后在 `lane&15` 上 xor{8,4,2,1} 求和） | `max(v,ε)` → `inversesqrt` |
| `n.x` / `n.y` | Q / K 的 `1/sqrt(Σ)`（f16 舍入一次） | Q 的 4 个 apply（`n.x`）、K 的 4 个 apply（`n.y`） |

**一一覆盖（可枚举）**

* 每个 `nr_norm_qk_pair` 调用处理 **4 个 component × 2 个 lane 半边 × 2 个张量 = 16 个 norm**，
  用 **8 条 `math.rsqt`**（每条指令产出 2 个有用值：lane 0 与 lane 16）。
* 每 kernel：c64/c128 = 1 个调用点 × `row_phase` 2 次；c256 = 2 个调用点（n05a 的 a/b 两个 M 块）。
  共 **32 个 norm = 16 条 rsqt**，与父 ISA 实测 `math.rsqt` 16 条逐条对齐（`_t06_sel.py`）。
* **无漏读**：`q0[c],q1[c],k0[c],k1[c]` 每个元素被 `sum_c` 读**恰好一次**；4 个 c 覆盖 8 行 × 32 dims。
* **无重复写**：每个 apply 只写 `[c]` 槽位，4 个 c 的写集合两两不交；`q0[c]` 只被 component c 写过一次。
* **尾块**：一个 WG 覆盖 4 个 SG × 8 行 × 2 个 row_phase = 64 个 token = 窗口长度，**整除，无尾块**；
  本改动不引入任何新下标/边界，尾块行为与父完全相同。

## Q2 删什么真实工作？

**删 0 条。** 如实记：本卡不是删除型候选。

| 候选可删项 | live 数 | L24 权重 | 为什么不能删 |
|---|---|---|---|
| `math.inv` | 1/组 | 30 | softmax 分母 `1.0/max(s,6.1e-5)`，§3 冻结倒数 |
| `math.rsqt` | 16/组 | 30 | Q/K 的 L2 norm，§3 冻结开方；16 条已是这款布局的下限 |
| `sel` | 81/组 | 1 | 16 = norm 的 `max(v,ε)`、64 = sealed exp 的 clamp、1 = 分母交换恒等；**全族上限 0.021 ms**，n31 已实测 144 条无收益 |
| `mov` 中的 narrow/widen/pack | 290/66/273 | 0.3 | 全是 §3 的舍入点，或 shuffle 只能搬 32 bit 造成的必装包 |
| 整数索引 `add` | 392/585/971 | 1 | L1（n04a/n09）：地址折叠 IGC 会重新展开，ISA 不降反升 |
| 调试转储 | 854/975/994 | — | 本夹具 `debug=0` 已整段跳过；L17 证明不是帧成本 |

细节与毫秒估值见 `ALUWR-AUDIT.md` §3/§4。

**那这卡改了什么**：把 4 个 component 的**求和**全部提到 4 个**开方+广播**之前（`nr_norm_component`
拆成 `nr_norm_sum` + `nr_norm_finish`，`nr_norm_qk_pair` 里先算 4 个 `v`、再算 4 个 `n`、最后 4 组 apply）。
被「移动」的只有独立语句的求值顺序，**没有一条指令被删、被加、被改**。

## Q3 重叠：原来怎么重叠、改完怎么重叠（RAW/WAR/WAW）

| 关系 | 父（每 component 串行） | 候选（求和先发、开方成簇） |
|---|---|---|
| **RAW** `sum_c → rsqt_c` | 立即相邻（0–1 条） | 4 个 sum 全部先完成，再各自开方；rsqt 与自己的 sum 之间隔着 3 棵别的树 |
| **RAW** `rsqt_c → narrow_c → pack_c → shuffle → mul_c` | 相邻（1–2 条） | 4 条 `narrow` 依次消费 4 条 rsqt，**第 i 条 rsqt 的延迟被第 i+1…4 条 rsqt 的发射遮住** |
| **WAR** `apply_c` 写 `q0[c]` vs `sum_{c+1}` 读 `q0[c+1]` | 不存在的地址重叠（不同下标） | 同左：仍不重叠（只是时序拉远） |
| **WAW** 4 个 apply 写 `[0..3]` | 两两不交 | 两两不交，且**顺序未动** |
| **独立链数（每 lane）** | 27 / 26 / 20（ISA 实测）；SPIR-V 后内联图 3 / 3 / 11 | 同口径 SPIR-V：**6 / 6 / 14（只升不降）** |

**关键点**：这里不新增依赖、不合并链、不串行化任何东西——只是把**本来就独立**的四条链
从「一条做完再做下一条」改成「同时开工」。L25 说这台机器是延迟受限（XVE 活跃 45%），
独立链是资产，不是成本。

## Q5 是否真落到 native（预测 + 判据，不声称已证明）

完整清单在 `NATIVE-PREDICTION.md`。三条硬判据（任一不成立即未落地）：

1. `math.rsqt` 仍 **16 条/组**（数学没动）；
2. 每条 rsqt 到首个消费者的距离从 **0–2** 涨到 **≥8**，成簇的 8 条之间 ≤6；
3. 相位内**首 rsqt 的地址严格变晚 ≥ +0x300 字节**（父 c64 `0x2E10` / c128 `0x3AF0` / c256 `0x6EF0`）。

已在 SPIR-V 层拿到机制的前兆（CPU 侧，可复跑）：`reduction shuffles before the first rsqrt` **4 → 16**，
`span(first..last rsqrt)` **429 → 99**（c64/c128）、**1036 → 742**（c256），
总 shuffle 数不变（37/37/57），`float_NC` 不变（80/73/8）。

## Q6 整体是否更快 / 本卡要测什么

| 层 | 量 | 臂 | 判据 |
|---|---|---|---|
| 门 | fixed（`1755e9c2…`）、fb2（`9c3e511e…`）、ordinary 末帧（`2b63d4ba…`） | base / cand | 逐字节 |
| 落地 | native ISA：rsqt 距离、首 rsqt 地址、指令数、max_r、scratch | base / cand | 见 Q5 三条 |
| 机制 | **同一次运行内两臂族级 `ALUWR`**（0.928526 ms 起） | base / cand | 下降且 **> 5 点漂移**（COUNTER-NOISE：3.79） |
| 整体 | ordinary 6×30 alternating | base / cand | FASTER_95 才算赢；**< 0.03 ms 必须第二批复现（L13）** |
| 反证 | `SENDWR` / `BARRIER` | base / cand | 必须不动（消息轴与 barrier 都没碰） |

**归因口径**：只有「native 距离变大 + 族级 ALUWR 下降 + ordinary 同向」三者一致才归因给本机制；
单独一项成立都按 `NATIVE-PREDICTION.md` §4 分诊。单链归因只写证据支持的部分：
本卡能证明的是**顺序**（SPIR-V）与**恒等**（数学），**不能**证明每条 rsqt 延迟多少周期。
