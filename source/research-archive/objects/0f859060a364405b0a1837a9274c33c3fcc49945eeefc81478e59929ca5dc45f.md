## Q1 映射：谁代表哪个 (token, channel/k)，覆盖是否一一

**几何**：`grid = 3 64 1`，`local_size_x=256` → 每 WG 8 个 subgroup × 32 lane；`n0 = wgid.y*16`；
`mA = wgid.x*128 + sg*8`，`mB = mA + 64`。每个 subgroup 拥有**两个互不相交的 8 token 行块**。

**累加器**：`MC = coopmat<float,Subgroup,8,16,Accumulator>` → 8×16 = 128 元素 = 32 lane × 4 component（`acc.length()==4`）。

**元素映射（可枚举，闭式）**：累加器元素 `(lane l, component ci)` ↔ **token 行 = m + (l>>4) + 2·ci**，**channel = n0 + (l&15)**，`ci∈0..3`。

| 生产者 (l, ci) | token 行 | channel | 消费者 |
|---|---|---|---|
| l=0..15, ci=0..3 | m + 0 + 2ci | n0 + l | `o[pc.p5.y + 行*1024 + channel]` |
| l=16..31, ci=0..3 | m + 1 + 2ci | n0 + (l-16) | 同上 |

一一性：`(l>>4)∈{0,1}` 与 `2ci∈{0,2,4,6}` 组合给出每个行偏移 0..7 **恰好一次**；`(l&15)` 在每个 `l>>4` 组里给出全部 16 列。故 128 个坐标互不重复、无遗漏，尾块见下。

**读映射**：
- A：`coopMatLoad(af, context, pc.p6.y + r*K + k0, K, RM)`，`K=1024` → 元素 `(行 i, k 道 j) = context[r*1024 + (k0+j) + i*1024]`，即 token 行 `r..r+7`、k 道 `k0..k0+15`。
- B：`coopMatLoad(b0, w, vit_wbase(wb,n0,k0,K), 16u, CM)`，权重布局 `W[N/32][K/16][32][16]` → `(n0/32, k0/16)` 块；本卡未动。
- 每 k 步：1 个 B 片段 + 2 个 A 片段（mA、mB 各一），**与父相同**（静态）。

**写映射**：`coopMatStore(res,o,pc.p5.y + m*1024 + n0, 1024, RM)` → token 行 `m..m+7`、channel `n0..n0+15`；由上面的双射，每个输出 half 恰好写一次。8 PASS × 3×64 WG × 128 元素 = 294912 half = 589824 B，与声明缓冲一致。

**尾块**：`live = 288` 是 8 的倍数，故 `m < live` 的块覆盖行 `m..m+7 ≤ 287` 全部是活行；父的 T2 逐行 `t<live` 守卫过去没有、现在也不会触发；`m ≥ live` 的块由**未改动**的 `if(m>=pc.p0.x) continue;` 跳过。

**候选只改了"喂给 A 载入的行号"**：活块 `rA=mA`、`rB=mB`（clamp 不生效，见 Q3 计数），死块的 B 片段改为读 clamp 行且结果随块丢弃；**store 地址与守卫一字未动**。

## Q2 删掉的是什么真实工作

正常执行路径上的逐条清单（不含 debug、不含编译器早已消掉的源码）：

| # | 删除项 | 静态依据 | 说明 |
|---|---|---|---|
| 1 | K 循环体内 2 个 subgroup-uniform 守卫 | 源 diff：2 个 `if` 在循环内 → 1 个 `if` 在循环外 | 64 个 k 步**全展开**（父 ISA：130 条条件 jmpi ≈ 2×64+2；128 dpas = 2×64），故父在展开体里带 **128 个谓词区域/join**，候选为 0 |
| 2 | 第二次 live 比较 | `OpULessThan` 5→4 | mB 守卫的比较消失 |
| 3 | 一条 push-constant 访问链 | `OpAccessChain` 22→21 | 第二个守卫的取 `pc.p0.x` 链消失 |
| 4 | join 处的谓词/掩码 mov（**预测**） | 同族实测：expand `mov 2551→780`、`指令 7233→4943`、`jmpi 136→7` | 父每步要为两个 join 物化谓词；提到循环外后整段变成直线块 |
| 5 | 每步 `af` 上被 join 强行串起来的 WAR | 源：两个 `coopMatLoad(af,…)` 由不同守卫区隔 → 同一基本块 | join 消失后调度器可重命名/流水，见 Q3 |

不计入删除（避免虚报）：`VIT_STAGE==0` 的 `dbg` store 与 `vit_cubic` 早已被 `#if` 预处理掉；`scratch`（F32 shared 桥）是 T2 父版本之前的历史，本 stage 本来就没有。

## Q3 重叠：原来怎么重叠，删 join 保护了谁的供料

| 值 | 生产者 | 每块消费者 | 最后消费者 | 下一次覆盖 | 关系 |
|---|---|---|---|---|---|
| `b0` (16×16 B 片段) | 每次迭代 `coopMatLoad(b0,w,vit_wbase…)` | `accA0`、`accB0` 两个 muladd | 同迭代末尾 | 下一迭代 load | RAW（load→2×muladd）、WAR（muladd→下一 load） |
| `af` (8×16 A 片段) | A load @rA / @rB | 紧随的 muladd | 同迭代 | 同迭代第二次 A load | RAW、WAR（**父被 join 隔开，候选同块**） |
| `accA0` / `accB0` | 初始化 0 | 每次 dpas 读改写 | epilogue `fma(w,y,acc)` | — | 循环内 RAW/WAR 自链，跨循环 RAW 到 epilogue |
| `context[]` / `o[]` | 外部 | — | — | — | 只读 / 只写；地址与守卫不变 |
| residual `y[]`、`w[]` | 外部 | — | epilogue fma | — | 只读 |

- 两条 dpas 链（A 行块、B 行块）本来就能在同一迭代内交错：`b0` 一次载入喂两条链。
- 父版本里，每条链的**下一次迭代 A 载入**被夹在两个守卫之间：guard 谓词是 subgroup-uniform，但仍是控制依赖 → 载入不能越过 join 提前发射。
- 删掉 join 后，展开体成为单一基本块，A 载入与 dpas 之间只剩数据依赖 → 调度器可把下一迭代的 UGM 载入提前（同族 expand 的可观察证据：`first_dpas 960 → 1608`，即**前置载入增长约 648 条**，最后 dpas 位置基本不变）。
- 目标不是把所有东西串起来：`b0`/`accA0`/`accB0`/epilogue 的供料关系一字未改；被删的只是"控制依赖"。

**RAW/WAR/WAW 结论**：没有引入新的 WAR/WAW；删除的 join 只解除"控制依赖"，不解除任何数据依赖。

## Q4 新增成本（逐项入账）

| 项 | 数量/量级 | 依据 |
|---|---|---|
| 外层 uniform 分支 | 1/subgroup（1280/1536 个 subgroup 走 true 边） | 分支谓词只依赖 `wgid.x`、`sg` → subgroup-uniform，**不产生 lane 掩码**，有效 lane 不变 |
| clamp 标量代数 | `OpUGreaterThan`+`OpISub`+`OpBitwiseAnd`+`OpConstant`+2×`UMin`，每 subgroup 一次 | 三元表达式被 glslang 编成 2 块 selection（不是 select），见下 |
| 新增 Function 局部 | +5（`live`、`last8`、`rA`、`rB` + 1 个匿名临时） | SPIR-V `OpVariable` 50→55，全部 storage class=Function；另有 `OpLoad` +6、`OpStore` +6 全落在这些局部上；**StorageBuffer 10、PushConstant 1、Input 3 全不变**，Workgroup 0。驱动会把 Function 局部 SSA 化成寄存器（父本来就有 36 个同类局部，Scratch=0） |
| **重复 A 读取** | 每列 +4 个片段（36→40）→ 每 dispatch **+131072 条窄 UGM send = +4.19 MB，即动态 A 片段字节 +11.11%**（37.75→41.94 MB/PASS） | `_tools/ledger-math.json`。这 4 个片段全部落在 clamp 行 280..287 = **16 KiB 热区**，且同 WG 的活 subgroup 本来就在读这段 → 命中 L1/L2；`context` 仅 589824 B，整体 L2 常驻，**DRAM 增量≈0** |
| 权重读 | 不变：`b0` 在父/候选都是循环内**无条件**载入（含死块） | 每列 1536 个 B 片段，两版相同 |
| A/B 读取条数（静态） | 不变：`OpCooperativeMatrixLoadNV` 2↔2、`StoreNV` 1↔1 | 分支只是把载入包进一层 uniform 分支，没有复制载入 |
| 地址计算 | `rA`/`rB` 各 1 次 UMin + 复用同一 `r*K` 表达式；`OpAccessChain` 反而 −1 | 无新增每迭代地址运算 |
| 同步/屏障 | 无新增（本 stage 无 shared、无 barrier） | `OpControlBarrier`/`OpMemoryBarrier` 0↔0 |
| 有效 lane / WG 数 | 不变（grid 3 64 1，256 线程） | plan 8 行只改 SPV 路径 |
| 活值峰值 | 累加器数不变（2×4 GRF-dword）；`af` 可能被重命名成 2 个片段寄存器 → 压力 +2 dword | 见 NATIVE 判据 7（spill 检测） |
| 代码体积 | SPIR-V +102 words（2486→2588，+4.1%）；ISA 预期**下降**（同族 −31.7%） | validate 输出 |

`live>0u?((live-1)&~7):0u` 被 glslang 编成 selection（1 个 `OpSelectionMerge` + 2 个 `OpBranch`），因此 SPIR-V 的 selection 计数仍是 4↔4、条件分支 7↔7——**静态计数看起来没变，变的是嵌套关系**：父是"循环内 2 个 selection"，候选是"循环外 1 个 if + 1 个三元 selection"。因为 ISA 是 64 步全展开，native 上才是 128→0 的差别。若要再省，可写成 `last8 = (max(live,1u)-1u) & ~7u`（无 selection），但会偏离 n11 的同机制写法，本卡不改。

## Q5 是否真落到 native（预测 + 判据，不声称已实现）

父身份捕获（`f08-register-chain-20261027/captures/native-f20-pixel-owner/ISA/CS_asm61c5144f4358fd6f_simd32_000000000000001b_26_orig.asm`，pipeline 26，sha `4e3ff2e6…d528`）：**总指令 5407、mov32 797、dpas 128、mov32/dpas 6.227、jmpi 132（条件 130）、send 1115、sync 767、first_dpas 832**。

期望（落地后）：`mov32 ≈ 200–350`（比值 1.6–2.7，锚点＝同族 contract 侧 2.27）、`jmpi ≤ 10`（条件 ≤ 8）、总指令 ≈ 3900–4400、`send 1115` 与 `dpas 128` 不变、`first_dpas` 前移（更深的载入前言）。

**"A 未落地"判据（硬）**：`mov32` 仍在父水位（≥ ~640，即 mov32/dpas ≥ 5.0）或 `jmpi` 仍 ≥ ~100 ⇒ 判 A 类"实现未落地"；**`mov32` 若仍 ~1400 以上（父水位的 1.7 倍以上，mov32/dpas ≥ 10）⇒ 必判 A 未落地**（同时也说明捕获计数口径与父不是同一口径，必须先对齐计数再解释）。

逐条可观察点与数值门槛见 `NATIVE-PREDICTION.md`（8 条，含反例判据）。本节只给预测，**不写"已证明"**。

## 本卡相对任务书字面的一处偏离（必须显式声明）

任务书写"行号 clamp 成 `rA/rB=min(m,last)`（`last=live-1`）"。**本卡实现为块对齐的 `last8=(live-1)&~7=280`**，理由：A 片段覆盖 8 行，若 clamp 到 `live-1=287`，死块会读行 287..294，**越出 288 行（589824 B）的 context 缓冲 7 行**；clamp 到 280 时死块读行 280..287，完全在界内。
- 不放松父的任何前提：父的 T2 头注释已声明"`live` 是 8 的倍数，故 `m<live` 的块覆盖行 `m..m+7<live`"，本卡沿用同一前提；
- 读域上界：父 287，候选 287（**相同**），只是候选多读 4 个落在同一 16 KiB 区域的片段；
- `last8` 只在 `mA<live` 的块内被用于 B 路径（`rA` 的 clamp 恒不生效）。

## 未证 / 未决（写进 RESUME 同项）

1. native 是否如预测落地（本卡零 GPU）。
2. 动态 A 读 +11.1% 的真实代价（是否被 L1 完全吸收）——只能由 native 的 send 计数与性能测得出。
