## 0. 先回答 CARD 规定的「首个候选：互斥阶段共址」——做不出来，缺哪条证明

CARD 要求先做互斥阶段 arena 共址（只在最后消费者退休后复用），并证读域/写域不重叠、屏障覆盖所有 owner。逐 shader 枚举后的结论是**本族没有可做的共址**，三条各自缺的证明写在下面；这不是方向禁令，是这三个身份的具体结构。

### 0.1 F07 C256（本卡站点，44 KiB = nrf_pair 4 KiB + nrf_mean 8 KiB + shT 32 KiB）

| arena | halves / bytes | 写域 | 读域 | 寿命 |
|---|---|---|---|---|
| `shT` | 16384 / 32768 | `[0,16384)` 一次 | `coopMatLoad(a, shT, m0*256+k0, stride 256)`，`m0=8j` → 行 `[8j,8j+8)` | 整个 j 循环；行 `[0,8j)` 在 j‑1 之后才死 |
| `nrf_pair` A 相 | 2048 / 4096 | `[sg*256+acc*128, +128)` → `[0,2048)` | 同 subgroup 的池化块 `base+(r0+k)*16+ch`，k∈{0,1,4,5} → `≤[0,2047]` | 每个 j（8 次），在 `nr_body_stage` 内 |
| `nrf_pair` B 相（父独有） | 同上复用 | `[sg*256+128, +256)` | `nrf_pair[sg*256+128+m*16+c]`（恒等拷贝，无转置） | `main()`，8 次 |
| `nrf_mean` | 4096 / 8192 | `[(4*ly+lx)*K+kk]` → `[0,4096)`，j 循环内逐步写 | DS A 操作数，`rowbase*K+k` 全 16 slot × K | 跨 j 累积，WG barrier 后一次读 |

三条共址尝试与缺的证明：

1. **`nrf_mean` → `shT`：不可能（需新增同步）。** j=0 就要写 slot 8/9 = `[2048,2560)`，而 shT 行 8..63 = `[2048,16384)` 还要被 j≥1 读。subgroup 之间在 j 循环内**没有**同步，行死亡是 per‑subgroup 而不是 per‑workgroup。要做共址就必须为每个 j 加 1 个 WG barrier（每派发 +8），这是**新增同步**，且收益只有声明 SLM 45056→36864，占用率收益在本卡无法测。**缺的证明：每个 j 的 WG 级退休保证**（现有 barrier 只有 3 个 WG 级：填 shT 后、debug 后、body 结束后）。
2. **`nrf_pair` A → `shT`：不可能。** j=0 的 stage 写正好是 `[0,2048)`，即 j=0 自己正在读的 shT 行 0..7。
3. **`nrf_mean` → `nrf_pair`：不可能。** 容量 4096 > 2048 halves，且两者在同一个 j 循环里同时活（池化 staging 进、pooled tile 出）。
4. `nrf_pair` B 相与 A 相**已经**共址（同一数组、同一 subgroup 的 256‑half 槽），所以本 shader 唯一的互斥对已存在；本卡把它**退休**而不是再共址（见第 2 问）。

### 0.2 F18 pre（ord 166/192/212）：arena 已经是最小，且 WAR barrier 不能删

`c3x_pre_c256`（166）单 arena `nr3_gbuf[4096]` = 8192 B，三相位：
(1) gather 写 `[0,4096)`（8 行 × 512 通道）；(2) 投影读 A `[0,4096)`（stride 512，8 个 SG 读同一 A），随后写 narrowed acc → `sg*32 + row*256 + col`，落在 **`[0,2048)`**，即 gather 的**前 4 行**；(3) blend 标量读 `[ps3*256+c3]` ⊂ `[0,2048)`。
声明 8192 = max(各相位) 已经是**峰值**，没有第二个 arena 可共址；而 (2) 的写域与 (1) 的读域（全 4096）重叠，所以第 82 行的 barrier 是**必需**的 WAR 覆盖，**不能删除**（CARD 的禁止项正好命中）。C128（192）与 C64（212）同构（C64 无 gather 相，`nr3_proj[1024]` = 2048 B，同样已最小）。

### 0.3 F18 body / contract：单相位，没有共址对象（且 contract 已有退休先例）

- `c3x_body_c256`（167）`shA[4096]` = 8192 B：expand 写 `[0,4096)`（32 行 × 128 通道），barrier 后 mid 全读 → 只有 RAW，一对相位，没有第二种用途。
- `c3x_body_c128`（193）`shA[8192]` = 16384 B（plan 保留 32768 B，见 §7 未决项）；`c3x_body_c64`（213）= 16384 B，同构。
- `block48_swin_body_2`（168）`shM[16384]` = 32768 B：整块 A 拷入后被 8 个 subgroup 共享（mA 与 sg 无关 = 8× 复用），单相位。
  **注意族内先例**：C128/C64 的 contract（194/214）已经被 `coefficient-reuse-combined` 换成**直接读 global A、声明 0 B**——即「把 arena 整个去掉」这条路在该族已经走过 2/3 宽度。C256 没做，是因为它的复用倍数是 8（C128 是 4），删掉会变成 8× 逻辑全局 A 请求（每 WG 32 KiB → 256 KiB）。这是**下一条具体改动**（见 RESUME），本卡不改。

**结论**：CARD 规定的首选（互斥阶段共址）在本族三条身份上分别缺「每 j 的 WG 级退休保证（需新增同步）」「峰值已最小的证明已成立但无可共址对象」「单相位无对象」。缺的是**可共址的第二个 arena**，不是读域/写域不明。于是本卡执行同一方向里可证的那一半：**退休** `nrf_pair` 的第二个相位（DS 输出暂存），并把生产者的最后一次写出直接落到消费者 tile 上。

## 1. 映射：每个 (lane, component) 代表哪个 (token, channel)

生产者 = DS 投影的 FP32 累加器 → `MAT_H`（8×16 cooperative matrix，`gl_MatrixUseAccumulator`）。一个 dispatch 覆盖 `(wx, wy) ∈ [0,11)×[0,7)`、`sg ∈ [0,8)`，`sg = 2*cb + sy`（`sy = sg&1`，`cb = sg>>1`）。

| 维度 | 取值 | 消费者要求 |
|---|---|---|
| 行 m ∈ [0,8) | 光栅 token `t = tbase + m`，像素 `px = px0 + (m&3)`，`py = py0 + (m>>2)` | `block22_out` 的 io_at layout 0：`((t/16)*(N/16) + c/16)*256 + (t%16)*16 + c%16` |
| 列 c ∈ [0,16) | 输出通道 `group*16 + c`，`group = cb*8 + rnd*4 + j` | 同上，`c/16 = group`，`c%16 = c` |
| 累加器槽位 | `(rnd, j) ∈ [0,2)×[0,4)` → `nb0 = cb*8 + rnd*4`，4 个 acc 覆盖 `nb0..nb0+3` | 32 个 16 通道组 = 512 通道，由 `cb` 与 `(rnd,j)` 唯一划分 |
| lane 内分量 | lane `l` 持列 `l&15`，4 个分量在行 `(l>>4) + 2*ci`（父代码的 `i = m*16+c` 与 `coopMatStore(...,16u,LROW)` 合成的恒等映射） | 与父一致（无转置） |

**一一覆盖证明**（`PROOF.json → ds_output_address_identity`，穷举 `11×7` WG × `{sy}` × 32 组 × 8 行 × 16 列）：

| 项 | 值 |
|---|---|
| 期望元素 | 1056 token × 512 通道 = **540,672** |
| 实际写入 | **540,672** |
| 地址不一致 | **0** |
| 行连续性违例 | **0**（`tbase%16 ∈ {0,8}`，`py0%4 ∈ {0,2}` 结构性成立，与 push 常量无关） |
| 重复写 / 漏写 / 越界 | **0 / 0 / 0** |
| 有效 (wx,wy,sy) 站点 / 被 mask | **132 / 22** |

恒等式（穷举验证，非推导）：`nrf_ds_at(px0+(m&3), py0+(m>>2), g*16+cc) == nrf_ds_at(px0, py0, g*16) + m*16 + cc`。

**尾块**：grid.y=7 但只有 6 行 4×4 tile 在 OH=24 内 → `(wy=0, sy=0)` 的 `py0=-2` 与 `(wy=6, sy=1)` 的 `py0=24` 被父的 `half_ok` 拒绝（22 个站点，逐条列在 PROOF）。像素域 44×24 全覆盖一次；`px=42,43` 两列（OW=44 > valid_W=42）在父与候选**都**写（`half_ok` 不看 valid_W），域不变。`0..` 的 padding token 两侧都不写。

## 2. 删了什么真实工作（正常执行路径，非 debug）

| 工作 | 静态 | 每 WG 动态 | 依据 |
|---|---|---|---|
| `coopMatStore(h, nrf_pair, sg*256+128, …)` DS 暂存 | 4（环体内，×2 轮） | **64** | 8 SG × 8 片段，每片段 128 halves |
| publish `subgroupBarrier()` | 4 | **64** | 每片段 1 次 |
| retire `subgroupBarrier()` | 4 | **64** | 每片段 1 次（SG 屏障执行数 128/WG） |
| 标量 SLM 半字读 `nrf_pair[sg*256+128 + m*16 + c]` | 1（环体内） | **8192** | 每 lane 4 次 × 32 lane × 64 片段 |
| 逐元素 `nrf_ds_at` 调用 | 1 | **8192 → 64** | 每元素 1 次（含 UDiv/UMod/IMul 族） |
| `nrf_write_group` 的标量循环本体 | 1 个循环 | 1 个循环（`OpLoopMerge 8→7`） | 逐元素 `m=i>>4, c=i&15, px=px0+(m&3), py=py0+(m>>2)` |

## 3. 重叠：RAW/WAR/WAW 台账（A、B、每组 acc、残差、norm/den 的生产者/最后消费者/覆盖者）

| 数据 | 生产者 | 最后消费者 | 覆盖者 | 类型 | 本卡动作 |
|---|---|---|---|---|---|
| `shT` | 派发开头 256 lane × 64 half | 每个 subgroup 的 A 读（j=7 最后一读） | 无（直到派发结束） | RAW（填充→读） | 不动；WG barrier 保留 |
| `nrf_pair` A 相 | body 每 j 的 2 个 narrowed 片段 | 同 subgroup 的池化块（j 同轮） | 下一个 j 的同一 256‑half 槽 | RAW + WAR（**intra‑subgroup**） | 不动；2 个 `subgroupBarrier` 保留 |
| `nrf_pair` B 相（父） | DS 片段 `MAT_H` | `nrf_write_group` 的标量读 | 同 subgroup 下一个片段的同一 128‑half 槽 | RAW + WAR（**intra‑subgroup**） | **删除**（读取者与写入者一起消失） |
| `nrf_mean` | body 8 个 j 逐步写（每 SG 自己的 32 通道切片） | DS 投影 A（跨 SG 全 256 通道） | 无 | RAW（**cross‑subgroup**） | 不动；派发中唯一 WG barrier 保留 |
| `nrf_o`（DS 输出） | 每 (group, 像素, 通道) 唯一写者 | 下一派发 `split16 b23` | 无重复写者 | WAW 无（划分唯一） | 写者从标量循环换成 8×16 块写，域不变 |
| `gY`/`imgout`/`dbg` | body 每 j | 后续派发 | — | 不变 | 不动 |
| 池化树（`top/bottom/sum*0.25`） | 4 个 `precise` half 节点 | `nrf_mean` 写 | — | 不变 | **不动**（NoContraction 4 = 4） |

关键点：被删的暂存是**同一 subgroup 自己**的槽（`sg*256+128` ⊂ `sg` 的 A 相区域），所以父用 2 个 `subgroupBarrier` 就够——本卡删掉的正是这对屏障所覆盖的那对依赖，**没有**削弱任何跨 owner 的覆盖。仍然并行的读旧值一处都没有减少：F18 pre 的 WAR barrier、本 shader 的 `nrf_mean` WG barrier、A 相的两个 SG barrier 全部保留。

## 5. 是否真落到 native（预测 + 判据，见 NATIVE-PREDICTION.md）

三条**必须**看到的、否则记 A 类「实现未落地」：

1. DS 区块内 `send.slm`（`store.slm.d16u32` 暂存写 + `load.slm.d16` 标量读 + `fence.slm.none.group`）每 subgroup 从约 56 条降到 **0**；
2. DS 区块内由暂存往返串起来的 `sync.allrd`/`sync.nop` 对消失，DS 片段的 4 个 acc 之间不再有同步边界；
3. 输出 store 的 `send.ugm` 仍然存在（每 subgroup 32 条 16‑bit 存储消息 = 父的标量路径；若驱动把 8×16 连续块降成每 lane 8 B，则降到 8 条，属**二阶收益**，不作为通过判据）。

反例判据：若 native 里 DS 区块的 `send.slm` 计数不变，或输出地址仍由 4 次标量地址计算+4 次 16‑bit 存储构成且没有任何块写特征，则本卡记 **A 类实现未落地**，不得用整体毫秒倒推机制。

## 6. 整体是否更快（本卡不能测）

- 要测的整体量：`f10-weight-return-separation-20261027/plan.txt`（`a024c3c5…`）= base 臂 vs 本卡 `plan.txt`（`ab62b56a…`）= cand 臂；两臂 6 组交替顺序、每组 `--pool --warm 1 --reps 30 --feedback`，540 样本全留，按 6 组均值差给 t(df5) 区间。
- 门：fixed `1755e9c2…`、fb2 末帧 `9c3e511e…`（`warm0/reps2/feedback/save-frames`）、ordinary 末帧 `2b63d4ba…`。
- 归因范围：本改动只覆盖 **1/232 派发**（ord 59）。这条 shader 自身指令 −4.1%（1965→1884；代码区 1540→1462 = −5.1%）、DS 段的同步与 SLM 往返全删，但全网占比未知，**预期单臂可能 INDISTINCT**。若 INDISTINCT，按 D 类处理：不推广成方向禁令，与下一条（F18 contract C256 arena 退休 / F07 C256 register pooling）**分开成臂**，禁止挑显著样本；禁止把本卡毫秒与任何历史批次相加。
- 单链归因只写证据支持的部分：能写「DS 段 SLM 往返与 128 次 SG 屏障执行被删」，不能写「全网因此节省 X ms」。

## 7. 未决项

1. `f3c128_body_ds`（ord 35）plan 保留 32768 B 而 SPV 只用 16384 B（`shA[8192]` halves）——**基线既有的 plan/SPV 不一致**，本卡不动，登记给审计（若 plan 字段是真实分配量，则该派发多占 16 KiB，可能压占用率）。
2. `block56/62_swin_body_2`（194/214）plan shared=0 且 SPV 无 Workgroup 变量，与 FAMILY-STATE 的「F18 body_2 现役接受」口径一致；C256（168）仍 32768 B，差异见 §0.3。
3. 本卡没有 GPU，`unknown` 三项（native store 宽度、GRF 峰值、真实 DRAM/L1 字节）只能在拿到捕获后闭合。
