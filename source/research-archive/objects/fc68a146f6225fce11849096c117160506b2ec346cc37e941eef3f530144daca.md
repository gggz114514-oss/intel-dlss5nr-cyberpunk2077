# NATIVE-PREDICTION — n05a-f05-c256-mreuse

**本文件只写"预测 + 判据"，不声称已实现。** 本卡没有跑任何 GPU 任务。
基准不是猜的：父 SPV（`9d61c4e3…`，与本卡父**字节相同**）在既有捕获里已有 ISA：

* 文件：`…/f05-k-consumer-tile/c256/captures/native-f20-pixel-owner/ISA/CS_asmfd78c91bb8744f0f_simd32_000000000000000e_13_orig.asm`
* 6,834 行，**224 条 `dpas`**（`fence.slm` 前 192、后 32）、1,014 条 `send`、2,353 条 `mov`、1 条 `fence.slm`。
* 与 `…/f05-k-consumer-tile/c256/NATIVE-COST.json` 的 `candidate_native`（send 1014 / mov 2353 / dpas 224 / barriers 1）逐项相等 ⇒ 该 ISA 对应本组 shader 身份。
* **身份限制**：该捕获来自 `native-f20-pixel-owner` 批次，plan 与驱动批次可能不同；F05 C256 的 SPV 字节未变，
  因此指令结构可作基准，但**必须**以本卡 plan 重新 native 才能称"落地"。

## 1. 父的实测分区域计数（基准，不是模型）

| 区域 | `dpas` | `load.ugm.d32x8`（权重，稠密 32 B/lane） | `load.ugm.d32x8t`（A 侧，8 条/tile） | 其它 |
|---|---|---|---|---|
| QKV（`fence.slm` 之前） | **192** | **192** | 512 | `load.ugm.d32x1t` 2（= 每 phase 一次的 `auxf` scale）、`store.slm.d32x8t` 64、`store.slm.d32x4` 4、`store.ugm.d32x8t` 128（debug） |
| attention（之后） | 32 | 8（8 个 score block 的 bias） | — | `load.slm.d32x4` 32（K/V 的 A tile 16+16）、`load.slm.d32x8` 2（`bq0/bq1`）、`store.ugm.d32`/`d32x4` 各 32、1 条 fence |

三个可直接核对的事实：

1. QKV 段 `load.ugm.d32x8` = **192** = 6 权重 tile × 16 ki × **2 个 row_phase** ⇒ 权重被真的发出两遍（不是被 CSE）。
2. `load.ugm.d32x1t` = **2** = 每 phase 一次 `auxf[pc.p5.x+h]` ⇒ **row_phase 在 native 完全展开**。
3. QKV 段 `dpas` = 192 = 权重 load 数 ⇒ 当前是 **1 载入 : 1 DPAS**。
   同时 QKV 段只有 **9 个轮转的 B 寄存器**（192 次 load / 9 个寄存器 ≈ 21 次复用）——
   即返回区深度约 9，不是"每 tile 一个专用返回区"。

## 2. 候选应产生的变化（逐条判据）

| # | 期望在 ISA 里看到 | 判据（若看不到就等于未实现） |
|---|---|---|
| N1 | QKV 段 `load.ugm.d32x8` **192 → 96** | 仍是 192 ⇒ **分诊 A（实现未落地）**：源码改了但权重 load 没合并 |
| N2 | QKV 段 `dpas` **192 → 192**（总数 224 不变） | 变化 ⇒ 数学被改了，必须停下查 |
| N3 | `load.ugm.d32x8t` **512 → 512**（A 侧不动） | 明显下降 ⇒ 编译器重排了 A 供料，收益归因要重写；明显上升 ⇒ 新增 A 搬运，分诊 B |
| N4 | `load.ugm.d32x1t` **2 → 2** | 变 1 ⇒ 编译器 CSE 了 scale（允许，但要记）；变 >2 ⇒ 新增重复 |
| N5 | `store.slm.d32x8t` 64 / `store.slm.d32x4` 4 不变；`fence.slm` 仍 1 | 数量或屏障变化 ⇒ 发布/同步被改了，分诊 B/E |
| N6 | QKV 段 DPAS 目标元组数 **8 → ≥12**，且 8 个 QK 元组在同一段内同时活 | 仍是 8 ⇒ 编译器把两块串行化了（B 无法共享），与此同现的会是 N1 不成立 |
| N7 | 每条权重 `send` 到它的**最后**消费者 DPAS 的距离 ~1 拍 → ~2 拍；在途 send 深度（同时发出未消费）不下降 | 若插入了 `sync.nop`/`allwr` 等等待包，或深度下降 ⇒ 省了 96 条却换成等待，**分诊 B**（F10/F05 已证的返回区耦合退化） |
| N8 | `scratch` 仍 0、`max r` ≤ 127 且无 spill | 出现 scratch 或 spill ⇒ **STOP**（合同的硬门） |
| N9 | `mov` 2353 → 2,300~2,450（可能 +50 量级，用于让两个 A 片段同时活） | 大幅上升（> +200）⇒ 搬运成本吃掉收益，分诊 B |

**总 send 预测**：1,014 → **918**（−96，−9.5%）。这个数字是"QKV 权重 load 减半"的直接结果；
如果实测落在 918 但整体不变快，属于分诊 C/D（机制落地但不在关键路径）。

## 3. 为什么"权重 send 减半"不等于 5 成收益

同一份 ISA 说明：本 shader 的 send 主体是 **A 侧的 512 条 `load.ugm.d32x8t`**（64 个 A tile，每个 8 条），
权重只有 192 条。本卡只动权重：

| | 父 | 候选 | 差 |
|---|---|---|---|
| QKV 段全局 load send（707 = 512 + 192 + 2 + 1 flat） | 707 | 611 | −96 |
| QKV 段 `dpas` | 192 | 192 | 0 |
| 全 shader send | 1,014 | ~918 | −9.5% |

而且这 96 条是**同址重复**：权重每 head 只有 48 KiB，重复读几乎全部命中 cache。
所以本卡省的是 **issue slot / 返回区占用**，**不是 DRAM 流量**。这一点决定了收益上限必须靠整体计时说话。

## 4. 明确的退化来源（native 上如何辨认）

1. **acc 活值峰值（+16 fp32 reg/lane）**：父在 QKV 段已占用 r24…r72 共 8 个 DPAS 目标元组，
   全 kernel payload 最高到 **r112**（上限 r127）⇒ 只剩约 15 个寄存器余量。
   判据：spill（scratch>0）= 硬失败；或 `max r` 顶到 120+ 且同批整体变慢 ⇒ 分诊 B，改用 S2（见 RESUME）。
2. **B 返回区**：9 个轮转 B 寄存器里每个的活值区间翻倍。判据见 N7。
3. **发布顺序**：候选把"块 a 的 Q/K/V"改成"两块 Q、两块 K、两块 V"，屏障前的 SLM 写序变化。
   `store.slm` 计数不变即视为无副作用；若编译器因此插入额外 `fence`/`nop`，按 B 记增量。

## 5. native 采集要求（交主代理）

* 臂：`base`（基线 plan）+ `cand`（本卡 plan），只换本组 16 个 PASS 的 SPV。
* 必须导出的量：`dpas` 总数与分段、`send` 按描述符分类（本文件表 1 的 5 类）、`mov`、`fence`、
  scratch、`max r`、以及 QKV 段内 send→dpas 的发出/使用顺序（用来判 N7）。
* 判据顺序先看 N1/N2/N8（落地 + 数学 + 资源），再看 N7（调度），最后才谈计时。
