# QUALITY - ViT QK static (sQ/sK per head), CPU study

`CPU_ONLY` / `quality_accepted=false` / `GPU_VERIFICATION=NOT_RUN`.
All values are **local ViT attention** relative L2 against an exact-FP16 reference of the same
kernel, on footprint dumps. They are **not** a network-output PSNR, not a temporal-stability
statement, and not a game-quality result.

Artefacts: `tools/s09_qk_static.py` (study + pack), `tools/s09-qk-static-study.json` (raw),
`tools/s09_report.py` (the tables below), `tools/s09-qk-static.log`.

---

## 0. Reference model validity (gate before any conclusion)

The exact-FP16 reproduction of this kernel (score -> `vit_exp` -> 64-key half den tree ->
pad subtraction -> single reciprocal -> PV -> `*inv` -> f16 narrow) was validated against the
FP16 teacher `T` dumps in the previous round:
`tools/vit-validation.json`, **relL2 3.7e-4 .. 4.4e-4 over 8 blocks x 32 heads x 3 frames**,
which is the f16 rounding floor. A wrong reference would have shown up as >=1e-3 here.

Independent cross-check of this round's re-implementation: the 24-combination aggregate below
reproduces the previous card's published numbers exactly (dynamic `T` 0.00538, static `sQK`
0.00581), from a freshly written code path.

| arm | sQ | sK | sV | sP |
|---|---|---|---|---|
| `ref` | exact fp16, no quantisation | - | - | - |

## 2. Headline: 24-combination aggregate

Mean over the 24 (frame, block) combinations of each block's mean-over-32-heads relL2:

| quantity | dynamic (deployed) | static sQ/sK | ratio |
|---|---|---|---|
| score (post-MMA, post-dequant, pre-exp) | 0.00717 | 0.00797 | **x1.111** |
| exp / P (0..127 unnormalised halfs) | 0.01145 | 0.01263 | x1.103 |
| context (PV numerator, pre-reciprocal) | 0.00711 | 0.00792 | **x1.113** |
| **T (final, half, after reciprocal + int8)** | **0.00538** | **0.00581** | **x1.080** |

Per-frame medians across the 8 blocks (dyn -> static):

| frame | score | P | context | T |
|---|---|---|---|---|
| F1-34189 (calibration) | 0.00688 -> 0.00751 | 0.01165 -> 0.01238 | 0.00728 -> 0.00800 | 0.00564 -> 0.00602 |
| F2-41444 | 0.00681 -> 0.00768 | 0.01156 -> 0.01299 | 0.00737 -> 0.00843 | 0.00565 -> 0.00614 |
| F3-43654 | 0.00685 -> 0.00771 | 0.01166 -> 0.01256 | 0.00735 -> 0.00792 | 0.00565 -> 0.00616 |

Read this as an **increment on an already-quantised path**: the deployed int8 attention
already sits at 0.00538 of local T error; closing the two Q/K amax reducers moves it to
0.00581, i.e. **+8.0% on T, +11.3% on the pre-reciprocal context**. The score amplitude grows
less than the context because the reciprocal and the den tree partially cancel the change.

## 4. Attribution: how much is the scale change itself

Same V/P path, only the Q/K step differs:

| comparison | mean | median | max |
|---|---|---|---|
| `static` vs `dyn` context | 0.00928 | 0.00922 | 0.01150 |
| `static` vs `dyn` T | 0.00620 | 0.00672 | 0.00834 |

So the two arms differ by ~1% of the context amplitude - the change is small, uniform and
entirely attributable to the Q/K step granularity (everything else is byte-identical by
construction, see CONTRACT §5.2).

## 5. Saturation (the hard constraint)

Fraction of codes for which `roundEven(v/s)` falls outside `[-127,127]` (i.e. would clip):

| frame | Q codes | K codes | heads with any Q clip | heads with any K clip |
|---|---|---|---|---|
| F1-34189 (calibration) | **0.000%** | **0.000%** | 0 / 256 | 0 / 256 |
| F2-41444 | 0.282% | 0.273% | 120 / 256 | 127 / 256 |
| F3-43654 | 0.141% | 0.273% | 117 / 256 | 127 / 256 |

Interpretation, stated plainly:

* On the calibration frame clipping is **structurally impossible**, because the per-head
  static value equals the largest of that head's five per-tile dynamic values.
* On unseen frames about half of the (block, head) sites clip **a few dozen codes out of
  ~590k** (<=0.28%). This is the expected cost of removing the per-tile adaptivity, and it is
  included in the relL2 numbers above - the study clips exactly like the shader
  (`clamp(roundEven(...), -127, 127)`).
* `P` saturation is **zero in every arm** because `sP` stays per-query dynamic. This card does
  not reopen the rejected static-P design.
* A headroom multiplier (x1.15 / x1.25) would remove this clipping at a measured cost:
  the previous card's sweep gives `sQK` 0.00581 (x1.0) -> 0.00663 (x1.25) -> 0.00755 (x1.5),
  i.e. x1.25 buys zero clipping for **+14%** local T error. The shipped packs are x1.0
  (calibration frame only, no eval-frame tuning); a x1.15 arm is the documented fallback if
  the GPU gate shows the clip is worse than predicted.

## 6. Why static Q/K is cheap here: resolution

`res = median(per-tile/chunk dynamic absmax) / (per-head static absmax)`, i.e. how much of the
dynamic value a static one already covers:

| frame | res Q (median / min / max) | res K (median / min / max) |
|---|---|---|
| F1-34189 | 0.911 / 0.892 / 0.927 | 0.920 / 0.903 / 0.931 |
| F2-41444 | 0.907 / 0.890 / 0.926 | 0.917 / 0.907 / 0.935 |
| F3-43654 | 0.916 / 0.903 / 0.938 | 0.918 / 0.911 / 0.940 |

The dynamic per-tile scale only buys 7-11% of resolution, and it is stable across frames
(<=3% drift), which is why a single calibration frame transfers. This rests on a structural
property, not luck: the producer L2-normalises the row and multiplies by a per-head static
scalar, so the row norm is constant and `max|Q|` is a fixed-norm order statistic; `|K| <= 1`
is a hard bound because K is L2-normalised.

---

## 7. What this study does NOT establish

1. No network-output metric. A local 8% error increment in 8 of 59 attention modules cannot be
   converted into a PSNR or a visual statement (errors do not add linearly).
2. No GPU agreement. The GPU arm must confirm that its T buffer matches this prediction to
   roughly f16 level; a 2x disagreement is an implementation bug, not quantisation
   (`JOBS.json` GPU-01 gate).
3. No statement about scenes outside the three frames. The clip fractions in §5 are the honest
   proxy for that risk, and they are small but non-zero.
4. No temporal/history behaviour: this kernel has no feedback path, but the network does, and
   only a 24-frame run can see it.
5. Nothing about `sV`, `sP`, or the 60 Swin attention modules - all still dynamic.
