## Q1 — Mapping: what does each (lane, component) represent, and does the consumer agree?

**Parent.** `if (sg < 2)`: `t = sg*32 + lane`, so lane *l* of subgroup 0 owns output row *l* and
lane *l* of subgroup 1 owns row 32 + *l*. One lane produces **all four output channels** of its
row: `boundary_project(t)` accumulates `residual.x/.y/.z/.w` over `c = 0..31` from
`shX[t*32+c]` and the four weight planes `wb[17024+c]`, `wb[17056+c]`, `wb[17088+c]`,
`wb[17120+c]`, then stores the four floats at `(py*1280+px)*4 + {0,1,2,3}`.

**Candidate.** `row = 8*sg + (lane >> 2)`, `ch = lane & 3`: lane *l* of subgroup *s* owns output
channel `l & 3` of row `8*s + (l >> 2)`. 8 subgroups x 32 lanes = 256 slots = 64 rows x 4
channels, a bijection; one lane runs the 32-term fold for its single channel and stores one
float at `(py*1280+px)*4 + ch`.

Machine-checked coverage (`tools/tail_model.py`, 25 `(wx, wy)` samples, `tools/tail-model.json`):

| check | result |
|---|---|
| P1 every (row, channel) covered exactly once in each form | pass (64x4 grid, both forms) |
| P2 row to (px, py) map identical (same `q = row/16`, `r = row%16` formula) | pass |
| P3 output address `(py*1280+px)*4 + ch` identical | pass |
| P4 term sequence identical: `c = 0..31` ascending, `shX[row*32+c]` | pass |
| P5 weight planes: `17024 + 32*ch` for ch = 0..3 == parent's wx/wy/wz/ww at 17024/17056/17088/17120 | pass |
| P6 FP operation multiset per output element: 32 multiplies, 32 adds | pass |

The tail block itself is unchanged: `px, py` are clamped by
`px >= 0 && px < 1280 && py >= 0 && py < 720`, and out-of-range rows store nothing — the same
test on the same values, evaluated by four lanes instead of one. There is no tail block beyond
the 64x64-row window: the guard covers the 1280x720 image, and the grid (169 x 97 workgroups,
98.4 % of them in bounds) is untouched.

The other stages' maps are unchanged and are audited in `BARRIER-AUDIT.md` §2 (the intervals
that the remaining four barriers still order).

subgroup's data is consumed, and program order inside a warp is enough. The remaining four

## Q5 — Will it land in native? (prediction + falsification, not a claim)

See `NATIVE-PREDICTION.md` for the full list. The three that decide "landed or not":

1. `sync.bar` **12 to 11** in the captured ISA, and the barrier at `0xE9D0` gone.
2. In the tail region, `store.ugm.d32.a32.bss[a0.0]` **4 to 1**, `load.ugm.d32x16t` **4 to 1**,
   `mul`/`add` per warp **129/126 to ~33/33**, `load.slm.d32x4` stays ~4.
3. `dpas.8x8` stays **64** and `max_r` does not rise; scratch stays 0.

If (1) or (2) does not appear, the card is class **A** (implementation did not land) regardless
of the frame time.

## Q6 — Is the whole thing faster? What to measure, with which arms

I cannot measure (no GPU). The measurement this card needs:

* **two arms, same batch, alternating**: `base` = chain-head plan
  (`accepted/n29-f01-alu-chain-20261027/plan.txt`, sha `d8875665…`), `cand` = this card's `plan.txt`.
  Both arms must be dispatched with the same grid (169 97 1) and the same push — the candidate
  does not touch either, and `cpu_check` is identical.
* **gates**: `fixed` (gold `1755e9c2…`) and `fb2` (gold `9c3e511e…`), then ordinary
  `--pool --warm 1 --reps 30 --feedback` (gold `2b63d4ba…`), 6 alternating pairs x 30 samples,
  `FASTER_95` required; below 0.03 ms a second balanced batch is required (L13).
* **counters**: per-PASS `GpuTime`, `XVE_STALL_BARRIER`, `XVE_STALL_ALUWR` for ord 230 in both
  arms. The hypothesis is directional and specific: `XVE_STALL_BARRIER` down (one of five
  executed barriers gone) and `XVE_STALL_ALUWR` down in the tail (four serial FP32 channels per
  lane to one, and 6 idle subgroups to 0). `XVE_STALL_SENDWR` should be flat (0.029 ms; messages
  are not the mechanism).
* **attribution**: this is a one-PASS change (1/232). Per L12/L3 the frame-level floor for a
  single point is real, so a flat frame with the predicted ISA signature means "landed,
  sub-floor", not "failed" — that is class C/D, not class A. A *slower* frame with the barrier
  gone and the tail's instruction count down would point at the loss of the 4-way ILP inside a
  lane (see `NATIVE-PREDICTION.md` §3).
