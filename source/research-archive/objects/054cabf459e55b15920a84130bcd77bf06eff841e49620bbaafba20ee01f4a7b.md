- `K.validate_spv(spv)` — `spv_validate_cpu.exe`
- `K.ident(p)` / `K.sha(p)` / `K.write_json` / `K.read_json`

**构建身份三件套（每卡必须做，缺一不可）**：
1. 用基线源 + 你的构建配方重编译 → 必须**字节复现**本 PASS 的当前基线 SPV；不能复现就记录工具链/NoContraction 差异，并证明你的候选与父的差异仅来自你的源码改动（浮点 NoContraction 逐条对齐 + operand signature 逐条相等）。
2. `candidate.spv` 必须过 `K.validate_spv`。
3. `plan.txt` 必须过 `K.cpu_check`，且 PASS 替换数、buffer 数、pool 字节与父一致（除你论证过的必要变化）。

**NoContraction 规则**：浮点 Fma 站点的 NoContraction 集合必须与父一一对应（除被删/新增且逐条论证的站点）。整数控制流 opcode 集合 `{128,130,132,134,135,137,138,139}` 按既有做法单独处理。`float_NC_checked` 数写进 BUILD.json。

## 3. 数学与数值合同（严格 FP16 线）

- 每个输出的 K 累加顺序不变；norm/den 归约树不变；half 舍入点不变；残差 seed 先后不变。
- 不顺便改 `exp`、倒数、FMA 收缩、clamp、saturate。
- 布局改动要按 FP 表达式逐项核对，不能只比最后帧。
- scratch 不得相对父增加；无溢出只是门，不是提速保证。
- 有效/无效 lane、WG 数、活值峰值、代码体积变化都要入账。

## 4. 每卡必须回答的六个问题（ANALYSIS.md 逐条，带可核对的清单/表格）

1. **映射**：生产者每个 (lane,component) 实际代表哪个 (token, channel/head/k)？消费者要求什么？给可枚举映射，证明一一覆盖、无漏读、无重复写、尾块正确。
2. **删什么真实工作**：正常执行路径上的 send / mov / shuffle / 转换 / SLM 往返 / 屏障，逐条列，不计 debug 声明、不计编译器已消掉的源码。
3. **重叠**：独立工作原来如何重叠？列 A、每块 B、每组 acc、残差、norm/den 的生产者、最后消费者、覆盖者，标 RAW/WAR/WAW。目标是删工作且保护供料，不是把所有东西串起来。
4. **新增成本**：重复权重/A 读取、地址计算、选择、shuffle、复制、同步、有效 lane 下降、WG 减少、活值峰值、代码体积，全部入账。逻辑字节 ≠ DRAM 字节；片段字节 ≠ 实际 GRF。
5. **是否真落到 native**：逐条给出你期望在 ISA 里看到的可观察变化（指令/寄存器/顺序），以及“若看不到就等于未实现”的判据。你没有 GPU，所以这里写**预测 + 判据**，不写“已证明”。
6. **整体是否更快**：你不能测，所以写清“本卡要测什么整体量、用什么臂、如何归因”。单链归因只写证据支持的部分。

## 6. 分诊（写 RESUME 与回报时必须选一类，不许含糊）

- **C 当前身份无净收益**：实现完整、门通过、整体仍慢/不显著。→ 归因到形状/owner/编译器/候选身份，不推广成方向禁令。
