# NATIVE-PREDICTION — n24-s5-gm-fold（可观察点与判据，不声称已实现）

本卡没有 GPU。下面全部是**预测 + 证伪判据**。判据顺序按合同 §8.5：先判落地（A 类），再判数值/资源，
最后才看整体计时。所有 baseline 计数取自**当前基线 SPV 字节的现有捕获**（producer = pipeline 32，
`CS_asmeeba6b6c2d1da7d1_…_32_orig.asm`，2661 条；consumer = pipeline 33，
`CS_asm4e6ba3ddc1931535_…_33_orig.asm`，1947 条）。

## 0. 主判据（一句话）

**consumer 侧必须出现 `load.ugm.d32x64t` 从 8 增到 ≈40，同时 `load.ugm.d32x8t` 从 256 掉到 ≈0。**
看不到 `d32x64t` ⇒ **A 类（实现未落地）**，不得用毫秒倒推机制。

## 3. 为什么这是可证伪的（不是「希望」）

1. **consumer 半边的形态与 seed 完全同形**：seed 是 `coopMatLoad(seed, imgin, addr, 16u, LROW)`，
   8×16 f16、stride 16、RowMajor，当前 ISA 里正好 8 条 `load.ugm.d32x64t`（每条 256 B）。
   候选的 A 载入是 `coopMatLoad(a, gM, base + k0*8, 16u, LROW)`，**同一个类型、同一个 stride、
   同一个 layout、同一个 256 B 对齐**（`mapping-proof.json` 证明 tile 基址是 128 half 的整数倍）。
   所以「会不会合并」不是新问题，而是**同一 kernel 里已经发生过的代码形态**。
2. **producer 半边的对齐也是 256 B**（`(w*64+m0)*128 + 256g`，全项都是 128 half 的倍数），
   但「连续 store 合并」在**本 kernel 内没有先例**，只有语料级证据（82 条 `store.ugm.d32x64t`，
   14 个 pipeline）。因此 producer 半边被单列为**较低置信度**。
3. 判据把两侧分开：**consumer 落地 + producer 未落地 = 部分落地**（仍记 A，但可只归因 consumer 的
   473,088 条/帧）。

## 4. 数值判据（先于计时）

| gate | gold | 要求 |
|---|---|---|
| fixed | `1755e9c2fadba97f08cb5b02b7a4294cde3675379bdec75352287505f7e129d6` | 逐位相等 |
| fb2（gates） | `9c3e511e97a5879247bc2965792c96dd62928dddfd85a48bbf25af1e807d3536` | 逐位相等 |
| ordinary | `2b63d4ba1967eebcda61698d538963f59bccaf6d690ef8168f1695a46c5d658d` | 逐位相等 |

本折叠是**纯地址置换**（元素 → 值的映射逐点不变，穷举已证），因此任何一位差异都是实现错误
（E 类），不是「方向无效」。最可能的错误形态（按概率）：producer 把 `acc1` 的列 tile 写到 `+16`
而不是 `+128`（症状：每 8 行里后 16 列错位、fixed 帧错）；consumer 忘了 `k0*8`（症状：只用 k 的前
16 个通道，其余重复读同一块）。

## 5. 若落地但 ordinary 为 D

按卡与 n16 的预注册规则：把「全局 store→load 布局折叠」这条轴（N16 的 S1–S7）**按 D 关闭**，
不再逐站点试；只在 RESUME/CAMPAIGN 记录该方向已被单读者、可逐字节证明的代表站点否证。
若落地且 ordinary 为 FASTER_95，则同一机制值得扩成 ViT 的 S1–S4 包或 Swin 的 S6 包（另开卡）。

## 6. 本卡不预测、也不声称的东西

- 不预测毫秒（L12/L13：2 PASS 作用域低于检出限，且消息下降可能被并发 WG 遮住）。
- 不声称 DRAM 字节下降（只降消息数）。
- 不声称 producer 的 `store.ugm.d32x64t` 一定出现（U1）。
