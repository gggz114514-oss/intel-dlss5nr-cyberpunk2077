# n25-f04-c64 — NATIVE 指纹与判据（BLOCKED 卡；不声称任何已实现）

本卡无候选，所以**没有"预期变化"**。本文件给两样东西：

1. **三宽度可比指纹**（§1–§3）—— 后人拿到 new capture 后可直接对表，判断身份是否漂移；也是任何 F04 新方案的基线。
2. **反证判据**（§4）—— 什么样观测会推翻本卡的 BLOCKED 判定。

所有数字由 `cost_breakdown.py` 从 current-identity ISA 现算（脚本内置断言：消息总数与 DPAS 数必须等于源码推导值）。

**从表里能直接读出的三个不变量**

1. `d32x64t` 的 **post 恒为 4**（= 合约 4 个残差 seed），只有 **pre** 随宽度变（32 / 64 / 128 = `4 hb × Ki × 2`）。**若某次捕获的 post ≠ 4，seed 结构被动了。**
2. `d32x8t`（`scale`）**恒为 16** —— 源码 4 次读、2 个唯一 tile、编译器 CSE 后 2×8 行。**若变成 32，说明 CSE 掉了（源码被改成不连续）；若变成 8，说明源码真的只读了 2 次。**
3. `store.ugm` 恒为 **224**（pre 160 = 128 debug hidden + 32 debug mLocal；post 64 = 32 生产 gY + 32 debug gY），**宽度无关**。debug 路径的 192 条是死代码。
4. `d32x8` 的 post 恒为 `2×Ki`（8 / 16 / 32 = 合约权重），pre 恒为 `4·Ki·2 + 16`（expand W + middle W）。

## 4. 反证判据：什么观测会推翻本卡的 BLOCKED

| 若在 current-identity 捕获上看到 | 推翻本卡的哪条结论 | 本卡应变成什么 |
|---|---|---|
| `load.ugm.d32x8` ≠ 56（pre≠48 / post≠8） | 权重读已在 L20 下界 | 重开，找可合并的权重读 |
| `d32x16t`/`d32x32t`/`d32x64t` 出现在 exec16 或 exec32 | `512B_per_message` | 权重/A 合并变成候选 |
| `Workgroup Memory Size` > 8192，或 `shared` 有未用空洞 | `shared_budget`（SLM 无处放权重暂存） | SLM 广播路线需重估 |
| `max_r` < 127 | `GRF_ceiling`（GRF 已顶格） | **seed 复用（+8 GRF）变成可支付** —— 这条最先受益 |
| `load.ugm.d32x8t` ≠ 16 | `scale` 已被 CSE 到 2× | `scale` 去重重新成为 −2 条候选 |
| 相邻同址重复 send 对 > 0 | ISA 无未 CSE 的重复读 | 出现新的可删重复 |
| `store.ugm` ≠ 224 且变化不是 debug 段 | debug 段是宽度无关死代码 | 需重新划生产/调试边界 |
| `dpas` ≠ 112 / `sync.bar` ≠ 1 | 数学或发布结构被改 | **立即停**（不是本卡结论被推翻，是实现错误） |

**"看不到即 A 类"的对应写法**：上表"应当看到"的一列就是本卡对当前身份的预测。
若新捕获与 §1–§3 逐项相符，则**不存在**新的可删机制 —— 这正是本卡的结论；
若不相符，按上表定位是哪一条被推翻，再决定开卡与否。

## 5. 给后续 F04 卡的复用方式（三步）

1. 用 `cards/n25-f04-c64/cost_breakdown.py` 重跑一遍（改 `WIDTHS` 即可换族/宽度），确认 §1 的 12 类消息与 §2 的 `dpas` 全部对上 —— 对不上就是身份漂移，先别动手。
2. 任何新方案先回答一句：**"它作用在权重（67.3% 的生产字节）还是作用在一侧很小的面上？"**
   C64 的权重占 67.3%、expand A 只占 19.2%；一个只动 A / seed / `scale` / SLM 行的方案，作用面天生够不到主导成本。
3. 再回答：**"它需要更多活值吗？"** 三个宽度的 `max_r` 都是 127，数据侧峰值也是 127 —— 需要更多活值就必须先说清寄存器从哪来。
