============================================================
0. 一句话结论
============================================================
F2 可以按名字对齐（同阶段、同 push、同 0..6 绑定，真的只换了 dtype）。
F20 不能：FP16 的 32→4 出口投影在融合核 s37 内部（16 个 FP16 coopmat），
INT8 把它搬到 surfaces 核里做标量 fp16 点积，中间体从 fp32 4 浮点/像素
（14,745,600 B）变成 fp16 32 通道/像素（66,060,288 B）。INT8 的 F20 链是
round4 时代的 32 通道尾，不是现役 s37 尾。这是本卡唯一的 BLOCKER。

2. 已证实的事实（可复算）
============================================================
* 基线复算吻合：mean 29.6088375 dB、pooled RMSE 0.033120260、min 29.2644571，
  与 QUALITY-24.json 完全一致（本卡自己的统计口径 = 平面 0 RGB、peak 1）。
* dtype 复核（独立于 ledger，全 288 派发 / 60 SPV）：
  INT8 计划 = 0 个 FP16 coopmat、2062 个 INT8 coopmat、0 个 dp4a；
  FP16 计划（232 派发 / 39 SPV）= 0 个 INT8、4459 个 FP16。ledger 结论成立。
* 但“FP16 矩阵 = 0”只对 coopmat 成立：INT8 计划的出口核一次 coopmat 都没有，
  却每像素做 4×32 次 fp16 乘 fp32 累加（117.9M MAC/帧）。属残余 FP16 标量矩阵（R3）。
* F2：两侧 push 32/32 字完全相同、绑定 0..6 同名同长、几何同为 84×48；
  INT8 只多出 7..10（32,768 B 权重 + 656 B 尺度 + 51,200 B body 权重 + 640 B 尺度）。
  53 vs 129 个 MMA 是 K16→K32 合并，不是丢阶段。→ 可按名字对齐。
* F20：s37 与 b70 的 push 0..15 相同、网格同为 169×97、local 32 相同；
  s37 的 p4=(17664,17696,1) 正好等于 postblend 的 skip gain 半偏移、main scale
  半偏移（17664+32）与使能位，p7.xy=(672,384) 等于 postblend 的粗网格 →
  证明 FP16 侧“折叠”被做进了 s37，INT8 侧拆成 ioport_block70_0。
* postblend 是纯 fp16 混合（0 矩阵、无 127 常量、无 FAbs）：写满 66,060,288 B
  （4 tap × 672 × 384 × 16 对 = 16,515,072 f16vec2，字节数精确等于缓冲长度）。
* 出口核：plane 0 = clamp(fma(min(ctl7,1), rgb−base, base))；实测 ctl7≈1，
  所以 plane 0 ≈ plane 1（99.5%+ 像素逐位相同）→ 显示值就是反馈值。
* alpha：p5.w bit0 = 0 → 恒定 1.0，24 帧 max|ΔA| = 0.0（R6，结构性无风险）。
* 历史 plane（不参与任何现有指标）：RMSE 0.0331213 ≈ 显示 RMSE 0.0331203；
  blend 权重 MAE 0.204、最坏 0.734（R4：本卡最该被量化的量）。
* 空间结构：误差随内容而非网格分布 —— 梯度最高四分位占 51.9% SSE（平坦 7.6%），
  32×32 块 p95/p50 = 3.10，无 tile/window 周期（峰值仅占谱 3.9%/6.7%）→
  没有尾层布局 bug 的形状证据。
* 通道偏置：R +0.00952、G −0.00771、B −0.01096；B 通道每项指标最差。
  单看 DC 修正在样本内 +0.372 dB，6 参数仿射 +0.621 dB（α = 0.925/0.978/1.030），
  逐帧 oracle 也只到 30.39 dB → “只是全局颜色”不成立（R11）。

3. 具名阻断（不可绕过，需主执行裁决）
============================================================
B1（R1）F20 阶段边界：s37 = 折叠 + body + 32→4 投影（输出 fp32 vec4/px）；
         INT8 = postblend + body（输出 fp16 32ch）+ 出口核（做 32→4）。
         集成必须逐阶段选择：(a) 把 INT8 只放进 s37 的 14/16 个位点（改动小、
         质量风险小，需在 s37 里新建 INT8 投影位点），或 (b) 整段换成 round4 尾
         （结构级替换，+132 MB/帧流量，必须整网重测）。二选一前不得宣称
         “INT8 与 FP16 只差乘加类型”。
         判别实验 = JOBS J1：现役 FP16 计划自身回放是否仍对捕获输出逐字节闭合。
B2（R7）DYNAMIC-SCALE-REMAINDERS 把 F2 / F20 / b39 记为 UNKNOWN，源码证明它们
         是 DYNAMIC：F2 “无任何静态激活尺度”（c32_i8_common.glsl L18-27/L42）；
         b70 有 8 个核内 amax（X,E,Y,Q,K,P,V,Ctx）；b39 有 1 个位点。
         建议 UNKNOWN→DYNAMIC_RUNTIME，总数 190 → 190 + 10 具名。
B3（R10）没有尾层局部臂：blended/body 都是 resident、无 dump。任何“尾层占误差多少”
         的说法现在都无法成立（JOBS J4 受 runner OUTPUT half 支持未证所限）。

4. 是否建议优先
============================================================
不建议优先“细化尾层量化”，建议优先“验证尾层 + 先定阶段边界”。
理由：出口的最后一个矩阵两侧都是浮点，细化它不能消除上游量化误差，只会新增风险；
误差无网格/周期签名，说明尾部没有布局 bug；真正未被测量的两个量（blend 权重、
history 面）恰好是唯一能让连续反馈不稳的量；而 INT8 的 F20 链在集成时可能被整体
替换，此刻在它上面做细化有做废的风险。
顺序：J1/J2（把 blend 与 history 变成可测量）→ R11 通道增益定性（是尺度 bug 还是
噪声）→ J3（8 帧自主反馈）→ 再决定是否按 (a) 在 s37 内做 INT8。
