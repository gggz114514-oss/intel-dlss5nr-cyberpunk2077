# CHAIN-AUDIT — n29-f01-alu-chain（F01 / ordinal 0 / `f1c32_image_pre`）

本文件是**任务 A** 的交付：在当前身份 ISA 里重建入口区的依赖链，给出「链上指令数 / 旁支指令数 / 链深度」，
并判定哪一段链**允许**被缩短（数学等价）而哪一段不可。

## 1. lane 坐标 → 73 条 gather 的地址

### 1.1 lane → pixel

`nrf_prepare_A(q=sg)`，`lane<16` 的 lane 各负责一个像素（`local_size_x=128`，4 个 SG）：

```
token  t  = 16*q + L                    (q = sg = 0..3, L = lane 0..15)
xl = 4*(q&1) + (L%4)      yl = 4*(q>>1) + (L/4)
px = WGID.x*8 + xl        py = WGID.y*8 + yl        (grid 168x96 => px<=1343, py<=767)
sx = px<1280 ? px : 2*1280-2-px      sy = py<720 ? py : 2*720-2-py      (镜像折回)
```

4 SG × 16 slot = 64 个 slot ↔ 8×8 tile 的 64 个像素，**一一覆盖**（P5：`equals_8x8_tile=true`，
每 SG 内 16 个互异）。映射到源图后：921600 个互异像素 + 110592 个反射重复 = 1032192 个 slot（P5 实测）。
另外 `if(lane<16u)` 之外（lane 16..31）**不做任何工作**：入口区只用到一半 lane。

### 1.2 pixel → tap / corner / channel

| 站点 | 地址公式（父 → 候选是否改动） | gather 数 |
|---|---|---|
| 源像素 `sampled` | `pc.p4.z + mirror(sy,H)*W*4 + mirror(sx,W)*4 + 4*ch`，ch=0,1,2 → **候选删掉两个 mirror** | 3 |
| 冷噪声 `noise` | `pc.p4.w + (py*1344+px)*3 + 4*ch`，ch=0,1,2 → 未动 | 3 |
| 深度 3×3 | 中心 `mirror(xy)` → **候选改为恒等**；4 邻 `xy+(±1,±1)` 仍走 `nrf_depth_at`（真会越界） | 5 |
| 历史 5 tap × 4 角点 × 3 通道 | tap∈{p0,pm,p2 组合}，corner (0,0)(1,0)(0,1)(1,1)，`clamp(ij+d,0,hi)` → **候选把 0 下界删掉** | 60 |
| 运动矢量 | `pc.p6.z + (mirror(...)*W+mirror(...))*2`，读 2 个 float → 未动 | 2 |

`ij = floor(pos-0.5)`，`pos` 由 `nrf_history5` 先 `clamp` 到 `[0.5, (ctl9,ctl10)-0.5]`，所以 `ij∈[0,W-1]×[0,H-1]`。
`W = ctl(9) = 1280`，`H = ctl(10) = 720` —— 与本卡 P1/P2/P4 的取值一致。

### 1.3 执行掩码：本帧真正执行的只有 6 / 73 条 gather（**本卡最重要的发现**）

入口区（`0x0390..0x4A90`，`lane<16` 的整段 body）= 1351 条指令、73 条 gather。
用本帧自己的 uniform 常量判定：`ctl(8)=0.0`，而 shader 的 `if(nrf_ctl(8)!=0.0){…}` 被编译成

```
[0C60] cmp (ne)f1.0 null r70.3 0.0S          // f1.0 = (nrf_ctl(8)!=0)
[0CD0] (W&~f1.0) jmpi L14160                 // =0x3750  => 整段 history+depth+motion 被跳过
```

再叠加 `flags&4 = 4`（冷噪声取夹具字段而不是 PCG）：

```
[3798] (W&f3.0) jmpi L14416                  // =0x3850  => PCG 噪声分支被跳过
[3840] (W) jmpi L18336                       // =0x47A0  => 直接跳到打包/SLM 段
```

| 段 | 地址跨度 | 指令 | gather | 说明 |
|---|---|---|---|---|
| live | `0x0390..0x0CE0`(168/3) ∪ `0x3750..0x3850`(18/3) ∪ `0x47A0..0x4A90`(48/0) | **235** | **6** | 源像素 3 + 冷噪声 3 |
| skipped | `0x0CE0..0x3750`（history/depth/motion） | 844 | 67 | ctl(8)=0 |
| skipped | `0x3850..0x47A0`（PCG 噪声） | 272 | 0 | flags&4 |
| 合计 | `0x0390..0x4A90` | 1351 | 73 | |

因此：**卡面假设的「73 条 gather 的地址链」在本身份里 62.5% 的指令、91.8% 的 gather 根本不执行**。
真正的入口热链只有 6 条 gather，其中 3 条（源像素）带着两个 `nrf_mirror` 的 32 位除法簇。
（live 段里 `sync.nop/sync.allrd/send.slm` 各 1–2 条，是 barrier 与 SLM 写，不在地址链上。）

## 2. 链 / 旁支 / 深度（任务 A 的正表）

口径：`chain` = 从 73 条 gather 的 send 反向切片（按最后一次写寄存器的到达定义）在 region 内的并集；
`int-tail` = 切片里只经过整数 ALU、在 float/内存边界停下的那一段（= 本卡**可以合法改写**的部分）；
`side` = region 内不在 chain 并集里的指令。深度在主指标里每条边记 1；`wdepth` 是按典型 ALU 延迟加权
（`mul/macl/mad`=5、`add/sel/cmp`=4、`mov`=1、`send`=20、`math.inv`=8）。

**表 1 — region 总账（静态）**

| 指标 | 值 |
|---|---|
| region 指令数 `0x0390..0x4A90` | **1351** |
| 链上指令数（73 条 gather 的并集，region 内） | **403** |
| 旁支指令数（region 内不在链上） | **948** |
| 其中整数地址尾（可改写，region 内） | **305** |
| 链深度（region 内最长路径） | **48**（源像素 3 条为 22；冷噪声 3 条为 8） |
| 整数尾深度（最深一条 gather） | **20**（源像素 3 条为 19；冷噪声 3 条为 9） |
| 加权深度（最深一条 gather） | 201（源像素 89；冷噪声 35） |
| 整数尾规模 | 单条 9–53 条（源像素 3 条 = 53） |

（链节点的完整集合是 408 个，其中 5 个在 region 之前的 prologue 里：`0x040/0x050/0x060/0x0A0/0x0C0`，
即 lane id 与 payload 拷贝；表内一律用 region 交集 403。）

**表 2 — 链 vs 旁支按指令类（region 内）**

| 类 | 链上 | 旁支 |
|---|---|---|
| `mul/macl/mad` | 51 | 255 |
| `add/add3` | 95 | 134 |
| `bit (shl/shr/and/xor/bfn)` | 79 | 119 |
| `sel/cmp` | 34 | 143 |
| `mov` | 57 | 198 |
| `math/round (inv/log/sqt/cos/rndd/frc)` | 14 | 24 |
| `send` | 73 | 7 |
| `ctrl/sync (jmpi/goto/join/sync)` | 0 | 68 |
| **合计** | **403** | **948** |

**表 3 — 只有 live 段才是钱（按执行掩码重算）**

| 指标 | live（235 条） | skipped（1116 条） |
|---|---|---|
| gather | 6（源像素 3 + 冷噪声 3） | 67 |
| 链上指令 | **81** | 386（与 live 有 64 条重叠：81+386-403） |
| 整数尾 | **69** | 293 |
| `math.inv`（32 位除法的倒数） | **2** | 11 |
| `macl` | 8 | 30 |
| 链深度 | 源像素 22 / 冷噪声 8 | 最大 48 |

结论：入口区**真正在跑**的地址链 = 81 条指令 / 69 条整数尾；其中源像素 3 条 gather 独占 53 条整数尾，
那 53 条里约 38 条是 `nrf_mirror` 的 32 位取模（`math.inv` 倒数 + Newton `mad` + `macl` 余数 +
`asr/xor` 符号修正 + 2×`sel` 反射），其余是 `mad` 行基址 + `shl`×4 + `add`。

## 4. 任务 A 的判定：哪段链允许缩短

| 候选方向（CARD B） | 判定 | 依据 |
|---|---|---|
| **B1 div/mod → 移位/掩码** | **不可用** | 取模的除数是 `period = 2*size`：本身份 `2*1280=2560`、`2*720=1440`，**都不是 2 的幂**；且 `W/H` 是运行期 uniform（ctl9/10），编译期无法化为移位。ISA 里对应 `math.inv`+`macl` 形式，不是 `udiv`。 |
