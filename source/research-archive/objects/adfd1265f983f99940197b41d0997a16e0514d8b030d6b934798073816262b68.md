## 2. 计划语法（必须用共享 planlib 解析，不要字符串全替换）

```
PORT_NETWORK_1 <distinct_pass_numbers> <buffers> <dispatches> <outputs>
BUFFER "<name>" <bytes> "<file-or-dash>"
PASS <group-number> "<name>" "<spv>" <n0> <n1> <n2> <g0> <g1> <g2> ...
BIND <binding> <buffer-index> <offset> <bytes>
PUSH <uint32...>
OUTPUT <buffer-index> <format> "<file>"
POLICY <buffer-index> <resident> <first-dispatch> <last-dispatch> <clear-first>
```

关键事实：
- `PASS` 的数字**不唯一**（同一 group 多个 dispatch）。主键是 0 基 dispatch ordinal（PASS 出现顺序）+ name + SPV SHA。
- 所有 `OUTPUT` 连续放在 `POLICY` 之前；`POLICY` 在索引 2 的字段才是 resident，末项是 clear-first。
- BUFFER 名称不是资源 ID；BIND 用 0 基 buffer index。
- Windows 路径统一正斜杠。
- 改 buffer 字节数时，必须同步所有 `BIND` 中引用旧全长的 bound；否则 runner 可能截断或越界。
- `planlib.py` 在 `W/tools/`，提供解析、逐字节 round-trip、按 buffer 名打补丁、按 dispatch ordinal 换 SPV、结构校验、diff、SHA。

## 3. 数据与 dump 的使用限制（重要）

- dump 文件多数是 **little-endian fp16**（`.bin` 大小 / 2 = 元素数）；`dump_c64_*_qx.bin` 等是 int8 或 packed，不能一律按 fp16 读。
- **FP16 教师 dump 可用于标定**：它是 FP16 网络真实中间值，`dump_block*_out.bin`、`dump_swin_*_Y/T/M.bin`、`dump_split16_*`、`dump_vit_*` 在 FP16 目录下语义相对可信；但引用前必须核对 dtype、布局、shape、文件大小。
- **INT8 中间 dump 不可当作逐元素 oracle**：本会话已核，除极早期边界外，多数 INT8 中间 dump 与 FP16 同名的 relL2≈1（缓冲复用/布局/阶段语义不同），只有 `replayed-network.bin` 与最终输出可靠。不要把死的/零 dump 当证据。若需要 INT8 局部 oracle，必须用受控 local arm（GPUS）另建，不在本轮。
- 现有受控局部臂：`D/c64-stage/`、`D/c64-b6-reconstruction/`、`D/family-isolation/`、`D/local-resident-v2/`。其中 `c64-stage/QUALITY.json` 的 CPU 参考与 GPU Y 逐位一致（audit relL2=0）。
- 不得把“CPU 估计”说成 GPU 结果；不得把单帧/单块结果外推到全网。
