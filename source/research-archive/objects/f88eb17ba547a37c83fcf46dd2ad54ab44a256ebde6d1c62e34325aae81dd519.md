## Q1 映射：每个 (lane, component) 代表哪个 (token, channel/dim)，消费者要什么

### 1.1 几何（三组完全一致，只有 K 的通道数不同）

一个 WG = 256 线程 = 8 个 SG（SIMD32）。`h = 2·WG.z + sg/4` ⇒ **每组 4 个 SG 服务一个 head**，
两 head 并发。每个 head 64 token × 32 dim。`t = sg%4` 是 token 块 owner。
所有 coopmat 形状：`MAT_A` 8×16 half（4 comp/lane）、`MAT_B` 16×16 half（8 comp/lane）、
`MAT_C` = `MAT_H` 8×16（4 comp/lane）。

### 1.2 生产者（QKV 投影）

| 张量 | 落点（section 内 half） | 写者 token | 元素 | 地址式 |
|---|---|---|---|---|
| Q | `[0, 2048)` | SG t：`m0 = 8t + 32·row_phase`（C256：`m0a = 8t`、`m0b = 8t+32` 同遍） | (token `m0+r`, dim `c+16·i1`) | `base + m0*32 + r*32 + c + 16·i1`（LROW 32，8 行 × 16 列，两个 half-tile） |
| K | `[2048, 4096)` | SG t：同上 16 token | (key `8·slot%… `, dim) | `base + 2048 + slot*128 + dim*8 + key%8`，`slot = 2·(m0/8) + key/8`（LCOL 8） |
| V（**候选**） | `[0, 2048)`（退役的 Q 平面） | SG t：**token `16t..16t+15`**（两个 M8 块 `vt`、`vt+8`） | (token, dim) | `base + 0 + vt*32 + r*32 + c + 16·i1`（LROW 32） |
| V（父） | `[4096, 6144)` | SG t：`m0 = 8t + 32·row_phase` | 同上 | `base + 4096 + m0*32 + …` |

**一一覆盖（可枚举）**：`build/lifetime.json.regions` 对每个 half 地址逐点枚举：

| | 父 | 候选 |
|---|---|---|
| Q | 2048 个地址，`[0,2047]` 连续 | 同 |
| K | 2048 个地址，`[2048,4095]` 连续 | 同 |
| V | 2048 个地址，`[4096,6143]` 连续 | 2048 个地址，`[0,2047]`（= Q 平面） |
| 每 head 合计 | 6144 half = 12288 B | **4096 half = 8192 B** |
| 每 WG 合计 | **24576 B** | **16384 B** |

无漏写、无重复写：每个 (token, dim) 在 Q/K/V 各出现**恰好一次**
（`v_token_ownership.parent_is_partition = candidate_is_partition = true`，
`each_token_stored_once = true`；4 个 owner × 16 token = 64，无余数）。

### 1.3 消费者要什么

| 消费者 | 读的地址集合 | owner 关系 |
|---|---|---|
| score 的 `Q^T`（B 操作数，LCOL 32） | `base + qg*32 + n*32 + dim`，`qg = 16t` ⇒ **`[512t, 512t+512)`** | **只读自己那 16 个 query** |
| score 的 K（A 操作数，LCOL 8） | `base + 2048 + slot*128 + …`，16 个 slot ⇒ **全部 2048 half** | 跨 SG |
| PV 的 V（A 操作数，LCOL 32） | `base + 0 + key*32 + dim`（候选）⇒ **全部 2048 half** | 跨 SG |

`Q^T` 的 16×16 B 操作数在 C64/C128 的源码里写在 8 个 key block 内（每个 block 各读一次同一地址），
**既有 native 证明 IGC 已把它 CSE 成 2 条 `load.slm.d32x8`**（n05e 普查：`32 d32x4 + 2 d32x8 = 34`
= 16 K + 2 Q + 16 V），所以父的有效 Q 读就是 score 段开头的两次读。C256 的父本来就把它提升到 block 外
（`bq0/bq1`）。**本卡不改这个结构**。

### 1.4 尾块

无尾块：64 token = 8 个 M8 块（整除），K = 64/128/256 = 4/8/16 个 k-step（整除），
V 的 owner 划分 4 × 16 token（整除）。图像边界（`pc.p1.z` 单点模式、window OOB token）
的零填充位置、取值与数量一个字未改——本卡不碰 `v00/v10/v01/v11` 那套判定（C64/C128）
以及 `w/pc` 推导（三组），也不碰 score 的 `auxf`/可视化地址。

## Q2 删掉什么真实工作（只看正常执行路径；debug 声明、UP 掉的源码不算）

| 项 | 父 | 候选 | 依据 |
|---|---|---|---|
| **每 WG 声明的 SLM** | 24576 B | **16384 B** | SPIR-V Workgroup 求和（三组 24576→16384） |
| **每 SM 驻留 WG** | 2 | **4** | 两次探针夹出 P∈[65536,73728)，两端 `floor(P/W)` 都是 4（见 SLM-LIFETIME.md §4.2） |
| DPAS / SG | 80 / 128 / 224 | 80 / 128 / 224 | `build/lifetime.json.dynamic_messages`；C128/C256 与既有 ISA 的 128/224 相同 |
| SLM load / SG | 34 | 34 | 16 K + 2 Q^T（CSE 后）+ 16 V；与 C128 父 ISA 的 34 逐项相等 |
| SLM store / SG（发布） | 6 | 6 | Q2 + K2 + V2 |
| UGM A tile / SG | 8 / 16 / 64 | 16 / 32 / 64 | V 段独立后必须自己读 A（C256 父本来如此） |
| UGM B tile / SG | 48 / 96 / 96 | 40 / 80 / 96 | V 权重被两个 M 块共享 |
| WG barrier（动态） | 1 | **3** | `OpControlBarrier` 1→3，三组同作用域签名 |

**真正被删的只有一样东西：那 8192 B 的第三个平面**（以及它带来的驻留约束）。
没有删任何消息类型、没有删 DPAS、没有删 SLM 往返、没有删 barrier（反而加了 2 道）。
"省下的消息"只在 C64/C128 的 B 侧出现（V 权重跨 M 复用 −8/−16 个 tile），
但被 A 侧重读完全吃掉还有余（见 Q4）。**本卡不靠删消息交差**。

## Q3 重叠：谁生产、谁最后消费、谁覆盖，RAW/WAR/WAW

### 3.1 父的时间线（源码顺序）

```
P1 QKV 投影: Q 写 / K 写 / V 写   （三平面互不相交，各 512 half/SG）
P2 barrier()                       （发布 Q/K/V）
P3 debug V echo（读全 V）
P4 score: Q^T 读（自己 16 query） + K 读（全 64 key，8 个 block）
P5 den 树 / P := half(P*inv)       （纯寄存器）
P6 PV: V 读（全 64 key）
P7 gT 直存（全局）
```

| 值 | 生产者 | 首个消费者 | 最后消费者 | 覆盖者 | 父的约束 |
|---|---|---|---|---|---|
| Q 平面 | 4 个 SG 各 16 token | — | score 的 `Q^T` 读（只自己那 512 half） | 无（本 PASS 不再写） | 跨 SG RAW，由 P2 关闭 |
| K 平面 | 4 个 SG 各 2 slot | — | 第 8 个 key block 的 A 读 | 无 | 跨 SG RAW，由 P2 关闭 |
| V 平面 | 4 个 SG 各 16 token | debug echo | PV 第 4 组的 A 读 | 无 | 跨 SG RAW，由 P2 关闭 |
| P 片段（8×MAT_H） | score DPAS | den 树 | PV 的 `nrh_join_rows_to_B` | `P*inv` 就地覆盖 | 寄存器，跨 P5 存活 |
| PV 累加器（4×MAT_C） | PV DPAS | — | `gT` 存 | 无 | 寄存器 |

**父的寿命区间两两重叠**（Q/K 同写同读，V 的写早于 Q 的最后读）⇒ **父的顺序里没有可重叠窗口**，
峰值活值 = 三平面 = 24576 B。这一步就是卡片 A 步的答案。

### 3.2 候选：搬生产者（不是"重排 phase"）

依赖事实（逐行核对）：V 投影**只**读 `gY`、V 权重 tile；**不**读 Q/K/S/P/den，**不**写 gT。
所以把整个 V 段搬到 P5 之后是纯位置移动，不拉断任何 RAW 边。搬完：

```
P1 Q/K 写（V 不再在此）
P2 barrier()   = B1（原有，发布 Q/K）
P3 score: Q^T 读 + K 读        ← Q/K 的最后读
P5 den / P*inv
P5b barrier()  = B2（新：退役全部 Q 读）
P6  V 段：读 gY + V 权重，DPAS，写 Q 平面（= V 平面）
P6b barrier()  = B3（新：发布 V）
P6c debug V echo（读 V，位置随 V 移动；循环界与目标地址不变）
P7  PV: 读 V
```

| 对象 | 生产者 | 最后消费者 | 覆盖者 | 候选的约束 |
|---|---|---|---|---|
| Q 平面（P1 写） | 4 SG | score 的 `Q^T` 读 | **V 段**（同 SG，同 512 half） | 同 SG 程序序 + B2；**跨 SG WAR = 0** |
| V 平面（= Q 平面，P6 写） | 4 SG | PV 的 A 读 | 无 | 跨 SG RAW，由 **B3** 关闭 |
| K 平面 | 4 SG | 第 8 个 block 的 A 读 | 无 | B1 |
| P 片段 / PV 累加器 | 同父 | 同父 | 同父 | 不变 |

### 3.3 逐 half 地址的 hazard 分类（`build/lifetime.json.hazards`，穷举，不抽样）

| 边 | 父（同 SG / 跨 SG） | 候选（同 SG / 跨 SG） | 结论 |
|---|---|---|---|
| **WAR** Q 读 → V 写 | 0 / 0（不同平面，地址不重叠） | **4096 / 0** | 同 SG，B2 + 程序序 |
| WAR K 读 → V 写 | 0 / 0 | 0 / 0 | V 不碰 K 平面 |
| WAR Q 读 → K 写、K 读 → Q 写 | 0 / 0 | 0 / 0 | 平面不重叠 |
| **RAW** Q 写 → Q 读 | 1024 / 3072 | 1024 / 3072 | B1（不变） |
| **RAW** K 写 → K 读 | 4096 / 12288 | 4096 / 12288 | B1（不变） |
| **RAW** V 写 → V 读 | 4096 / 12288 | 4096 / 12288 | **B3（新增）** |
| WAW | 无（每地址一个写者） | 无 | — |

计数单位 = 每个 half 地址 × 每个 SG 对，含两个 head section（4096 = 4 SG × 2 section × 512 half；
16384 = 4 × 2 × 2048）。**跨 SG WAR 从"不适用"变成"精确 0"**，这是 Q1.2 的归属改写带来的。

**新增的 B2 无法省掉**：Q 的 `Q^T` B 片段读和 V 的 store 在同一个 SG 内、但 **lane→byte 映射不同**
（B 片段：lane L 读 `n·32 + dim`；V store：lane L 写 `token·32 + dim`），所以"同 invocation 程序序"
覆盖不了跨 lane 的 WAR，必须一道 WG 级屏障。本卡不用 `subgroupBarrier`/裸 `memoryBarrierShared`：
无 GPU 时那些原语的驱动落地不可验证。

## Q4 新增成本（全部入账，详见 `COST-LEDGER.json`）

| 项 | C64 | C128 | C256 |
|---|---|---|---|
| A tile 重读（V 段） / SG | **+8**（+64 消息） | **+16**（+128 消息） | **0**（父本来如此） |
| B tile（V 权重跨 M 共享） / SG | −8（−8 消息） | −16（−16 消息） | 0 |
| **UGM 消息净增 / SG** | **+56** | **+112** | **0** |
| **UGM 消息净增 / 帧** | **+3.73 M** | **+5.78 M** | **0** |
| barrier / WG | +2 | +2 | +2 |
| QKV 段独立链 / lane | 6 → 4 | 6 → 4 | 8 → 8（不变） |
| 峰值活矩阵 / lane | 6 → 4（−32 B/lane） | 同 | 8 → 8 |
| 静态 SPIR-V 指令 | +128 | +132 | +13 |
| DPAS / SLM 消息 / coopmat 传输条数 | 0 | 0 | 0 |
| 有效 lane / WG 数 / grid / token tile | 0 | 0 | 0 |

* **帧级消息价**：+9.51 M（第二档）。按 L22 的帧均值 31 ps = **≈0.29 ms**；按 n05a 的串行单价
  126 ps 上界 = ≈1.19 ms。L22 明确"线性模型最多高估 4 倍"，所以 0.29 ms 更可信；两者都写进未知项。
  **第一档为 0**，这是主代理把它定为主交付的全部理由。
* **C64/C128 的 A 重读不可回避**：唯一替代是把 4 个 V 累加器（64 B/lane）跨 score 段保活，
  叠加在 8 个 P 片段之上 = +16 GRF，而全族 `max_r = 127`（L4/n05e 的 −0.349 ms 就是这么来的）。
* **逻辑字节 ≠ DRAM 字节**：新增的 A 读是**同一 WG 刚读过的行**（父归属）或**同 WG 兄弟 SG 刚读过的行**
  （候选归属），命中 L1/L2 的概率高；本卡不声称 DRAM 字节不变，只声称消息条数增加是真实的。
* **片段字节 ≠ 实际 GRF**：以上"活矩阵"按 MAT_C/MAT_H 的逻辑字节算，实际 GRF 分配由 native 门看。

## Q5 是否真落到 native：预测 + 判据（不声称已实现）

完整清单见 `NATIVE-PREDICTION.md`（顶部写死硬判据）。摘要：

1. **硬判据**：SPIR-V `shared` 总字节 **24576 → 16384**（本卡已实测：`build/build.json`），
   且 plan 行第 2 字段同步成 16384（本卡已做，36 行 / 16 行两档）。
   **若捕获 ISA 的 kernel attribute `Workgroup Memory` 仍是 24576 ⇒ 判 A 类"实现未落地"**，
   不许用毫秒倒推机制有效。
2. 屏障 `OpControlBarrier` **1 → 3**；ISA `sync.bar` 应为 1 → 3（±1，若 IGC 合并），
   三段作用域签名不变（Workgroup/Workgroup/264）。
3. C256：**UGM 消息一条都不多**（A 64 tiles、B 96 tiles 不变）；C64/C128：A 侧 `load.ugm.d32x8t`
   8→16 / 16→32 tiles（**+64 / +128 消息**），B 侧 `load.ugm.d32x8` 48→40 / 96→80。
4. DPAS 80/128/224、SLM `load.slm` 34、`store.slm` 6、`fence.slm` 数量必须与父相等。
5. `scratch = 0`、`max_r ≤ 127`（父 127）；C256 的独立链数应保持 24。
6. 若 ISA 里 V 的 `store.slm` 目标寄存器/地址仍指向 `+0x2000`（4096 half 平面）而不是 `+0`，
   或 Q 平面在 score 段之后仍被写第二次 ⇒ 判"别名未落地"。

## Q6 整体是否更快：测什么、用什么臂、怎么归因

* **臂**：`base` = 链头 plan（`d8875665…`）；`cand` = 本卡 **第一档** `plan-c256.txt`（`21292385…`，
  只替换 16 个 C256 PASS）。第二档 `plan.txt`（`af6c1287…`，36 行）作为后续臂，**先不派发**。
* **顺序**：gates `fixed`（末帧 `1755e9c2…`）→ gates `fb2`（末帧 `9c3e511e…`）→ native（两臂 ISA）
  → resources（占用率/`Workgroup Memory`/scratch/max_r）→ **ordinary**（`--warm 1 --reps 30 --feedback`，
  末帧 `2b63d4ba…`）→（可选）控制探针：把新声明再填充回 24576 half（49152 B）跑一次，
  确认驻留台阶真实存在。
* **ordinary 设计**：两臂 6 组交替（ABABAB…），每臂每组 30 样本 = 360 样本全留，不裁剪、不重跑；
  按进程组均值做配对 t(df=5)，报 95% CI。FASTER_95 才算采纳；<0.03 ms 按 L13 需要第二批复现。
* **归因边界**：本卡只改 F05 三组的 SLM 地址基与 V 段位置，**不跨批相减毫秒**、不把组合收益算到本卡。
  第一档的归因很干净：**零消息代价的纯占用率变化** ⇒ 若第一档为正，则"驻留 2→4 的收益"被直接测出；
  若第一档为 0 或负，则说明 F05 的驻留在 2 上已经不缺（与 L29"寄存器在 16 KB 以上也封顶"的观察一致），
  这时第二档不该派发。
* **预期量级**（不是承诺）：反向探针说"驻留减半 = −1.219 ms"，第一档只覆盖 C256（占 F05 帧时间约 1.25 ms，
  按 DPAS 份额 41% 估）。若向上的弹性与向下同量级，第一档上限 ≈ 0.4–0.5 ms；实际可能远小
  （弹性不对称，见 `OCCUPANCY-ELASTICITY-F05.json.caveat`）。
* **若为负**：先看 native 是否只落了"SPIR-V 字节"而 ISA 仍 24576（A 类），再看 `XVE_STALL_BARRIER`
  是否因 +2 屏障上台阶（B 类），最后才按 C 类归因到形状/owner。
