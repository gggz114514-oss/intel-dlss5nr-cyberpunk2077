## 1. 映射：每个 (lane, component) 代表哪个 (token, channel)

### 1.1 几何

- WG = 256 线程 = 8 个 simd32 子组；`shared float16_t mLocal[4096]`（8192 B，与 `Workgroup Memory Size` 一致）。
- grid `42×24×1`（ord 9/217 为 `43×25×1`）→ **1008–1075 WG/PASS**。**无 z 维**：一个 WG 覆盖整个 64-token 窗口（C128 是 `×2`、C256 是 `×4`）。
- `g = sg % 2` → M 通道 `32g..32g+31`（**只有 2 个不同 g**）；`pair = sg / 2` → token `16·pair..16·pair+15`（4 个 pair）。
- 每 SG 4 个 `MAT_C`(8×16 f32)，行组 `tA = 16·pair`、`tB = tA+8`；列 tile `cg0 = 32g`、`cg1 = cg0+16`。

### 1.2 输出域一一覆盖（可枚举）

8 个 SG × (16 token × 32 通道) = **64 token × 64 通道 = 4096 元素 = WG 全域**。
`(pair, g)` 是 `{0..3} × {0,1}` 的笛卡尔积，`sg = 2·pair + g` 是双射 ⇒ **无重叠、无缺口、无重复写**。

- 尾块：`64 = 4×16`（pair 整除）、`64 C = 2×32`（g 整除）、expand `K=64 = 4×16`（ki 整除）、
  contract `K=64 = 4×16`（ki 整除）、hidden `128 = 8×16`（tile 整除）⇒ **无残块**。
- 图像边界只由 `c64_img_half_index()` 的 `oob` 谓词 + clamp 处理；本卡**未改**该函数（父与"候选"是同一份字节）。

### 1.3 mLocal 生产/消费映射（本卡未改，用于 §3 依赖表）

| 元素域 | 生产者（唯一） | 消费者（多重度） |
|---|---|---|
| (token 0..63, C 0..63) | `sg = 2·(token/16) + (C/32)`，每 SG 写 4 个 `MAT_H` | 8 个 SG 各读自己 2 个 token 组的全部 64 通道 |
| 生产元素数 | 8 SG × 4 × 128 = 4096 = 64×64 | 无重复写、无漏写 |
| 消费元素数 | **8 SG × 1024 half = 8192 half = 2× 4096** | 三宽度**最小**（C128 4×、C256 8×） |

### 1.4 各段 (A, B, 输出, K)

| 段 | A | B | 输出 | K |
|---|---|---|---|---|
| expand | `imgin[8 token][16 in_ch]`，`ki=0..3` | `pack + we + ((128g+h0)/16)·1024 + ki·256` | 8 token × 16 hidden，每 SG 8 个 tile = 128 hidden | 64 |
| middle | 激活后的 hidden CH（`c64_ch_to_a`） | `pack + wm + cg·128 + h0` | 8 token × 16 M 通道 | 128 hidden |
| contract | `mLocal` | `pack + wc + (cg/16)·1024 + ki·256` | Y | 64 M 通道 |

## 2. 删什么真实工作 —— **净删除 = 0**

本卡没有候选源码，所以**正常执行路径上没有任何 send / mov / shuffle / 转换 / SLM 往返 / 屏障被删除**。
下表是"每一条被评估的机制会删什么、以及为什么最终一条都不能留"：

| 机制 | 会删的真实工作 | 计数 | 为什么不能留 |
|---|---|---|---|
| expand A 4×→2×（`hb` 32→64） | expand A UGM 读 + 半字散布 mov + oob 分支 | −16 msg / −4096 B / −64 mov / −16 jmpi | **n03(C128) / n03b(C256) 已测同一机制**；CARD 明令禁止重复；且 §5 证明 C64 是它最弱的一档 |
| seed 复用 expand A | seed UGM 读 | −4 msg / −1024 B | 要把 4 个 `MAT_H` 从 expand 段跨 middle 段活到 barrier 后 = **+8 GRF/lane**，而 `max_r = 127/128`（§4）→ L4 |
| `scale` 去重 | `scale` UGM 读 | 源码 −2 msg | **编译器已 CSE**：ISA 实测 `load.ugm.d32x8t` 只有 16 条 = 2×8 行，源码 4 次读已成 2 次 → 已在 native 下界（L18） |
| 跨 SG 权重去重 | expand/middle/合约 权重 UGM 读 | −96 / −48 / −24 条（跨 SG 层面） | 见 §2.1 —— 两条路都被堵死 |
| 权重读加宽 | 消息数 | 0 | L20：exec16/32 上不存在 x16/x32/x64 形式；512 B/条已是下界 |
| SLM 发布/消费省消息 | SLM 往返条数 | 0 | 行跨距 128 B、行只 32 B ⇒ 每片段必 8 条 32 B = 行粒度下界 |
| gY 布局跨 PASS 折叠 | store 条数 | 0 | L19 已把全局 store→load 折叠轴判 D |
| 去掉 debug 路径 | `store.ugm` | −192 msg / −6144 B | **不是帧成本**（L17 实测 +0.005 ms INDISTINCT），且按合同不计入收益 |
| 静态算术 / 地址折叠 | 整数指令 | 静态 −数百 | L1/L3：不付钱；n04a 在 F05 C64 同型已测 −0.098 ms SLOWER_95 |

### 2.1 跨 SG 权重去重为什么是死路（本卡最关键的一条排除）

C64 的 `g = sg % 2` 意味着 **8 个 SG 里每 4 个共用同一个 g**，而 expand/middle/合约 权重的地址只依赖 `(g, h0, ki)` / `(g, h0)` / `(g, ki)` ——
**4 个 pair 的 SG 需要完全相同的权重**。要删这个 4×，只有两条路：

1. **SLM 广播**：1 个 SG 读 + 写 SLM，其余 3 个从 SLM 读。
   消息数 `4×32 = 128` → `32(UGM) + 32(SLM 写) + 96(SLM 读) = 160`，**+25%**；SLM 流量 +64 KiB；还要在已满的 8 KiB `shared` 上再挤权重暂存区。
   按 L2（消息数下降才付钱）/ L12+L19（SLM 往返是要删的东西）→ **否**。
2. **改 owner/几何**让 8 个 SG 拥有互异权重 → 需 8 个不同 `g` = 8×32 = **256 个 M 通道**，而 C64 只有 **64** 个。
   → **对本形状在数学上不存在解**。

**冗余倍数是宽度的函数，不是可删机制：**

```
跨 SG 权重冗余   = 8 SG / (C/32 个不同 g) = 256 / C   →  C64 4× / C128 2× / C256 1×
mLocal 消费多重度 = C / 32                            →  C64 2× / C128 4× / C256 8×
```

C64 在权重上冗余最大、在 M handoff 上冗余最小 —— 两者都是 `local_size=256 + 32 通道/SG` 的算术结果。

## 4. 新增成本 —— **0**（本卡无改动）

但把"被否决机制各自会付的成本"入账，便于后续卡引用：

| 若实现 | 会新增 | 量 | 与既有教训的关系 |
|---|---|---|---|
| expand A 4×→2× | 同时驻留 expand acc | 4 → 8（峰值 8→12，+32 GRF 逻辑） | L4；n03/n03b 实测 max_r 仍 127 但无 spare |
| seed 复用 | seed 片段跨 middle 段存活 | +8 GRF/lane | L4；文件已 127 |
| 跨 SG 权重广播 | 屏障 / SLM 写读 | +1 barrier、+96 SLM 读、+32 SLM 写、消息 +25% | L2 / L12 / L19 |
| 跨 SG 权重改 owner | WG 数 / grid / shared | 全变（新卡） | 超本卡边界 |

**本卡真实的 GRF 事实（供任何后续卡当预算前提）**：

| 指标 | C64 | C128 | C256 |
|---|---|---|---|
| `max_r` | **127** | 127 | 127 |
| 数据侧最高寄存器 | **127** | 127 | 127 |
| send 返回窗最高 | 117 | 113 | 117 |
| acc 占用带宽 | **76 GRF**（r16–r91） | 70 GRF（r12–r81） | 76 GRF（r16–r91） |
| acc 链 / 峰值并发 | 12 / **8** | 12 / 8 | 12 / 8 |

**"宽度更窄 ⇒ 寄存器更松"是错的**：C64 与 C256 的 `max_r`、acc 带宽**完全一样**。这是排除一切"抬活值"机制的硬依据。

**逻辑字节 ≠ DRAM 字节**：本卡报的所有字节都是**请求级**（消息级）字节，不声称 DRAM 流量。
被删的 A 读在同一 4 KiB 上短窗口内重复，大概率命中 L1。本卡没有 resources 臂（无候选），所以不做任何缓存断言。

## 5. 是否真落到 native —— BLOCKED 卡的用法：可falsify 的指纹 + 反证判据

本卡没有候选，所以没有"预期变化"。取而代之，给出**当前身份的完整可复算指纹**（详见 `NATIVE-PREDICTION.md`），
以及**三个能推翻本卡 BLOCKED 判定的观测**：

| 若在 current-identity 捕获上看到 | 则本卡的哪条结论被推翻 | 后果 |
|---|---|---|
| `load.ugm.d32x8` ≠ **56**（Pre 48 / Post 8） | "权重读已在 L20 下界"（§2、PROOF P5 的 `512B_per_message`） | 说明有可加宽/可合并的权重读，本卡应重开 |
| exec16/32 上出现 `d32x16t` / `d32x32t` / `d32x64t` | 同上 | L20 在本身份上不成立，权重合并变成候选 |
| `Workgroup Memory Size` > 8192，或 `shared` 有空洞 | "SLM 无处放权重暂存"（`shared_budget`） | SLM 广播路线需重估 |
| `max_r` < 127（即 GRF 有余量） | "GRF 已顶格"（`GRF_ceiling`） | seed 复用（+8 GRF）变成可支付 |
| `load.ugm.d32x8t` ≠ **16** | "编译器已把 `scale` CSE 到 2×" | `scale` 去重重新成为 −2 条消息的候选 |
| 相邻同址重复 send 对 > 0 | "ISA 无未 CSE 的重复读"（PROOF P4 `unCSE_leftovers`） | 出现新的可删重复 |

**"看不到即 A 类"的对应写法**：以上任何一条若不成立（即观测值与上表"应当看到"一致），
就**不能**声称有新的可删机制 —— 这正是本卡的结论。

## 6. 整体是否更快 —— 不测，并说明为什么"不测"是可辩护的

- **本卡不申请 GPU**（`GPU-REQUEST.json`：`request=NONE`，0 job）。GPU 由主代理串行统一执行，本卡无候选。
- **为什么不是"测了才发现没用"**：逐条排除给出的都是**结构性**否决（GRF 顶格、512 B/条、g 数、`shared` 满、行粒度下界），
  不是"实测不显著"。L18 已确立先例：源码层冗余在 native 已到下界时，**卡在源码层就该 BLOCKED，不该烧 GPU 时间**。
- **如果将来有人坚持要测**（例如主代理要一个"三宽度同机制"的封口臂），正确的臂设计是：
  - `base` = 基线 plan `a024c3c5…`；`cand` = 同一 `hb` 32→64 变换在 C64 上（7 PASS，`replaced==7`）；
  - 门：fixed（`1755e9c2…`）、fb2 末帧（`9c3e511e…`）、resources（zprof GpuTime）、native；
  - ordinary：warm1 / reps30 / feedback，6 组交替独立进程对，全部 360 样本保留，t(df=5) 于对均值差；
  - **预注册的期望**：上界 `0.4574 × 0.76 × 0.096 ≈ 0.033 ms`，低于 ±0.10 ms 下限 ⇒ 预期 INDISTINCT。
    若测出 −0.2 ms 级变化，**首先排除分配/绑定差异**（F04 有过 0.2486 ms 的分配退化先例，见 `f04-package-ablation-20261027`）。
- **单链归因边界**：C64 只占帧 2.52%（隔离时间和 0.4574 ms / 18.1637 ms），F04 族合计 11.96%。
  7 个 PASS 里每个只删 16 条消息，任何单宽度结论都不许外推到族。
