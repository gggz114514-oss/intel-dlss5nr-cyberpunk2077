# NATIVE-PREDICTION — n04a-f05-c64-feed（第 5 问：是否真落到 native）

本卡没有 GPU。下面全部是**预测 + 判据**，不是"已证明"。父侧（本组当前身份
`0d83192b…`）的 native 事实来自已记录的 ISA 抓取，已逐条核对；候选侧一律标注为预测。

- 父 native（只读证据）：`f05-kv-consumer-layout/family/captures/native-f20-pixel-owner/ISA/CS_asm6a22246177be2653_simd32_0000000000000006_5_orig.asm`
  sha256 `02c958289484b66bcedad442d1de71bca1e9d09d9e0f15acfe21b9576343909c`，4229 条静态指令。
  它与本组 SPV 的绑定见 `f05-kv-consumer-layout/PARENT-NATIVE-BINDING.json` 与 `COMBINED-NATIVE-BINDING.json`
  （`full_pass_identical: true`，C64 pass 块与 family plan 逐字节相同）。
- 父侧结构（本卡已核）：QKV 投影 = 2 个 row_phase × 4 个 K 步 × 6 个权重 send / 6 条 DPAS；
  权重 send 全部 `load.ugm.d32x8.a32.bss[a0.2]`、exec `(16|M0)`、rd:8；
  QKV 两段共 782 / 4229 条静态指令（374 + 408）。

## 0. 父侧已证事实（这是判据的基线）

1. **地址寄存器与权重返回区同体**：row_phase0 的 8 个地址 payload 寄存器里 4 个（r7, r8, r18, r22）
   同时是权重返回区；row_phase1 是 2 个（r7, r15）。
2. **返回区被反复回收**：row_phase0 的 24 条权重 send 只用 12 个返回区（r19 4 次、r22 5 次、r27 3 次），
   row_phase1 只用 9 个。每条 send 恰好被 1 条 DPAS 消费（24:24）。
3. **每 send 一次的 16-wide `mul ... *32`**：QKV 两段 `mul` 共 49 条（25 + 24），即每个权重 send 一次
   （per-lane 字节偏移）。这是候选声称可以共享的量，但父侧没有被共享。
4. **地址等待是显式编排的**：QKV 两段 `sync.nop` 共 103 条；`$n.src`（源读退休）串在
   `send → dpas → 下一次 send` 之间（例 r19: 0x0DC0 → 0x10A8 → 0x10C0 → 0x1328 → 0x1340 → 0x13F0）。

**判据使用顺序**（先不花计时就能落锤的部分）：
P6 → P8 → P1 → P2 → P3/P4/P5。P6/P8 不成立 = 实现错误或换了机制；P1/P2 不成立 = A（实现未落地）；
P1 成立而 P3–P5 恶化 = B（有副作用，按最大副作用修一版）。

## 2. 期望的指令/寄存器层面形状（如果真落地）

- `wq_row` 期望**不出现**为 per-lane 向量，而是一个 subgroup-uniform 标量（父的对应量是 r1.2 / r2.9 / r121.x 一类的标量基址，
  `add3 r2.10 = r1.2 + r2.9 + imm`）。候选应当把它变成 **1 个**基址 + 每次 send 一个立即数。
- `wk` 期望以"每 K 步 1 次 `add`"的形式出现 4 次（×2 相位 = 8 次），而不是 48 次地址重算。
  验收：QKV 两段里出现 ≤ 8 条"基址 + 256 倍数"的标量 add。
- 权重 send 的地址 payload 期望从 {r4,r5,r6,r7,r8,r10,r18,r22} 这种"共享 scratch"形状，
  变成**两个一组**（一相位内每步两个：一个给 Q/K 组、一个给 V 组）或**每步一个**的长寿命标量。
  只看"寄存器编号变了"不算落地，必须看到 **∩ 返回区为空/≤1**。
- 期望**不出现**：新的 `sync.nop` 批量增加（> +20）、新的 `sel`/`join`、scratch 非 0、shared 变化。

## 3. 反面判据（明确写出来，防止事后找理由）

- 如果 native 与父**逐字节相同** ⇒ 候选是身份变换，记 A，不记"方法无效"。
- 如果 native 变成"每个片段一个独立返回区（6 个）" ⇒ 那是"增加 B 预取数"，属于本卡明令避免的方向，
  即使更快也**不接受为本卡结果**（另开卡）。
- 如果 QKV 段指令变少但 score/PV/存储段变化 ⇒ 说明改动越界（本卡只应影响 QKV 地址），必须查 SOURCE-DIFF 是否被误改。
- 如果 `dpas` 数量从 80 变 79/81 或每 acc 的 K 序改变 ⇒ 数学违规，直接 E。

## 4. 与 timing 的关系（不得混淆）

本文件只给"实现是否落地"的判据。即使 P1/P2 成立，也**不能**据此声称任何毫秒收益：
QKV 供料地址链只是该 PASS 的一部分，该 PASS 只是 232 个派发位置里的 8 个。
毫秒只能由两臂 ordinary 批次（6 组交替 × 30 reps）给出，且只作整网归因，不作单链归因。
