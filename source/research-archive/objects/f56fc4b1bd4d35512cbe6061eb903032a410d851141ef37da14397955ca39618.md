# n18b-f01-gather — NATIVE-PREDICTION（第 5 问：可观察点与判据）

本卡**没有候选**，所以这里不写"期望在 ISA 里看到什么"，而写三件事：
(A) 当前 ISA 已经是什么样（这是本卡结论的观察点）；
(B) 如果将来有人真按卡面机制去做，**必须**在 ISA 里看到的形态，以及"看不到就等于未实现"的判据；
(C) 入口 gather 上下一步（宽度合并）的 native 判据。
所有观察点都只要求 **native ISA 捕获**（不需要计时），因此可以低成本复用现有 manifest 形态。

---

## A. 当前 ISA 已经落地的"去重"：掩码

捕获：`queue/n17-f20-body/native/captures/native-native-base/ISA/CS_asm54249010bf7e593b_…_orig.asm`
（kernel hash `54249010bf7e593b`，sha256 `61f4d97a…1dcddb`，= 链头 ord 0 的 SPV `ecc9dd39…`）

| # | 观察点 | 期望值（实测） | 判据 |
|---|---|---|---|
| A1 | lane 序号构造 | `0x0060/0x0090/0x00B0`：`0x76543210` + 8 + 16 → r92 = 0..31 | 看不到这 3 条 ⇒ lane 序号换了寄存器，后续判据要用新寄存器重算 |
| A2 | lane<16 谓词 | `0x0340 cmp (32\|M0) (lt)f0.0 null<2>:uw r92.0<1;1,0>:uw 0x10:uw` | 看不到对 `0x10` 的 32-lane `lt` ⇒ 守卫不是掩码，需重新判断载荷 |
| A3 | 区域入口 | `0x0390 (~f0.0) goto (32\|M0) L19088 L19088` | 双目标同址 + `~f0.0` = 纯 if 区域入口 |
| A4 | 73 条 gather 全在区内 | 偏移 `0xB90…0x3830` ⊂ `(0x390,0x4A90)`；`outside=0` | 有任一 gather 落在区外 ⇒ 那一条按 32 lane 记载荷 |
| A5 | gather 无逐指令谓词 | 73/73 `send.ugm (32\|M0)` 无 `(f…)` 前缀 | — |
| A6 | shK 写回也在区内 | `0x4A70/0x4A80 store.slm.d32x4.a32.flat[A+0x400/0x410]` | — |
| A7 | 写回地址不 clamp lane | `0x4900 shl r22=r68<<8`、`0x4990 shl r20=r98<<4`、`0x4998 add`、`0x49F0 shl <<1`；区域内对 r90/r92/r98 的 `and/min/sel` = **0 条** | 出现 clamp ⇒ 掩码可能不是唯一守卫，本卡结论要重审 |
| A8 | 反证 | A7 + 金帧通过 ⇒ 掩码必然在硬件生效 | 若某次捕获出现 A7 的 clamp，则 A8 失效 |

**载荷结论**：A3+A4 ⇒ 每条 gather 64 B（16 lane×4 B），每 lane-program 4672 B，每派发 301.40 MB；重复 = 0。

> n18 之前的基线（`5bd64f2b…`，sha256 `6c50aea7…`）同构，只是谓词换成 `f3.0`、区域 `(0x390,0x6E90)`、gather `0xB90…0x5C10`。**两代都是 73/73 在区内**，说明这不是 n18 改动带进来的。

## B. 若有人仍按卡面机制实现，ISA 必须出现的变化（"看不到 = 未实现"）

| 机制 | 期望可观察变化 | 看不到即判定 |
|---|---|---|
| 去重（把重复那一半的读变成"一次"） | **不存在合法的 ISA 形态**：重复那一半本来就是掩码外。若真出现 `send.ugm (16\|M0)`（执行尺寸 16）或 gather 条数下降，只可能来自宽度合并或几何改动 | 消息条数不变 ⇒ 机制未落地（A 类）；若有人以"逻辑字节减半"宣称落地，按 A 类记 0 |
| SG 内寄存器广播 | 16 次 shuffle 级搬运/值，**gather 条数不变** | 条数不变 ⇒ 无收益（S1 已被证明无共享值） |
| 跨 SG SLM 广播 | 出现 73 级 `store.slm` + `load.slm`，并新增 `barrier`/`fence.slm` 的 **workgroup 作用域**；`PASS 0` 头 shared 字段必须 > 9216 | 若 shared 仍 9216，则 SLM 必然被覆盖/越界 ⇒ 直接 E 类（数值失败） |
| lane 归属改动（32 token/SG） | `PASS 0` 头 grid 从 `168 96 1` 变 `84 96 1`，且下游片段形状变 | 头没变 ⇒ 改动没有真的发生 |

## C. 下一步（宽度合并）的 native 判据（本卡不建候选，只给判据）

候选形态：把 21 个像素读的 3 条通道消息折成 1 条更宽读（`vec4` 视图，或两次 8 B）。

| # | 观察点 | 判据 |
|---|---|---|
| C1 | `load.ugm.d32`（标量通道 gather） | 73 → **≤52**（理想 31）；不变 ⇒ A 类 |
| C2 | 宽读消息（`load.ugm.d32x16t/d32x32t/d64…`） | 允许上升；若 1 条 16 B 读被拆成 4 条 d32，则 C1 回到 73 ⇒ 判 A |
| C3 | `store.slm` / `dpas` / `scratch` | **必须不变**（2 / 132 / 0） |
| C4 | `PASS 0` 头 shared | **必须仍是 9216** |
| C5 | 帧 | fixed `1755e9c2…`、fb2 `9c3e511e…` 不变（16 B 读会多读 alpha，但 alpha 不参与任何表达式；若帧变了 ⇒ E，先查对齐） |
| C6 | 对齐 | 若出现 `load.ugm.d64`（8 B）而非 16 B，说明基址只保证 8 B 对齐 ⇒ 停，改回标量 |

## D. 不声称的部分

- 本卡没有候选，所以**没有任何"已实现"的断言**。
- A1–A8 是**静态 ISA 观察**（栈上无 GPU），它们证明的是"消息载荷/活动 lane"，不是"实际 L1 事务数"；后者需要内存计数器，本卡没有。
