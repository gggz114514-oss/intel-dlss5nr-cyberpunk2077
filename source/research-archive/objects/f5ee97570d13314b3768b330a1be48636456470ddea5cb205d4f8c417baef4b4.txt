READ THIS FIRST - three reusable results
 1. TOOL: `clock_runner --dump-intermediates` dumps exactly the buffers whose plan row
    `POLICY <resource> <resident> <firstPass> <lastPass> <clear>` has resident == 0. `swin_9_debug`
    is resource 50 with resident = 1, which is why n02d's probe and my first attempt produced no
    dump. `probe/lanemap-probe.plan.txt` flips that single field to `POLICY 50 0 0 233 0` and the
    dump appears as `dump_swin_9_debug.bin` (458752 B). No runner change needed.
 2. SHAPE LAW: the 8x32 fp32 accumulator is NESTED (control 8x16 128/128; NESTED 256/256;
    LANE_COL 32/256; SWAP_HALVES 0/256; EXOTIC 4/256). Merged component i == the old q0[i],
    component i+4 == the old q1[i]. Three merged accumulators = 48 GRF = the parent's six.
    Note: the reader's `MMA32 vs converted acc` row reads 0/256 by construction (it compares two
    unrelated quantities) and is not a failure signal.
 3. MESSAGE CEILING: a per-lane `send.ugm` tops out at 8 GRF = 32 B/lane x 16 lanes = 512 B, which
    is exactly one 16x16 fp16 tile, so our weight B loads are already saturated at 1 message/tile.
    Merging two tiles into one 1 KB fragment load still costs 2 messages. Per subgroup the
    projection reads 6 tiles x 8 k-steps x 2 phases x 512 B = 48 KB => 96 messages is a floor.
    The wide classes the campaign saw elsewhere (`d32x64t`/`d64x64t`) are exec-1 reads of a
    contiguous block (`send.ugm (1|M0) ... a0.0 ... rd:4/8` + a `mov (32|M0)` broadcast), i.e.
    uniform/bulk reads, never per-lane operand loads. Corpus-wide check over 2038 ISA captures:
    **no x16/x32/x64 load class occurs at exec 16 or 32** - operand loads are always `d32x8` at
    exec 16 with 8 GRF = 512 B = exactly one 16x16 tile. Details in MESSAGE-WIDTH.md section 8.

CLOSED / NOT PURSUED
  * 96 -> 48 weight messages: unreachable from the shader or the asset (MESSAGE-WIDTH.md section 3).
    The only route to fewer bytes is to break the 2x per-phase duplication, which needs 12 live
    accumulators = 96 GRF, measured by n05e at -0.349 ms.
  * Q/K merge on the NESTED law: correct but pointless (0 messages, 0 GRF). Source kept.
  * element access (`m[i][j]`) as a way around the lane map: rejected by glslang 16.5.0
    (`left of '[' is not of type array, matrix, or vector`; only uniform component subscripts).

WHAT THE MAIN AGENT SHOULD DO WITH THIS CARD
  1. Do not queue B1 as an arm. If the goal is F05 C128 time, the only lever this card can still see
     is occupancy, and on the NESTED law the merged form does not change it (48 GRF both ways); the
     24-GRF branch needed LANE_COL.
  2. Keep stage-1's pack assets as a proven asset-rewrite recipe: permutation + BUFFER-EDITS plus a

  3. If a future driver emits `rd:16` per-lane loads, reopen this card: the merged Q/K/V source is
     already written, compiled and NC-clean in b1-unbuilt/.
