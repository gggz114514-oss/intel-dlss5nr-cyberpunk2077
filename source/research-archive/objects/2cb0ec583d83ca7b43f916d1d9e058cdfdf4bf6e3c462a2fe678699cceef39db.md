# NATIVE-PREDICTION — n09c-f09-b-share

预测 + 判据。**本卡没有 GPU**，下列 native 数字全部是"期望/若看不到即判未落地"，
不含任何"已证明"。基线取自只读捕获
`queue/n09b-f09-sx-stage/native/captures/native-native-cand/ISA/CS_asm873c258babc364b2_simd32_..._orig.asm`
（= 链头 plan 对这 16 个 PASS 实际绑定的 SPV；本卡 `PARENT-EVIDENCE.json` 独立复算过）。

## 0. 父身份 ISA 实测（本卡独立统计，与 n09b RESULTS 一致）

| 量 | 父 | 说明 |
|---|---|---|
| 静态指令 | **892** | 全 kernel |
| `send.*` 合计 | **112** | 含 1 条 gtwy EOT |
| `dpas` | **64** | 32 k-step × 2 MulAdd |
| `sync.*` | **122** | `sync.nop` 89 / `sync.allwr` 32 / `sync.allrd` 1 |
| max register | **127** | 已在顶格 |
| 第一条 dpas 偏移 | 0x3344 | |
| mov / add / mul / shl | 139 / 212 / 87 / 48 | |

消息直方图（每条消息的总字节按 ISA 形状：[16 lanes × 8 dword] = 512 B，[1 lane × 64 dword] = 256 B）：

| 消息 | 条数 | 每条字节 | 归属 |
|---|---|---|---|
| `send.ugm load.ugm.d32x8.a32.bss[a0.0]` (16\|M0, rd:8) | **64** | 512 | 权重 B 片段（16×16 f16），2/k-step |
| `send.ugm load.ugm.d32x64t.a32.bss[a0.2]` (1\|M0, rd:4) | **32** | 256 | A 片段（8×16 f16），1/k-step |
| `send.ugm load.ugm.d16u32.a32.bss[a0.0]/[a0.2]` | 12 + 1 | 64 | seed 的 `input_value`/`weights` 标量读 |
| `send.ugm store.ugm.d32x64t.a32.bss[a0.0]` | 2 | 256 | 末次 store（side0/side1） |
| `send.gtwy ... end of thread` | 1 | — | 线程结束 |

稳态每 k-step（父，ISA 0x0B20–0x0CC0 区间可见）：
`add r2=…`(权重地址) → `send B0` → `send A` → `send B1` → … 4 条 `mul.hf`/`mov` 的
seed 收尾 → `or r20=…512`(A 地址推进) → `add r2/r3`(权重地址推进) → 下一轮 `send A` →
`sync.nop`。
**每 k-step：3 条 load 消息 + 3 条地址整数运算 + 2 条 dpas。**

## 1. 期望在候选 ISA 里看到的变化（逐条）

| # | 观察点 | 父 | 候选期望 | 若看不到 ⇒ |
|---|---|---|---|---|
| **L1** | `load.ugm.d32x8`(权重, 512 B) 条数 | 64 | **32** | 仍是 64 ⇒ 共享 B 没落地（A 类） |
| **L2** | `load.ugm.d32x64t`(A, 256 B) 条数 | 32 | **64** | 仍是 32 ⇒ 第二份 A 被别的形式替代，必须逐地址核对（见 L2b） |
| **L2b** | 每 k-step 两条 A 消息的地址差 | — | **+0x100（256 B = 128 half）**，且四条 `send` 的地址寄存器对只有两套基址 | 差不是 0x100 ⇒ 索引折叠错（E 类，先看数值门） |
| **L3** | `dpas` 条数 | 64 | **64**，且仍是两条独立累加链（acc0/acc1 各 32 次） | ≠64 ⇒ 结构错（E 类），不许当性能结论 |
| **L4** | `store.ugm.d32x64t` 条数 | 2 | **2**，地址窗口与父逐字节相同（+0x200 差） | 4 条或 1 条 ⇒ 末次 store 覆盖面变了（E 类） |
| **L5** | seed 标量读 `d16u32` | 13 | 13 ± 2 | 大幅减少 ⇒ seed 被优化掉（E 类） |
| **L6** | max register / spill | 127 / 0 | ≤127 / 0 | >127 或出现 spill ⇒ B 类（活值账见 COST-LEDGER A3） |
| **L7** | `sync.*` | 122（nop 89 / allwr 32） | 122 ± 10 | 明显上升 ⇒ B 类（新增长依赖/等待） |
| **L8** | 每 k-step load 字节 | 2×512 + 256 = **1280 B** | 1×512 + 2×256 = **1024 B（−20%）** | 字节没变 ⇒ 权重没省（A 类） |

**判"落地"的最小充分集**：L1（权重消息减半）+ L3（dpas 不变）+ L8（每 k-step 字节 1280→1024）。
L2 是同一件事的另一面，允许出现下列合法变体：
- 变体 α（最可能）：`d32x64t` 32→64，每条 256 B；
- 变体 β：IGC 把两个 8×16 A 合成一条 512 B 的 A 消息（则 `d32x64t` 仍 32 但每条 512 B）——
  这时 L2 的条数不变，**必须看 L8 的字节账**才能判落地，不许只看条数。

## 2. 期望不动的量（动了就是实现/数值问题，不是收益）

- `dpas` 64、两条累加链、末次 `store.ugm` 2、seed 标量读 13 条量级；
- 无 `store.slm` / `load.slm` / `sync.bar` / `signal barrier` / `fence.slm`（n09b 已清零，本卡
  不碰 SLM/布局，出现任意一条即回退到父的 SLM 往返 ⇒ A 类）；
- 无 gtwy 承载 scratch、无 spill；
- 静态指令数：**不期待大降**。父每 k-step 3 条地址整数运算，候选仍是 3 条（少一条权重地址
  推进、多一条 A 的 +0x100 推进），所以预期 **892 → 884 ± 16**（唯一确定的减项是 seed 块
  不再访问 `m0` 变量：SPIR-V 侧 −8 `OpLoad` / −1 `OpStore` / −1 `OpVariable`，IGC 本来也会
  CSE 掉，故不构成 ISA 收益）。
  ⇒ **本卡不是"删指令"型收益**（对照 n09b 的 1684→892）；若 GPU 报告只看静态指令数，
  会把它误判成 INDISTINCT。
- 索引/寄存器：`max_r` 127 顶格，父与候选的 fragment 活值账是 12 → 8 dword（见 COST-LEDGER），
  不期待寄存器压力上升。

## 3. 成本面也必须观察到（避免只报好的一面）

- **A 消息 +32 条/线程**（32→64），A 逻辑字节 64→128 KiB/WG；
- A 的冗余度 4× → **8×**（同一 WG 的 8 个子组读同一份 128-half 块）；但每 WG 每 k-step 的
  **distinct** A 足迹仍是 512 B（父是两块 256 B，合计相同），因此 DRAM 侧不期待增加，
  L1/L2 命中是预测、不是证明；
- 每 k-step load **消息条数不变**（3 条），变的是每条的大小分布 ⇒ 若这一代 LSU 按"条"计费，
  收益可能接近 0。这正是本卡要分辨的：**字节账（L8）成立而整体不显著 = C 类，
  不能推广成"共享 B 无效"**。

## 4. 归因顺序（合同 §8.5）

1. 先看 L1/L2/L3/L8 是否形成处理（A 类判据）；
2. 再看数值门（fixed / fb2 gold 逐字节）与资源；
3. 最后才看 ordinary 两臂差；单链只归因"这 16 个 PASS 的权重消息减半"，
   不跨批次相减毫秒、不与 F10 的 0.422 ms 相加。

## 5. 本卡**没有**证明的

- IGC 是否真的让两条 MulAdd 共用同一次 B 载入（源码/SPIR-V 是单次载入 + 两个消费者，
  `PROOF.json`/`BUILD.json:spirv.candidate.dataflow.shared_b=true`，但 ISA 由驱动决定）；
- 8× A 放大是否被 L1/L2 吸收；
- 任何时间量。
