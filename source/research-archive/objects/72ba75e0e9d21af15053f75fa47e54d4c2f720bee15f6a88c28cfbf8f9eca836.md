## 2. 身份纪律（每卡必做）

1. **先复现父**：用冻结工具链把父源编出 SPV，必须与父部署 SPV **逐字节相同**；
   不同则先查 argv/macros/include，不带着差异施工。
2. **再改源**：改动必须是可枚举的最小集（删/改的行、每处给出源码行号）。
3. **SPV 差分归因**：`spirv-dis` 不可用就用自写 word 级 diff，把新 SPV 与父 SPV 的
   每条差异指令列出来，并证明"除了目标改动之外没有别的变化"（指令集合增减、ID 重编号、
   NoContraction 装饰、shared 变量大小等分别登记）。若存在无法归因的差异，写 FAIL 并停。
4. **plan 身份**：若生成 plan，必须给 plan 内每条 delta（spv/shared/grid/drop/policy）的
   old→new 与理由，并跑 plan_lint / validate_pool_upload。
5. 每卡 `build-receipt.json` 记：argv 全文、输入文件 sha256、输出 sha256、rc、时间。

## 3. 资格词汇（不得混用）

| 标记 | 含义 |
|---|---|
| `CPU_STRUCT` | 源码/地址/寿命的整数或布尔证明，CPU 静态 |
| `OFFLINE_COMPILE` | glslang 编出 SPV、spv_validate_cpu result=0 |
| `SPV_IDENTITY` | 相对父的 SPV 差分已逐条归因 |
| `NATIVE` | pipeline-create 的 native 指令/SLM/scratch 统计（需 GPU，ef 本次不做） |
| `GATE` | 数值门（fixed/fb2/30帧/逐帧字节相等），需 GPU |
| `ORDINARY` | 普通整网计时（同 runner/输入/分配/参数、≥3 进程对×30 样本），需 GPU |
| `QUALITY` | 画质/PSNR 合同，需 GPU |

**规则：只有 CPU/离线证据的卡只能标 `CPU_STRUCT`/`OFFLINE_COMPILE`/`SPV_IDENTITY`，
不得写 PASS、不得写毫秒、不得写"通过数值门"。** 缺 native 就写"native 未知"。
声明 SLM ≠ native 分配；BIND 字节 ≠ DRAM 字节；scratch ≠ spill；不加历史收益。
