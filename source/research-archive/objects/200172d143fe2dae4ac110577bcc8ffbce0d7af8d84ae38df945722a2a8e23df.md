# n10b-f10-pipeline · native 可观察点与判据（预测，不是已证）

卡片本身**没有** GPU 工作。本文件只给「主代理取到两臂 ISA 后，按什么逐条判落地」。
所有数字都是**预测值或父身份的已知值**，没有一条是本次实测；本卡不写「已证明落地」。

## 0. 怎么取

- 臂：`base` = 现役链头 plan `719f100b…`（F10 SPV `228dee8a…`）；`cand` = 本卡 plan `2343827a…`（SPV `9afa8526…`）。
- 用法与 `COMMON.native_job()` 相同（gtpin `--dump_isa` + clock_runner `--pool --warm 0 --reps 1`），两臂同批。
- 只看 16 个 F10 PASS 的那一支 ISA（PASS 值在 plan 里是 25/29/…，**不要用 PASS 值当主键**，用 ordinal + name + SPV sha）。
- 判读顺序（合同 §8.5）：**先 P1/P5（有没有形成处理）→ 再 P2/P3/P4（代价与资源）→ 最后才允许看 GpuTime**。

## 2. 判据（逐条可观察，任一条不成立就按右列分诊）

### P1（硬，资产）：三块 B 不变
- 期望：**首 DPAS 之前仍有 3 条权重 UGM send**；三条的**返回区互不重叠**、各 8 GRF；每 k-step 每 SG 仍 **3** 次权重读。
- 允许：区号可以移动（寄存器分配会变）——判据是**分离 + 早于首 DPAS + 次数不变**，不是「仍是 r22..29」。
- 不成立 ⇒ **B 类（牺牲已接受资产）**，立刻停，不看时间。

### P5（本卡机制点，落地与否就看这条）
- 期望：kc 环体里 `sync.bar`（连同它的 `send.gtwy … signal barrier` 与 `send.slm … fence.slm.none.group`）出现在
  **staging 的 16 条全局 send 之前**；父里它在 staging 的 16 条 `send.slm store` 之后、首 DPAS 之前。
- 静态旁证（SPIR-V，本卡已测）：环体 own 偏移 **13/424**（候选）vs **384/397**（父）。
- 不成立（barrier 仍在 staging 之后）⇒ **A 类（实现未落地）**。

### P6（强形式；不成立不算失败，只算「强形式未实现」）
- 期望：16 条 staging `send.slm store` 落在该 slice 的 DPAS 块**之后**（真正把全局读延迟藏进 24 条 DPAS）。
- 若落在之前：说明只落了 P5（barrier 挪位 + 跨 warp 重叠），**不得**在 RESULTS 里写成「全局读延迟已藏进 DPAS」。
  修法见 `RESUME.txt` §6（显式 load/store 拆分 + 寄存器预算），但那是下一版，不是本版。

### P2（硬门）：scratch = 0，且环体没有新增内存/DPAS 消息
- 期望：`scratch` 报告值 **0**（>0 立刻回退，**硬门，不得先测再看**）。
- 期望：环体内消息计数与父逐项相同：16 条 staging 全局读 / 16 条 staging SLM 写 / 每 k-step 2 条 A 读 + 3 条权重读 + 6 条 DPAS。
- 期望：新增指令**全部**是整数比较、分支、phi（+3 条件分支/迭代）；环体 ISA 增量 **≤ 40 条**。
- 不成立（scratch>0，或出现第 17 条 staging 读、第 4 条权重读、第 7 条 DPAS，或环体增量 > 40 条）⇒ **B 类**。
- ⚠ 口径偏差（已在 `ANALYSIS.md` §7 记）：CARD 的 P2 字面要求「kc 环体指令数下降或持平」，本卡**不删任何工作**，
  环体必然多出环的离入 guard（SPIR-V 558→585）。因此 P2 按「增量全是整数控制 + 无新增内存/DPAS 消息 + scratch 0」判。

### P3 / P3'：`sync.bar` 不增加
- 期望：静态 `sync.bar` 仍 **4**（`signal barrier` 4、`fence.slm` 4）。
- P3'：若 IGC 把 i=0/i=8 剥出循环导致静态 **5**，则必须同时看到**动态仍 8**（一个环体 barrier + 一条剥离出来的），
  判「落地但形状变化」，并把多出来的那份写进成本；静态 5 且动态 9 ⇒ B 类。

### P4：`send.` 总数不增加
- 期望：**566**（= 父值）。增加 ⇒ 说明 stage/consume 的某一块被复制（剥离/展开），B 类。

### P7：首 DPAS 与寄存器压力
- 期望：首 DPAS 偏移**后移**（父 5632；候选前面多了第二个 staging 块，预计更大）；`max_r` ≤ 255。
- 若首 DPAS 前移到 5632 之前，检查是不是 stage 块被整体挪到了后面（那会同时违反 P1 的「早于首 DPAS」）。

## 3. 与 CARD 四条硬判据的对应

| CARD | 本文件 | 一句话 |
|---|---|---|
| P1 首 DPAS 前 3 条权重 send、三块不重叠 | P1 | 资产不变即可，位置可动 |
| P2 kc 环体指令数不增、scratch 0 | P2（+ 口径偏差说明） | 硬门是 scratch 0；增量必须全是整数控制 |
| P3 `sync.bar` 不增加（n10 后 4） | P3 / P3' | 静态 4；剥离时看动态 8 |
| P4 send 总数不增加（n10 后 566） | P4 | 566 |

## 4. 什么**不能**用来判落地

- **不能用毫秒**判「机制是否有效」（合同 §8.5）。
- 不能因为 `first_dpas` 后移就判变慢：后移是本卡的**预期**（多了一个 staging 块在 DPAS 之前）。
- 不能把 `sync.*` 总数（父 260）当作 barrier 数；barrier 数是 `signal barrier` / `fence.slm` / `sync.bar` 三者各自的 4。
- 不能把「三块 B 返回区仍是 r22..29」当成通过条件；也不是「变了就失败」。
- 不能把本卡的 P5 通过写成「全局读延迟已隐藏」；那需要 P6。

## 5. 若 native 显示「未形成处理」（A 类）

按顺序查这三件事，再决定是否重做：
1. 环体 barrier 是否真的在 staging 之前（P5）。若 IGC 把 barrier 沉到 stage 之后，说明它把 `if(i>0) barrier()` 与 stage 块重排了——那需要把 stage 显式拆成「load 块 / store 块」并把手动顺序写死。
2. 静态 `send.` 是否 566（P4）。若变成 582（+16），说明 i=0 的 stage 被剥离复制了；改法是把环的入口改成「先 stage 后 barrier 的 8 次迭代 + 尾部 consume」，但那条路会复制 k 循环（+12 send），因此要重新算 P4。
3. 环体是否出现 `jmpi` 目标爆炸（guard 被展开成 3 份）：把两个 guard 合成一个（barrier 与 stage 用同一谓词/blocks 合并）再测。
