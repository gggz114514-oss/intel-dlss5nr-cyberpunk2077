# n11-vit-ffn — NATIVE-PREDICTION（第 5 问：可观察点与判据）

本卡没有 GPU。下面全部是**预测 + 判据**，不是“已实现”。父的 native 身份来自本卡只读捕获
（NATIVE-INDEX 记为 `identity=CURRENT`, baseline pipeline 22）：

    run/dsh-fp16-same-family-20261023/nat-k11-s32-native-000/gtpin/ISA/
      CS_asm48ac0230660a2c52_simd32_0000000000000001_0_orig.asm
    sha256 f5f655b127f9da6206cf7ee9023bd85fa6ffb322f948f8412b3893ac661d065b   837450 B

父的驱动统计（同目录 `compile/native-capture.json`）：Instruction Count **7231**、
Basic Block Count **272**、Scratch 0、**Loop Count 0**、Workgroup Memory 0、subgroup 32。
本卡自己的静态解析（`NATIVE-ANALYSIS.json`，与驱动统计一致）：7233 行指令、dpas 256、
send 1217（`send.ugm` 1216 = `(16|M0)` 宽 128 + `(1|M0)` narrow 1088，外加 1 条 `send.gtwy` 出口）、
`mov(32)` 1568、`mov(8)` 736、`sync.nop` 1096、`jmpi` 136、`cmp` 4、0 回边。

## 1. 期望看到的变化（按重要性排序）

同族实测锚点（`VIT-FFN-NATIVE-COMPARISON.json`，三份 CURRENT 捕获本卡自算）：
expand mov32/dpas = **6.12**（判定在循环内）、contract = **2.27**（判定在循环外、循环卷回）、
projection = **6.23**（判定在循环内、2 个累加器）。判定位置比累加器个数更能解释搬运量，
所以本卡预测 expand 的“按组搬运”被整块删掉；保守下界用 contract 的残留（约 2.27/dpas ≈ 590）。

| # | 观察量 | 父 | 期望候选 | 判据 |
|---|---|---:|---|---|
| O1 | `mov (32|M0)` 条数 | 1568 | **≤ 600**（理想 ~30–100，保守 ~590） | 若仍 ≥ 1400 ⇒ **A 实现未落地**；300–600 记“部分落地” |
| O2 | `Instruction Count` | 7231 | **5400–6400** | 落在区间外见 §3 |
| O3 | `dpas.8x8` 条数 | 256 | **256（必须不变）** | 变了 ⇒ 数学/形状被改，直接 E |
| O4 | `send.ugm` 总数 | 1216 | **1216（必须不变）** | 变了 ⇒ 供料被改 |
| O5 | 其中 `(16|M0)` 宽 / `(1|M0)` narrow | 128 / 1088 | **128 / 1088** | narrow 变多 ⇒ 多读了 A 行 |
| O6 | Scratch Memory Size | 0 | **0** | 非 0 ⇒ 溢出，B 类副作用 |
| O7 | Loop Count | 0 | **0** | 变 1..n ⇒ IGC 把循环卷回去了，代码形态反了 |
| O8 | Basic Block Count | 272 | 250–290 | 暴涨（>400）⇒ 分支被复制成多份 |
| O9 | `jmpi` 条数 | 136 | **≈8**（仅序言/尾声） | 仍 136 ⇒ 循环内分支还在 |
| O10 | 每步（1 个 k0）指令数 | 106 | **≈ 78–82** | 若仍 106 ⇒ 搬运没删 |
| O11 | `sync.nop` 条数 | 1096 | 900–1050 | 记分板变化，仅记录不判失败 |

预期的新形态：64 个展开步里，每步只剩 2 条宽 send + 16 条 narrow send + 11 条 `mov(8)`
（A tile 行→lane 重排，**这条不能删**，它是内存布局决定的）+ 4 条 DPAS + 地址计算；
4 个累加器整段停在 DPAS 操作数寄存器里原地累加（`dpas ... src-acc == dst`），
不再出现 `r52..r82` 这一组“家”寄存器。

## 2. 也可以接受的中性结果

* O1 减半而不是归零（例如只剩 8 条/步 = 512 条）：说明编译器只去掉了一部分 join，
  仍算部分落地，按 B 类记增量账（“还剩哪一侧的 join”要写清）。
* O2 略高于 6400 但 O1/O9 达标：说明删掉的搬运被调度补偿了，仍算落地，整体计时照测。

## 2.1 反例与边界（必须一起读）

F13 contract（94…129，已是现役）**已经**把判定提到循环外，但它的 mov32/dpas 仍有 2.27，
不是 0。这说明“提到循环外”本身只能去掉**按 DPAS 组**的那部分，剩下的属于**回边**上的
循环携带值溢出。expand 是完全展开（0 回边），所以本卡预测能全删；但若 IGC 仍然保留
一部分，请在 RESUME/回报里按“部分落地 + 增量账”写，不要把 2.27/dpas 这个残留说成机制无效。

另一个边界：F16 projection 有 2 个累加器却是 6.23 mov32/dpas，说明**搬运量与累加器个数无关**，
所以“减少累加器”不是本族的省搬运手段（而且会改读取量，见 ANALYSIS §0）。

## 3. 三类“不算落地”的判据

* **A（实现未落地）**：`mov(32)` ≥1400 且 `jmpi` ≈136。含义：join 不是搬运的成因，
  或 IGC 在更上层就把 `if(mA<live)` 变成谓词、并按谓词复制累加器。→ 下一条改动改走
  “给两个 A tile 各自独立变量 + 把 clamp 变成地址选择”（见 RESUME 的 next-2）。
* **B（实现落地但有副作用）**：O1 掉了，但 Scratch ≠0、或 narrow send 变多、或
  `Instruction Count` > 7231。→ 先修最大的一项（溢出优先）。
* **形态反转**：`Loop Count` ≥1 且 `Instruction Count` < 1200。含义：外层 if 让 IGC 放弃整体展开，
  循环被卷回，动态代价不可比。→ 记 A/B 混合，候选作废，不要拿整体毫秒倒推机制无效。

## 4. 数值侧同步判据（与 native 一起看，不互相替代）

* fixed 门 `1755e9c2…`、fb2 末帧 `9c3e511e…`、ordinary 末帧 `2b63d4ba…`（合同 §8.1 三套 gold）。
* 232 个派发全在，无 NaN/Inf，scratch 0。
* 若数值失败，先查 `rA/rB` 是否在 `[0, live-1]`（`PROOF.json.read_domain` 已枚举），
  再查 epilogue 的 `m>=live` 守卫是否被误改（本卡未改）。

## 5. 明确不声称的东西

* 不声称“24 条 mov 值 X 毫秒”。F10 的教训：只能归因完整机制 + 调度响应。
* 不声称“XMX 利用率”或“DRAM 带宽”有任何改善：本卡没有计数器臂。
* 不声称 S32/S64 那类 tile 重排方向已被证伪：本卡只证明在 4 累加器预算下它没有读取量空间，
  且 8 累加器版本已被测过（S64/K11 噪声、S64/K09 回归）。
