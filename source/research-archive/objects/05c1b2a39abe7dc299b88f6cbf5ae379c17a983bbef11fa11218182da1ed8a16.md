# C32 FFN owner/layout candidate — GPU verified

Baseline is the preserved F20-linear-scale2 plan, not bare COMBO-1. Candidate changes C32 ordinals 1,2,3,4,227,228,229 and their exclusively owned weight packs. F20 ordinal230 is unchanged. No deployment or stable-package replacement performed.

## Outcome

Fixed and two-frame feedback gates match gold byte for byte. All ordinary final feedback frames also match their paired baseline (SHA256 2b63d4ba1967eebcda61698d538963f59bccaf6d690ef8168f1695a46c5d658d).

Initial 3 process pairs ×30 samples: saving 0.382366ms, t(df2) CI95 [-0.021866,0.786598], INDISTINCT. These results remain retained, not discarded.

One fixed-size independent confirmation cohort was specified before execution: 6 process pairs ×30, alternating order, warm1 feedback, no instrumentation or per-pass timestamps, no outlier deletion. Result: saving **0.443900ms/frame**, CI95 **[0.245007,0.642792]**, approximately **2.021%** of the concurrent F20 baseline. All six differences positive. Secondary pooled nine-pair result: 0.423388ms [0.290216,0.556561]. No further timing of this identity is needed. Confidence intervals use independent process-pair means, not 180/270 frame samples as independent units.

F20's previously validated saving remains preserved. Do not add historical F20 and C32 point estimates and present the sum as a measured combined gain versus COMBO-1: this experiment measures C32's increment with F20 present.

## Implementation and mapping proof

AMD provides the principle: orient production so the accumulator can directly feed the next matrix operand. Its hardware lane maps are not copied. On this B580 measured map, CH and A have the same component coordinates; both are M8×N16, four halves per lane. The FFN alone now uses token rows and feature columns. Expansion accumulator -> half narrowing -> unchanged scalar activation -> A is local component transport. Contraction consumes each hidden K16 group in original order. Its half residual seed is widened before K0, as in the parent.

Expand and contract 16×16 weight tiles are transposed offline by uint16 bit copies. Per pack, exactly8192 half elements are permuted; all bytes outside these regions were independently checked unchanged. Every modified buffer has only target-pass consumers. Bindings, sizes, PUSH words and dispatch grids are unchanged. Matrix operand exchange still required GPU validation; it was not assumed bit-exact solely from algebra.

After contraction, a fixed register butterfly restores the original feature-row/token-column layout once. QKV, norm, attention, output projection and residual use the original source tail verbatim. For combined component d=0..7 and lane l, input coordinate is (2*(d%4)+l/16+8*(d/4), l%16). The desired transpose is (l%16, 2*(d%4)+l/16+8*(d/4)). Three component/lane-bit exchanges followed by swapping lane bits0 and4 achieve this. CPU symbolic enumeration checked all256 entries; an initial select-polarity error was caught and corrected before compilation/GPU execution. Each stage packs two independent values per uint shuffle; there is no floating arithmetic in the permutation. All32 lanes participate uniformly.

The build reproduces the parent SPV byte-identically and transfers its66 NoContraction decorations with checked operand signatures. No changes to norm trees, exp approximations or activation formula. Diagnostic X/E/Y data retain their logical coordinates; five legacy debug header metadata writes were omitted in the replaced FFN region, so diagnostic header equivalence is not claimed. The normal path does not execute these writes.

## Register and lifetime limits

The persistent FFN accumulator payload remains four float matrices ×four components =64B/lane; input operand payload remains32B/lane. Hidden groups are scoped and immediately consumed. Exit transpose input has16B/lane per16×16 tile; each packed pair return adds4B of logical temporary value. These are source payloads, not physical peak GRF allocation. Selections and packing increase short-lived temporaries; the measured code also contains more mov instructions.

Both natives reference at most r127 and both have zero scratch sends. This establishes no observed compiler scratch spill in these artifacts; r127 is not an allocation-size/occupancy measurement. Actual allocated GRF count and exact peak liveness remain unavailable, so no claim of unchanged register occupancy. End-to-end measurements already include the net cost of the new transpose, selections, loads and scheduling.
