1. 本卡做了什么（按 CARD.txt 的 A/B/C 三步）
----------------------------------------------------------------
[A] lane-map 探针（探针本身需要 GPU，故写成"上 GPU 的第一步"）
    问题: 8×64 f32 累加器带的 component k of lane L 到底持有瓦片的哪个 (row,col)？
          密封头文件只测到 8×16（row=2c+(L>>4), col=L&15）与 16×16。
    工件: probe.comp / probe.spv d50ed5ca… / probe-plan.txt 862f0ccb…（replaced==7，
          cpu-check 通过；**不进计时/门/部署**），判读器 probe_read.py（含 --synthetic 自检）。
    为什么必须 GPU: lane map 是驱动/编译器 SPIR-V→ISA 降级的性质；SPIR-V 里 component
          访问只是一个不透明类型的下标，CPU 侧无法读出。CPU 侧能证的只是"这个假设足够、
          且其他分支可判别"（PROOF.json.P3 + probe_read.py 的三态判读）。
    判读（probe_read.py，角色一致性测试，抗重复值）:
          H1   → k=4b+c 成立，候选**按构造数值精确**，直接进数值门
          PERM → 另一个同 lane 双射：改 NRH_C64_AT() 一行重建，零指令代价
          CROSS-LANE → 机制死（提取需跨 lane，≥64 shuffle vs 省 56 消息）⇒ 按 C 收尾
          NO-BASE → 探针臂没跑（--dump-intermediates / debug / 偏移），不是布局结论
    自检（CPU，未花 GPU 槽）: H1 合成 → H1 + 密封律 128/128；NAIVE 合成 → CROSS-LANE；
          人为置换 → PERM 且还原出该双射。见 probe-selftest-*.json。

[B] 寄存器预算（BUDGET.md）
    一条 8×64 带 = 2048 B = 16 GRF/线程；今天 bias 峰值 8 GRF（8 站点串行复用）。
    实测基准: 整核 r127；屏障之后 bias 段水位 r108（regwindow.py）。
    W1（本卡实现，两条带同时在场）= 32 GRF = +24；W2（h-外提，一次一条带）= 16 GRF = +8，
       代价是 shK 块读复制（load.slm 16→24，528 交织 mov 可能 →592，除非 igc 做 CSE）；
    W3（半宽 8×32）= **不是退路**：h-内仍是 32 GRF，h-外提则每行只有 128 B 连续
       ⇒ 32 条 128 B 消息/SG，既过不了 ≤16 门也省不下寄存器。卡里的"半宽"前提不成立。
    门（写死）: scratch 0 且 max_r ≤127 ⇒ 预算成立；否则 B 类，改 W2 并连 SLM/mov 一起报。

[C] 实现（candidate.comp / candidate.spv 242d6033…）
    8 个 `coopMatLoad(bias,fb,…,64u,LROW)` 站点 → 2 条 8×64 带读
    （基址 pc.p2.w+(t0+0)*64、+(t0+8)*64，行跨度 64 ⇒ 各 2048 B 连续）。
    保持: 每列块 2 条 shK 块读 + 4 条 DPAS（**128 不变**）+ 32 条 precise f32 加（左操作数逐项相同）
          + 8 处 nrh_narrow 半精度舍入点（OpFConvert 26→26）+ exp/den 树 + 唯一 barrier（1→1）
          + 64 个 `(16,16,B)` 块读（528 交织 mov 的来源，计数不变）。
    净: 每 SG bias 消息 64→8（−56，或 256 B 形态 64→16，−48）；执行路径 UGM 读 182→126（−30.8%）；
        逻辑字节守恒 4096 B；代码体积 −2244 B。
