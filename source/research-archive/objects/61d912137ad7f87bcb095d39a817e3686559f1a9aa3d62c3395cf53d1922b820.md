# Four independent exact F20 trials

Baseline: `f20-score-owner/plan.txt`, SHA256 `d655b6b16c1c7949d912812e84748c503c33278a8f32f5fe12438de2d510e666`. These are individual trials against that baseline, not a combined plan. Original P03 and the latest exact baseline are preserved.

## Q normalization directly in its score consumer

Keep QKV publication and the original norm tree. Leave raw Q in shared memory, load the existing two score A fragments, and apply `H(Q*n)` followed by `H(result*scalar)` there. The complete-query owner already owns every subsequent consumer of these values. Mapping is enumerated over all 2048 Q elements; no raw 32-value register cache is introduced. K still needs the existing publication barrier.

Source-level saving: 4096 bytes of Q-scale reads plus 4096 bytes of normalized-Q writes per workgroup. Score Q reads remain. Costs: coefficient addressing, half2 assembly and temporary scale values. The two Q fragments existed in the parent; new scale temporaries retire before score MMA. This is not a claim about physical peak GRF.

CPU caught a compiler detail before GPU execution: `precise` propagated backward into seven scalar norm operations. Those unrequested decorations were removed; the final eight NoContraction sites are fold3, K-scale1, Q-scale2 and bias2. Norm source is identical. GPU fixed/fb2 gates pass, but native total instructions increase 4209→4321 and SLM sends515→527. Deleting source bytes alone does not establish lower runtime cost.

## FFN expand→activation→contract, one interaction check

Rebase the existing peer8-fouracc FFN prefix onto the latest score-owner. This is explicitly the same FFN mechanism previously inconclusive on P03, tested once in a changed downstream compilation context. It preserves eight subgroups, expansion weight reuse, each output's K accumulation order and original activation rounding. Own fragments remain in registers while only peer fragments cross shared memory.

The inherited logical fragment peak is144 bytes/lane, excluding compiler temporaries; do not call that allocated GRF. Fresh native proves four disjoint expansion accumulator banks, their K16 consumers, all16 contract pairs with both weights issued before the first MMA, no overlapping B return banks, and no scratch instructions. Static instructions4209→4142, SLM515→451. Static DPAS64→80 includes alternate owner paths and is not a dynamic MAC increase.

## K consumer tiles using retired fold storage

Norm still reads row-major raw K. Scale writes normalized K into the retired2048-half shX slab with address `(c/16)*1024+(t/16)*256+(c%16)*16+t%16`. All2048 addresses are unique. Score consumes row-major16×16 K-transpose tiles from that slab. This leaves arithmetic and the producer publication barrier unchanged.

No new shared allocation; source K read/write byte count is unchanged. Fold shX consumers have retired before this reuse; debug output writes are behind the retained full-workgroup debug-context barriers. Normal output does not write shX. Added cost is scatter addressing and stores16 half elements apart for adjacent feature pairs. Native increases to4411 instructions,548 SLM sends and1473 MOV, versus4209/515/1356. The consumer-only simplification has not deleted total static work. Timing must judge the complete producer/consumer chain.

## Weight records matching the Intel B fragment

Offline repack48 weight tiles into32 lane records of8 half values, using measured B coordinates `k=2*d+(lane&1), n=lane>>1`. Load a uvec4 record and explicitly unpack its four half pairs. Each subgroup still requests512 bytes per B tile; all weight bits and matrix operations are preserved. Only resource475's selected matrix ranges change; all bytes from half offset16896 onward remain identical, including the final projection at17024. Original pack is untouched.

The baseline already uses wide weight loads: this is a test of assembly/address overhead, not a fix for hypothetical scalar DRAM loads. GPU gates pass. Native grows to4687 instructions and2322 MOV despite fewer static UGM sends. Static DPAS56 versus64 reflects a changed compiled layout/unrolling and must not be represented as fewer mathematical operations. There are no native scratch instructions. The record unpack/assembly costs must be paid in the timing comparison.

The first implementation used `unpackHalf2x16`, which returns f32, followed by an explicit f16 conversion. Native review identified extra conversion MOV: hf←f844 and f←hf378, against the parent's300/90. Preserve this failed implementation and its timing. One justified repair changes only those four calls to `unpackFloat2x16`, an actual half-bit decode; pack, mapping and arithmetic stay identical. Its native conversion counts return exactly to300/90, with4259 total instructions and1604 MOV. Integer uw←uw moves remain575 versus270 in the parent: eliminating numeric conversion does not eliminate fragment assembly. This repair receives one separate exact gate/native/resource/timing set, not a rerun of the previous identity. Source and native evidence are in `f20-packed-bitdecode/`.

## Measurement and decision

Main agent owns source, mapping proofs, native review and interpretation. Luna executes explicit GPU manifests only. Each arm: fixed and two feedback frames against exact gold; native; three alternating parent/candidate process pairs with warm1/reps30/feedback; one driver resource capture. Keep all samples. Compute95% t interval from the three process-pair differences, not180 falsely independent samples. Resource/profiling time is never ordinary evidence. No automatic fusion of winners and no sum of gains.

Static counts above include debug and alternative control-flow paths. They explain generated-code changes, not elapsed stage time or isolated causality. Physical GRF allocation remains unknown; driver scratch is checked separately. The fixture is synthetic. Exact equality in these runs does not establish correctness on every possible input.

Final measurements are written to each arm's `ORDINARY-REVIEW.json`, `RESOURCE-REVIEW.json`, and the batch `EXACT-FOUR-RESULTS.json`.
