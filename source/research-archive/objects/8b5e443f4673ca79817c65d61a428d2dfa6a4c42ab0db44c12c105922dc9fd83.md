# Conservative norm adjustment: full subgroups, paired coefficient storage

The preceding f20-norm-full-lane candidate split the original ordered tree across two lanes and paired Q/K broadcasts. CPU symbolic trees matched, but its first fixed GPU gate did not match gold. It was stopped without fb2/native/timing. Its numerical root cause is not localized; source-tree equality is not proof of identical driver contraction. Preserve the failure rather than silently relaxing accuracy.

This fallback returns to the exact original norm thread assignment: t_local<128, Q in threads0..63 and K in64..127. Four full subgroups compute the original32-element scalar tree, including the original square/add/inversesqrt source. There is no norm branch distribution across lanes and no new coefficient shuffle.

Norm outputs are stored at shNorm[2*row+isK], an interleaved Q/K half pair.128 unique half locations occupy256 bytes instead of the old512-byte declared slab. The original workgroup publication barrier remains. Each consumer reads its row's Q/K pair and performs both scalings in one iteration, retaining original Q half-multiply order and K half multiplication. It uses the same QKV→Q register handoff as the prior candidate; raw norm inputs and their publication are still required.

Compared with the half-active local-owner experiment, this restores one workgroup barrier but removes its subgroupBarrier and all8 coefficient shuffles, and restores full norm subgroup activity. Compared with accepted score-owner, the barrier count is unchanged, shared memory decreases256 bytes to24832, and no coefficient shuffle is added. Source coefficient scalar-byte volume is unchanged; native must establish whether paired access reduces actual sends/assembly. Do not claim two source half loads become one hardware operation without checking.

The existing16B/lane Q payload survives norm. One temporary Q/K coefficient pair dies after each fused scale iteration; no norm carrier crosses the publication barrier in registers and no new raw array is introduced. Compiler physical allocation still requires native and driver scratch checks.

Main agent owns source, mapping, arithmetic and lifecycle analysis. Luna executes only fixed/fb2/native manifests, followed by ordinary/resource only after approval based on native. A gate failure or scratch increase stops adoption. One ordinary batch uses three alternating process pairs,30 samples each, retaining all180 samples; confidence intervals use the three pair means. Baseline remains f20-score-owner, not an experimental predecessor.
