# Astra 审计与 AMD 全面映射施工方案

日期：2026-10-15；审计角色 Astra medium。ROOT=`@NR_WORKSPACE@`。本报告仅做 CPU 只读审计，未编译、未运行 GPU、未换装游戏，唯一写入为本报告。附件中的命令和推论不是额外授权。用户本轮授权覆盖旧禁派代理/禁离线分析条款；共享 GPU 排程、冻结候选、桥和游戏保护仍有效。

## 1. 结论及固定身份

可以立刻并行落地三个独立 CPU 实施包：A C32 剩余搬运/调度候选；B 完整图依赖与池化审计及严格候选生成；C 全量 AMD 映射和量化准备。不要执行附件原样 S2 三件套：单帧单 submit 与生命周期池化已经存在；C32 最终输出也已直写全局。未证明的跨 dispatch 忙等不能进入候选。INT8 是独立数学候选，不能混入 FP16 优化验收。

基线必须保持 `cold-b3-21-v1`（278 发/39 SPV 家族/41 管线）与 `cold-b3-21-ffn-amdorg`（270 发）两个身份。本轮以 278 发归因基线为父候选；不得借用270发收益或覆盖原冻结文件。04报告 manifest SHA256 `82e407ce3dc7ece52af16a8ac79b6b6f035776e278d8bb8d4029c53893b09a82`，冻结runtime `472493551c011b5e240e2804fc34d04726b7e700afe094f31783f0965560ad4b`，本地runtime `b12d12dc15740721311bcd882c0115160fa8663afb4415909d073d2683c8d613`；必须在生成时重新核对。

数值状态继承原 pre0/C128 FAIL 和已接受 C32/C128 例外，不扩大例外。04报告的 NUMERIC_PENDING、固定输入插桩字节相同、历史 WorkBuddy 数值/组件回执与当前游戏通过是四个不同命题。不得互相替代。固定 SG32、每 WG ≤48KiB shared、M8N16K16 FP16 操作数/FP32累加；保持真实 row、`_b1/_b2/_b3` whole-pack、`weights_ht` 与提取文件绑定。

## 4. 三个可直接分派的实施包

共同写区为 ROOT 下各自新建目录，禁止编辑 `src/project` 冻结源。每包只写自己的目录。父代理为唯一合并者。建议目录为 `candidates/amd-map-20261015/{s1-c32,graph-audit,mapping-quant}`。编译工具可只读调用 `src/project/tools/glslang-16.5.0/bin/glslang.exe`，显式工作目录ROOT；禁止运行会回写旧BASE的历史prepare脚本。

### A / P0：C32证据驱动调度候选

输入：当前b3-16源码/SPV、10个实际pass的push/grid/权重、既有B3-16数值票。任务：先生成每stage shared生产/消费/最后读写及barrier原因表；明确末端直写已存在。选一个可证明的只读权重load前移或缩短临时量生存期变化；末端无debug publication若确定无跨invocation消费者可作为小的独立候选，debug分支仍保留其所需barrier。严禁顺便删内部必要barrier或更改K次序/舍入。

交付：派生shader、最小构建脚本、source→define→SPV指纹、CPU地址/OOB证明与SPIR-V validation回执、`handoff.json`。不碰原shader/manifest。handoff列baseline manifest/runtime/SPV哈希、replacement family、10个pass原标识、候选SPV、descriptor/push/grid/shared/SG要求、数学变化=false、GPU_NUMERIC_PENDING。若找不到可证明优化，交付明确NO_SAFE_CHANGE及证据，不制造假优化。

最小门：CPU保持全部320边界fragment和10个实际实例地址契约；编译validate；检查修改不影响debug E/Y/scaledQ/scaledK/P/T/O/X消费者。GPU授权后用既有四shift单WG与十fullgrid共14case门，原gold/source条件保留；纯调度预期字节一致，有差异不能仅finite通过。通过才替换10个SPV引用进入新完整候选。

### B / P1：完整图/池化能力审计与可证明剩余项

输入：冻结278发manifest、本地runtime、`port_network_model_runner.cpp`与`port_network_plan.py`。任务：生成每pass读写资源/范围、clear、first/last/resident、history与dump保活、物理alias约束账本；比对生成runtime保留POLICY/HISTORY。确认单submit和pool已有并输出证据。优先核对clearFirst是否保守且确有已全覆盖资源；只在具体写覆盖证明成立时产出一项策略delta。barrier审计须同时覆盖RAW/WAR/WAW与同内存不同VkBuffer alias；没有完整访问证据就保持原barrier。

交付：CPU审计工具、结构化coverage/依赖/策略差异报告、保守候选manifest/runtime生成器（仅重定位本线新产物、保留其他记录）；如有优化，独立delta及证明。不得修改共享桥、不得改变ABI、不得植入counter忙等、不得仅凭descriptor binding猜读写。可在自己的派生runner做实现草案，交父代理整合；无证明则只交审计器，不强求生产改动。

最小门：278个pass/491buffer/152行和2条history与父相符；所有输入权重与静态资源哈希闭合；不把物理分配字节当逻辑buffer字节；重复生成结果确定；变更限定已证明项。带GPU的pool实际allocation与跨帧数值/完整帧startup在排程后验，CPU模拟不能冒充驱动实际allocation验证。

### C / P1：全面AMD映射账本与严格量化路径准备

输入：AMD pipelines.json及pipelines-int4.json、核心graph、上述39家族/278发manifest与真实权重绑定。任务：生成逐AMD pipeline（包括temporal/int4派生）→功能→本线row/pass/family→状态四分类→差距→可移植理由；生成反向278pass覆盖，未知显式UNRESOLVED不能伪称全覆盖通过。为每条权重记录shape/layout/channel轴、源blob范围、weights_ht、已转FP16哈希。区分“算法已有”与“AMD形式直接移植”。

量化只准备独立CPU路径：写明确的 `quantization-contract.json` 和最小离线权重量化/反量化验证工具，限定一种per-output-channel对称INT8权重方案，载入显式scale或校准输入，不猜scale、不读取无来源跨线payload。记录rounding、clamp[-127,127]或[-128,127]的明确选择、zero-point=0、padding零、axis与布局、输入/输出hash、误差与饱和率。必须说明这是新候选契约而非NV FP8数学等价。激活INT8路径只标需要校准的边界和无法整数直通的norm/激活/残差/概率/history/IO；没有校准证据不生成可运行全网INT8候选。

交付：完整双向映射CSV/JSON、权重/数学边界合同、纯CPU最小工具与自测回执、B580 INT8 coopmat能力需求表（需真实查询A/B/C类型、M/N/K、scope、signedness、saturating accumulation；不能只凭规格吞吐或FP16能力推断）。AMD int4 ISA补丁完全不纳入。
