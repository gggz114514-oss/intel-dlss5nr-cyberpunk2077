# n23-f05-shape / NATIVE-PREDICTION (rev 4 - after the stage-1 and probe measurements)

Both arms have now run. This file records **what was predicted, what was measured, and what any
future candidate would have to show** - the criteria stay hard-coded so a non-landing cannot be
re-labelled as a landing.

## Arm 1 - `cand` = stage-1 (V pair merged), already run

| # | observation | parent | predicted | **measured** |
|---|---|---|---|---|
| N-1 | `send.ugm ... load.ugm.d32x8.a32.bss[a0.2]` (QKV weight loads) | 96 | 80 | **96** |
| N-2 | `dpas` | 128 | 128 / 112 | **128** |
| N-3 | accumulator GRF span | 48 | 48 | **48** |
| N-4 | `store.slm.d32x8t` / `d32x4` | 64 / 4 | 66..68 | **64 / 4** |
| N-5 | `max_r` | 127 | <= 127 | **127** |
| N-6 | static instructions | 4813 | ~-50 | **4705 (-108)** |
| N-7 | wide message classes | none | - | **no `d32x16` / `d32x32t` / `d32x64t` appeared** |
| N-8 | `gates/fixed` + `gates/fb2` golds | `1755e9c2..` / `9c3e511e..` | must match | **byte-exact PASS** |

Reading: **N-1 did not move, so the message mechanism did not land -> triage A for the message
count.** N-8 passing byte-exactly is the strong positive result of the round: the 12 permuted packs
are semantically identical to the sealed ones and the 8x32 accumulator produces the same values.
`MESSAGE-WIDTH.md` shows N-1 was never achievable: the per-lane message ceiling is 512 B and one
16x16 tile already fills it, so a merged 1 KB fragment load is necessarily two messages.

| # | measurement | result |

Consequence for the accumulator budget: three merged 8x32 fp32 accumulators = 3 x 16 = **48 GRF**,
equal to the parent's six 8x16. The 24-GRF branch (LANE-COL) does not exist.

## What a future candidate would have to show (hard criteria)

1. **Full B1 (Q/K/V merge) landing evidence**: the weight-load class count **96 -> 48**. Since
   MESSAGE-WIDTH proves 48 needs a 1 KB per-lane message, the numeric criterion to look for first is
   a per-lane load with **`rd:16`**, or a `d32x16` class at `(16|M0)` + `a0.2`. Without that class in
   the ISA, 48 is unreachable and a claim of 48 would be an artefact.
2. **Partial landing** (stage-1 kind): 96 -> 80 would have meant the merged 16x32 load became one
   message. It did not, and the ceiling explains why.
3. Side-effect gates for any future merge: `dpas` <= 128, `max_r` <= 127, `scratch` not above the
   parent, `first_dpas` 2560, `sync/sync_allwr` 293/11, and golds byte-exact (numerics are the final
   arbiter, as this round showed).
4. **Never** accept a message-count reduction as a win if the golds moved: the two are independent,
   and stage-1 is the proof that byte-exactness is achievable while the message count is not.

## The reusable tool fact (why the probe worked)

`clock_runner --dump-intermediates` dumps exactly the buffers whose plan row
`POLICY <resource> <resident> <firstPass> <lastPass> <clear>` has `resident == 0`. `swin_9_debug` is
resource 50 with `resident = 1`, which is why neither n02d's probe nor the first attempt here
produced a dump. `probe/lanemap-probe.plan.txt` sets it to 0 and the dump appears as
`dump_swin_9_debug.bin` (458752 B). No runner change was needed.
