## 0. 计数口径（先固定，避免拿错指令族）

| 观察量 | 计数方法（ISA 文本） | base 实测（n04a） | 候选预测 | 判据 |
|---|---|---|---|---|
| 权重 tile 消息 | `send.ugm … load.ugm.d32x8.a32.bss[a0.2]` 的行数（`rd:8`，16-lane） | **48** | **24** | 不等于 24 → **N1 失败** |
| 权重区其它 d32x8 | `…d32x8.a32.bss[a0.0]` | 8 | 8（不应变） | 变了 = 别的东西被动了 |
| A 行消息 | `send.ugm … load.ugm.d32x8t.a32.bss[a0.0]` 的行数（`rd:1`） | **64** | **128** | 不等于 128 → **N2 失败** |
| DPAS 总数 | `dpas.8x8` 的行数 | **80** | **80** | 变了 → **N3 失败，直接停** |
| QKV 段 DPAS | 前 0 段（首个权重 send … 首个 `store.slm` 之后）的 DPAS | 48（全核 80 − attention 32） | **48** | 变了 → 数学被动 |
| QKV 段 acc 基址 | QKV 段每条 dpas 的目标寄存器号，去重 | `{35,43,51,59,67,75}`，间距全 8 | **8 个，间距全 ≥8** | 仍 6 个 → **N5 失败** |
| 最大寄存器号 | 全核出现过的最大 `rN` | **127** | 127 | 不是 127 也要看 |
| scratch / spill | IGC 报告里的 scratch 区大小；ISA 里是否有 scratch 访问 | 无（0） | **0** | > 0 → **N4 失败，STOP** |
| send 总数 | 所有 `send.*` 行数 | **422** | **462**（−24 +64） | 偏差 > ±4 要逐条追 |
| 静态指令数 | ISA 行数 | 4,229 | 约 4,229 + O(200)（多 64 条 send + prologue） | 只记录，不作门 |

> QKV 段的窗口定义：**从第一条权重 send 到第一条 `store.slm`**。注意父内核的第一批 A 行 send 早于
> 第一条权重 send，所以这个窗口只含 phase 0 的 24 条 DPAS（用于读基址，不用于总数）；总数用
> "全核 DPAS − attention 32" 的口径。

## 1. 期望在 ISA 里看到的八条（N1–N8）

| # | 期望 | "看不到就等于未实现"的判据 | 类别 |
|---|---|---|---|
| **N1** | `load.ugm.d32x8.a32.bss[a0.2]` **48 → 24** | 仍是 48 → 源码层面的"每 tile 载一次"没有形成处理（**A 类：实现未落地**），不得用整体毫秒倒推机制 | 主门 |
| **N2** | `load.ugm.d32x8t.a32.bss[a0.0]` **64 → 128** | 不是 128 → 第二遍没有真的重读（可能被 IGC 折叠/复用返回区），必须逐条读 ISA 解释为什么，不许假设"反正省了" | 主门 |
| **N3** | `dpas.8x8` **80 不变**，QKV 段 **48 不变** | 变了 → 数学/映射被动了（E 类），立刻停并回到 PROOF.json | 硬门 |
| **N4** | `max_r` 仍 127 且 **scratch = 0** | scratch > 0 → spill，**B 类（实现有副作用）**；先修寄存器（例如把 V 遍的 A 载入再前移、或把 Q/K 两块的 B 返回区分槽）再谈计时 | 硬门 |
| **N5** | QKV 段 DPAS 目标基址变成 **8 个**（每 acc 8 GRF），父是 6 个 `{35,43,51,59,67,75}` | 仍 6 个 → 8 acc 没有形成（A 类）；出现 8 个但间距 <8 → 分配器紧排，需按 BUDGET-C64.md §7.1 重算预算（结论不翻转） | 主门 |
| **N6** | send 总数 **422 → 约 462**；首个 DPAS 地址可能后移（Q/K 遍 prologue 变长） | send 总数偏差 > ±4 → 有别的消息类型被增删；首个 DPAS 后移只记录，**不作门** | 记录 |
| **N7** | 权重返回区仍 `rd:8`、A 行仍 `rd:1`；**不出现新的 send 消息类型**；`sync.allwr` 变化只反映累加器退休合并 | 出现新消息类型（例如 `load.ugm.d32x4`）= 实现走偏 | 记录 |
| **N8** | 每个权重 tile 的返回区活值长度 +1 条 MMA（B 的 WAR 触点后移一条） | 若 native 出现额外的 `sync`/等待包住 B 返回区，说明这条副作用被硬件看见了；据此判 B 类而不是 D 类 | 归因 |

## 2. 资源与门（与 native 同一批）

## 3. 分诊预登记（合同 §6，必须选一类）

| 观察 | 分类 | 下一步 |
|---|---|---|
| N1 不成立（权重仍 48） | **A 实现未落地** | 读 ISA 找 IGC 在哪里把两次载入合并了；不要报"权重复用无效" |
| N1 成立、N2 不成立（A 行没翻倍） | **A 实现未落地（部分）** | 逐条追 A 返回区；可能是返回槽位复用 |
| N1/N2/N3 成立，但 scratch > 0 或出现新等待 | **B 实现有副作用** | 最大副作用是第二遍的 A 重读；第一修法：V 遍 A 载入前移、或 Q/K 两块 B 返回区分槽 |
| 全成立、门过、整体显著快 | 采纳候选（成包或单族） | 主代理定 |
| 全成立、门过、整体不显著/变慢 | **C 或 D** | 归因写"权重减半 vs A 读翻倍的净权衡"，**不**写成"C64 权重复用方向无效"；按同族成包处理 |
| 数值失败 | **E** | 先查 m0a/m0b 的 K 列主序边界（m0b = 56 时到 1920+128 = 2048，正好填满 K 区）与 Q/V 的 row stride |

## 4. 若主代理想证伪 D1 的预算（可选，本卡没有提交这个候选）

D1（12 acc）不装是**预算判定**，不是实测。要证伪/证实它，只需要一个**不计时、不过门**的 native 槽位：
编一份 12 acc 的 C64 变体，只看 `scratch / max_r / QKV 段 acc 基址组数`。

- 若 `scratch = 0` 且基址是 **12 个 8 GRF 块**（或 12 个 4 GRF 紧排块）→ 本卡的 8 GRF/acc 与 125 GRF
  投影被证伪，D1 应重开；
- 若 `scratch > 0` 或出现 12 个基址但溢出 → 预算成立，D1 永久关闭。

本卡**没有**做这件事（卡要求先交预算、只做一个形态），也没有替主代理做这个决定。

## 5. 本卡明确不声称的东西

- 不声称 native 已经看到 N1/N2/N5（那要 GPU）。
- 不声称 −24 条 8-GRF 消息值多少毫秒；也不声称 +64 条 1-GRF 消息不值钱。
- 不声称权重 tile 减半是 DRAM 收益（同地址重复读，几乎全 cache 命中）。
- 不声称两个 pass 之间没有串行化（源级无依赖，native 见 N6/N7）。
