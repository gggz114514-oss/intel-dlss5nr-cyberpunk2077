采纳主审计纠正：BBL30 [0xEA0..0x14F0] = **QKV 投影**（非 score）。
源 s22_register_p.comp：`shared float16_t phase[4096], qkv[6144]`（qkv 本就是
shared——我此前"qkv K 侧 UGM"与存储类直接冲突，撤回；"bq0/bq1 驻留 SLM"无据，撤回）。
循环：kc=0..511 step64（外）；k=0..63 step16（内）；a0/a1 从 sy 两块 M8；三块 b 从
weights 经 wq_tile；六 acc00/01/02/10/11/12；每 b 复用两次。
native 证据链：[1500] 内层 r1.0+=16；[1510] jmpi 0xEA0（回 BBL30 头）；
[1580] 外层 r1.1+=64；[1590] cmp r1.1<0x200(512)；[15A0] 外层回边 → 结构与 QKV 完全对应。

一、地址公式闭合（UGM=weights，SLM=sy）
---------------------------------------------------------------------
wq_tile(r,k) = pc.p3.y + ((r/16)*32 + k/16)*256 （元素；hf×2=字节）
native 链（逐 PC）：
  [0EA0] r2.8 = r1.1 + r1.0          （kc+k）
  [0EC0] r3.4 = (kc+k) >> 4          （wq_tile 的 k/16 项）
  [0EF8] r20 = r150 + r3.4；[0F18] r28 = r20 << 8   （×256 项）
  [0F30] r32 = r1.6 + r28            （r1.6 = pc.p3.y 基址）
  [0F98] acc0 = r8 × 32              （(r/16)*32 项，r8 = 0x76543210 步进向量）
  [1000] r18' = (r32<<1)[0F78] + acc0 = **weights 字节地址**
  [1040] send.ugm r50 ← r18'（$19）；[1290] r5 链（$11）；[1380] r4 链（$12）
  → 三条 UGM = wq_tile(h*96+n0+{0,16,32}, kc+k) 的三块权重 b ✓（n0 三档由
    三个地址寄存器链的常量差区分）
SLM 侧：
  [0EB0] r4 = r154 + r1.0；[0EF0] r18 = r4 << 1（sy 元素×2字节）
  [0F10/0F20/0FD0/0FD8/0FE0/0FE8/0FF0] r18 + {384,640,128,896,256,512,768}
  = 行步进 128B（64 hf/行）× 8 行 = **一个 M8K16 片段 8 行**；两组 8 条 = a0/a1 ✓
  → 16 条 SLM = sy[mA*64+k] / sy[mB*64+k] 两片段的逐行读取 ✓
DPAS 操作数角色（地址级判定，ISA 顺序 ≠ GLSL 形参顺序——主审计警告实证成立）：
  ISA src1 = UGM 载入 = **GLSL B（weights b）**；ISA src2 = SLM 组装 = **GLSL A（sy a0/a1）**
  [1300] r9  += src1(r50=b0) × src2(r36=a?)   → acc0X
  [13F0] r75 += src1(r94=b1) × src2(r36)      → acc0X+1 列
  [1410] r85 += r50 × r32（另一 sy 片段）      → acc1X
  [1420] r67 += r94 × r32
  [1490] r59 += r14(b2) × r36 {$12.dst=[1380] UGM 写完成}
  [14A0] r41 += r14 × r32
  六累加器 = 2(sy 片段) × 3(weights 块) = acc00/01/02/10/11/12 ✓
  独立累加器、非单串行链（复证主审计）。

二、每线程执行次数交叉验证（§3 证据）
---------------------------------------------------------------------
内层 4 次（k 步进 16，0..63）× 外层 8 次（kc 步进 64，0..511）= **32 次/线程**。
latency 记录 freq（per dispatch，非族累计）：BBL30 各指令行 freq = 73,728 / 98,304
（两种（16|M0)/（32|M0) 宽度口径），split16_b26_l2 网格 6×4=24 WG… ×8SG×4 内层
×8 外层 = 6144…与 73,728 = 24×8×32×8? ——精确核对：freq/32 = 每内层块的
dispatch 线程数；73,728/32 = 2,304 = 24 WG×96? ——数字与 6×4×8SG×4×8=6,144 差
12×，说明 freq 计数含 SIMD 通道或 dispatch 聚合口径 ——**此项留作未决**
（不影响映射闭合；freq 口径与线程数换算需查 GTPin LatencyRecord 语义）。

三、UGM 发出 → 首消费（§2 追源）
---------------------------------------------------------------------
[1040]（b0，$19）→ 首消费 [1300] dpas（{$19} 等待）：间隔指令含 12 条 SLM 发出、
  8 条 sync.nop/allrd、约 20 条地址/搬运——独立工作存在，能否掩蔽 UGM 延迟未测。
[1290]（b1，$11）→ [13F0]（{$11}）：间隔更短（约 8 条）。
[1380]（b2，$12）→ [1490]（{$12.dst}）：间隔含 [1370] sync.allrd ($9,$10) 与
  2 条 sync.nop——b2 的返回等待与 allrd 同区。
SLM 返回约束：a0/a1 的 16 条 SLM 返回经 [10A0-10F0]/[1258/1270] 的 $N.dst 等待与
  mov 组装进入 r36/r32——组装链本身是 6 条 DPAS 前的必要串行段（长度 = 16 载入
  + ~12 mov，PC 距离≠周期）。
六 acc 并行提供掩蔽潜力；实际是否隐藏 UGM/SLM 延迟 = 未决（需调度级证据）。

四、[14B0..14E8] 累加器复制与循环携带（§3）
---------------------------------------------------------------------
逐 DPAS 输出复制：[1330] r22←r9、[1430] r108←r75、[1450] r124←r85、
[14B0-14C8] r116..r122←r59..r65、[14D0-14E8] r140..r146←r41..r47
（r67 的对应复制未在区间内出现——留查）。
复制目标全部为**循环携带**：首读者在循环退出后（[1620]/[1780]/[1AA0..2300] 的
QKV 输出窄化 mov）。
逻辑 acc 数据量 = 6×512B = 3072B/SG（96B/lane 均摊）✓（主审计数字）；
每迭代复制 ~5-6 个 acc ≈ 2.8–3KB 的 mov 流量；复制期间 dpas 输出与复制目标
**同时存活**（瞬时活值加倍）。
复制成因假说（待主审计复核）：dpas dst 足迹与后续 send 返回块重叠
（如 [1380] 返回 r14..r21 与 acc 尾部寄存器相邻/相交），编译器把 acc 搬到
不被返回块覆盖的寄存器；子寄存器级生命周期证明未完成——不能从最大 r 号推峰值
（按任务规则保留）。
若假说成立，31/32 次复制的"快照"语义是否多余仍取决于 dst 足迹是否真被覆盖
——未决，不在本轮断言。

六、最小诊断定义（交主审计裁定后才采集；§4）
---------------------------------------------------------------------

还是 sy-SLM 组装链？**
