## 诊断 B 的实际配置与结论不符

两个诊断 runtime 的第 560 行 PUSH 完全相同，word15 都是 4294967295，即有符号 -1。只有第 554 行 PASS 的 gy 不同。

| 配置 | 实际 ty bias | 实际 dispatch |
|---|---:|---|
| 诊断 A | -1 | 84×49×1 |
| 诊断 B | -1 | 84×48×1 |
| 完整失败候选 | 0 | 84×48×1 |

因此诊断 B 并未采用完整候选的几何，A/B 也没有执行所声称的“ty bias -1→0”对照。保留 -1 却减少一行 workgroup，会遗漏 body 的 tile_y=95，共 168 个 tile，即 2688 个像素、86016 个 half 元素。B 的失败不能用于证明重锚定改变了 K/V 交换伙伴，更不能作为硬件结构不可融合的证据。

具体生成错误在 ROOT/build/amd-layout-fusion-workbuddy-20261016/make_diag.py:88-92：处理 PUSH 时只看 out[-1] 是否 PASS，但实际 PASS 与 PUSH 之间有五条 BIND；条件从未成立，t[16] 没有被改成 0。诊断 A 只支持其实际固定输入下的 body 路径透明性，不能证明未由它执行的 DS epilogue 全部正确。

这项配置错误不改变完整候选数值 FAIL 的裁决，但原回执、RESULTS、台账、GPU 票和 INT8 入口中依赖 A/B 的根因结论应撤回或标未证。无需重跑旧 B 来维护原结论。

## 完整池化 tile 不必由一个工作组独占

父 nr_tok_addr 的 body tile 坐标为 tx=2wx+sx、ty=2wy-1+sy，其中 sx、sy 为 subgroup 的二维偏移。一个 body tile 为 4×4 像素，四个独立的 2×2 均值都在该 tile 内。因此每个均值所需四个像素属于同一个父 subgroup；跨工作组的是完整 4×4 池化 tile 的两半，不是均值运算自身。

当前 DS 用 M8×N16 cooperative matrix，能够按 4×2 个池化像素输出半个 tile。保留父 dispatch 84×49 和 bias -1 时，一条尚未实现的适配路线是：

- 保留 body 分窗、K/V 伙伴、half 出栈和原 skip4 写回，修改 DS 的局部均值到全局坐标映射；
- 对局部 4×4 池化 patch 使用 py=4wy-2+local_pool_y；
- 两个 M8 半块的起始行为 py0=4wy-2+2×(sg&1)，保持原通道分配与 K 顺序；
- 用有符号坐标和真实边界守卫抑制首尾无效半块，再按原 io_at 写出。不能让负 y 转成无符号后参与地址计算。

独立整数坐标核对覆盖 64512 个有效池化像素，各有唯一 owner，无重复和遗漏；32256 个 128-half 的 M8 写区间连续且互不重叠，恰覆盖 block4_out 的 4128768 个 half 元素。相应半块没有跨 4×4 tile 边界，因此当前尺寸下不必为此强制逐元素 scatter，也不需要跨工作组等待。

这是地址和所有权的 CPU 可行性证据，尚无对应新实现、SPV、数值或性能结果。不能提前宣称会通过或会变快，但它足以说明“必须重锚定、否则无法融合”的推论不成立。原 E1/E2/E6 的覆盖集合和指令骨架检查也不能再称为值等价证明；相同覆盖范围和指令结构不能抵消输入邻域变化。

## 阻塞不能推广到其他方法

父 pass2 的 F1 body 实际为 dispatch 168×96、ty bias 0；父 pass271 的 F2 body 为 84×48、ty bias 0。它们均不具有此次 F3-C32 的 -1 锚点，F2 尤其不能引用同一负锚点作为停工前置。

F3-C64/C128/C256 的目标分别是 output-c64、output-c128-full、output-c256-epi-only 最终输出 pass 与 DS 合并，attention 已处于其他 pass，不能直接套用 C32 完整 body 的跨 subgroup K/V 组织推断。各自需要实际输出 owner 与 DS store 的映射分析，当前只能标未实施、未证明。

AMD fswin_t.comp:2348-2361 的单 wave/head-split 条件是该 RDNA shader 分支及暂存组织的实现前提；nr_graph.cpp 的 pool 网格断言是该 host 分支的接口检查。这些事实可以指导移植，但不是对 B580 的不可行性证明，更不能约束本线只能由一个 WG 写完整池化 tile。L1/L2 布局接口和 F1 的 seed/history 前置也不是本候选失败后才出现的新阻塞，仍按施工单推进。
