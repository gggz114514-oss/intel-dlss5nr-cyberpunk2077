# Astra 独立审计：FP16 的剩余价值与 INT8 的正确比较方式

日期：2026-10-28。只读源码、计划、SPIR-V 和已有实测；本轮没有 GPU、编译、游戏写入或部署。文中所有时间均为已有记录，不是本轮新测。机器可回读身份、位置、独立CPU普查和关键引用均已并入 `EVIDENCE.json`。

## 结论

**现有证据足以建议把后续研究重心从广泛的 FP16 微优化转向 INT8 原生实现的评估；不足以认定 INT8 已能明显更快，更不足以替换现役。成熟 FP16 的逐位等价调优已接近目前这套 Vulkan/驱动实现的工程收益边界，但没有证据证明已接近 B580 的硬件极限。** 前一判断置信度中等，后一个“未证明硬件极限”的结论置信度高。

这种判断不是预设 FP16 到头。最近仍有真实结构优化获利，说明当前代码/编译器组织有影响；但同类容易删除的开销已大量消失，继续从小冗余、单条屏障和局部重排中获得明显整网收益的依据变弱。INT8 给出的新自由度是操作数密度、K32供料与中间表示，而不仅是更换MMA指令。线性链与动态attention在这方面的收益条件不同，混合精度完全可能比“所有MMA都INT8”更合理；目前仍是机制判断，不是性能结论。

**当前 INT8 性能不能代表 INT8 路线的上限。** 最新 v15 静态覆盖已完成，但主要仍沿旧组织作dtype施工，尚未取得现役FP16同等级的生产消费优化。公平审计要区分三个问题：同组织下dtype替换的收益与转换税、INT8原生生产消费设计带来的结构收益、与成熟FP16相比的实际净收益。目前只有代码机制和局部数值材料，缺少完成这三个比较的设备证据。v15表现差只能判v15，未实现的原生潜力也不能计作已经存在的加速。

## FP16 的空间在哪里，哪些已经没有了

本轮直接解析当前 39 个不同 SPV 的 Workgroup 声明，而不是相信 plan 的 `shared` 字段：

| 当前族 | PASS | 当前实际声明 shared | 工程含义 |
|---|---:|---:|---|
| F04 D034 | 33 | 全部8192 B | expand/activation/middle 已寄存器直交，M 跨 owner 发布仍必要；不是未融合旧 D1/D2/D4 |
| F05 attention | 36 | 全部16384 B | n36 的 arena 生命周期复用已经全族生效，不能继续以24576 B为父 |
| F06 output | 33 | **全部0 B** | C64/C128 原本已直读 gT，C256 n39 删最后 staging；旧交接建议“继续查 C64/C128 恒等 staging”已经过时 |
| F08 split16 FFN | 16 | 2048 B | 仅 debugTile 声明；正常 projection→activation→contract 已是寄存器链 |
| F09 / F13 | 16 /16 | 全部0 B | 再靠删 shared 不存在现成收益 |
| F10 | 16 | 20480 B | 已有权重返回分离和 arena/地址改造，继续减声明容量并未自动变快 |
| F20 | 1 | 24576 B | 单个长派发；删屏障/消息和改owner已有负例，不能把声明容量等同瓶颈 |

本轮还核实了两类必须区分的证据：

- **方向可行但实现失败**：F10 原生产消费布局版本 B 比成熟 A 慢；权重返回寄存器分离后的 C 在同批相对 A 净省 **0.422047449 ms**，相对 B 省0.740972496 ms。说明布局与编译器寄存器分配可以耦合到足以改变方向结论，不能拿第一次失败判布局或 INT8 无效。
- **真实低收益边界**：后续13个采纳步骤，最终同批只省1.2734 ms；大量低权重冗余、源码重排、删 `sel`、消息卡没有净收益。n39 又省0.103768 ms是真实结构删除，但如今该族所有宽度已无这一项。

这支持“FP16 当前工程机会已经变窄”，不支持“硬件已饱和”。`max_r=127` 是最高引用寄存器索引，不足以单独证明全部分配/occupancy/spill；SLM容量推导是约束，不是实测驻留。旧 XMX TFLOPS 估算自己保留了512/1024 MAC两种约定，不能转成独占XMX耗时或“75%等待可删”。阶段时间仍未独立分离。

还有一处源码注释误导：当前F05 C128文件顶部仍说score/PV有4/8 SG闲置，但实际n36代码按`sg/4`处理两个head，全部SG进入score/PV。旧注释不能算作尚未优化的半数执行资源。当前16KiB arena也已是Q/V生命周期复用后的结果。

剩余 FP16 结构性空间主要是寄存器分配与跨宽度 owner 选择，实施成本高且可能损失权重复用/ILP。没有可靠证据给它承诺再降数毫秒。F07 C256 的45056 B看似醒目，但整个族原诊断仅0.22 ms，其中单个C256约0.084 ms；不是应继续主投的方向。派发间间隙约0.382 ms也不能支持大规模 persistent 重写的优先级；该数只限制删间隙，不能用于排除减少跨算子数据流量的融合。

## INT8 当前事实与转换税

旧“129残余、静态关闭28、实际接线25”不是最新状态。本轮CPU普查直接读实际 plan/SPV，确认 v15 矩阵覆盖完成，逐位置结果在 `EVIDENCE.json`。与此同时，**零FP16站点不是原生INT8设计，更不是更快的证明**：

| 位置 | 当前FP16组织 | v15组织/增加成本 | 结论 |
|---|---|---|---|
| F05 C64/C128/C256 | 全族16KiB shared；现有P寄存器交接/arena复用 | 23056/27152/**48144 B** shared；C256保留half QKV/P，又增sy8、sq8、sk8、P8、V8、max/scale，静态barrier 8→12（相对其旧父） | dtype减半同时复制格式/量化归约，必须重做生命周期；不能原封移进最新FP16 |
| F08 | 正常路径寄存器链，仅2KiB debug | 旧INT8模块38912 B shared | 直接替换会丢现役组织收益，不公平 |
| F13 | 已有FP16两M权重复用 | INT8源码真实 qA producer→contract 直读，scale可折入epilogue；但旧qX需独立producer | 这里有可复用资产，也显示“只有换dtype”不是全部事实 |
| C32 F1/F2 | 已优化入口/尾部与body交接 | F2新增16384码点/WG、7次SG max、额外共享归约/屏障；F1候选捆绑历史未部署FFN改动且无自身设备参考 | 矩阵覆盖完成与产线成熟度有明显差距 |

F13 的旧实现有一个尤其直接的教训：把输入量化放进每个输出通道WG，曾重复128遍，源码记录单PASS约+1.19 ms/+5.7M SEND；后来独立qX生产者去掉重复。**静态scale仅删除scale求值，不会自动删除乘法、舍入、clamp、转型、重排或重复扫描。** 原生路线必须让真正的上游生产者在已有store时生成码，并让下一算子直接读这些码。

量化链中的 INT32→float 是必要的：activation、norm、softmax、残差不能简单保留整数累加。可以删除的是half/INT8双份物化、独立扫描、同一值重复量化、无消费者的镜像、每K迭代重复scale。不是要求把所有浮点指令消灭。

历史R17曾有结构性数值错误，后续累计链已绑定`r17-fix-a-dequant/spv/r17_pre_c256_i8_fixa.spv`（本轮核到SHA `0f4afb9b…f0b206`）；旧20dB不能直接判最新v15。R07等单帧PSNR属于误差测量，不是自身整数参考闭合。v15仍有F1参考缺口、block31旧pack尺度表缺陷等已知问题。这些是该累计包的成熟度问题，不能推导为所有INT8算子的固有限制。

## AMD FP8 对照实际说明什么

本机对照根为 `D:/nr-work-20261011/_mochi/DLSSNR-AMD-main/windows`。本轮读的是 `build/arch/rdna4.sh`、`shaders/rdna4/pipelines.json` 和 `ffwd3_t.comp`，即产品构建选择的RDNA4路径；不是仅存在于源码中的默认/候选分支。根中未取得可用Git分支名，故以文件SHA和产品defines定位，不冒称已验证AMD游戏部署。

实际 ffwd3/ffwd3w 启用 FP8 e4m3、FP32累加、packed/paired量化、group-major owner；fm2让同一权重服务两个token tile。代码在projection结果→量化片段→activation→量化片段→contract间在寄存器传递，最后直接写下游FP8/tiled布局。并不是每个矩阵先落half、重新扫描再量化。它证明**低精度要作为数据流组织来设计**这一工程原则。FP8可表示范围、量化指令及AMD wave/WMMA映射与Intel INT8不同，不能把其owner和shuffle数量原样照抄。

## 真实剩余结构开销：存在不等于可净删除

| 现状 | 本轮依据 | 能推导什么 / 不能推导什么 |
|---|---|---|
| F04的M仍跨owner发布 | 三宽均`mLocal[4096]` half，生产者写后barrier，contract再读；expand→act→middle已寄存器链 | 8KiB表示与跨owner交接是真实成本；contract需要不同owner产生的列，不能把它叫无用副本或宣称删除即获利 |
| F05 Q/K/V仍需共享供料 | 当前双head、16KiB Q/V复用；score/PV寄存器概率交接已存在 | 生命周期和表示仍影响资源，但旧24KiB、半数SG空闲、P整块暂存等旧事实不能重算为剩余收益 |
| F10仍有共享的输入/片段交接 | 当前20KiB smem、kc发布循环及必要barrier | 比零shared复杂，但先前减至16KiB未有明显收益；必须区分所需跨SG数据和身份staging |
| F08/F13仍有32位累加器及权重活区 | 当前寄存器链/两M权重复用；INT32同样是32位累加 | INT8操作数减半不等于accumulator或GRF减半，打包/shuffle与scale可能抵消 |
| 网络仍保留真实跨算子浮点边 | 激活、残差、norm/softmax的必要变换，后继消费前可能重新量化 | 有一部分可合并在生产末尾，有一部分数学上必须存在；静态scale不能自动删除转换税 |

因此本审计能指出**剩余工作与代价**，不能把所有这类指令/字节兑换成确定毫秒。没有同组织dtype与原生组织的对照，不能量化INT8净收益；没有当前全族阶段占时，也不能承诺FP16还能整体下降到某个数字。

仅作规模解释：若一个2.17 ms参考范围的完整族最终有效加速2×，全帧只省约1.09 ms；F04+F08+F13的旧诊断范围约4.35 ms，即使整体2×也只是约2.18 ms。这是`T*(1−1/r)`的情景算术，**不是性能预测或硬上界**，更不能把2×矩阵吞吐等同2×完整族。当前F08已改造，上述旧时间还可能高估现实可获范围。

## 审计结论的置信度与证据缺口

| 判断 | 类别 / 置信度 | 理由 |
|---|---|---|
| 最新Full为232 PASS/约17.45 ms；最新Small为108 PASS/约9.98 ms fixed | 已证事实，高 | 原始同批记录、runtime和SPV身份可回读；两种计时口径没有混成严格A/B |
| FP16已有大规模生产消费、owner、SLM/寄存器寿命改造 | 已证事实，高 | 当前源和SPV，与持续改造结果一致；F10从退化到净收益的因果链明确 |
| 常规逐位等价FP16优化已接近当前工程收益边界 | 工程推断，中等 | 主要易删边界已消耗，近期很多方向不再获利；仍有0.10ms级结构成功，故不是“全部到头” |
| FP16已到B580硬件极限 | 不支持 | 缺少可靠的硬件饱和/阶段极限证据，当前代码/编译器组织也仍能改变表现 |
| v15静态INT8矩阵覆盖已完成 | 已证事实，高 | 独立操作数级普查0 FP16/2062 INT8，无缺失模块 |
| 当前INT8与现役FP16优化成熟度不同，直接慢不能否定路线 | 已证事实＋推断，高 | 288对232 PASS、动态attention格式并存、F08 shared巨大差异，且v15零整网GPU执行 |
| INT8原生数据流有比当前dtype替换更大的潜力 | 机制推断，中等 | 本地ViT量化去重复、C2寄存器码交接、AMD产品FP8链证明机制可行；Intel具体成本仍未测 |
| INT8能明显更快且连续画质可接受 | 未知 | 缺最新整链/代表子链原生实现的端到端、native资源与连续反馈证据；不能由TOPS或单帧PSNR补齐 |

对用户“是否该转向INT8”的直接答案是：**值得把探索重点转过去；现在还不能把它当已证实更快的后端。** 继续无目标地打磨成熟FP16微优化，获得明显收益的依据已较弱；以未优化INT8现状判路线失败同样站不住。当前材料最缺的是公平的实现成熟度与净收益证据，而不是更多静态覆盖计数或罕见数值边界证明。微小画质差异可以按用户偏好交换性能，但结构性错误与持续反馈劣化不能被记作普通量化误差。
