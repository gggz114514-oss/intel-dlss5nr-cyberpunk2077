## 3. 本轮定位并修复的真实缺陷

### 3.1 适配 runtime 路径被 `std::quoted` 去掉反斜杠（rev3）

- 现象：`nrvk_backend_init` 失败 `rc=-8`，错误路径为 `E:NR-Workspaces...`（无反斜杠），读不到 `swin_1_weights` 等冷资产。
- 原因：`port_network_bridge_backend_plan.inc` 用 `std::quoted()` 读取路径；C++ 的 `std::quoted` 把 `\` 当转义符，单反斜杠路径被吞掉。
- 修复：新增 `read_quoted_path()`，逐字符读到闭合引号，保留原始反斜杠；仅改路径解析，不改 plan 语义、buffer、SPV、网络数学或布局。
- 验证：`plan_path_test` 解析 487 buffers / 266 passes / 1 output / 2 history，152 个 cold 文件 + 266 SPV 路径全部存在；`buffer0` 路径以 `E:\` 开头。

### 3.2 输出槽资源/fence 所有权悬空（rev4，关键）

- 现象：修复路径后，前 3 帧成功；第 4 帧复用 0 号输出槽时，宿主 `queue->Wait` 返回 `E_INVALIDARG`（0x80070057），`GetCompletedValue()` 返回 0x80004005；随后 `nr_failed=1` 永久闩锁，游戏里 NR 消失、帧率回到无 NR 水平。
- 原因：`nrvk_process` 把 `slot.res` / `slot.fence` 直接放进 `NRB_Result`；宿主 `Attach` 取得所有权并在 Pending 销毁时 `Release`，但槽本身没有额外引用。0 号槽第一次回收后再复用，槽里的指针已经是悬空对象。
- 修复：返回 `out->color` 和 `out->ready_fence` 时各 `AddRef()` 一次，宿主释放自己的引用，槽保留自己的引用；生命周期与 `NRB_Result` 合同一致。
- 验证：修复后同一会话 `processed_count` 连续增长到 828，`nr_failed=0`，`slots_in_flight` 回落到 0，`consumer_retire` 正常。

### 3.3 安装脚本失败自动回滚（rev2）

- `Install-VK102Package.ps1` 的 catch 用 `Write-Error`，在 `$ErrorActionPreference='Stop'` 下会跳出 catch，自动恢复不执行；已改为 `Write-Warning` + 逐项恢复/哈希校验，并在模拟游戏树做正常/故障注入预演。

## 4. 显存与卡顿（停止原因）

- **真实占用**：Task Manager 现场专用 GPU 内存约 **11.4 / 12.0 GB**，GPU 95%；关闭游戏后回落到约 1.3 GB（其他应用），说明进程退出/`NRVK_Shutdown` 的释放路径是通的，没有进程级残留。
- **采样口径错误（已修）**：短测脚本原先把 `GPUProcessMemory` 的每引擎/LUID 行相加，同一份分配被重复计入，出现 12 GB 卡上“22 GB 线性增长”的假曲线。已改为按进程取最大值（`Sample-RuntimeStatus.ps1`），与 Task Manager 的 per-process 口径一致；旧 CSV 的 `dedicated_mb` 绝对值不可用，`staging_*` 列仍有效。
- **真正无上限的结构（已修）**：nrvk 的 `staging` map 按游戏 color/motion/depth/exposure 指针缓存，切场景/资源集会新增组且从不释放。rev5 改为有界 LRU（当前 1 组 + 上一组，共 2 组），切资源集时销毁旧组的 D3D12 committed resource、Vulkan imported image/memory/view；并新增 `staging_groups`、`staging_bytes` 状态字段。
- **短测验证**：r5 + 诊断 ASI 运行 971 帧，`staging_groups` 始终为 **2**，`staging_bytes` 始终 **37.5 MB**，`processed_count` 持续增长、`last_status=0`；没有随帧数增长的 NR 缓存。短测后已回滚。
- **剩余 11.4 GB 是容量压力，不是泄漏**：计划 buffer 总声明 1,515.53 MB，按 lifetime 池化实际约 **620.7 MB**（425.4 resident + 195.3 aliased nonresident）；输出槽 3 × 14.7 MB；加游戏本体在 2560×1440 SR、当前纹理/RT 设置下接近 12 GB。要留安全余量，只能降游戏纹理/RT、关闭非必要 GPU 应用，或进一步缩计划池；这不是“回收失败”。
- 用户明确停止，没有继续测试；本轮未形成“游戏性能通过”结论，也没有把显存压力下的帧时当作候选成绩。
