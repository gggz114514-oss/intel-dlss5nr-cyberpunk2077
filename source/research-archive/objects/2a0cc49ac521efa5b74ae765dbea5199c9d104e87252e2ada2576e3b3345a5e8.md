## 3. SPIR-V 差分归因（`evidence/SPV-DELTA.json`）

方法：对父/子的**函数体指令 (opcode, word-count) 做多重集差分**，再对每条缺失指令
解析结果类型；`gM` 存储点用"指针链回溯到 binding=5 的 storage buffer 变量"判定
（操作数语法用 40 行探针核对过：4456=类型、4457=load、4458=store、65 的 base 在 word 3）。

三宽结果完全一致：

| opcode / word-count | 父有子无 |
|---|---:|
| `OpCooperativeMatrixStoreKHR` / 6 | 4 |
| `OpAccessChain` / 6 | 4 |
| `OpISub` / 5 | 16 |
| `OpSRem` / 5 | 16 |
| `OpLoad` / 4 | 28 |
| **合计** | **68 条 / 320 word** |

- **"子有父无" = 空**（没有任何新增指令）；`word(parent) − word(child) = 320` 与缺失集逐字相符。
- **缺失集中没有任何浮点类型指令**（结果类型解析：int / pointer / 无结果），即
  没有删掉任何 half/float 运算或窄化。
- `binding=5` 的 store：父 4 → 子 0；其余 4458 store 20 → 20 不变（`mLocal`/debug/`gY`）。
- `OpCooperativeMatrixLoadKHR` 20 → 20、barrier 23 → 23、全局变量集合不变。

**边界**：这是"多重集 + 指针链 + 结果类型"级别的归因，不是逐 ID 同构证明。
它足以说明"消失的是那 4 条 gM 组存及其整数地址算术，没有新增指令"，
但不声称每条指令的 operand 逐一等价。

## 4. 删掉的成本（源级有效写，不是实测 DRAM）

- 受影响 PASS：33（C64 7、C128 11、C256 15），workgroup 合计 **17,556/帧**（从 232 计划的
  dispatch 字段求和：C64 7322、C128 5922、C256 4312）。
- 每 WG 少 4 次 8×16 half 组存 = 128 half = 256 B。

- 这是"没人读的发布"，不改变任何读者可见字节；**不是** DRAM 实测、**不是** register spill、
  **不折算毫秒**。审计给出的 561,792 次是另一种计数口径（每 WG 32 次），本卡不采用。

## 6. 已知诊断副作用（必须写清）

使用 `--dump-intermediates` 时，transient 会被加入 OUTPUT 并置 `resident=1`，
删掉 `gM` 写会改变 M 的 dump 值。因此：
- 旧 `gM` dump **不再可用于等价门**；
- 本卡 gate 只比较帧输出（fixed / fb2），不把 M dump 纳入；
- 需要 M 诊断的父保持原样，不混用。
