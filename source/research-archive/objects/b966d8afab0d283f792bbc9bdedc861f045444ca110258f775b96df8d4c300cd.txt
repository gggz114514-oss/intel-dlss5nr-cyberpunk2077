2. 三个工具做了什么
====================================================================
2.1 patch_merge.py —— 严格 patch 合并器（schema dsh-plan-patch/1）
- 主键：BUFFER 用名称；dispatch 用 0 基 ordinal + 期望 PASS name；PUSH 用 (ordinal, word)；OUTPUT 用 index。
- 只按行编辑（planlib 结构原语），不做任何字符串全替换；改动后逐行对比原文件，
  出现计划外的行变化立即失败（UNEXPECTED_LINE_CHANGE），行数必须不变；重新解析后再比对
  buffer/spv/push/bind/output/policy 模型，保证“写下去的就是想写的”。
- 强制校验：base_sha256 必填且匹配；每个新文件必须存在、绝对路径、正斜杠；
  file-backed BUFFER 的 bytes 必须等于磁盘字节数；SPV 替换必须给 expect_new_sha256；
  可选 expect_old/expect_old_sha256 防基线漂移；重名 BUFFER、未知名称、同一资源多次编辑、
  两个 BUFFER 指向同一新文件、共享旧资源被拆、BIND resize 越界、OUTPUT 非 basename、
  OUTPUT 结构（必须恰好 1 条且在 POLICY 之前）、POLICY 被改、未知 patch 字段 —— 全部显式失败。
- 冲突不静默：一次列出全部冲突（code + message + detail），exit=3，且不写输出文件；
  成功时报告 base/out SHA、改动行号、每个文件前/后 SHA、校验摘要。
- BIND 跟随规则：只有“整段绑定”（offset 0 且 bytes == 旧全长）随 resize 自动更新；
  部分绑定不自动缩放，越界即失败 —— 避免 runner 截断而不自知。
- 额外安全：resize 时扫描 PUSH 中是否存在等于旧字节数的常量，给出警告（不自动改）。

2.2 freeze_candidates.py —— 24 份候选身份冻结（schema dsh-candidate-freeze/1）
- 对 D/c64-family-static/combo-*.txt 全部 24 份记录：plan SHA/字节数、header、dispatch 数、
  全部 489 个 file-backed BUFFER 的 SHA/字节数、60 个 SPV 的 SHA/字节数、OUTPUT 身份
  （index/format/文件名）、捕获输入 buffer 及其绑定位置。
- 24 份 plan 除“每帧 2 个捕获输入路径”外完全一致，因此存 1 份规范布局 + 每帧 overrides，
  哈希表按路径去重（535 个文件、60 个 SPV）；每份 plan 另有 resource_digest / spv_digest
  封存其解析后的完整资源身份。
- 与 HANDOFF-IDENTITIES.json 对账：66 条（6 文件 + 60 SPV）全部 match，required_mismatch=0。
  combo-34189 = 2b5481d5ce6b8ec8c1f62e68d2057b39d5267825d655e844a2ee2c5500f1c690；
  QUALITY-24.json = a2ea6f8d855c94da874953b42f95b0d3e30b53d598984056bb0c50da439c8681。
- --verify 模式：重算全部 plan/文件/SPV/quality 并输出 plans_missing/plans_changed/
  extra_plans/files_missing/files_changed/spvs_missing/spvs_changed/resource_digest_mismatch；
  任一漂移 exit=2（N3 用篡改副本证明四类都能被抓到）。

2.3 model_diff.py —— 资源级模型差异（schema dsh-model-diff/1）
- 分类：MODEL_WEIGHT / SCALE / SPV / BIND / PUSH / OUTPUT_PATH / INPUT_BINDING。
- 捕获输入单独成区（CAPTURE_INPUT，非模型类）：dataset 路径、pre.bin/post.bin/network-output.bin，
  以及绑进这些 BUFFER 的 BIND/槽位/捕获 dispatch 的 PUSH 元数据；模型清单里绝不出现，
  并有硬检查（capture_leaks 必须为空）失败即退出。
- 同族异帧自检（--sibling）：c64-34189 对 c64-41444 的模型清单必须为空，实际为空；
  两帧差异 = 2 个捕获输入路径 + dispatch 0 的 PUSH word 22 → 归入 CAPTURE_INPUT。
- 结论（c64-family 对 c32-equalized 父本，均 combo-34189）：
  MODEL_WEIGHT 8、SCALE 8、SPV 16、BIND 24、PUSH 0、OUTPUT_PATH 0、INPUT_BINDING 8，合计 64；
  structure 为空（header/dispatch 数/名称/POLICY 全一致）。
  明细：8 个 C64 FFN 的 weights（28672 B 不变）、scales（1856→2368 B）、
  producer+contract 各 8 个 SPV、24 条 BIND 因 scale resize 跟随（每 block 3 条）、
  8 条新增残差输入槽 BIND 8 → block{4,5,6,7,62,63,64,65}_out。

4. 发现与风险
====================================================================
发现
- 24 帧候选中“捕获绑定”不只是 2 条 BUFFER 路径：dispatch 0（f1c32_image_pre）的 PUSH word 22
  每帧不同（34189=646070429，41444=600422528），属于捕获元数据；生产合并绝不能整段复制
  PASS/BIND/PUSH。MODEL-DIFF.json 已把它归入 CAPTURE_INPUT 并给出证据。
- c64 对 c32 的模型差异完全落在 8 个 C64 FFN block 上：8 weight + 8 scale + 16 SPV +
  24 条 resize 跟随 BIND + 8 条新增残差输入槽；无 PUSH/OUTPUT/结构变化。
  因此生产基线只需应用这 64 条，且必须保留自己的输入与历史语义。
- 现有 906 个 BUFFER 中 489 个 file-backed，路径互不共享（0 个重复路径），
  且所有 BUFFER.bytes 与磁盘文件大小完全相等；patch_merge 把这两点作为硬不变量。
- 冻结与 handoff 完全一致（66/66），combo-34189 与 QUALITY-24 身份可复核。

风险 / 未闭合
- 未跑 GPU：无端到端/画面/性能结论；quality_accepted=false，candidate 绑定捕获输入，禁止部署。
- 动态尺度仍未完成：attention Q/K/V/P 与 QKV 投影 A 侧仍是 per-workgroup/per-query amax（S10/S11 范围）。
- BIND 自动跟随只覆盖“整段绑定”；部分绑定的 pack 改布局必须显式改 BIND，否则工具会拒绝越界，
  但“能装下”的部分绑定不会被自动缩放 —— 合并者需自行核对。
- PUSH 可能编码尺寸/几何：工具只对“等于旧字节数”的 PUSH 常量告警，不自动修改；需人工确认。
- 冻结是快照：候选目录新增文件或我们之外的人重跑 build 脚本都会使 --verify 失败，这是设计意图；
  每次合并前应重跑 --verify。
- MODEL-DIFF 只给结构/资源级差异，不含数值等价性；merged plan 仍需 planlib 校验 + GPU 复验。
