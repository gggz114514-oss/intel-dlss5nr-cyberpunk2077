# N17C F20 Q+Y — NATIVE PREDICTION (contract §4 Q5)

**Nothing here is measured.**  This card ran no GPU task, captured no ISA of its own candidate
and deployed nothing.  What follows is (a) the exact ISA deltas the change must produce, (b) the
criterion that voids the arm if it does not, and (c) how to reinterpret each failure.  The parent
numbers come from the read-only capture
`f10-weight-return-separation-20261027/captures/native-f20-pixel-owner/ISA/CS_asm76902ef344609c8a_simd32_0000000000000027_38_orig.asm`
(sha256 `121a38aa…`, kernel `76902ef344609c8a`, pipe 38 / ord 230), re-accounted in
`build/isa-sites.json`.

The capture to compare against is the **same pipe/ordinal capture of the candidate plan**
(`cards/n17c-f20-qy/plan.txt`, sha256 `9d12139a…`).  Per contract §8.7 an older native capture is
not the current identity: this card's own capture is the authority.

## 3. What the four predicated groups look like in the ISA

The parent emits the stage-3 pair and the stage-4 Q pair as plain `send.slm (1|M0) … 0x0200C504`
sequences whose address registers are built with `or rX, r92, <imm>`:

| group | parent addresses | base immediate | meaning |
|---|---|---|---|
| stage-3 Y pair | segment 3 (16 messages, `0x5F20`–`0x6080`) | — (address from `%98` + offsets) | `shY` publication |
| stage-4, region 2 (V) | `0x67F0`–`0x69C0` | `12320` = 4096 + 2·4096 | `shArena` V plane pair |
| stage-4, region 1 (K) | `0x7710`–`0x7A60` | `8192` = 4096 + 4096 | `shArena` K plane pair |
| stage-4, region 0 (Q) | `0x87D0`–`0x8950` | `4128`/`4096` = 4096 + 0 | `shArena` Q plane pair ← **this is the group that must stop issuing** |

In the candidate the same instructions must still be present (static 160) but inside a predicated
region.  Two shapes are acceptable, one is a failure:

* **acceptable** — a uniform branch (`jmpi`/`goto` with a scalar predicate) skips the group, or the
  sends carry a scalar predicate that is false at `p0.z = 0`;
* **acceptable** — IGC hoists the `p0.z` test to the top of the kernel and removes the group, in
  which case N3 changes to 128 and the runtime saving is already static;
* **failure (A class)** — the group still issues unconditionally with the two `load.slm.d32x8t`
  groups gone: then only the load half landed and the message saving is 32, not 64.

## 4. Register budget: what to look for, and what to do if it spills

| quantity | parent | prediction | if it differs |
|---|---:|---:|---|
| `scratch` | 0 | **0** | `> 0` ⇒ the two retained pairs collided at the stage-4 → stage-6 window; drop one half of the composite (Y-only was measured `scratch = 0`) and re-capture.  Do **not** quote a timing from the spilled arm |
| `max_r` | 127 | 127 | 127 is the last register; a value below 127 with `scratch = 0` means the allocator had slack (also fine) |
| `mov` | 1 687 | 1 660–1 700 | above 1 700 ⇒ the 8 Q component copies became moves; the live range is then longer than the coalesced case, which raises the spill risk (check N6 first) |

The composite's live-value peak is `handoff` 4 + `yhalf` 4 + `score_q` 4 = 12 GRF at the stage-4
`j = 0` iteration against the parent's 8 (the parent holds the Q store payload there instead of the
retained pair).  Net **+4 GRF** if the allocator coalesces `score_q` onto the store payload
(measured behaviour of the Q-only card: `mov` 1 687 → 1 679, instructions −55, no spill), worst
case **+8 GRF**.  The interval also contains the stage-4 → stage-6 debug dump block, which is the
tightest point of the card.

## 5. What this predicts for the dispatch and for the frame

| quantity | value | derivation |
|---|---|---|
| runtime messages / warp | 640 → **576** (−10.0 %) | §2 minus the 107 debug-only static messages |
| runtime messages / dispatch | 83 932 160 → **75 538 944** (−8 393 216) | 131 144 warps (16 393 WG × 8) |

| frame share of the PASS | 7.5 % | 1.367 ms of the 18.16 ms isolated sum |
| ordinary CI half-width to beat | 0.068 ms | `cards/n17-f20-body/RESULTS.json`, 6 groups × 30 reps |
| measured single points (32 messages each) | Q **+0.0257 ms**, Y **−0.0181 ms** | same-size ablations, opposite signs ⇒ the per-32-message effect is bounded by ≈0.026 ms |

So: the composite is the smallest ablation of this mechanism that can clear the frame floor, and
it clears it only if one fragment transport is worth more than ≈1.1 µs (0.068/64·1000).  That is
the number the request in `GPU-REQUEST.json` is designed to settle, and it is the same number the
cross-SG probe (`cards/n17b-f20-transport/PROBE-ANALYSIS.md`) would settle for the other 48
transports.

## 6. Run order and what may be quoted

1. `native` (both arms) → classify A/B/C by N1–N11 **before** looking at any timing.
2. `resources` (per-PASS `GpuTime`, 1 sample/arm, parent spread 7.1 µs) → corroboration only.
3. `gates` `fixed` + `fb2` → must equal the parent gold exactly (this card claims identical
   arithmetic; a frame delta is class E).
4. `ordinary` (6 alternating groups × 30 reps, paired CI95) → the only number that may be quoted
   as a timing result, and only with the triage class attached.

If N1/N2/N4 land and the CI still crosses zero, the verdict is **D (INDISTINCT)** for the
intra-subgroup class and the direction closes; if they do not land, the verdict is **A** and the
next move is to fix the landing, not to reinterpret the mechanism.
