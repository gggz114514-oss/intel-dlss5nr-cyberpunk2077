# n02d-f02-bias-wide — NATIVE-PREDICTION（第 5 问：可观察点与判据）

**本卡的候选没有在本卡跑过 GPU，因此下面全部是预测 + 判据，不是“已落地”的声称。**
采集口径按合同 §8.7：以本卡候选那一批 capture 为权威，n02c 的基线数字只作对照。

流程顺序（合同 §8.5“落锤顺序”）：**先看 native 是否形成处理（A 类），再看数值/资源，最后才看整核计时。**

## 2. 候选的预期（逐条写死）

| # | 观察点 | 预期 | 看不到就等于 |
|---|---|---|---|
| N1 | `load.ugm.d32x16t`（bias） | 64 → **0** | **A 类：实现未落地**（不是方向无效），不许换写法重跑 |
| N2 | 新增宽读 | `load.ugm.d64x64t` **+8**（每条 512 B）**或** `load.ugm.d32x64t` **+16**（每条 256 B）；两种都必须**成对报告类型与条数** | 若出现的是 `d32x1t` / 每 lane 一条的 64 B 读 ⇒ IGC 把 coopmat 载入标量化了，记 A 类（实现未落地） |
| N3 | 宽读的地址形状 | 每组 4（或 8）条消息的地址增量是 **+512 B（或 +256 B）连续**，两组基址相差 **+2048 B**（band0 = `pc.p2.w+(t0)*64`，band1 = `+2048 B`）；**不再出现** 8 条一组的 256 B 步长模式 | 若仍是 256 B 步长的 8 条一组 ⇒ 宽片段没成形（退化成 gather） |
| N4 | `dpas.8x8` | **128 不变** | 变化即实现错误 |
| N5 | `sync.bar` | **1 不变**（仍是 `@0xb520`） | 增加即新增同步 = B 类 |
| N6 | 528 条交织 mov | **528 不变** | 变化即动了 `NRH_B` 块读（本卡不该动） |
| N7 | `add :f,:f,:f` | **32 不变**，且顺序不变 | 变化即数学/顺序变了 |
| N8 | bias 窄化 mov | **64 不变** | 变化即舍入点变了 ⇒ E 类 |
| N9 | 最高寄存器 | **≤ 127** | >127 ⇒ B 类（预算不足，按 `BUDGET.md` 改 W2） |
| N10 | scratch | **0** | >0 ⇒ B 类，同上 |
| N11 | shared | **8192 B 不变** | 变化即引入了 SLM 中转（本卡没有） |
| N12 | 静态指令总量 | 4958 → **≈ 4850±60**（每站点少 7 条 uniform 地址 add、少 8 条消息发射，多出 2 条宽读的 4~8 条消息） | 若反而增加 100+ ⇒ 编译器把宽读拆了 |

预期净账（每 SG）：bias 消息 **−56**（64→8）或 **−48**（64→16）；
执行路径 UGM 读 **182 → 126**（−30.8%）或 **134**（−26.4%）；总消息 **209 → 153/161**。

## 3. 判据层次（写死）

1. **A 类阈值**：`load.ugm.d32x16t` 没降到 ≤16 ⇒ 记“实现未落地”；此时**不许**用整体毫秒倒推机制有效性。
2. **实现正确性**：N4/N5/N6/N7/N8 任一变化 ⇒ 实现错误，先修，不进计时。
3. **副作用**：N9/N10 不过 ⇒ B 类；按 `BUDGET.md` 的 W2（16 GRF，代价 +8 `load.slm`、528 mov 可能 592）修一版再测。
4. **数值门**：`fixed` = `1755e9c2fadba97f08cb5b02b7a4294cde3675379bdec75352287505f7e129d6`、
   `fb2` = `9c3e511e97a5879247bc2965792c96dd62928dddfd85a48bbf25af1e807d3536`（合同 §8.1）。
   两套都过才允许看计时；任一不过 ⇒ **E 类**，首差第一嫌疑人是 component 映射（先看 `LANE-MAP.json`）。
5. **前置**：`LANE-MAP.json` 判读必须是 `H1` 或 `PERM`；`CROSS-LANE` ⇒ 机制判死，不做计时。

## 4. 计时臂与归因（第 6 问的可执行版）

- **臂**：`base` = 链头 `accepted/restore-n10-f10-next-20261027/plan.txt`（`719f100b…`）；
  `cand` = 本卡 `plan.txt`（`4c41368b…`，只在链头替换本组 7 行，`replaced==7`）。
- **整体量**：`ordinary`（`--pool --warm 1 --reps 30 --feedback`）两臂 **6 组交替**的组均值差，
  配对 95% CI（df=5）；不用单点、不做剔除、不重跑（同 n01b 协议，可直接比）。
- **门**：`native`（本文件的 N1..N12）+ `resources`（scratch/max_r/shared/WG 数）+ `gates fixed`/`gates fb2`。
- **归因边界**：
  - 本卡只动 7 个 PASS 的 bias 读；F02 族占全链 1.366038 ms / 18.1637 ms = **7.52%**（`PASS-TIME-RANKING.json`），
    所以整体毫秒的变化上限受族占比限制，不要把整核 delta 直接当机制收益；
  - 同身份同 7 PASS 上 n01b 省 32 条消息 → +0.012712 ms、CI[−0.006922,+0.032346] **INDISTINCT**；
    本卡省 56 条，是同一数量级上的更大步长，但**协议分辨率是否够**仍需实测，不能先验声称显著；
  - n02c 已证这张 16 KiB 表 **dispatch 不变、全命中 L1/L2**，64 条消息**不付 DRAM 字节**，
    且已与 12 条 `dpas.8x8` 交织 ⇒ 属 L12（被并发隐藏）类，收益只能来自发射槽释放；
  - 单链归因只写证据支持的部分：若 ordinary 显著，归因写“bias 段发射槽 −56/SG”；
    若 INDISTINCT，按 D 类记，不推广成“宽读无价值”（这是唯一还没被测过的形状）。
