## 4. 输入 scale 资格

- 静态权重尺度：全部由 FP16 权重现算（`amax_k|W|/127`），**密封量化器 = `roundEven(half(W·(1/sW)))`**，
  十份 C128 pack 与十五份 C256 pack 均可逐字节复现。
- 动态激活尺度：全部在核内从当次激活导出（per-workgroup / per-tile / per-query / per-(window,head)），
  **没有把静态权重尺度当动态 Q/K 尺度用**。
- **仍未标定**：R08 血统的 `c128_b{N}_sc` 表、C-producer 的 `invX` 仍是
  `SINGLE_FRAME_DIAGNOSTIC_NOT_CALIBRATION`。这是"资格"缺口，不是覆盖缺口。

## 6. 具名缺口（复审请按此判）

1. **零 GPU 执行**：v15 从未上设备。这是最大的缺口，一条单帧就能开始填。
2. **F1 的血统**：`f1c32_image_pre` 的运行基线 `c32a_f1_transport.spv`（`cd803785…`）**源码不在树内，
   无法逐字节复现**。F1 候选由历史部分候选 `c32_f1_i8.spv` 派生，因此相对运行基线**捆绑了两项
   未部署变更**（① FFN 改 INT8 ② body 64 + lift 1 改 INT8）。它不是"基线 + 纯矩阵替换"。
3. **F1 无任何数值参考**（无抓取、无 oracle）。
4. **block31 pack 缺陷未修**：G3 绑的 `174bf517` 其 `ws[]` 尺度表退化（`ws[8]·ws[3]=0`），
   修好的 `9166f9c8` 是 `0.115711 / 8.642212`。换包会改掉所有 PSNR 比较的基线身份，属 X5/协调入口决定。
5. **C256 attention 声明 shared 48,144 B，距 B580 上限 49,152 B 仅 1,008 B**；occupancy 未知。
6. **16 个已废弃的 file-backed buffer 仍声明未绑**（456/458 ioport + 723–738 C32 body1 旧 pack），
   为免重编号整个资源 id 空间而保留。
7. **plan_lint 的 notes 44 条是工具缺陷**（它把 BIND 字段序读成 resource,offset,bytes），不是新问题；
   BIND 边界一律用 `tools/strict_bind_check.py` 判。
8. R16 的抓取帧退化（ViT 输入 absmax 5.6e-4 vs skip 32.5），该位置**没有能区分的数值证据**。
