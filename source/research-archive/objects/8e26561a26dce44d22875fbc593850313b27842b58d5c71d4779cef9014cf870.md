## 1. 映射：生产者每个 (lane,component) 实际代表哪个 (token, channel/head/k)？

本卡**不改映射**（被删的两条语句只写 `dbg`，不参与任何输出的产生）。下表是候选的映射，
可在 `proof_cover.py`（n20 目录）与本卡 `step8_stores.py` 上复算，`covered_exactly_once = true`。

### 1.1 片段归属（8 SG × 2 r × 4 acc = 64 个 8×16 片段）

| sg | q=sg/4 | c=sg%4 → n0 | r | acc | m 起 | n 起 | 输出元素数 |
|---:|---:|---:|---:|---|---:|---:|---:|
| 0 | 0 | 0 → 0 | 0 | accA0 / accA1 | 0 | 0 / 16 | 128 + 128 |
| 0 | 0 | 0 → 0 | 0 | accB0 / accB1 | 16 | 0 / 16 | 128 + 128 |
| 0 | 0 | 0 → 0 | 1 | accA0 / accA1 | 32 | 0 / 16 | 128 + 128 |
| 0 | 0 | 0 → 0 | 1 | accB0 / accB1 | 48 | 0 / 16 | 128 + 128 |
| 1..3 | 0 | 1..3 → 32/64/96 | 0,1 | 同上 4 个 | 0/16/32/48 | n0, n0+16 | 同上 |
| 4..7 | 1 | 0..3 | 0,1 | 同上 4 个 | 8/24/40/56 | n0, n0+16 | 同上 |

- `m ∈ {0,8,16,24,32,40,48,56}` 每个**恰好一次**（`mA=(q+4r)*8`，`mB=mA+16`）；
  `n ∈ {0,16,…,112}` 每个**恰好一次**（4 个 c 组 × 2 列块）。8×8 = **64** 片段，无漏无重。
- 每片段 8 行 × 16 列 = 128 个输出元素；64×128 = 8192 = 64×128 （每 WG 的 Y 元素数），写域两两不交。
- **删掉 dbg store 后**：`gY` 的 64 条写消息一条不少（`step8_stores.py`：父 8 个 `OpCooperativeMatrixStoreKHR`，
  其中 4 个的指针链里有常量 `81920`＝dbg 基址；候选 4 个，`with_dbg_pointer = 0`）。

### 1.2 被删的 `dbg` 副本代表什么

| 项 | 值 |
|---|---|
| 目标 | `DbgBuf` binding 4（声明**仍在**，descriptor 集合未变） |
| 地址 | `81920 + m*128 + n`（**不含 `w`**） |
| 覆盖 | 64 个片段各 1 份，每 WG 64 KiB 逻辑写；**264 个 WG 写同一段地址** |
| 结论 | 这是一条**诊断用的、跨 WG 互相覆盖的** dump 路径（`debug != 0` 才有意义），生产帧里恒假 |

> 这张表就是“为什么删它是安全的”：它是 `gY` 的**第二份拷贝**，不是消费者，也不是任何计算的输入。
> 反过来，它也是**唯一**让 `narrowed` 这个 f16 staging 有两个读者的东西 —— 见 §3 的 WAR。

## 3. 重叠：独立工作原来如何重叠？（A、每块 B、每组 acc、残差、norm/den 的生产者 / 最后消费者 / 覆盖者）

本段没有 norm/den（`c128_norm_sum32` 未进模块），也没有残差 seed 的先后关系（seed 是 `imgin` 的 f16 拷贝）。
重叠分析只对 A/W/acc/收尾四类做：

| 值 | 生产者 | 最后消费者（父） | 覆盖者（父） | 父的 hazard | 候选的变化 |
|---|---|---|---|---|---|
| `a`（MAT_A, m=mA, k=16ki） | `load.ugm.d32x8t`（staging `r12/r13`） | 2 条 DPAS（`accA0/accA1`） | 下一条 `load.ugm` 复用同一 staging | **WAW**（staging 复用）+ **RAW**（DPAS 读） | 不变 |
| `a'`（m=mB） | 同上（staging `r14/r15`） | 2 条 DPAS（`accB0/accB1`） | 下一次 ki 迭代 | WAW + RAW | 不变 |
| `wb0/wb1`（MAT_B，16×16） | `load.ugm.d32x8`（`rd:8`） | 4 条 DPAS（两块 m × 2 个 n） | 下一次 `r` 迭代重载同 tile（n20 记 2× 冗余） | RAW；跨 `r` 的 **WAW** | 不变 |
| `accA0/1, accB0/1`（MAT_C，各 8 GRF = 32 GRF） | `MAT_C(seed)`（f16→f32） | `MAT_H(accX)` 窄化 | 无（single assignment） | RAW 链 8 步 | 不变 |
| `narrowed`（f16 staging `r12..r15`） | 收尾 `mov (16|M0) r12/r13/r14/r15 ← acc` | **① `gY` store ② `dbg` store（父）** | 下一次 `r` 迭代 | ② 是**额外的 WAR 延长者** | **候选只剩 ①** |
| `yrow` 地址（`r120/r122/r124`） | `add rNNN = r56 + 1024/1536/2048`（`0x0CB0..0x0CE0`） | mB 的 Y store（`0x1450/0x17E0/0x1BA0`、`0x4580/0x4910/0x4C90`） | 无 | 长活值（跨整个 kernel） | 不变（本来就不喂 dbg） |
| `dbg` 地址料（`r4..r11`） | 门控区内部 | 门控区的 8 条 store | 生产段复用同一批寄存器 | 候选里整段消失 | **删除** |

要点：**唯一的“重叠收益”是 `narrowed` 的 WAR 延长者消失** —— 它原本迫使 f16 staging 与 row 地址
在 `gY` store 之后继续活着，直到 `dbg` store 把它读走。这是一个**真实的活值区间缩短**，但它缩短的是
`r12..r15`（低位 staging），不是 `r120..r124`（决定峰值的行地址）。所以本卡的目标是“保护供料、只删死读”，
而不是把 A/W/DPAS 串起来。

## 6. 整体是否更快（本卡不能说，所以写清要测什么、用什么臂、如何归因）

> **已被 §0 的实测取代**：同批 ordinary 6 组 × 30 样本已跑完，

> 这与“删的是死代码、动态工作量不变”的预期一致；按 L13（<0.03 ms 不可判）该差不得记为收益。

- **本卡不提出任何毫秒主张**，也不许把 debug 删除报成收益（合同禁止）。`debug == 0` ⇒ 动态工作量不变，
  物理上的唯一差别是模块小 1464 B、ISA 少 186 条静态指令、前导段可能重排。
- 要测的整体量只有一个：**`n21 plan` vs 链头 `719f100b…` 的同批次 ordinary 帧时**（warm1/reps30/feedback，
  两臂 6 组交替）。归因口径：本卡删的是死代码，**预期 ≈ 0**；按 L3/L13，任何 <0.03 ms 的差都不可判，
  出现也**不得**记为收益，只能记为“重排噪声”。
- 归因只允许写到这一句：*若帧时变化，唯一可能的物理通道是代码布局/调度，而不是“少做了工作”*。
- **真正该测的是 step B**（M4）：它才是同时降字节与消息的形态（每 WG load 208→144 KiB、权重消息 256→128）。
  step B 的前置条件（≥32 GRF）由本卡的 native 捕获给出，见 `RESUME.txt` §五。

## 附录 A：卡面前提的两处修正（不改历史证据，只登记）

1. **“384 条 = 48 个 coopMatStore×8”**：源码里 `if (debug)` 只有 **8 个**（4 acc × 2 个 `r` 体），
   SPIR-V 里是 **4 条** `OpCooperativeMatrixStoreKHR`（`r` 循环在 SPIR-V 仍是循环，由 IGC 展开），
   ISA 里是 **8 个门控区 × 8 行消息 = 64 条** `store.ugm`。386/384 与任何一层都对不上，
   本卡按 **ISA 实测 64 条/线程** 记账（与 n20 §2.1 的 `store.ugm 128 = 真 64 + dbg 64` 一致）。
2. **“已用 r124”**：naive 扫整份 ISA 得 **127**，因为 `0x0000` 那条 `and` 用 `r127.0` 存 flag；
   真实数据活值上界是 **124**（`r120/r122/r124` 是 mB 的 Y 行地址）。判据因此拆成
   `max_r_data=124` / `max_r_any=127` 两个量，决策用前者。
