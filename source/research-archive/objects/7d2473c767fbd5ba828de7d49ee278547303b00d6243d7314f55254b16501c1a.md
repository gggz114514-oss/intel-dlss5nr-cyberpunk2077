## 真正差异，不是统一转置就能解决

AMD fswin_t.comp:170 起明确采用 feature×token，weights 为 A、activation 为 B。其测得的 16×16×16 FP8 片段 C 可接 B，故中间的 feature 行自然成为下一乘法的 K。QK 采用 K×Q^T，分母沿 key 行归约。此设计选择来自它自己的片段映射。

Intel 当前 register_handoff.glsl:19–35 给出的实测 C/CH/A 映射一致：row=2*component+(lane>>4)，column=lane&15；A/C 是 8×16，而 B 是 16×16、8 个 half/lane。适合保留 token×feature，使结果直接成为下一乘法 A。换成 AMD 的字面朝向，就必须将两个 M8 输出拼成 B16，涉及跨 lane 搬运；不能由 AMD C=B 的事实推导 Intel C=B。当前 body 已采用适合 Intel 的直接 C→A 路径，不需要再转回 AMD 朝向。

AMD plain C32 的一个 wave 持有全窗口，不能据此把 B580 的八 SG 机械压成一 SG。FP8 一个值只有一个字节，Intel 本线 half 为两个字节，累加片段形状也不同。同样的窗口会有不同寄存器压力和可用并行度。AMD 源码自己的 NR_K_REGS 检查还指出：两 wave 时每 wave 只拥有半窗，按全窗寄存器寻址会越界。这里借鉴的是所有权合同，不是宏名或 wave 数。

## 已实现：F20 完整 query owner

P03 score 将 `m0=8*(sg/2+4*j), n0=32*(sg%2)` 分给两个子组，二者分别生产同一 query 的前/后 32 个 key。den/PV 却需要 `m0=8*sg` 的完整 64 key。这条不一致要求 4096 half 的 P 写入共享，再由 PV owner 读回。

新代码 score 固定 `m0=8*sg`，两轮 `n0=32*j` 生产自己的全部 key；CH 的每个分量直接写入同一 lane 的 p_cache。随后沿用父 den 与 PV。Q 的 K0/K16 两片只加载一次，四个 key tile 共用；没有新增权重读取，没有新增转置、shuffle 或 owner 选择。den 的既有 shuffle 与 owner 谓词完整保留。

4096 个元素的覆盖与 owner 逐项枚举见 PROOF.json 和生成器。每个 score 的 MMA 顺序仍 K0→K16；bias 在 float 中相加，随后 half 舍入和原 exp。den 的半精度树、零 seed、倒数位置、归一化 half 乘法均不改，PV 按 K0→16→32→48 累加。fold、FFN、QKV、norm 和 output 算术源码保留，7 个 NoContraction 装饰对齐继承。

## 成本与生命周期

每 WG 删除 P 写8192B、P读8192B、重复Q读4096B，共 **20KiB 逻辑 SLM 流量**；删除一道正常路径屏障。shXP 不再需要存 P，仅供早期 fold 和 debug O，4096 half 缩为2048 half；共享声明29184→25088B。上述是源级逻辑账，不是显存流量或实测耗时。

score 段新增活值不是零：Q 的两片保持到全部 key 消费，第一对 P 片段跨第二对 score 的计算存活。保守片段负载小计由72→96B/lane，增加24B（不含地址、临时值和分配器 packing）。它不是物理 GRF 数；不能用静态最大 r 编号当寄存器峰值。score 结束 Q 与 float 累加器退休，den/PV 的 P 缓存大小与父一样，不把新活值带到后半段。

八 SG 全程参与，score 的64次 MMA/WG和64次 K tile 加载不变。Q tile 加载32→16，真实减少供料。原 Q/K scale→score 屏障仍保留；只有不再存在跨 SG 读者的 P 发布屏障被删除。没有撤掉 K/V 的必要同步。
