# 报告33：组合收益未成立的成本对照与C3符号更正

2026-10-17。承接报告32。CPU复核原始单硬件回放计数器，未运行GPU、编译或修改封存件。用于回答“为什么组合没有进步”，并补充报告32未逐项指出的C3符号错误；报告32的整图计数及不晋升裁决保持有效。

**当前证据支持的解释：若干局部优化确有进步，但输入融合增加了其他工作，完整组合仍未测出净加速；最关键的寄存器供料、布局和设备依赖方法也未全部落实。不能把少11发等同于整帧变快，更不能归结为噪声吞掉既成收益。**

原始三臂普通整网中，这三个候选的median点估计也都比两个父慢，但未同时越过005差界，仍须写UNCERTAIN，不升级为明确回归。这一测量方向与增加工作量相容，尚不足以逐项证明耗时因果。

## 2. 合并派发节约的成本并非全部净收益

原先分核之间的显存交接被融合前言、shared staging、寻址/重排等工作替代；C3源码和上述计数器证明新交接并非零成本。整图仍有收益项：combo-v2的ALU1减少161～164M槽、GPU读取减少217～257MB；但同时SEND增加8.55～9.37M槽、SLM读取增加114.51～118.75MB，ALU2额外增加5.947392M槽。

因此这不是“所有局部都更省、为何加起来没有收益”的情况。部分方法省、部分方法加成本；成员冲突还替换了原先C5的部分优化，组合必须独立验收。

combo-v2的occupancy关联画像约76.5%→71.7%，总停摆画像约52.1%→53.5%。这是并发/等待尚未改善的证据线索，**不是已经证明GRF溢出、SLM驻留上限或某一种停摆独占了多少ms**。新核没有新增原生scratch，也不能据此断定寄存器压力不高。

## 3. 实际进步与未实现部分分开

- C5独立子组合确有约0.29ms明确收益；不是所有工作都没有进步。
- 最终combo-v2为31.573827ms，两父为31.564244/31.329869ms；相对中点偏慢0.126771ms，按双父差界仍UNCERTAIN。没有已证的最终组合加速。
- 完整ViT公共布局、F8完整寄存器链、若干ALU/供料/同步适配、M24/M25真实设备链仍OPEN。部分时间用于修正数值、owner、ABI和证据错误，不能记作性能改善。
- XMX双硬件回放污染feedback、M23沿用旧图索引等缺陷，使部分“瓶颈已改善”判断缺少有效测量基础；它们不使普通整网测速失效，也不能当作普通整网未加速的执行原因。

ALU槽、读写字节减少不保证关键路径缩短：可能减少的是与其他工作重叠的成本，也可能被新成本抵消。现有证据不能给出各项独占ms分账，不能编造“省了X毫秒又被Y吃掉”的精确因果。

## 4. 对005续作的具体影响

1. 在新的总账/纠正包修正C3的ALU1及SEND方向；封存原件不改。不能据错号将C3归为确定的轻量化成功。
2. 将减少staging、地址/重排与冗余矩阵工作作为已有C3适配的成本目标；复用原来的owner、数值、资源和负例，不重新跑同一身份追CLEAR。
3. C5明确受益部分保留；整图候选不以最少派发数或“所有方法都放进去”为目标。已有combo-v2保留为研究候选，不晋升。
4. 按报告32继续真正未完成的寄存器供料、保原归约序的公共布局和设备依赖方法。必要新身份以同批实际ns/ms验收；计数器只能辅助解释。先修已复现的XMX回放scope和M23图身份，不用失效画像安排施工。

方法仍为005固定M01—M26；本报告不添加新方法，不启动GPU、不切INT8，也不证明硬件达到上限。
