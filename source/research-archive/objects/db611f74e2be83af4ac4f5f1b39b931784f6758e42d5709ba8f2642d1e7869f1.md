# NATIVE-PREDICTION — n09-f09-f11-store（F11，15 PASS）

**本文件是预测 + 判据，不是“已实现”的声明。本卡没有 GPU、没有 native 采集、没有计时。**
父方基线数据来自只读历史采集（`f10-kv-retired-input/family/captures/native-f20-pixel-owner/ISA/CS_asm585aeef5165a31b8_simd32_0000000000000014_19_orig.asm`，sha256 `9c1942e1…779c`，见 `NATIVE-BASELINE.json`）。15 个 F11 PASS 共用同一 SPV ⇒ 同一 ISA，故“父 ISA”只有一份。

## 2. “地址已经折叠”的可观察证据位

- 父：4 条 store 各自带独立偏移寄存器（`r4` / `r9` / `r18` / `r1`），偏移在 0x00C0–0x0220 段分别算；这在 native 上表现为 **≥4 组** `add/shl` 链。
- 候选：源码只有一次 `tiled()`（`ob`）与一次 `tiled(t0,0,512)`（`xbase0`），其余是常量 {+8, +8192, +8200} half（+16, +16384, +16400 B）。
- 判定方式（不依赖我的预测是否对）：把 4 条 store 的偏移操作数**溯源到定义指令**，若它们的定义是“同一基址 + 立即常量”，说明折叠落地；若是 4 条互不相关的 `add/shl` 链，说明 IGC 已经把父的 8 处求值折成 4 组（即父已折叠，本卡无空间）。

## 3. 判据表（分类按 CONTRACT §6）

| 观察结果 | 分类 | 结论措辞 |
|---|---|---|
| N1 静态指令数下降 **且** N2/N3 至少之一下降，N5–N10 全部不变 | **C→（有实现，量级待测）** | “地址重算删除已落到 native”，效果量级交给 per-dispatch GpuTime |
| N1–N4 全不变，其余全不变 | **A 实现未落地** | “IGC 已把 8 处 `tiled()` 折成 4 组基址+常量；本卡不构成收益，方法未被证伪” |
| N5/N7/N8/N10 任一变化 | **E 数值/实现错误** | 先定位首差（store 地址、读取量、DPAS 数、scratch） |
| ISA 变了但 ordinary 未检出 | **D INDISTINCT** | 单点作用域小 ⇒ 同族成包，禁止挑显著样本 |
| ISA 变了、per-dispatch 变快、ordinary 变慢 | **B 实现有副作用** | 先查 §4 里最大的副作用项 |

## 4. 副作用清单（native 侧重点盯这几项，按可能性排序）

1. **3 个 uniform 标量跨环存活**（`wo/xo0/xo1`）：看标量寄存器/统一寄存器占用是否上升，是否把 `a0.0`/描述符准备挤出早期窗口。父的首 send 在 0x0220，前 37 条全是准备 ⇒ 若候选把 store 地址提前到环前，前 37 条可能变长（很可能 +3…+8 条），这是**预期副作用**，必须在 ISA 差值里扣除后再算净收益。
2. 地址 setup 提前是否推迟首 DPAS（父首 DPAS 在 0x3A30 附近的 `dpas.8x8 … {Atomic,$3.dst}` 那条之前有 sync.nop）：若首 DPAS 偏移后移 ⇒ 供料被推迟，判 B。
3. store 发出顺序（0x3BA0/3C50/3C60/3C70）是否改变 ⇒ 若改变，可能是 IGC 重排而非本意，需记录。
4. 是否出现 spill/fill：本 kernel scratch=0，若候选出现 spill 说明标量寿命伤害了分配（判 B，立刻回退到“只折 store 地址、不动环内偏移”的降级版）。

## 5. 降级/下一版（若判 A 或 B）

- 降级版 A′：只保留 `ob` 一处基址 + 3 个常量偏移（**不动环内** `(k/16)*256`），把 A1/A2 的 3 个 uniform 标量拿掉——用来区分“环内强度削减”与“epilogue 折叠”两项贡献。
- 若 A′ 仍 ISA 不变 ⇒ 明确写“F11 末次 store 的地址层已无空间”，把本族下一步转为 **成对权重跨 M 块复用**（第二方向，见 RESUME），不得把 A 写成方向禁令。
