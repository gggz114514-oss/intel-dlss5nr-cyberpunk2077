## 3. 尺度合同表（Q / K / V / P 逐段）

完整机读版：`evidence/SCALE-CONTRACT.json`。共同约定：
**量化 = 一次 FP32 乘（乘 1/step）、一次 `roundEven`、一次 `clamp[-127,127]`；step = absmax/127。**
"K 内恒定"指：该尺度沿该条 MMA 的归约轴（K）是常数——这是 int32 累加器能用**一个**反量化因子
的充要条件。

| 族/段 | 操作数 A / B | 尺度粒度 | K 内恒定 | 反量化位置 | K32 对齐 | padding | INT32 上界（实测） |
|---|---|---|---|---|---|---|---|
| split16 QKV | 激活码 / 权重码 | 权重：per 输出通道 `wsc`（父既存） | 是（K=512 通道轴，权重按 n 索引） | `STORE_QKV_I8` 出口（f32） | 512 = 16×K32 | 无 | 512·127² = **8,258,048** |
| split16 **QK** | Q 码 / K 码 | **sQ、sK 各 per workgroup = per (head, window)**，各一个标量 | **是**：sQ 对 32 个 head dim 恒定（按 query 行），sK 对 32 个 head dim 恒定（按 key 列） | QK 出口一次 `sQ*sK` 标量乘（FP32），在父的 bias 加法与 MC→MH 窄化之前 | K=32 = head dim 正好，无尾 | window 外 token 读 0 → 码 0，贡献 0 | 32·127² = **516,128**（合成实测 37,529） |
| split16 **PV** | P 码 / V 码 | sP **per query**（该 query 的 64 个归一化 P 的 max/127）、sV **per (head, window)** | **是**：sP 对 64 个 key 恒定，sV 对 64 个 key 恒定 → 两个 K32 片共用一个 `sP*sV` | PV 出口一次 `CF(acc)*sfm`（sfm 是每 query 广播的 f32 表），再**一次** CH 窄化 | K=64 key = 2×K32 | window 内无 padding；死输出在 store 处按 `valid` 剪掉 | 64·127² = **1,032,256**（合成实测 118,709） |
| ViT **QK** | K 码 / Q 码 | **sQ per workgroup**（本 WG 64 query token × 32 dim 的 absmax）、**sK per (WG, 64-key chunk)** | **是**：两者都是 32 维归约上的单一标量 | 每片一次 `f*=(sQ*sK)`（FP32 逐分量），在父的 MC→MH 窄化之前 | K=32 = head dim | key ≥ 288 填 0 → 码 0；其 P 在 den 之后清零 | 32·127² = **516,128** |
| ViT **PV** | V^T 码 / P^T 码 | **sV per (WG, chunk)**、**sP per (query, chunk)** | **是**：sP 对 64 个 key 恒定（两片共用）、sV 对 64 个 key 恒定 | 每 K32 片：`MF8(acc) * (sV*sP[query])`（每 query 因子由列广播 8×16 f32 表承载），再加进父的 f32 ctx；父的"全部 chunk 之后一次 MH 窄化"未动 | K=64 key = 2×K32 | 最后 chunk 的 32 个 padding key 保留 exp(0) 进 den（父合同），其 P 码 = 0 | 32·127² = **516,128**（每片从 `AC8(0)` 起算，跨片/跨 chunk 是父的 f32 ctx） |

**P 的归一化顺序（两族不同，禁止串用）**

| | split16（本卡） | ViT（本卡） |
|---|---|---|
| P 进 PV 前 | **已归一化**：`sp[e]=sp[e]*inv`，`inv=1/max(Σ稀疏树,2^-14)`，每 query 一个 | **未归一化**：`P=vit_exp(·)`，直接进 PV |
| reciprocal 位置 | PV 之前 | **全部 5 个 64-key chunk 之后**，`1/max(den,6.198883056640625e-05)` 只作用在 context 分子上 |
| int8 码是哪个 P | 归一化后的 half | **未归一化**的 half，尺度 per (query, chunk) |
| den 用什么 | 同一个归一化 P | **仍是 f16 P**（pair 树 + `shuffleXor(16)`），所以 den 与 PV 仍是父的原数 |
| 结果 | 两者都保持父的原顺序；split 的 P≤1 故不饱和 | ViT 的 P 恒 >0；per-(query,chunk) 尺度把 64 key 的 max 映到 127 |

**没有借用静态权重尺度**（可查的 5 条，与 R12 同款论证 + 本卡的核内证据）：
① sQ/sK/sV 只来自 `shared uint shQMax/shKMax/shVMax` 的 `atomicMax`（值由本 WG 当次激活算出），
sP 只来自本 lane 寄存器 P 的 max + 一次 `subgroupShuffleXor(16)`；② 全模块没有任何
`ws[]`/`wsc[]`/`aux` 参与这四个尺度（ViT 模块只读 `ws[10]` 且只用在父的 qT epilogue）；
③ 轴不同：既有权重尺度是 per 输出通道，物理上无法表达 per-token / per-query；
④ 量级不同：既有 `wsc` 1.6e-4…3.4e-4，本卡 sV 2.8e-2 量级；
⑤ 寿命不同：`wsc` 在 QKV store 内消费完，QK/PV 的尺度在 norm 之后产生。

**为什么这样不会掉精度（ViT 的特有理由）**：ViT 的 Q 与 K 在 producer 里已经 L2 归一化
（`vit_nb04_qkv_int8.comp`：`z*inv`，`inv=inversesqrt(max(‖·‖²,6.2e-5))`；Q 再乘 per-head
`scale`），所以所有行同量级，per-workgroup / per-chunk 的 absmax 与逐行 absmax 只差一个
binade 以内；这一点在真实抓帧上被测量到（§7）。

## 4. 内核改动（锚点式，逐条可查）

### 4.1 split16（两个模块同一套 6 处锚点，`port_qk_split16.py`）

| 锚 | 改动 |
|---|---|
| A1 | 新增 `shared uint shQMax,shKMax;`（4 B + 4 B） |
| A2 | `if(lid==0u){shVMax=0u;shQMax=0u;shKMax=0u;}` |
| A3 | 在父的 norm pass（`lid<64`，Q/K 行在寄存器里）逐行取 `amq/amk` → `atomicMax`；由**父已有的 post-norm barrier** 发布，**不新增 barrier** |
| A4 | 在 post-norm barrier 之后、V absmax 之前，写 Q 码 → `sy8[0,2048)`、K 码 → `sy8[2048,4096)`，然后 `barrier()`。`sy8` 是 QKV staging 区（QKV 循环结束后已死，P 码在 C6 相才再次占用），**所以 Q/K 码不占新 shared** |
| A5 | QK：`for(k=0;k<32;k+=16)` 的 2 条 f16 MMA → **1 条 K32 int8 MMA** + 一次标量反量化；两块（`acc0/acc1` = 两个 16-key 组）都换 |
| A6 | `#define SY8_Q 0u` / `#define SY8_K 2048u` |

**只新增 1 个 workgroup barrier/次 dispatch**（A4 的发布），因为最大值复用父的 post-norm barrier。
shared 24,576 → **30,732 B**（+sv8 2048 +shPsf 4096 +3×4，与 R12 的 PV 候选同一批新增 + 本卡 8 B）。
下游（bias、`exponential2` 配对 exp、P 归一化、PV 顺序、qT/T 出口）**一行未改**。

### 4.2 ViT（`port_qk_pv_vit.py`，4 个边界 + 一段整体 body）

| 锚 | 改动 |
|---|---|
| HDR | 段变更说明（尺度合同、两族 P 时机不串用） |
| V1 | 新增 `shared int8_t sk8[2048],sv8[2048],q8[2048],p8[4096]; shared float shPmf[512]; shared uint shQMax,shKMax,shVMax;`（共享 8192 → **20,492 B**） |
| V2 | 父的"每 score SG 载入两个 f16 Q 片" → **全 WG 一次性把 64 query × 32 dim 量化成 `q8`**（两遍：absmax → 码），3 个 barrier（对整次 dispatch 一次性） |
| V3 | sk/sv 填充同址同零填；同遍里取 K/V 的线程内 max 后 `atomicMax`（每线程 1 次，不是每元素 1 次）；随后一遍量化出 `sk8/sv8`；每 chunk +2 个 barrier（尺度归零发布 + 码发布） |
| V4 | score body：每 8-key 片 **1 条 K32 int8 MMA**（A=K 码 8×32 RM stride32，B=Q 码 32×16 CM stride32，方向仍是 `S^T=K·Q^T`），一次 `f*=(sQ*sK)`，然后父的 MC→MH 窄化、`vit_exp2` 配对 exp、den 树、padding 清零、debug 顺序**全部逐字保留**；**P 不再走 `nrh_join_rows_to_B` 寄存器交接**，改为按 sealed CH 映射 `(row=2·ci+lane/16, col=lane%16)` 落到 `p8[key][query]`（本 SG 独占自己的 16 列）；`subgroupMemoryBarrierShared()+subgroupBarrier()` 后做 PV：2 个 K32 片 × 4 个 dim 片 = 8 条 int8 MMA，每片 `MF8(acc)*(sV*sP)` 后加进父的 `ctx0..ctx3`（f32）；父在 5 个 chunk 之后的一次 `MH` 窄化与 `1/max(den,…)` 位置**未动** |

**barrier 预算（每 64-key chunk）**：父 2（sk/sv 发布 + WAR）→ 本卡 4（+尺度归零发布、+int8 码发布），
另加 1 个 subgroup barrier（P 发布，PV 读写者在同一 SG 内）。5 个 chunk → 每 WG +10 WG barrier。

| 新增 workgroup barrier | +1 / dispatch | +2 / chunk（+10 / WG） |

| 新增全局读写 | **0**（Q/K/V 仍是父原有的那次读） | Q 多读一遍 4096 B / WG（absmax 与码两遍；父是一次进 SLM） |
| 新增描述符 / push 字 / dispatch | 0 / 0 / 0 | 0 / 0 / 0 |

owner / 活区：split16 的 Q/K 码 writer = 全 256 线程（一次），reader = 8 个 SG 的 QK MMA；
Q/K 码寿命止于 score 结束，P 码（`sy8`）在其后独占同一块。ViT：`q8` writer = 全 WG（一次）、
reader = 4 个 score SG；`p8` 的 writer 与 reader **都是同一个 score SG**（各占 16 列，无跨 SG 共享），
这是只用一个 subgroup barrier 就够的原因；`sk8/sv8` 每 chunk 由全 256 线程重写，
WAR 由父的 chunk 末 barrier 保证。

### 7.2 split16：**没有抓帧**（本臂只能合成 + 解析界）

`evidence/ORACLE-SPLIT16.json`，seed 20261024，32 个 (window, head) 样本；模型：Q=单位向量×aux 尺度
（尺度取 R12 实测范围 0.0145…2.446 均匀抽样）、K=单位向量、V~0.6N(0,1)、aux bias 0.05N(0,1)
（覆盖父的 64×64 query×key 整格），全部 float16。

| 指标 | 值 |
|---|---|
| T（context，父一次 CH 窄化后）rel_L2 | mean **1.10%**、max **1.56%** |
| SNR min / corr min | **36.15 dB** / **0.999870** |
| absmax 绝对误差 max | 0.00465（参考 absmax 均值 0.214） |
| 归因（单段 INT8） | QK 单独 0.59%、PV 单独 0.92%、两者 1.10% |
| score rel_L2 | mean 1.07%、max 1.18%；`max\|Δscore\|` 0.0159（score absmax 1.559） |
| 解析界 | `\|Δscore\| ≤ ½sQ·Σ\|K\| + ½sK·Σ\|Q\| + 32·¼sQ·sK`，均值 0.0271，**32/32 全部落在界内** |
| 饱和 | Q 0.055%、K 0.049%、V 0.053%、P 1.84%（P 的 argmax 恰为 127） |
| INT32 实测最大 | QK 37,529 / 上界 516,128；PV 118,709 / 上界 1,032,256 |

合成模型的偏差已登记：`exponential()` 的 clamp 把 z 钉在 [1.03125,1.56934]，而 L2 归一化 + 实测
aux 尺度上限 2.446 使 score ≤ 2.45 → z ≤ 1.41 **永不触 clamp 边界**；因此本合成里注意力是"平"的
（`64·mean(pmx)` = 1.63，max 2.27），无法产生极端尖锐分布。**尖锐注意力下的 P 尺度行为未验**
（见 GAP-SHARP）。这也正是 ViT 侧用真实抓帧测出 per-chunk 标量尺度会崩到 51%、必须用 per-query 的原因。

### 7.3 需要一个什么抓帧（精确说明，不编数字）

split16 l2 本臂要真实数据参考，需要一次诊断 run 同时 dump 出（任一 block ∈ {23…30,40…47}）：

1. `qkv` 板（6144 half / (window, head)）在 **norm 之后**的 Q/K/V 三片 —— 或者等价地
   `qT`（540,672 B int8）+ 该 PASS 的 `T`（1,179,648 B half，block30 变体）；
2. 该 PASS 的 `aux[p4.x + h*4096 + …]` 64×64 bias 与 `aux[p4.y+h]` 每 head 注意力尺度；
3. `qx8` int8 输入片与 `wqkv` int8 包（只需 sha256 与 sX 一列），用来把父路径的 QKV 段也纳入。

有这三样，本卡的 ORACLE 可以升级为"真实非零数据上的段级 reference"（现在是合成）；
**没有它们之前，§7.2 的百分数只是实现参考，不是质量或数值门结论。**

## 10. 具名缺口（不假修）

- **GAP-GPU**：无设备时段。gate（fixed / fb2）、per-PASS capture、ordinary 3×30、画质全部未跑。
  本卡不建 job 文件（避免被误当已排队）；需要的 argv 由父会话按既有 runner 生成。
- **GAP-CAP（split16）**：本族没有 Q/K/V 或 T/qT 抓帧（§7.3 给了精确清单）；现有
  `alpha-ctrlattn-*` 的 `qT32..38` 是 ViT 的，`dump_split16_b30_pool` 只是 b30 的池化输出。
  G3 血统的诊断 run 里 ViT 的 QKV dump 是**全零**，也是同类缺口。
- **GAP-B31PACK**：block31 的 weights 包 `ws[]` 头退化（`174bf517…`），父 epilogue 的 invT 因而是
  非尺度；修好的包 `9166f9c8…` 在 `vit21-blocks31-38-v1/pack/`。**属 X5，本卡不擅自换**（换包会污染
  本卡的数值归因）；换包后 block31 的 qT 指标才有意义。本卡的 QK/PV 矩阵路径**不受影响**。
- **GAP-SLM**：静态 shared 8,192 → 20,492 B（ViT）、24,576 → 30,732 B（split16）。
  对 occupancy 的影响只有设备能读；本卡不声明"没有影响"。
- **GAP-BARRIER**：ViT 每 chunk +2 个 WG barrier、split16 每 dispatch +1 个。是慢的一侧，
  属"先正确后性能"的主动取舍，未做 reorder/redux 优化。
- **GAP-SHARP**：split16 的合成数据注意力是平的（`64·pmx` ≈ 1.6），极端尖锐分布下 per-query sP
  的行为未验；解析界只覆盖单元素误差，不覆盖"P 码在小分量上归零"的累积效应。
- **GAP-QT**：qT 码域一致性只有 77–87%（ViT，block32–38），过零翻转的 max\|Δ\|=254 说明
  少数元素符号会翻；是否可接受属质量问题，本卡不自设阈值。
- **GAP-MERGE**：本卡不合并累计计划。`MERGE-RECIPE.json` 给了逐 PASS 的 old→new 字段与
  v6 冲突检查（24/24 仍绑父模块 → 无同 PASS 冲突），由父会话串行合入 v7。
- **GAP-QUANTISER-TIE**：核内量化用"乘 1/step"（与 R12/R04 实测 adapter 同算术），
  不是除法；若要逐码复现离线包，tie 处会差 1 码（R08 已记录同一现象）。
