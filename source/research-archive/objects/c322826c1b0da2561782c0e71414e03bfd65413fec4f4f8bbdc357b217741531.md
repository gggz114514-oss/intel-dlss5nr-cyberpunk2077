三、§2 纠正的落实（指标定义，284 counter 目录原文）
---------------------------------------------------------------------
单位/分母/采样域（catalog 原文，scope=2=GPU 级，storage 3=uint64、4=float32）：
- GpuTime(unit2=纳秒)：测量期间 GPU 经历时间。分母=每次 PASS 的 GPU 区间。
- XVE_ACTIVE / XVE_STALL / XVE_THREADS_OCCUPANCY_ALL / XVE_STALL_*（unit1，float32）：
  **百分比**，XVE 全域时间占比；stall 各分项可同时成立（"Multiple stall reasons can
  qualify during the same cycle"）→ 不可相加为独占毫秒（前期报告已按此限定，
  此处再次确认分项定义：ALUWR=等 ALU 写 GRF/ACC；BARRIER=等 Gateway 写 Notify；
  PIPESTALL=就绪但无法调度（GRF 冲突/send 占用等）；SBID=等记分板令牌；
  SENDWR=等 SEND 消息从 XVE 派发）。
- XVE_INST_EXECUTED_*（unit0=周期数? 实为计数槽，uint64）：ALL 线程占用的执行槽；
  ALU2 与 XMX_FP16 槽数恒等（DPAS 管道镜像，本次数据复核成立）。
- GPU_MEMORY_BYTE_*：设备本地内存（HBM/GDDR/LPDDR）字节；LOAD_STORE_CACHE_BYTE_*：
  LSC 字节、**不含 SLM**；SLM_BYTE_*：SLM 字节。三者分母均为测量区间，互相独立。
- AvgGpuCoreFrequencyMHz（unit9）：测量均值，非锁频声明。
执行槽比例不得换算时间（ALU/SEND/XMX 可重叠）——前报告的速率分层保留为
"网内对照事实"，本表不再用作时间论断。
r127 措辞纠正：最高静态引用≠分配量≠阶段峰值（详见 NORMAL-PATH 勘误）。
静态 DPAS 间隔：已按正常路径复核（64 位点全部存活；最长间隔 [0xA950..0xCA28]
为 score→PV 真实依赖链，非 debug 膨胀）；静态 sync 513 条已按类型区分
（sync.bar 仅 NORMAL-PATH 列出的三道 + 其余阶段，见 PC-DEPENDENCIES）。

七、成功标准逐条回答（§6）
---------------------------------------------------------------------
1. 下一条 PV DPAS 的两个输入由谁生产：
   F01 [14CD0]：A=P 片（r36 起，join 后）← P 归一化（r24=inv，math.inv [13D90]）；
   B=V（r8 起）← [14BE0] SLM 载入 $12。双 RAW。
   F20 [CA28]：A=P（r17）← 归一化循环 + [C130] 屏障后装载；B=V（r46）← SLM 装载。
2. 阻止发射的边：F01 = exp clamp acc 链 + 两道 allrd 栅栏 + P join 的间接寻址链；
   F20 = 两道组级 fence + 归一化循环的 16×(send 等待+mul) + exp clamp 链。
3. 独立工作为何未掩蔽：F01 无 WG 屏障、靠 4 SG 独立性掩蔽——线程槽占用 97.7%
   但 ALUWR/PIPESTALL 高（线程级依赖即等待）；F20 的 6/8 SG 在 den 期间空闲，
   掩蔽不足（fence 等全组）。逐 send 的掩蔽程度 = unknown。
4. PC 级证据 vs 结构证据：上表 latency 行 = PC 级；"P 全就绪才进 den"、
   den 重载关系 = 结构级（S37-DEN-LOAD-COVERAGE）。
5. 证伪观测：若 [9480]/[C0E0] fence 在无插桩下不占主导（例如未来硬件
   stall-sampling 显示 SBID 内存细分占主导），则"组级可见性主导"被证伪；
   若把 exp clamp 链的 producer（mad acc）换成独立累加器后 clamp 等待不降，
   则"acc 依赖链"解释被证伪。
