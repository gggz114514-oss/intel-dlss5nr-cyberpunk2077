== 候选机制（具名）==
AAR（Accumulator All-Retire）+ APB（A Panel Base binding）
  AAR: 六个 f32 累加器在收尾段入口全部窄化并退休；V 先发布（因为 accV1 是 K 循环里 A 的
       最后一个消费者），两个 f16 值各自立即 store，不再跨 Q/K norm 与 4 次发布存活。
       父用同一个 `narrowed` 变量串行化两次 V 窄化 -> 改成两个作用域值。
  APB: `const uint aPanel = (w*64u+m0)*128u` 每面板绑定一次，A 流地址成为单一仿射标量。
  位等价：不改任何浮点表达式/顺序/舍入点；只改发布顺序与一个整数不变式的绑定位置。

== 已证（CPU 侧，可复核）==
1. A 供料的指令形状在本身份是下界：每片段 8 条 32 B 行 send（gY 行距 256 B、每行只需 32 B）
   + 4 条 32 B 同宽 mov（8 条 32 B 返回装进 4 个 {row+4,row} 操作数寄存器的下界）。
   当前基线 native 复核: d32x8t 行 send = 257 = 128(QKV) + 128(PV) + 1；上半区组装 mov = 64 = 2×32。
2. 与 f05-a-return-separation/A-PROVENANCE.json 逐项一致：128 行 / 32 B 有效 / 64 B 分配 /
   每行 6 DPAS / 每 DPAS 8 行 / 16 片段 / 每片段 4 条复制（每条 1 行）/ 96 DPAS。
   唯一需解释项：58/128 行 `overwritten_A_labels` 非空 = 64 B 分配包络复用，不是 32 B 载荷被覆盖
   （与 NAMED-CONFLICTS 第 3 条同结论），已在 ANALYSIS.md §7 解释后才动手。
3. A 退休已经即时：最后 DPAS 0x0DD0 -> 地址覆盖 0x0DE0 -> 下一片段首条 send 0x0E00（3 条指令）。
4. 映射一一覆盖：token 0..63、K 0..127、每 head 输出通道 0..95 各一次；qkv 发布地址
   6144 半字/head 无重复写（PROOF.json 机器校验，failures=[]）。
5. 唯一还能删的 A 工作量是"重复片段"（WG 内两 head 各读一遍同一 16 KB），需要 12 个 f32
   累加器 = 96 GRF；本身份 6 acc 已占 48 GRF、峰值 ~107/128 -> 装不下。权重侧同理
   （16 token 共用一次 B 也要 12 acc）。这是**本身份的下界**，不是方向禁令。
