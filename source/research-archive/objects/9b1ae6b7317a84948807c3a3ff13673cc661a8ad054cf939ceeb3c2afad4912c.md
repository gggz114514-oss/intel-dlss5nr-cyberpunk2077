## 2. 期望看到的变化（按可信度从高到低）

### P1（中等可信）`mov` 与总指令数下降
* 依据：IR 层实测 −433 指令，其中 `OpStore −114`、`OpAccessChain −112`、`OpLoad −54`、`OpVariable −58`。这些在 ISA 里只能变成寄存器搬运或什么都不留。
* 量级：**上限 ~160 条 `mov`**（20 站点 × 8 个元素级操作）。若驱动完全合掉则为 **0**。
* 判据：`mov` 从 2245 → **≤2245**，总指令从 4958 → **≤4958**。严格下降才算落地。

### P2（中等可信）`mov` 的结构变化：debug 段多出窄化、正常段少一层
* 具体可观察：`mov (16|M0) rX<1>:hf rY<1;1,0>:f`（f32→f16 的 16-lane 窄化）在 **debug 基本块内增加约 20 条**，同时正常路径上对应站点前的同类窄化**不再需要额外的 4-GRF 中转**。
* 判据：把 `mov … :hf ← …:f` 按基本块分类统计，debug 块（由 `pc.p0.z` 比较后的跳转守护）内的条数上升，正常路径条数不升。

### P3（低可信，需寄存器直方图）长寿命 4-GRF 值减少
* 依据：改前 `if(debug)` 的读使 pre-activation 半片段跨整个激活存活（WAR）；改后该值只活在分支内。
* 判据：若驱动给出每指令的寄存器占用，20 个站点各自的"激活前值"应从跨越激活区间的 4 GRF 降为分支内 4 GRF。**没有这个计数就是 unknown**（合同：scratch=0 不证明驻留不变）。

## 3. "看不到就等于未实现"的判据

| 观察结果 | 结论 | 分类 |
|---|---|---|
| 总指令数下降、`mov` 下降，§1 全部不变 | 机制在 ISA 落地 | 可进数值/资源/整体计时 |
| 总指令数、`mov`、基本块数**三者完全不变**，且 §1 全部不变 | 驱动在 SPIR-V→ISA 阶段已把逐元素拷贝合掉；机制在 IR 落地但**物理上不形成处理** | **A 实现未落地**（不是方向无效） |
| 指令数上升 / `scratch` 出现 / SLM 变大 | 新增副作用（debug 分支重复窄化或寄存器压力） | **B 实现有副作用**：先按 COST-LEDGER.added 修一版 |
| `dpas/send.slm/sync.bar/math.rsqt` 任一变化 | 实现错误 | **E 数值/实现错误**，先定位再谈性能 |
| 全部门过、整体 ordinary 不显著 | 单点作用域小（7/232 派发、40/128 DPAS） | **D INDISTINCT**，按同族成包，不许挑样本 |
| 门过、整体显著变慢 | 形状/owner/编译器/候选身份 | **C 当前身份无净收益** |

## 4. 归因纪律

* 只能说"这 7 个派发里 40/128 个 DPAS 的 A 供料方式变了，且 IR 少 433 条指令"。
* **不能**把整体毫秒差写成"删除逐元素拷贝的收益"：本卡同时改了 20 个站点，且 debug 路径多了 8 次转换。
* 本卡没有把 20 个站点拆臂（同一 SPV 字节只能整组替换），所以**站点级贡献不可分离**，这条写进未决项。

## 5. 本卡用 ISA 证据否掉的两个读法（供后续卡复用）

1. **A 交接不是那 528 条 16-lane 交织的来源。** 父 ISA 里有 528 条
   `mov (32|M0) rX.N<2>:uw rY.M<32;16,1>:uw`（占 4958 条的 10.6%），形态是"把 16-lane 两半交织"。
   因为 `nrh_coord_A` 与 `nrh_coord_CH` 逐字相同、`nrh_to_A` 是逐 component 恒等，A 交接本身不可能需要 lane 交织；
   这些交织出现在 **load 侧**（线性内存 → 片段），属宽读/窄读卡（N15）与内存布局，不是本卡能动的。
2. **逐元素半拷贝在 native 里几乎不存在。** 全模块 `mov (1|M0) …:hf` 只有 **11** 条。若逐元素拷贝要各占一条指令，
   应有 ≥160 条。因此"删逐元素拷贝"在 **这个身份** 上大概率已经是免费的——这是 P1 上限取 160、下限取 0 的原因，
   也是本卡把 A 类判据写在最前面的原因。

## 6. 实测回读（预测 vs 实测；主代理 GPU 阶段，本卡未运行 GPU）

| 观察项 | 预测（本文件 §1/§2） | 实测 v1 | 判定 |
|---|---|---|---|
| `dpas.8x8` / `send.slm` / `send.ugm` / `sync.bar` / `math.rsqt` / `sel` | 全部不变 | 128/25/570/1/16/220，全不变 | ✅ 硬不变量成立 |
| scratch / SLM | 0 / 8192 | 0 / 8192 | ✅ |
| `mov` | ≤2245（上限 −160） | **2421（+176）** | ❌ 方向相反 |
| 总指令 | ≤4958 | **5107（+149）** | ❌ 方向相反 |
| P2 `hf←f` 窄化按基本块分类 | debug 块 +≈20 | **+160 条（432→592），正好 20×8** | ✅ 预测对了机理，方向被判为副作用 |
| P3 长寿命 4-GRF 值减少 | 低可信 | 无法从指令直方图分离 | unknown（仍无寄存器直方图） |

**结论**：P1 落到了"变多"一侧，判据表里对应 **B 实现有副作用**（不是 A：ISA 确实变了；不是 E：硬不变量全对、门逐字节过）。
副作用具名：`if(debug)` 里的 pre-activation 窄化被重算一遍。修版 `candidate-v2` 的预测与判据：

| 观察项 | v2 预测 | 若不符 |
|---|---|---|
| `hf←f` 窄化 | **432**（回到父值） | >432 ⇒ 还在重复；<432 ⇒ 驱动把两处不同窄化合并了，需要重新解释 |
| 总指令 | **≈4947**（4958 − 11） | <4900 ⇒ 恒等拷贝其实不免费，本卡可升级为候选臂；=4958 ⇒ 恒等拷贝完全免费，本族到顶 |
| 硬不变量 | 全部不变 | 任一变化 ⇒ 先查实现 |

**本卡由此得到的定价（可复用方法）**：用"人为加一份重复工作，看 ISA 涨多少"给源码操作定价 —— 本卡量出
**一次 half 窄化 = 8 条指令**、**一次恒等 A 拷贝 ≈ 0.55 条指令**。这比读 SPIR-V 更硬，且不改数学。
