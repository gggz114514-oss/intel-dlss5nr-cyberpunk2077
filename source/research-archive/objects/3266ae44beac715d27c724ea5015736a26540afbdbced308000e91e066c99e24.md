| `scratch` / workgroup mem | **0 / 0** | 不新增 SLM、不新增 barrier |

| 静态块数 / 循环 | 35 / 1（不变） | 控制流形状不变 |

**与 C128 卡（n06）的形态对照**——本卡的判据就是按这张表写的：

| | C128 父 → n06 候选（**已实测**） | C64 父 → 本卡候选（**预测**） |
|---|---|---|
| 512 B 权重 `load.d32x8` | **64 → 32**（−50%） | **8 → 16**（+100%，已经最小） |
| A+seed `load.d32x8t` | 320 → 320 | **96 → 64**（−33%） |
| `dpas.8x8` | 64 → 64 | 16 → 16 |
| `send.ugm` | 481 → 449（−32，−6.7%） | 211 → ≈187（−24，−11.4%） |
| instructions | 2257 → 2005（−252） | 1004 → 950–1050 |
| scratch / max_r | 0 / 127 | 0 / ≤127 |

⇒ **不要**把"C128 权重 64→32"当成 C64 的判据：C64 的对应形态是 **A 96→64**，
权重反而会 8→16。若看到权重仍是 8 而 A 仍是 96，说明实现完全没落地。

## 3. 判据（按合同 §8 的顺序：先 native，再数值/资源，最后整体）

1. **A 类（实现未落地）**：`d32x8t` 仍 96，且 `d32x8` 升到 16，`dpas` 16。
   ⇒ IGC 把共享 A 重新物化成 2 条；机制方向未被证伪，但本候选无效。
2. **B 类（副作用）**：`scratch > 0`、`max_r > 127`、或 instructions > 1200。
   ⇒ 先查 +2 瞬时 scale 与 4-DPAS A 窗口；按 RESUME §5 降级（把 scale 载入下沉到 seed 前的最小作用域，
   或把 `b2/b3` 的载入挪到第二条 DPAS 之后再发）。
3. **D 类（组内不显著）**：A 96→64、权重 8→16、DPAS 16 全中，但 resources 的 7 个 PASS 无同向变化。
   ⇒ 组内天花板（7 PASS ≈ 105–135 µs，0.6–0.7% 帧）决定整帧必然 D；按合同记为"当前身份无净收益"，
   不推广成方向禁令。
4. **E 类（数值）**：gates `fixed` frame0 ≠ `1755e9c2…` 或 `fb2` 末帧 ≠ `9c3e511e…`。
   ⇒ 先查 seed/scale 索引（`ars+16j`）与 store 地址（PROOF 已穷举 4096 元素，若真失败，问题在
   native 侧的 bank/对齐或 debug 路径，不在映射）。

**可观察的"落地"正面证据（缺一不可）**：
- `d32x8t` 从 96 掉到 64（A 的重复读消失）；
- `d32x8` 从 8 升到 16（4 个 n-block 都被读）；
- `dpas.8x8` 仍 16（K 序未动）；
- `scratch = 0`（A 的 4-DPAS 窗口没有引发 spill）。

**不能当证据的东西**（C128 卡的教训）：
- "相邻两条 DPAS 共用同一 A 寄存器" —— IGC 会重载复用寄存器号，父里也有大量相邻共用；
  唯一可靠的是 **载入条数**与 **DPAS 条数**。
- "整帧求和变化" —— 同一对样本里非目标 PASS 也会漂移 >3%，不可归因。

## 4. 如果要做 native 采集（主代理串行作业）

- 作业：`native`（两臂 base/cand），随后仅当 §3 正面证据齐备才做 `resources`（逐 PASS GpuTime）。
- 期望的两臂差异**只**出现在上表 4 个量上；两臂的 `dpas`、`store`、debug 路径计数必须完全相同。
- 若两臂 kernel hash 相同 ⇒ 候选没有形成新内核（A 类，先查 plan 是否真的替换了 7 行）。
