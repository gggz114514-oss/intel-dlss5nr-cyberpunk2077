## 1. 时钟域定义与跨时钟域铁律

本诊断涉及 **3 个独立硬件/OS时钟域**。不同时钟域的原始 tick 绝对禁止直接相减，CPU 墙钟时间与 GPU 异步执行时间绝对禁止相加。

| 时钟域 | 计数器来源 | 频率查询 API | 转换公式 (ms) | 作用范围 |
|---|---|---|---|---|
| **CPU_QPC** | `QueryPerformanceCounter` (`std::chrono::steady_clock`) | `QueryPerformanceFrequency(&qpc_freq)` | `(t1 - t0) * 1000.0 / qpc_freq` | `CyberpunkNRBridge.asi` 与 `nrvk_bridge.dll` 的所有 CPU 线程阶段边界 |
| **D3D12_DIRECT_QUEUE** | `ID3D12GraphicsCommandList::EndQuery` (`D3D12_QUERY_HEAP_TYPE_TIMESTAMP`) | `game_q->GetTimestampFrequency(&d3d_freq)` | `(t1 - t0) * 1000.0 / d3d_freq` | 游戏主 Direct 队列 `game_q` 上的所有 D3D12 命令列表（含 ASI 的 `prep_list`/`composite_list`/`deferred_list` 与 `nrvk_bridge.dll` 的 `copy_list`） |
| **VK_COMPUTE_QUEUE** | `vkCmdWriteTimestamp` (`VK_QUERY_TYPE_TIMESTAMP`) | `VkPhysicalDeviceLimits::timestampPeriod` (ns/tick), `timestampValidBits` | `((t1 - t0) & valid_mask) * timestampPeriod * 1e-6` | `nrvk_bridge.dll` 在 `c->queue` (`VK_QUEUE_COMPUTE_BIT`) 上提交的 `slot.cb` 命令缓冲 |

### 跨模块与跨 API 关键规则
1. **D3D12 跨 DLL 同队列同域性**：虽然 `D0..D3`、`D6..D9` 位于 `CyberpunkNRBridge.asi`，而 `D4..D5` (`staging_copy`) 位于 `nrvk_bridge.dll`，但二者录制的所有命令列表均提交到**同一个 `ID3D12CommandQueue*` (`game_q`)**。因此它们共享完全相同的 D3D12 Direct Queue GPU 时钟域，原始 tick 可直接相减（通过 `(frame_id, control_epoch)` 对齐）。
2. **禁止跨 API 原始 tick 相减与禁止破坏 T5 扩展契约**：`create_vulkan` (`nrb_vulkan_processor.cpp:264`) 严格限定 3 个设备扩展（`VK_KHR_cooperative_matrix`、`VK_KHR_external_memory_win32`、`VK_KHR_external_semaphore_win32`），不开启 `VK_EXT_calibrated_timestamps`，不做跨时钟域零点拟合。
3. **跨 API 信号量唤醒与调度等待净包络**：利用各自时钟域内的同帧区间差直接求取：
   - D3D12 同队列跨 API 包络：$\Delta T_{\text{D3D\_handoff}} = \text{ms}(T_{\text{composite\_start}} - T_{\text{copy\_end}}) = \text{ms}(D_6 - D_5)$
   - Vulkan 同命令缓冲执行包络：$\Delta T_{\text{VK\_exec}} = \text{ms}(T_{V6} - T_{V0})$
   - 跨 API 信号量唤醒 + 队列调度 + CPU 提交 composite 净开销：
     $$\Delta T_{\text{cross\_api\_wait}} = \Delta T_{\text{D3D\_handoff}} - \Delta T_{\text{VK\_exec}}$$

## 2. 陈旧注释清理核查（代码实证 vs 历史注释）

源码审计确认 `nrb_vulkan_processor.cpp` 存在 3 处早期遗留注释与实际编译执行代码不符（诊断源码中予以修正标注）：
- `nrb_vulkan_processor.cpp:8` 注释写有 `→ CPU 等待 f_cp 完成（输入方向：真实生产者 fence CPU 等待）`，但实际代码在 `nrb_vulkan_processor.cpp:512` 仅执行 `game_q->Signal(c->copy_fence, ++c->copy_fence_value)`，**没有任何 CPU 等待 `copy_fence` 的调用**。
- `nrb_vulkan_processor.cpp:683-685` 注释写有 `且 process() 前 sync_queue() 已 CPU 等待队列完成`，但实际在 deferred 路径中走的是 `submit_deferred_identity` (`deferred_identity.cpp:839`)，当 `NRVK_PreparedGpuOrderedV1` 返回 `1` 时 `bypass = true` (`841`行)，**跳过了 `prepared` fence 的 CPU 等待**。
- `nrb_vulkan_processor.cpp:831-832` 注释写有 `无 wait 信号量（输入方向已由 copy fence CPU 等待保证）`，但实际代码在 `840-844` 行明确绑定了 `tsi.waitSemaphoreValueCount = 1; tsi.pWaitSemaphoreValues = &c->copy_fence_value; si.waitSemaphoreCount = 1; si.pWaitSemaphores = &c->copy_ready;`，即**完全由 GPU Timeline Semaphore (`copy_ready`) 在 GPU 侧等待 D3D12 staging copy 完成**。

### 3.2 位于面板 `total` (`nr_started → ended`) **之内**的 CPU 区间

`total` 定义为 `nr_started` (`831`行) 到 `ended` (`1063`行) 的 CPU 墙钟包络：
$$\text{total} = \text{prep} + \text{host} + \text{composite\_submit} + \text{tail}$$

| 一级区间 | 子区间 | 起点 → 终点锚点 | 源码位置 | 实际含义 | 包含/可加性关系 |
|---|---|---|---|---|---|
| **`prep`** | — | `nr_started → nr_prepared` | `deferred_identity.cpp:831 → 880` | `queue->Signal(prepared, 1)`、`gpuhandoff::prepared_bypass` 判定；仅当 `bypass == false`（首帧或 motion readback 采样帧）时含 CPU 等待 `prepared` fence 与 Map/Unmap。稳态下 `bypass == true`，纯 CPU 调用（~0.009 ms），**非 GPU prepare 耗时** | 一级分区 1 |
| **`host`** | — | `nr_prepared → nr_modeled` | `deferred_identity.cpp:880 → 932` | 填充 `NRB_Frame` 并同步调用 `processor->process` (`nrvk_process`)：含等待上一帧 Vulkan fence、录制并提交 D3D12 `copy_list` + `Signal(copy_fence)`、录制并提交 Vulkan `slot.cb` + `vkQueueSubmit`、写 `component_status.json`。**非 GPU 网络推理耗时** | 一级分区 2 |
| ↳ `host` 子项 | `host_vk_wait_prev_fence_cpu` | `vkWaitForFences` 前 → 后 | `nrb_vulkan_processor.cpp:599 → 608` | `pfn_WaitForFences(c->device, 1, &c->network_fence_pending, VK_TRUE, ...)`：验证上一帧 Vulkan 网络是否在上一帧 `completion` 等待期间早已完成（预期 ~0 ms） | `host` 的子区间 (`⊂ host`)，不与 `host` 重复相加 |

| ↳ `tail` 子项 1 | `tail_submit_cpu` | `nr_pre_sr` → `tail_wait_start` | `deferred_identity.cpp:981 → 1042` | 提交 `deferred_list` (XeSS/SR，`1019`行) + 提交剩余游戏命令列表 `if (begin < count) original_execute(...)` (`1023`行) + `queue->Signal(item.completion, 1)` (`1027`行) 的纯 CPU 提交耗时 | `tail` 分区 4a |

## 4. GPU 时间戳锚点与阶段分解表

所有 GPU 时间戳均在既有命令列表录制期间写入，仅在原有最终完成（D3D12 侧 `item.completion` 达到 1、Vulkan 侧 `network_fence_pending` / `slot.cb_fence` 达到 signaled）确认后异步读取，**零新增 Fence / Event / WaitForSingleObject**。
