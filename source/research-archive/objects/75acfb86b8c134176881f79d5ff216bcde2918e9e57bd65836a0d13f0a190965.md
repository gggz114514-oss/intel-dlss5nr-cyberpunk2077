# F20 norm coefficients owned by their Q/K consumers

One candidate against the latest accepted exact score-owner baseline. It builds on the preserved Q-producer-handoff source, which itself had no confirmed performance gain. Neither earlier candidate is silently treated as an accepted baseline.

Each of eight subgroups owns eight Q/K rows. Lanes0..7 compute Q coefficients; lanes8..15 compute K coefficients. The exact scalar square/add/inversesqrt tree is unchanged; only row assignment and execution predicate change. Norm active-thread count remains128 per workgroup, but the work changes from four fully active subgroups to eight half-active subgroups. This may cost additional SIMD issue time even with the same scalar arithmetic count.

K scaling consumes coefficients from lanes8..15 using subgroup shuffle. Q fragments retained from QKV consume coefficients from lanes0..7. For each of four component rounds, row=8*sg+2*d+lane/16. K pair columns=2*(lane%16),+1; all2048 K elements have unique writers. Every coefficient source is an initialized lane in the same subgroup. No cross-subgroup register transfer is assumed.

The original QKV publication barrier remains. The norm→scale workgroup barrier becomes an explicit subgroupBarrier because each raw Q/K row is read and scaled only by its own subgroup. The normalized K publication workgroup barrier remains before score can read other subgroups' K. Debug publication barriers remain. shNorm's512-byte allocation is removed. Original norm128 scalar stores and source-level2048 coefficient reads are replaced with eight shuffle calls per subgroup; source byte counts are not measured physical bandwidth.

Compared with Q-producer-handoff, a32-bit coefficient carrier per lane survives norm through Q scaling. Retained Q still costs16B/lane across norm. No new raw32-value cache is added. Physical allocation/occupancy cannot be inferred from these payload sizes. Norm temporaries now execute in all8 subgroups, which is an explicit cost/risk.

CPU enumeration proves128 unique norm producers,2048 unique K writers and exact source-lane correspondence. The reduction arithmetic source is byte-identical and no scalar-half NoContraction was added. All8 intended fold/scale/bias decorations are retained. Compiler contraction could have changed with the predicate, so fixed/fb2 exact gates were mandatory; both passed.

Native shows64 DPAS,12 workgroup barriers (parent13),no scratch instructions. Total static instructions4400 vs4209 parent; SLM sends553 vs515; UGM253 vs237; MOV1424 vs1356. Relative to previous producer-handoff, instructions4282→4400 and SLM511→553 also increase. Therefore the removed coefficient publication/barrier does not imply less total generated work. Static counts include debug/alternative paths and are not a causal timing breakdown.

One three-pair ordinary batch measures against score-owner, warm1/reps30/feedback, all180 samples retained. A separate driver capture checks scratch0 and expected shared24576 bytes. No profiling time is used as performance evidence; no same-identity retry to seek significance. Main agent owns source/proofs/native interpretation; Luna executes only the explicit GPU manifests.
