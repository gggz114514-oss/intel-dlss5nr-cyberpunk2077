# NATIVE-PREDICTION — n20-f18-ups-contract（F18 UPS C128 contract，ord 194）

本卡 **没有候选**（BLOCKED），所以这里不含"本候选的预测"。本文件保留两样后续卡可直接复用的东西：

1. **基线不变量指纹**：任何动这个 PASS 的候选，native 必须复现这些数（本卡捕获 = 权威身份，见 `BUILD.json.isa_scan`）。
2. **四个被裁定机制的可观察点与判据**：将来若条件放开（寄存器/授权），照这张表就能判"实现是否真落地"。

判据写法遵循 `CONTRACT.md` §8.5：先看 native 是否形成处理（A 类），再看数值/资源，最后才看整体计时；
native 看不到预期变化时，不许用整体毫秒倒推"机制有效"。

## 2. 各机制的可观察点与"未落地"判据

### M1 — 互斥阶段 arena 退休复用（N14 方向）
- **不适用**：基线 `Workgroup Memory Size = 0`、`send.slm = 0`、`OpControlBarrier = 0`。没有 arena。
- 若有人强行引入 SLM 暂存来"复用"：预测出现 `store.slm` ≥512/线程级 + `load.slm` + 至少 1 条 barrier_send，
  且 UGM A 行消息不下降（读取目标从 L2 改到 SLM，条数不变）。**这就是"未落地/换汤不换药"的判据**：
  只要 `load.ugm.d32x8t` 仍是 256，A 的 4× 就没有被卖掉，只是换了一条路径。

### M2 — 生产者末次 store 折进消费者布局（N16 方向）
- 需要改 ord 193 / 上游 body 的 SPIR-V（越权）。若将来授权成组做：本 PASS 侧的可观察变化是
  `load.ugm.d32x8t` **256 → 128**（A 放大 4×→1× 的等价形态是**行消息减半**，因为每 tile 仍 8 行但 tile 数减半不可指望；
  正确判据是**每个 (m,k) tile 只被一次 subgroup 载入** → 消息 2048→512/WG，即 256→64/线程），
  以及 seed 的索引/oob 链（≈40 条标量 + 8 个条件块）消失。
- **未落地判据**：若 store 侧字节没变（`store.ugm` 仍 64 条生产消息）、`load.ugm.d32x8t` 仍 256，则只是改了源码写法。

### M3 — 4 acc 重划分 1m×4n（已裁定不建）
- 预测（由 `proof-cover.json` 代数给出，不是猜测）：
  `load.ugm.d32x8t` **256 → 128**/线程（-32 KiB A/WG），`load.ugm.d32x8` **32 → 64**/线程（+128 KiB W/WG），
  `dpas` 64 不变，`store` 不变，静态指令约 **-15%**，活值 +12~16 GRF。
- **未落地判据**：两个消息数没有同时朝这两个方向移动（A 没减半 或 W 没翻倍）→ 源码改了但 IGC 重排回了原形态。
- **落地也算输的判据**：若 native 落地但 overall 慢/不显著，按 C 类归因到"字节换槽位不划算"，不要写成"tiling 方向无效"。

### M4 — 8 accumulators 4m×2n（已裁定预算不足）
- 预测：`load.ugm.d32x8` **32 → 16**/线程（W 128→64 KiB/WG），A 行消息 256 不变，
  `dpas` 64 不变，**累加器 GRF 32 → 64**。
- **落地判据**：权重消息减半 **且** `Scratch Memory Size` 仍 0 **且** max register index 没有顶到 128。
  三者任一不满足 = 溢出或调度退化，属 A/B 类。
- **前置条件**（写进 RESUME）：必须先拿到 ≥32 GRF 的空间——例如删掉 debug store 路径后重测寄存器分配，
  或证明 4 acc 的 8 条 GRF/acc 在 16-lane DPAS 下可以压到更小。没有这一步，M4 不必再试。
