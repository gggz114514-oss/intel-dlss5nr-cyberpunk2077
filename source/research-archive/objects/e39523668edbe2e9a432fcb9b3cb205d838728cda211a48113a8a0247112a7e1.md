## 2. Why one fused kernel, and what each segment now does

R02 and C2 are not two priorities of the same PASS; they are two *different* rewrites of
it. R02 replaced the FP16 QKV block and left the `sE8` shared staging in place; C2 deleted
`sE8` (18432 → 10240 B) and left every FP16 site untouched. Picking a winner would either
hand the network 40 FP16 matrix multiplies per PASS (choosing C2) or throw away the K32
register staging (choosing R02). Same class of conflict as R07-C128 and solved the same
way: **one kernel that satisfies both contracts**.

Kernel structure, in execution order (all inside `if (sg < 4u)`, one invocation per
subgroup, `local_size_x=128`):

| # | segment | operand form | MMA | parent |
|---|---|---|---:|---:|
| 1 | X → E expand | `I8A w8` × `I8B sT8` (X codes) | 16 | 16 i8 |
| 2 | E → contract Y | four `CH8x16` code words joined **in registers** (`c2_i8_join_B`) → `I8B`, × 4 int32 accumulators | 16 | 16 i8 |
| 3 | **QKV** | `I8A w8[32768+…)` × `I8B sT8` (Y codes), K=32 in one step per 8 output rows | **12** | 24 f16 |
| 4 | norm / score bias / exp / denominator / reciprocal | **unchanged scalar FP16** (not a matrix multiply) | – | – |
| 5 | **QK** | `I8A sK8` (workgroup K tile) × `I8B sQ8`, K=32 in one step per 8 keys | **8** | 16 f16 |
| 6 | **PV** | `I8A sV8` × `I8B sP8` (stride 64), two 32-key slices into the *same* int32 fragments | **8** | 16 f16 |
| 7 | **output** | `I8A w8[45056+…)` (WO) × `I8B sT8` (Ctx codes) + the parent's `H(Y*ars)` seed | **4** | 8 f16 |

Everything the parent did in scalar half or in a narrow is kept verbatim: `nr_act_h`
(MpCubicSilu), `nr_norm32_pair` (per-token `inversesqrt` over 32 dims, one xor-16 partner
exchange, no `subgroupAdd`), the score bias add (`precise`, per component), `nr_exp_h2`
(the packed-exponent trick), the 64-key half denominator tree, the reciprocal, the two
residual seeds `H(X*rs)` / `H(Y*ars)`, the out-of-bounds rule, the image stores, and every
debug echo address. **The FP16 chain that is left is scalar, not matrix.**

Dequant convention, uniform across all four segments — two kinds of scale, never mixed:

```
static  sW[n]   = amax_k |W[n,k]| / 127      offline, per output channel, in fsc
dynamic sAct    = amax(rounded halves)/127    in-kernel, per token / per query / per dim
dequant         = int32acc * (sW[row] * sAct[col])        one rank-1 f32 multiply
narrow          = exactly one, at the point the parent narrowed
```

| segment | static side | dynamic side (granularity) | why that granularity |
|---|---|---|---|
| QKV | `sWq/sWk/sWv[32]` | Y: **per token** (max over its 32 channels) | Y is the A-side activation; a per-tensor Y scale is exactly what R02 could not calibrate for blocks 2…69 |
| QK | `sK[key]` **in shared** (dynamic, published with K) | Q: **per token** | both operands are dynamic; the factor is `sK[key]·sQ[query]`, constant along the contraction (32 dims) |
| PV | `sV[dim]` **dynamic per dimension** (max over all 64 keys) | P: **per query** (max of the rounded half row) | the contraction axis is keys, so a per-key V scale is *not* foldable; per-dimension is the finest foldable one |
| output | `sWo[32]` | Ctx: **per query** | contraction is over the 32 context dims |

The P quantiser reuses R06's proven form: the scale is the row maximum of the **rounded
half** P, and since `half()` is monotone the largest code of a row is exactly 127, so the
clamp never removes a bit. The same argument holds for every dynamic scale here — the
maximum element of each token/query/dimension codes to exactly 127.

INT32 bound: `127 · 127 · K` with K = 32 (QKV, QK, output) or 64 (PV) →
≤ 1 032 256 < 2²⁴, so `int → float` is exact and int8×int8 products are exact in int32.
Measured on the capture: absmax **53 003 / 169 943 / 90 287 / 125 822** (§7).

## 5. Declared shared memory and barriers (C2's contract)

| | parent | C2 | **candidate** |
|---|---:|---:|---:|
| declared workgroup bytes | 18432 | 10240 | **13056** |
| workgroup variables | 4 | 3 | 7 |
| `OpControlBarrier` / `OpMemoryBarrier` | 3 / 2 | 2 / 1 | 5 / 3 |
| private bytes | 0 | 0 | 0 |

**13056 B = 2048 (one reused int8 tile) + 2048 (sK8) + 2048 (sV8) + 2048 (sQ8) + 4096
(sP8) + 256 (sKsc, 64 f32) + 512 (sVpm, 128 f32).** Against C2: −8192 B (`shK` + `shV`, the
two half attention slabs, which are now dead — the only readers of `shK`/`shV` were the
FP16 QK A operands and the FP16 PV A operands) and +11008 B (the int8 attention tiles). Net
**+2816 B vs C2, −5376 B vs the parent.**

The reused tile (`sT8`) is the only aliasing in the module, and it is disjoint by lifetime:
X codes (written by `nr_i8_put_x`, read once by the expand) → Y codes (written after the
contract, read once by the twelve QKV steps) → Ctx codes (written after PV, read once by the
four output steps). Each pair of lifetimes is separated in program order by at least one
barrier, and all three use the identical per-subgroup partition (`sg*512`). Without the
reuse the declaration would be 15104 B.

Barriers vs C2: **+1 workgroup barrier** and +2 subgroup publication pairs
(Y and P; X was already there). The workgroup barrier exists for one reason only:

* **V's per-dimension scale is the maximum over all 64 keys**, and the 64 keys are spread
  over four subgroups. The four partial maxima are published by the *existing*
  cross-subgroup barrier (`sVpm`), and the V codes then need one more publication before PV
  can read them. Everything else that is workgroup-wide (K codes + per-key K scale) rides
  the existing barrier, because each subgroup writes its own 16 keys. Q, P and Ctx are
  per-subgroup and use subgroup publication.

The alternative — a **static** V scale from the pack — would remove that barrier, and it is
what R02's contract sketched. It was rejected because it requires a per-block V calibration
that does not exist in the repository (only block1 has any capture at all), and a scale
copied from another block is exactly the stale-pack defect that invalidated C2's first arm.
The cost is named in §6.2 instead of hidden.

## 6. What this illustration deliberately does *not* do, and the two trade-offs

### 6.1 Not done on purpose
* no `shK`/`shV` half slabs left behind for the matrix path (both deleted with their
  readers); the debug echoes still write Q/K/P/Ctx/O from registers at the parent's
  addresses, so the diagnostic ABI is unchanged;
* no change to the scalar half chain, so the *activation/exp/denominator* numerics are the
  parent's, by construction;
* no weight/resource pre-residency changes (weights and scales are read-only, static).

### 6.2 The two trades, stated
1. **+2816 B declared SLM vs C2.** A PASS that had zero FP16 matrix multiplies needs int8
   operands where the FP16 path kept half operands in registers (`nrh_join_rows_to_B` — the
   ten register B handoffs are all gone). The int8 B map is not the CH map, so those
   operands must come from memory. This is the price of the coverage, paid on the card whose
   point was SLM reduction; it is still below the parent's 18432 B.
2. **+1 workgroup barrier.** See §5: dynamic per-dimension V scale.

### 6.3 Not repaired (inherited)
The frozen G3 scale table's first 164 entries are used unchanged by the expand/contract path.
C2's `SCALE-ROUND-PROOF` observation about `sS·invS = 127.000002` does **not** apply to the
current table (`ecdcea95…`, `sS·invS = 1.00000002`), so nothing is inherited as a defect here.

## 8. Named gaps

1. **`GATE` not run.** No GPU slot; the seven PASSes have never been executed in this
   organisation. Frame equality vs G3 and PSNR are **unmeasured**. The card does not claim
   `数值通过` or `质量通过`.
2. **Per-position reference exists for block1 only.** Blocks 2, 3, 4, 67, 68, 69 have weight
   and scale packs but no activation capture, so their integer reference is missing. What is
   needed is exactly one thing: **a diagnostic capture of those six PASSes in this plan with
   `p0.z=1`** (the same mechanism that produced the block1 dump — the
   `c32-i8-debug-eact-v1` plan plus `--pool --warm 0 --reps 1`, 50,176 B debug buffer per
   PASS), because the debug buffer holds X, Y, Q, K, P, Ctx and O for each tile. The
   `amd-map` `gpu-numeric` body_1 cases do **not** substitute: they run a different module
   (`c32_complete_fp16.spv`) with a different weight pack (§7).
3. **The extra workgroup barrier is a real cost** (§5/§6.2) and its dynamic effect is
   unmeasured. A static per-dimension V scale would remove it and needs a calibration that
   does not exist yet.
4. **`NATIVE` unknown.** No pipeline was created: native SLM vs the declared 13056 B, GRF,
   scratch, occupancy, and the measured int8 `M8N16K32` behaviour on this organisation are
   all unverified. The measured ABI is a prior from
   `candidates/dsh-int8-same-family-20261023/abi-probe/I8-ABI-MEASURED.json`, not a
   measurement of this module.
5. **Pool cost.** The fourteen superseded G3 packs stay uploaded (§3.3) — ≈ 234 KB of dead
   residency, deliberately not deleted because of resource-id renumbering.
6. **Q/K/V/P/Ctx scales are dynamic per token/query/dimension**, which removes R02's
   `invY` calibration blocker but also means the quantiser *adapts at run time*: a frame
   whose distribution differs from the calibration frame cannot clip (the max code is always
   127), it can only lose relative precision. That property is asserted from the code, not
   measured on more than one frame.
7. **Weight packs are `amax/127` per channel**, so the ~3–6 % of codes at ±127 are
   structural; a finer quantiser (row-wise MSE/percentile) is not attempted here.
