## 2. 三个陷阱，逐条回答（附证据）

### (a) 没有 half 输出 —— 计划里本来就没有，不是本卡删的

`producer_quant.comp` 的 `OUTPUT_Q` 在 `-DNATIVE=1` 下是 `int8_t`，`imgout`（binding 3）就是 qX 存储；半图只在 `#if !NATIVE` 的死路径里。
计划侧事实（G3，未改一个字节）：

| 证据 | 值 |
|---|---|
| G3 `block9_swin_body_4` BIND 3 | res **49** `block9_out`，**2,064,384 B**（= 16,128 token × 128 ch 的 int8，不是 4,128,768 B 的 half） |
| G3 `block10_swin_body_4` BIND 3 | res **56** `block10_out`，2,064,384 B |
| res 49 的读者 | `block10_swin_body_1`(ord 30) BIND 2、`block10_swin_body_2`(ord 31) BIND 2、`block10_swin_body_3`(ord 32) BIND 2 —— 全部声明 2,064,384 B |
| res 49 的 POLICY | `POLICY 49 0 29 31 0`：写者 29 + 两个读者 30/31（第三处绑定见下） |

结论：**这条出口的 half 图在 G3 里不存在，也没有任何 half 读者**。所以本卡既不新增 half 输出，也不删——`emit_quant()` 的
`coopMatStore(q,imgout,addr,8u,LCOL)` 原封不动。作为对照，另外九条 C128 出口（`output-c128-full.spv`）的 BIND 3 是 half、读者读 half，
两者是**不同契约**（见附 B）。

### (b) qX 布局 `(2,128,8)`：谁真的读它，以及为什么不能换成 token-major

**消费者不是 R08 的 kernel。** res 49/56 的读者是 `C-d1.spv`/`C-d2.spv`，源码 `pilot_common.glsl` + `pilot_d1.comp`/`pilot_d2.comp`
（部署目录 `v6-m8col-20261019/source`、`v3-m8col-scale-repair/source`，sha 见 `evidence/QX-LAYOUT-CONTRACT.json.sources`）。逐字引用：

```glsl
// pilot_common.glsl（部署版，input_addr 是唯一的 qX 地址函数）
uint input_addr(uint m,uint c,uint wx,uint wy,out bool oob) {
    uint tile=m>>4u,slot=m&15u;
    int tx=2*int(wx)+pc.p0.z+int(tile&1u),ty=2*int(wy)+pc.p0.w+int(tile>>1u);
    oob=tx<0||ty<0||tx>=pc.p0.x||ty>=pc.p0.y;
    if(oob)return 0u;
    return (((uint(ty)*uint(pc.p0.x)+uint(tx))*2u+(slot>>3u))*128u+c)*8u+(slot&7u);
}
MA load_entry_A(uint base,uint k,bool oob) {           // pilot_d1.comp 的 A 操作数
    MA x;
    if(oob)x=MA(QT(0));
    else coopMatLoad(x,gx,base+k*8u,8u,COL);           // stride 8, COL
    return x;
}
// pilot_d2.comp 的 seed（残差）操作数
    else coopMatLoad(seed,gx,seedBase+n*8u,8u,COL);    // 同一个 base 公式, stride 8, COL
```

而 producer 的写者：

```glsl
// producer_quant.comp（部署版，本卡逐字保留）
uint addr=(((uint(ty)*uint(pc.p0.x)+uint(tx))*2u+(slot>>3u))*128u+n)*8u+(slot&7u);
coopMatStore(q,imgout,addr,8u,LCOL);
```

两者对 `(slot,c)` 是**同一个函数**。机械证明（`build/qx_layout_contract.py` → `evidence/QX-LAYOUT-CONTRACT.json`）：

| 检查 | 结果 |
|---|---|
| 采样元素（4 个 tx × 3 个 ty × 16 slot × 128 c = 24,576）写者地址 vs 读者地址 | **0 处不一致** |
| 同一 map 是否把 1008 个 tile × 2048 单元双射到 `[0, 2064383]` | 是（2,064,384 单元，无重号、无空洞，`absmax=2064383`） |
| 反证：若换成 R08 的 token-major `((tile*16+slot)*128+c)` | 只有 **48/24576 = 0.195%** 单元碰巧同址（`(slot,c)=(0,0)` 与 `(7,127)` 两类退化点）——两种布局实质不同，选错会整体错位 |
| qX 边覆盖（用**候选 plan 自己的 PUSH** 取 tiles/shift/grid） | `b9_body_4 → b10_body_1/_2`：写 1008 tile / 读 1008 tile / **缺 0**；`b10_body_4 → b11_body_1/_2`：同样 1008/1008/缺 0；四条边 `same_qx_resource = true` |
| OOB 处理 | 读者在 `oob` 时直接 `x=MA(QT(0))`，**不读**缓冲区；写者 OOB 时 `return`，两者集合一致（b9→b10 有 136 个枚举 OOB，b10→b11 有 48 个） |

所以：**布局是部署契约，不是选择。** 本卡不改它，也不改消费者；如果以后要换成 token-major，必须同时改 `pilot_common.glsl`（等于换掉下一块的整个 FFN）。

一处需要说明的细节：`b9` 的 producer PUSH shift=(0,0)、`b10` 的 consumer shift=(-1,-1)。因为地址只由**绝对** tile 坐标 `(tx,ty)` 决定，
shift 只决定"谁去覆盖哪些绝对 tile"；上面覆盖检查已证明 1008/1008 全覆盖，所以 shift 不同不构成错位。
另：`BIND 2` 在 producer 与 attention 里都是"声明但从不读取"的 binding —— `evidence/SPV-FACTS.json` 记的 `access_chains`：本卡模块 **0**、父 b9 模块 **0**、
`attention-c128-ownership.spv`（`6e48e108…`，即 ordinal 32 那个第三处绑定）也是 **0**；而本卡模块 binding 3 是 **1**（qX store）。
这正是 G3 的 `POLICY 48/49 … last=31` 敢在 ordinal 32 之前结束的原因，属父既有事实，本卡未改。

### (c) 量化器吃 raw FP32 累加器：本臂必须保持，且本臂没有 half 可"钉"

父 `emit_quant(acc0,…)` 收 `MAT_C`（float32 coopmat），在**未舍入**的累加器上做 `clamp(roundEven(acc*invX),±127)`；半图只在 `if(debug)` 路径里生成。
本卡保留这一点，理由是可证的而不是偏好：

1. **这个臂没有 half 输出**（(a)），所以不存在"量化器输入必须等于 imgout 收到的 half"的约束；
2. **D2 的残差 seed 读的是 qX**（`seedf[i]*rs`，`rsf = sc[784+n] = sX*residual_scale`），不是 half —— 它的一致性对象是 qX 码本身，与"是否先窄化"无关；
3. 改为钉 half 会改变本臂自身的历史数值身份。我在真实抓取上量了这件事：**若钉死 half，0.024%（494 / 2,064,384）的 qX 码会变**
   （`evidence/INT8-REFERENCE.json.qx_codes_half_pinned_variant_vs_parent`）。R08/unified 那个臂需要 half 是因为它同时写 imgout half 并让残差读 half，
   那是**另一套契约**，不能移植到这里。

因此：`emit_quant()` 的实现与地址一字未改，只把进入它的累加器从"FP16 MMA 的 FP32 结果"换成"int32 点积 × 一次反量化 + 同一个 seed"。

计算结构（相对父的唯一算术改动，全文见 `evidence/SOURCE-DIFF.txt`）：

```
父 : A = half(T),      B = half(W),  acc = float32 MMA (K16 ×8), acc += seed, qX = roundEven(acc·invX)
本卡: amax = max|T_window| (per 64-token workgroup), invC = 127/amax, sC = amax/127

      iacc = Σ_k int8(qA)·int8(qW)             (K32 ×4, INT32 精确)
      acc  = seed + float32(iacc)·(sW[n]·sC)   ← 反量化只做一次
      qX   = clamp(roundEven(acc·invX), ±127)  ← 与父同一个量化点、同一个地址
```

引用/种子/debug 路径**未动**：`seed = H(gY)·pack[ars+n]`、`emit_quant` 的 `addr` 与 `LCOL/8`、`if(debug)` 的 dbg 写、`NR_D4_MODE` 诊断开关。
`p4.x`（FP16 的 `wo` 偏移）在向量里保留但不再被读——int8 码表是独立 buffer，整张 128×128 就在 offset 0。

5. **A 量化器是逐 workgroup 动态 amax**（与 R07 九条 C128 相同做法），不是静态标定；它给 A 的饱和 0.0129%，但没有跨窗口一致性保证。
