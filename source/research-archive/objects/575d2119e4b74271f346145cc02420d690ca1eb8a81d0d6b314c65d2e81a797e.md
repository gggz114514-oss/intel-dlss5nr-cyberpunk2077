# Direct QKV -> norm -> normalized publication

This is a separate transport/scheduling experiment after body-norm established the exact norm helper can pass fixed/fb2 on F20. It is not an identical retry of the unsuccessful scalar norm implementations.

Each SG produces rows 8*sg..8*sg+7. A MAT_H component ci belongs to row 2*ci+(lane>>4), column lane&15, with the second MAT_H providing column+16. The norm helper reduces within each16-lane half, hence it never needs values from another SG. Four components cover each row/channel once. Original per-output K0 then K16 MMA order remains unchanged. Independent projection rounds are V,K,Q; weight tiles are unchanged and loaded once per original use.

V is stored as before. K/Q are normalized directly in the half fragments and only their normalized values are published. Thus no other SG reads a raw Q/K row and the old raw-QKV publication barrier is unnecessary. The final post-scale barrier is retained for cross-SG K/V consumers; the earlier post-contract WAR barrier remains intact. Debug=true retains the existing barrier before its normalized-Q/K dump. This does not remove cross-SG K/V communication.

Lifetime: existing handoff0/1 remains until final Q projection. Only the current projection half0/half1 (16 logical bytes/lane) is normalized; there are no persistent new raw Q or K arrays across projection rounds. Norm temporaries for one component retire before the next. Physical allocation and scratch still require driver/native checks.

Source-level savings relative to accepted baseline per WG: raw Q/K store8192B, norm raw reads8192B and separate scale raw reads8192B removed; shNorm write/read traffic and512B declaration removed; two normal-path WG barriers removed. Normalized Q/K writes remain. Weight traffic and matrix work unchanged.

Important added cost relative to body-norm: Q and K are now separate projection rounds. The helper's Q/K input arguments are duplicated, with only its first coefficient consumed. The reduction no longer packs two distinct Q/K trees together; the source schedules four XOR stages x four components x two rounds, rather than four XOR stages x four joint-Q/K components. This may increase shuffle issue work even if duplicate arithmetic is eliminated. Native inspection and ordinary timing must decide whether removed SLM traffic outweighs this cost. No claimed gain from source byte counts.

The scalar C7 candidates failed; explicit Fma source alone did not establish native fusion. This direct variant instead preserves the full accepted body norm helper and its exact16 NoContraction decorations, which the preceding body-norm F20 variant already verified numerically. Every newly generated candidate still requires its own gates.
