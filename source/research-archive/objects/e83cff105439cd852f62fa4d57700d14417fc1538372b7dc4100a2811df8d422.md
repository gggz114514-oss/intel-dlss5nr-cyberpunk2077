## 3. 本臂 INT8 参考状态（关闭规则 3）

### 3.1 谁产生池化后输入的 scale

* **张量来源**：`skip4`（C32 672×384，16,515,072 B）由 `PASS 4 block4_swin_body_1` 写出；在 278 发 INT8 控制里该 pass 是 `candidates/int8-coverage-v2-20261020/C/c32-i8-debug-eact-v1/spv/c32_body1_i8.spv`（即 R02 的 C32 INT8 体，**它自己只写 FP16 输出，不发布输出 scale**）。
* **捕获**：`run/int8-coverage-v2-20261020/v2-g3-diag-002/dump_skip4.bin`
  `sha256 3bb2d41489a343e4107c81201004ccdd146c983be926c04391f941ba5b84b915`，16,515,072 B。
  该 run 的 plan = `candidates/int8-coverage-v2-20261020/plan-g3-diag.txt`（`daea39be…f616c3`），receipt：`rows=152 passes=290 nan=0 inf=0 normal_close=true reps=1 warm=0`。
  **选它的理由**：只有该臂的 PASS 4 才是 `c32_body1_i8.spv`，与本卡要接线的 plan 一致；`v2-g1chain-l2diag-001` 的 skip4 来自 FP16 C32 体，不能作为本臂 scale 来源（仅用于验证父仿真）。
* **算法**：用父自己的四点 half 池化树（`top=a+b`、`bottom=c+d`、`sum=top+bottom`、`v=sum*half(0.25)`，逐运算 half 舍入）算出全部 64512×32 个 `v`，取 `amax=80.4375` → `sV = f32(80.4375/127) = 0.6333661675453186`，`invV = 1.5788655281066895`。
* **饱和/利用率**：2,064,384 个 code 中，`|code|=127` 仅 **1** 个；`code=0` 与 distinct code 数见 `SCALE-CONTRACT.json`。
* **状态**：`CLOSED_SINGLE_FRAME_DIAGNOSTIC`——**单帧诊断，不是标定**；多场景标定 OPEN（§6-G1）。

### 3.2 权重 `axmax/127` 的来源

`ioport_4_ioport_pack.fp16.bin` 的 `[33536,37632)` 区间（模型权重本身，不是历史候选重打包值），按输出通道取 absmax/127；区间 sha256 与 `composable-deltas.json` 的 after-region 相同，说明本卡读的正是当前部署的 DS_WB。**权重侧无数据依赖，离线闭合。**

### 3.3 参考是什么、谁生成、是否非零、是否已过

* **局部 oracle**：`tools/r03_analysis.py` 的**精确整数 CPU 仿真**——同一量化规则、同一 int32 累加（最大 `|acc| = 21267 < 2^24`，整数完全精确）、同一 f32 反量化、同一 half 窄化。因此“候选 = 参考”由构造保证（只差 native 的 int32 加法顺序，而整数加法可交换，**结果与顺序无关**）。
* **父侧参照**：同一 `skip4` 上父模块的 f32 累加仿真。该仿真先在**有父输出捕获的成对 run**（`v2-g1chain-l2diag-001`，`dump_skip4.bin` `d24ccc97…` + `dump_block4_out.bin` `ad9d923a…`）上验证：rel 2.20e-4、bit-equal 99.9966%，才用于 `v2-g3-diag-002` 的输入。
* **非零**：是（`candidate_absmax = 69.6875`，父 69.75；非全零、非 NaN）。
* **是否已过**：

| 指标 | half 臂 | qx 臂 |
|---|---|---|
| 最大绝对误差 | 0.81640625 | — |
| 相对张量 absmax | **1.170%** | 1.380% |
| RMS | 0.1854789366438854 | — |
| NRMSE / absmax | **0.2659%**（界 0.5% → 满足） | 0.2830% |
| 逐元素 half 相同比例 | 0.68% | — |

| 项 | 父 | 候选 | Δ | 说明 |
|---|---|---|---|---|
| shared / WG | 512 B | **256 B** | **−256 B** | `a_half` half → `a_i8` int8 |
| shared 写字节（源级） | 8,257,536 B | 4,128,768 B | **−4,128,768 B** | 同一 4,128,768 次 store，元素 2 B → 1 B |
| MMA 指令 / dispatch | 64,512 | **32,256** | **−32,256** | 2 N16 × 2 K16 → 2 N16 × 1 K32 |
| coop matrix load / dispatch | 96,768 | **80,640** | **−16,128** | A 2→1、B/B1 4→2；**新增** scale 片段 2 |
| coop matrix store / dispatch | 32,256 | 32,256 | 0 | 输出 store 不变 |
| barrier / dispatch | 16,128 | 16,128 | 0 | 池化发布 barrier 保留 |
| 权重读字节（源级） | 33,030,144 B | 16,515,072 B | **−16,515,072 B** | 4 个 512 B tile → 2 个 |
| scale 表读字节（源级） | 0 | **+16,515,072 B** | **+16,515,072 B** | 2 个 512 B 片段/WG（每通道步进沿 8 行复制，避免假设分量坐标映射） |
| 量化 code point / dispatch | 0 | 4,128,768 | +4,128,768 | 与父的 4,128,768 次 `a_half` 写同一位置（替换，不是额外扫描） |
| int32→f32 分量转换 / dispatch | 0 | 129,024 | +129,024 | 2 片段 × 4 分量 |
| 反量化乘 / dispatch | 0 | 129,024 | +129,024 | 每输出通道一次 |
| f32→f16 窄化 / dispatch | 32,256（父的 `MAT_H(acc)`） | 32,256 | 0 | 位置不变 |
| pack 文件 | 1（fp16 37632 B） | 2（int8 2048 B + scales 5120 B） | +1 | 均离线生成 |

**owner 与活区**：`a_i8[256 B]` 为 WG shared，32 条 lane 在池化循环内写、唯一一次 barrier 之后由 A 片段 load 读；活区 = 池化循环→A load（与父的 `a_half` 同构）。`aa`/`bb`/`bb1` 活到两条 MMA；`ci0`/`ci1` 各自活到自己的 epilogue 块（两块互斥，未引入同时存活的第三份副本）；`st0`/`st1` 在反量化乘里即死。

**没有删掉仍被使用的 half 读者**：`block4_out` 仍是 half（8257536 B），当前 C64 入口读的就是它；qx 臂是**同一份数学的第二个编译期分支**，不是替换（§6-G2）。

**scale 片段读的优化路径**（登记，不在本卡做）：若采用 `register_handoff.glsl` 里已验证的 SG32 M8N16 分量→(row,col) 映射，则每片段只需 16 个标量（64 B）而不是 512 B 的复制块，可把上面 +16,515,072 B 降到 +2,064,384 B。本卡故意不用该映射，以避免把正确性绑定到另一张卡的量测结果上。

## 6. 未解决阻碍（关闭规则 6，具名）

| 编号 | 状态 | 内容 | 谁提供什么 / 下一步 |
|---|---|---|---|
| **G1** | OPEN | 池化后输入 step 只是**单帧诊断**（一个 fixture 的一次 dump），不是多场景标定 | 协调入口分配 GPU 时段 → 在验收 fixture 集上各 dump 一次 `skip4`（同一池化规则）→ 重跑 `packs/gen_r03_packs.py`，重算 `sV`；或由 R02 的 C32 INT8 体直接发布输出 step（`qX` + scale），则本卡可零捕获闭合 |
| **G2** | OPEN | qx 臂的“C64 入口 qX”具体布局是 **R04 的输入契约**，本卡只保证“与 half 输出同一 `io_at` 索引空间的 int8 元素”，不声称是 C64 INT8 入口格式 | R04 定义入口布局后，二选一：改本卡 `SC_OUT` 段与 store 寻址，或在 R04 侧做一次具名适配；在此之前 half 臂是唯一可接线身份 |
| **G3** | OPEN（质量风险） | 逐元素 `abs0.01+rel0.02` 不满足（36.2% 在界内，最差 73.4×），NRMSE 0.266% 满足；根因是单一张量激活 step 的绝对底噪 ≈0.18 | 方案 A：把 **per-input-channel** 激活 step 折进离线权重 pack（`W'[k][n] = W[k][n]·sV[k]/sV_ref`，再按通道量化；只需重打包 + 重算参考，不改内核结构，但会改变权重量化误差）；方案 B：接受该位置噪声，由整网画质门裁决。二者都要 GPU 时段才能验 |
| **G4** | OPEN | `NATIVE`（SLM/GRF/occupancy/DPAS）、`GATE`（fixed/fb2）、`ORDINARY`、`QUALITY` 全未跑 | `run/r03-ioport4/jobs.json` 已就绪；需要 GPU 时段与协调入口排程 |
| **G5** | OPEN | 本卡 plan 接在 **278 发 INT8 控制**（`plan-g3-production.txt`）上；当前生产父（232 发 FP16 主线）不含该 pass 的 INT8 形态 | 等 INT8 主线封版后把本卡的 4 行 delta 重放到新父 plan；delta 已按行记录，可机械重放 |
| **G6** | 已登记 | scale 片段读带来 +16.5 MB/dispatch 源级读（常量 5 KB，cache 常驻） | §5 末尾的 16 标量方案；性能阶段处理，不作为覆盖阻塞 |

**没有把任何未完成项改称“例外”。** 本卡不声称全网 INT8 完成、不声称数值门通过、不声称 native 收益。

## 7. 与 GUIDE R03 原文的逐条对照

| GUIDE 要求 | 本卡落实 |
|---|---|
| 保留四点 half 池化树 | 表达式逐字保留（父 29–33 = 候选 75–79） |
| 在 `v` 产生处量化 | `a_i8[i]=int8_t(clamp(roundEven(float(v)*invV),-127,127))`，与池化同一循环、同一 owner，无第二遍扫描 |
| `a_half[8*32]` 改成消费者可加载的 INT8 tile | `a_i8[8*32]`，`coopMatLoad(..., RowMajor, ld=pc.p1.x=32)`，索引 `i=m*K+k` 与父写索引相同 |
| K32 一次消费配两个 N16 输出 | 一条 `coopMatMulAdd` per N16，K32 单步；MMA 指令数减半 |
| 最终直接生成 C64 入口 qX | 输出仍**直接**写消费布局（layout0，无 scratch）；qx 臂额外提供同索引空间 int8 输出（入口格式待 R04，G2） |
| 需要 half 的读者另保留 | `block4_out` half 输出完整保留，当前 C64 入口不受影响 |
| ds_pixel 两种布局、有效区与 padding 逐位置核对 | §1 + `LAYOUT-PROOF.json`（两分支各 4,128,768 对全等、整 dispatch 恰好写一次、输入双射、有效区 guard 拒绝 0 像素） |
| 不是 NON_MATRIX、不许以 transport 豁免 | 审计的两处静态 FP16 MMA 就是被替换对象；候选 0 处 FP16 MMA |
