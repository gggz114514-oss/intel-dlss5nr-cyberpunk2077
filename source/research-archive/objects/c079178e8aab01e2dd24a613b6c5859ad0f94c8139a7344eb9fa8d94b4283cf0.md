# n02d-f02-bias-wide — BUDGET（第 B 步：寄存器预算，三种写法的峰值）

**结论先行**：宽片段 = **16 GRF/线程**（8 行 × 64 列 f32 = 2048 B = 16×128 B）。
本卡的候选按“两条带都在场”的写法（W1）实现 = **32 GRF 常驻**；低寄存器的
W2（一次一条带，16 GRF）代价是**复制 8 条 shK 块读**（会打破 528 条交织 mov 的不变量）。
卡的“半宽形态”退路经算术证明**不成立**（既没降寄存器，也丢了消息收益，见 §3）。

## 1. 三种写法的峰值（逐项算，不猜）

记：一条 8 行 × 64 列 f32 带 = 512 个 f32 = **16 GRF**（每 (lane, component) 一个 dword）。
一个 SG 的 bias 瓦片 = 16 行 × 64 列 = 1024 f32 = 2048 dword = **32 GRF**。

| 写法 | 结构 | bias 常驻 GRF | 相对今天 (8) | 消息/SG | dpas | 528 movs | SLM | 屏障 |
|---|---|---:|---:|---:|---|---|---|---|
| **W1**（本卡 candidate.comp） | 两条带在 block 0 之前一起读入，按父结构 4 个列块依次消费 | **32**（16+16） | **+24** | **8**（512 B）或 16（256 B） | 128 不变 | **不变**（shK 块读不复制） | 0 | 0 |
| **W2** | h-外提：先跑完 band0 的 4 个列块，再读 band1 跑 4 个列块 | **16**（一次一条带） | **+8** | 8 / 16 | 128 不变 | **可能要变**（见下） | 0 | 0 |
| **W3** | 半宽 8×32 片段（4 个/ SG），h-内 | **32**（4×8） | +24 | **32**（每条 128 B） | 128 | 不变 | 0 | 0 |
| W3' | 半宽 8×32，h-外提 | **8** | 0 | **32**（128 B） | 128 | 要变（同 W2） | 0 | 0 |

### 1.1 为什么 W1 一定是 32 GRF

两条带服务的是**同一批列块**：列块 b 的 4 个站点里，band0 与 band1 各占一半
（源码 `p0b` 来自 `qa00/qa01`，`p1b` 来自 `qa10/qa11`，同一个 `{ ... }` 块内）。
8 个 8×16 站点按 (h,b) 分成两半，而 b 是外层循环 ⇒ **b 从 0 开始时两条带都必须在场**。
一条带 16 GRF，两条 32 GRF。这与片段形状无关（瓦片是 4096 B，b 内层结构必然全驻留）。

### 1.2 为什么 W2 是 16 GRF，代价是什么

只有把循环改成 **h 外层**（band0 的 4 个列块消费完再读 band1），才能一次只驻留一条带。
代价是每个列块的 **2 条 `load.slm.d64x64t`（shK 16×16 half 块）在两个 band 段各发一次**：

- 消息：`load.slm` 16 → **24**（score 段 8 → 16）；
- **528 条交织 mov**：n01b 已定位 528 = 68 个 zip 块 = 64 个 `d64x64t` 块读 × 8 + 尾块；
  其中 shK+shV 占 17 块/136 条。shK 读翻倍 ⇒ **+64 条 zip mov（528 → 592）**，
  除非 igc 把两条**地址相同、其间无 SLM 写**的 `OpCooperativeMatrixLoadKHR` 做 CSE
  （二者的 memory-access 字面量都是 0，即非 volatile，**允许** CSE，但不保证）。
- 也就是说：W2 用“可能打破 528 不变量 + 8 条 SLM 消息”换 16 GRF。

### 1.3 为什么 W3（卡的“半宽退路”）不算退路

半宽片段（8 行 × 32 列）在 `fb` 里**不是连续段**：行跨度是 64 个 f32（256 B），
而一个 8×32 片段每行只取 128 B ⇒ **每行一个极大连续段 = 8 段 × 128 B**。
按 n02c 实测的定价规则（条数 = 窗口内极大连续行段个数）：

```
8×32 片段:  8 条 128 B 消息/片段 × 4 片段 = 32 条/SG   （64 → 32，只减一半）
8×64 带  :  4 条 512 B 消息/带   × 2 带   =  8 条/SG   （64 → 8，减 7/8）
```

而且 W3（h-内）依然是 32 GRF；要降到 8 GRF 必须走 h-外提（W3'），又回到 §1.2 的 shK 复制。
**⇒ 半宽形态既拿不到 ≤16 的门槛，也省不下寄存器。本卡不实现它。**

## 2. 本卡的判定与门

- **实现 W1**：它是唯一**结构上不可能**多花消息、多花 mov、多花 SLM、多花屏障的写法；
  唯一风险是寄存器。
- W1 的寄存器风险入账方式：
  - 今天 bias 段的落值峰值 8 GRF（8 站点串行复用同一批）；
  - W1 需要 32 GRF 常驻 ⇒ 该段活值峰值至少 +24；段内水位已到 r108 ⇒ **有溢出风险**；
  - 但整核水位 127 出现在 barrier **之前**（输入/展开段），bias 段的活值集合远小于 108，
    所以 **32 GRF 不必然溢出**，这是一个只能由 native/resource 回答的问题。
- **判据（写死，交给 GPU 臂）**：
  - `scratch = 0` 且 `max_r ≤ 127` ⇒ W1 预算成立，直接看计时；
  - `scratch > 0` 或 `max_r > 127` ⇒ **B 类（副作用）**，下一版改 W2（16 GRF），
    并把 `load.slm 16→24`、`528 mov → 592`（若未 CSE）一起报；
  - `load.ugm.d32x16t` 没降 ⇒ **A 类**，与寄存器无关。
