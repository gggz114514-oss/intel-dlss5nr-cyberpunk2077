## 1. 映射：生产者每个 (lane,component) 代表哪个 (token, channel)，消费者要什么

### 1.1 生产者 → token / pixel

`nrf_prepare_A(q=sg)`，`lane<16` 的 16 条 lane 各产出一个 **token 的 16 个 feature**：

```
token t = 16*q + lane                          (q = sg = 0..3)
xl = 4*(q&1)+(lane%4)      yl = 4*(q>>1)+(lane/4)
px = WGID.x*8+xl           py = WGID.y*8+yl          grid 168x96 => px<=1343, py<=767
sx = px<1280 ? px : 2*1280-2-px      sy = py<720 ? py : 2*720-2-py
```

覆盖性（P5 实测，`tools/proof-ranges.json`）：

| 断言 | 结果 |
|---|---|
| 4 SG × 16 slot 是 8×8 tile 的双射 | `equals_8x8_tile=true`，`per_sg_disjoint` 全 true |
| 每 SG 16 个 slot 互异 | true（4 个 SG 全过） |
| slot 总数 | 168×96×64 = 1032192 = 1344×768 |
| 映射到源图后的互异像素 | **921600 = 1280×720** |
| 反射重复 slot | **110592（10.71%）** —— px≥1280 或 py≥720 的 slot 折回到镜像像素 |
| 折回坐标是否在范围内 | `sx_in_range=true`，`sy_in_range=true` |

本卡**不动**这张映射的任何一项：token、feature、写者、读者、顺序都不变；唯一改动是"读哪个 `f[]`
元素"的**算式**，而算式被 P4/P6 证明逐元素相等。

### 1.2 16 个 feature 槽（固定，`packed[0..7]` = 8 dword = 16 half）

| j | 值 | 来源 | 分支 |
|---|---|---|---|
| 0,1 | 噪声 x,y | 冷噪声 `f[ni..ni+2]`（`p5.w&4`）或 PCG 高斯 | 统一分支（本身份取冷噪声） |
| 2 | 噪声 z | 同上 | |
| 3 | `ctl(6)` | 控制常量 | |
| 4,5 | centered r,g | `(sampled-0.5)*0.125`（f16） | ← **本卡只缩短 `sampled` 的地址** |
| 6 | centered b | 同上 | |
| 7,8,9 | history r,g,b | `nrf_history5`（f32）→ f16 | `ctl(8)!=0`（本身份 **不执行**） |
| 10,11 | `ctl(0)`,`ctl(1)` | uniform | |
| 12,13 | `ctl(2)`,`ctl(3)` | uniform | |
| 14 | `ctl(4)` | uniform | |
| 15 | 0 | 常量 | |

### 1.3 消费者要求

写：`shK[q*256 + lane*16 + j]`（half），两条 `store.slm.d32x4`（32 B/lane = 16 half/lane）。
读：`subgroupMemoryBarrierShared(); subgroupBarrier()` 之后 `coopMatLoad(a0, shK, q*256, 16)` 与
`coopMatLoad(a1, shK, q*256+128, 16)` = 两个 8×16 A 片段；用：`nrf_lift` 的
`acc[token][n] = Σ_k feature[token][k]·w[n][k]`（K = 16 feature，n = 8 通道 × 4 lift 组 = 32 通道）。

消费者要求的是**同一批 bit**：所以本卡只需要证明"地址逐元素相等 ⇒ 读到的 float 相同"，不需要（也不许）动
feature 的打包顺序、half 舍入点或 K 序。

### 1.4 尾块 / 无效 lane

* `lane<16` 之外不做任何工作（`[0390] (~f0.0) goto L19088`），token 越界由 `tok_oob` 统一门控输出 store。
* 输入像素不会越界：折回后 `sx∈[0,1279]`、`sy∈[0,719]`（P5），因此源像素读的两个 `nrf_mirror` 是恒等 —— 这就是本卡第 2 处改动。
* 反射重复 slot（10.71%）不是本卡引入的，也不是本卡能修的（属于 plan 的 grid/图像尺寸）；它们照旧写自己的 token。

## 2. 删掉的是什么真实工作（正常执行路径）

三处源码改动（`SOURCE-DIFF.patch`，全部落在整数地址尾，`CHAIN-AUDIT.md` §2 的 `int-tail`）：

| # | 站点 | 父 | 候选 | 依据 | 本帧执行？ |
|---|---|---|---|---|---|
| 1 | `nrf_hist_linear` 的 4 个角点 | `clamp(ij,0,hi)`、`clamp(ij+(1,0),0,hi)`、`clamp(ij+(0,1),0,hi)`、`clamp(ij+(1,1),0,hi)` | `ij`、`min(ij+1,hi)` 的 3 种组合 | `pos` 已被 `nrf_history5` clamp 到 `[0.5,(W,H)-0.5]`，`pos-0.5` 精确，`ij∈[0,W-1]`：0 下界恒假；`ij+1>=1>0` 也恒假 | **否**（`ctl(8)=0`） |
| 2 | `nrf_rgba`（源像素读） | `base + mirror(sy,H)*W*4 + mirror(sx,W)*4` | `nrf_rgba_clamped`：`base + sy*W*4 + sx*4` | `sx/sy` 本身已是镜像折回且落在 `[0,W-1]×[0,H-1]`（P3/P6） | **是** |
| 3 | `nrf_depth_at` 的中心探针 | `mirror(xy)` | `nrf_depth_at_in`：`xy` 直读 | `xy` 就是折回后的像素，在范围内 | **否**（`ctl(8)=0`） |

逐条计数（源码层；ISA 层的预测见 §5 与 `NATIVE-PREDICTION.md`）：

| 项 | 站点数 | 每条省掉的操作 |
|---|---|---|
| `i%period` 的 32 位取模（`mul/macl` + `asr/xor` 符号修正 + 2×`sel` 反射） | 源像素 2 轴（live） | 每轴 1 个取模链：ISA 里是 1 条 `math.inv` + Newton `mad` + `macl` 余数 + `asr/xor` + 2×`sel`；`list 0B90` 的两段合计 ≈38 条 |
| 同上 | 深度中心 2 轴（skipped） | 同上，静态 |
| 角点 clamp 的死下界 | 5 个 `nrf_hist_linear` 实例 × (4+1+1+2) | 每实例 8 条 clamp 操作（`max(0,·)` 与 `ij+1>=1` 的下界）→ `min(·,hi)` 1 条 |

**没有删**（逐条声明，防止把"看起来像工作"的当收益）：

* 消息一条不删：73 条 `load.ugm.d32` 全部保留，立即数分布不变（`+0x0:28 / +0x4:23 / +0x8:22`）。
* 冷噪声 3 条、深度块 5 条里的 4 邻、运动 2 条：源码未动（它们的坐标真的会越界，`nrf_mirror` 必须留）。
* 任何 float 表达式（`fract`/`floor`/`mix`/`uv=(xy+0.5)/vec2(W,H)` 的 2 次除法）、任何 half 舍入点（36 条 `mov :hf←:f`）、
  任何 K 序/归约树/残差 seed：全部不动（SPIR-V 侧无 `OpF*` opcode 变化，NC 189→189）。
* SLM 往返（2 写 + 2 读）、`subgroupBarrier`、`sync.allrd`：不动。
* **不重复 n18**：n18 删的是"clamp 之后多余的镜像取模"（4 个角点）；本卡删的是 n18 明确保留的
  `nrf_rgba`（源像素）与中心探针，以及 n18 没碰的 clamp 下界。n18 的站点本卡一条没重做。

## 3. 重叠：独立工作原来如何重叠（本卡前后完全一致）

| 数据 | 生产者 | 最后消费者 | 覆盖者（WAR/WAW） | 依赖 |
|---|---|---|---|---|
| 源像素 3 个 float（`sampled`） | 本 lane 的 gather（地址链本卡缩短） | `centered→cn→packed[2,3]` | 无（`f[]` 只读） | RAW：地址→gather→cast |
| 冷噪声 3 个 float | `f[ni..ni+2]` gather | `packed[0,1]` | 无 | RAW |

| A 片段（16 token × 16 feature） | `lane<16` 写 shK，随即 `coopMatLoad` | `nrf_lift` 的 4 次 `dpas` | 无（读入寄存器后 shK 该区间才被 K 覆盖） | RAW：pack→barrier→load |
| shK（2048 half） | ① feature pack ② K | ① A 片段 ② QKᵀ 的 B 片段 | feature 区被 K 覆盖 = WAR，已被"先 load 后 store"保护 | 不变 |

缩短的只是"地址 → gather"这条 RAW 边的**上游长度**（源像素那 3 条：整数尾 53 → 预测 ≤18，深度 19 → 预测 ≤7）。

## 5. 是否真落到 native：期望在 ISA 里看到什么（预测 + 判据）

完整判据见 `NATIVE-PREDICTION.md`，这里只列最硬的三条（都在 ordinal 0 的 kernel 内，IGA 可直接数）：

1. **`math.inv` 在入口体（live 段 `0x390..0xCE0`）里 2 → 0**；整个入口区 `13 → 11`。看不到下降 = A 类未落地。
2. **源像素 3 条 gather 的地址尾 53 → ≤18 条**，且 `tail depth 19 → ≤7`：判据是这三条 send 的偏移寄存器
   （父 `r10`）的上游不再有 `asr/xor` 符号修正与 `macl` 余数；`macl` 在 live 段 `8 → ≤6`。
3. **73 条 `load.ugm.d32.a32.bss` 必须仍是 73**，立即数分布 `28/23/22` 不变；`dpas`、`send.slm`、
   `subgroupBarrier`、36 条 `mov :hf←:f` 全不变。

`max_r` 不得高于父：这是 capture 侧属性，写成 GPU 门（见 `GPU-REQUEST.json` 的 gates）。

## 6. 整体是否更快 / 本卡要测什么（以及为什么我预测"很可能不显著"）

* **臂**：`base` = `accepted/n27-f07-20261027/plan.txt`（sha `ea053b92…`，其 PASS 0 行 = 父 SPV）；
  `cand` = 本卡 `plan.txt`（sha `d8875665…`）。两者**只差第 504 行**（PASS 0 的 SPV 路径），已核实 1 行 diff。
* **门**：`fixed`（`--warm 0 --reps 1` → `1755e9c2…`）+ `fb2`（`--warm 0 --reps 2 --feedback --save-frames` → `9c3e511e…`）。
  任一不一致 → E 类，先查首差阶段。**注意**：本卡的等价性是"读同一个 4 字节 float"，所以两门必须都过；
  若只有 fb2 过而 fixed 不过，说明改动触碰了控制流而不是纯地址。
* **整体量**：ordinary `--warm 1 --reps 30 --feedback`（末帧 gold `2b63d4ba…`），two-arm-6-alternating。
* **有效量**：同一批采两臂计数器，看 `f1c32_image_pre` 的 **`XVE_STALL_ALUWR` 折算毫秒**（父 0.385 ms / 1.247 ms 的 30.9%）。
* **归因**：只有 PASS 0 的 SPV 变了，其余 231 个 PASS 字节相同 ⇒ 任何整帧差只能来自 F01。
* **我的预测（诚实版）**：live 入口体 235 条里删约 38 条（-16%），但整帧 17.14 ms 里 F01 只占 1.247 ms，
  且**入口体只是 F01 的一小段**（`0x390..0x4A90` 之外还有 barrier/coopMat/dpas/输出）。按指令数比例线性外推
  `ΔALUWR ≈ 0.385 × (38/235) × (入口体占 F01 的比例) < 0.02 ms`，**低于 L13 的 0.03 ms 阈值**。
  除非 F01 是"每个 WG 的前段延迟受限"（gather 地址链在 barrier 之前，整条 WG 的关键路径从它开始），否则应判
  **D INDISTINCT**，不许用整帧毫秒反推机制有效。
* **本卡给出的下一个方向（给主代理）**：`ctl(8)=0` 说明 F01 的 0.385 ms ALUWR **不在** history/depth 地址链上
  —— 它在 `0x4A90` 之后的 coopMat/dpas/cast 段。下一张卡应审那一段的依赖链（`dpas` 累加器链 + `hf←f` 转换），
  而不是继续缩短入口地址（入口地址链在本帧只剩 81 条，最多再省 20 条）。
