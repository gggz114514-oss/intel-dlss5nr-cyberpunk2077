## 关键结论

- **纯 glslang 编译即可字节一致**：35/39；**需要 NoContraction 装饰迁移**：4/39（`f1c32_image_pre`、`block1_swin_body_1`、`f2c32_block66_fused`、`s37_fold_body_r1a_v1`）。
- **必须带 -D 宏才能编译**的 3 个 shader：
  - `split16_b23_l3`（F11，15 个 PASS，ord 63/67/…）：源码第 10-12 行 `#if KIND!=1 && KIND!=4` → `#error Active swapped projection supports KIND1/KIND4 only`；本 PASS 是 **KIND=1**（32×64 swapped projection，4SG×32token×16channel）。KIND=4 是 outview half_tail 变体，基线不派发。旁证：`c2-layout/layout0-unify-l2-v4/build-receipt.json` 的 S23 记录 `defines:{"KIND":1}`。
  - `split16_b30_l3`（F12，ord 91）：**KIND=2**（A 取自 gt）。旁证：`work/zcode-fp16-fullnet-handoff-20261024/build/f12a-b30-direct-a/build_f12a.py` 用 `-DKIND=2`。
  - `split16_b30_l4`（F12，ord 92）：**KIND=3**（A 取自 gp，finalhead）。**坑**：该 `.comp` 第 55 行仍引用 `scratch[...]`，看似源码不全；那段 staging 在 `#if KIND!=3` 里，KIND=3 时被预处理掉，所以同目录的 `split16_common.glsl` 不需要声明 `scratch`。不带 -D（KIND 默认 0）编译才会报 `scratch : undeclared identifier`。
  - `t3_b39_project_blend`（F17，ord 133）：**PROJECT_PAIR=2**（grid.y=16=512/(16×2)）；缺省时第 62 行 `PROJECT_PAIR` 未定义。
- **装饰迁移的 4 个**（父模块与做法）：
  - `f1c32_image_pre`：父 `c32-no-gain-diagnosis-20261026/combined-existing/f01.spv`，全量迁移；`len(keep)==len(parent NC)=189`。
  - `block1_swin_body_1`：父 `c32-feed-owner-20261025/kv-tile/candidate.spv`，全量迁移，185。
  - `f2c32_block66_fused`：父 `c32-entry-chain-20261025/f2-direct/candidate.spv`，**先削掉父的 `full_norm` 装饰（16 个 FP 节点）再把子模块自己的 `full_norm` FP 节点加入 keep**，其余继承；否则对齐会把 16 个重写的 helper 节点装饰搬错。
  - `s37_fold_body_r1a_v1`：父 `c32-boundary-followup-20261026/f20-pixel-owner/candidate.spv`，全量迁移，45。
- **头文件歧义**（同名不同内容，选错必错）：`register_handoff.glsl` 265 份/11 种、`split16_common.glsl` 193 份/13 种、`vit_nb04_mpair.glsl` 93 份/22 种、`c64_c128_common.glsl` 62 份/4 种。配方用 `header_pins` 钉字节。
- `glslang` 的 include 解析顺序是「**包含者所在目录优先，然后 -I 顺序**」，所以「同名头文件在源目录里」时 -I 无效；本卡所有配方都把真实取到的字节 pin 下来。
- 上一轮 `IDENTITY-232.json` 记录 16 raw + 1 decorated、22 失败，失败原因全部落在三类：**缺 -I**（`#include` 找不到）、**缺 -D**（`#error`/未定义宏）、**缺装饰迁移**（能编译但字节不同）。没有一类需要改源码。

## 头文件 pin

31 个 shader 需要 `#include`。工作区里同名头文件有多份不同内容（例如 `register_handoff.glsl` 11 种、`split16_common.glsl` 13 种、`vit_nb04_mpair.glsl` 22 种），选错就必错。每个配方因此钉住**实际被 glslang 读到的字节**：

- `compile.header_pins[name] = sha256`：该 shader 编译时真实读到的头文件内容；
- `compile.header_origins[name]`：该内容在工作区里的原始位置；
- `compile.pinned_include_dir`：本卡 `evidence/headers/<spv12>/` 下的副本，只给这一个 `-I` 也能字节一致（`reproduce_any.py` 默认走它，`--workspace-headers` 走原始目录）。
