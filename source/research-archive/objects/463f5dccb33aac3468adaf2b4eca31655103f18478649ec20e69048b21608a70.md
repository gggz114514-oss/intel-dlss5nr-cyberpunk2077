2026 年 10 月 16 日。实施方为 WorkBuddy，完成后由本对话 Codex 审计。目标是在已通过的 clear-prune-001 上继续落实 AMD 最终全网组织中的布局统一和跨层融合，减少真实的中间写回、回读、地址转换和派发。按下面的具体语义链施工，保留失败候选供 INT8 复验，不重跑已有实验。

## AMD 最终方法的读取和处置

本轮附带的 PREPARED_INPUTS.json 已绑定父身份、目标 pass、相关资源和 AMD 源文件指纹，并摘出所选 pipelines 的完整 defines。它是 CPU 定位材料，不是写覆盖或数值证明。不要重扫 39 族；只补目标链的真实访问与编译绑定。

AMD 参考根为 ROOT/src/amd-reference/linux。每项先串起最终 pipelines.json 的定义、nr_graph.cpp 的实际选择条件、shader/include 的完整分支和后续注释；分别记录已采用、精度限制下替换、B580 适配、未实施。存在 pipeline 名称不能证明 host 已选它，已有相同家族不能证明融合边已经完成。

| 方法 | 必读最终实现和注释 | 本线目标 |
|---|---|---|
| 全网公共布局 | src/core/nr_graph.cpp:1-18；src/core/nr_native_plan.cpp；src/core/tinlayout.hpp；shaders/rdna4/gemm1x1.comp；pipelines.json 的 gemmvproj/gemmproj 等 | 借鉴 producer 直接按消费者公共布局写出。保留 FP16，不移植 e4m3 数值格式。 |
| 输入整链 | nr_graph.cpp:2540-2591；pipelines.json 的 fswinimagepreds32 及 host 实际选用的 temporal/nohi 变体；fswin_t.comp；include/image_input.glsl、image_noise.glsl、fswin_body.glsl | 图像 features、16→32 lift、首 C32 body、2×2 mean pool 的完整组织。 |
| 解码上采样整链 | nr_graph.cpp:2984-3018；fswinfusedup32/64/128/256；fswin_body.glsl:70-94、350-355、469-499 | 低分辨率 projection 一次供四角，blend 直接供 body，不再落两个中间张量。 |
| 编码降采样整链 | nr_graph.cpp:3110-3146；fswindsp32/64/128/256；fswin_body.glsl:2750-3025、3074-3158 | body 的最终 half 值直接供 2×2 mean，再做 learned projection，同时保留 decoder 需要的 skip 写回。 |

必须处理注释里的适用条件，不能只移植宏名：

- NR_POOL_VECTOR_STORE 的目的包括保留标量 half 运算再合并转换和写入；DPP16 注释明确讨论了不同舍入。DPP16 的部分等价理由依赖 e4m3 将微小差异量化成同一个零，本线 FP16 不能采用这一理由放宽数值。
- NR_POOL_ST16 打包的是两个 e4m3 字节，经 f16 view 发出 16 位写入，不是两个 FP16 元素的向量写；本线按真实 FP16 字节宽度重建对应机制。
- NR_DS_IDENTITY_FAST 的前提是 raster、crow 和 writer_rows/rows 确实相等。AMD 注释明确区分 C32 的尺寸条件；不能把其 1080p/4K 结论直接套到本线输入和 padding。
- NR_UPS_KOUTER 注释已记录无收益且未发布，不把它当最终默认优化重试。NR_POST_REUSE 的 one-wave 条件和 RDNA fragment/lane 坐标也不直接当成 B580 SG32 的保证。
- 输入路径的 NR_NOISE_FIELD、NR_PRE_FULL=71、NR_HALF_RTE 和 temporal 变体要连同 seed、flags、noise/history 生命周期核对。不能用固定 cold 噪声替代真实 feedback；新增噪声预计算如需额外派发，必须计入整链和普通整网。

AMD 的 FP32 norm、e4m3、量化舍入等数值选择不覆盖本线已有数学合同。移植组织方法时保持父版本的运算顺序和 half 边界，清楚记录精度适配；不要借本阶段修复或掩盖既有 pre0/C128 独立原参考未通过项。

## 布局统一施工

公共二维激活接口首先采用现有 layout 0，即 tile4x4_channel16 的 FP16 版本。沿用已编译 ioport_common.glsl 中 io_at() 的真实地址定义；其索引单位为 half，push 中的 byte/half/float 单位逐字段注明。ViT 的二维视图 W=24、H=12 来自真实 block30/38 接口，不能只由 288 token 猜出任意宽高。

### L1 打通 block30 到 ViT 再到 block39 的公共激活接口

父 pass 116 产出 canonical block30_out，117/118 消费它；121、126、131、136、141、146、151、156 产出 block31..38_out。后续各层 FFN expand 和 residual contract 继续读前一层输出，157 的 project-k1024 读 block38_out，158 的 postblend 读其 projection。

把这些外部激活的生产和全部实际消费同时迁到公共 tile 地址，包含 residual 路径。第一份候选必须覆盖这条完整接口链，不能只改 manifest.layout 或只改生产者。ViT 内部 A/Y/QKV/T 的私有矩阵布局如不跨该接口，可保留；不改 attention 算法，不重做已完成的 directA/tileB 优化。

block30_out 分配有 padded_tokens=384，逻辑 token 为 288，block31..38_out 则按实际分配处理。保持既有 crop、padding 和未定义区策略；不把改变排列顺带包装成减内存或删清零。若布局单独变慢，保存结果，再判断它是否为后续具名融合的必要条件；只有明确消除真实交接的组合才做一次集成验证。

### L2 打通 split16 与投影的其余布局接口

逐边覆盖 83 产出的 block22_out、split16 b23..30 对外输出及 skip30_l3、158 产出的 block39_out、split16 b40..47 对外输出，以及 190→191 的 block47_out 接口。当前存在 raster_token16、canonical_row_c 和 planar_view_sub，不能统称一个已统一接口。

按实际 KIND0/1/2/3/4 和输出语义修改读写地址，保留 split16_b30_pool 的额外输出、KIND3 的无 residual 1024 通道 head，以及 KIND4 的 outview 作用。共享源不等于相同 ABI，编译和数值门分别绑定实际变体。KIND2 的 skip 与 pool 双消费者必须一起覆盖。

若某段局部矩阵布局在 B580 上必须保留，交出完整公共布局候选、失败证据和一次由真实寄存器/访存证据引导的适配结果，解释剩余接口如何交接。不要另添独立 repack 派发来宣称消除了布局岛；也不因一个局部变体变慢便否定整套公共布局路线。

布局证明按逻辑坐标进行：旧、新布局各自解码到同一 canonical 坐标后逐位比较有效数据，分别核对 padding 契约和唯一 writer。物理字节排列不同，不要求两个中间 buffer 的原始字节串相同；最终 frame/history 输出仍遵守原来的逐字节门。

## 跨层融合施工

优先顺序为 F1 输入整链、F2 block66 解码整链、F3 编码降采样整链。沿用新公共接口，独立候选保持单项 delta；最后只集成有收益或确为必要前置的变化。不需要等全局所有布局岛都成功后才写独立可推进的融合核。

| 候选 | 父语义 pass | 完整目标和必须保留的输出 |
|---|---|---|
| F1 image-pre | 0 features → 1 lift → 2 C32 body → 3 mean pool | 按 fswinimagepreds32 的完整组织实现。features 和 lift 不再独立落地；skip0 仍供 pass275 解码端使用，必须保留，block0_out 保留。无额外辅助派发时 4→1；如需 noise 等辅助工作，按真实派发计数。 |
| F2 decoder66 | 269 projection → 270 postblend → 271 C32 body | 按 fswinfusedup32 完成 projection、四角复用、gain/skip blend、body 输入交接。保留 block66_out 和 skip4，移除不再有消费者的 projection/blend 中间缓冲。无额外派发时 3→1。 |
| F3 encoder | 7→8；24→25；49→50；82→83 | 从 C32 边开始，再把同一有效机制用于 C64/C128/C256 的最终输出→mean→learned projection。最后三条只融合实际最终 output pass 与 DS，不宣称整个四段 body 已融合。skip4/8/14/22 仍供 decoder 使用，均保留。每条无额外派发时 2→1。 |

F1 的 features/lift 分配分别为 33030144/66060288 B；F2 的 projection/blend 分别为 4128768/16515072 B。这些只是可移除逻辑张量的分配量，不是已测 DRAM 流量或毫秒收益。它们的首次清零已在父版本删除，不能重复认领该部分收益。

每条完整方法先把图、数据寿命、half 交接和全部消费者落实，再按实际 B580 资源证据做一次有理由的适配。推荐复用已接受 C32 WG128 body 的数学实现和既有接口钩子，调整前后交接与生命周期；不要重写 norm/attention 树或重开 1SG 整窗试验。若完整融合失败，保留完整候选，才可用一个具名分段候选定位问题；分段成功不写成完整 AMD 方法成功。

融合后的寄存器交接仍必须执行父版本原本写回 FP16 时发生的舍入。F3 还要证明 2×2 的四个 half 值如何由当前 subgroup/workgroup 的真实 owner 汇合；若跨工作组，不能用普通 barrier 假装可见。通过 B580 合法的分块或必要局部 staging 适配，并完整计入成本；设备端忙等链继续 OPEN。

## 不重复的实验边界

继承 ROOT/run/register-handoff-20261016/experiment-catalogue.json、int8-revisit-002/index.json，以及 ROOT/run/amd-port-20261015/round5-rejection.json、round6-rejection.json、round7-rejection.json 的身份和结论。只读索引，不重哈希旧大库存。

- 不重跑完整 C32 单 SG body/tail、gather WG128、NC/packed 完整尾，也不重扫 split16 attention v2/v3/v4。
- 不重做 276+277 RGB 输出融合。新 F1 是输入链，F2 是 269..271 解码输入链，两者与旧 RGB 尾路线区分清楚；275..277 保持父行为。
- 已有 mean+learned DS、coarse-owner postblend、project-K 专项和 ViT directA/tileB 不再各自重做。新收益只归于新消除的跨 pass 交接。
- 不把源码名字相同当成已试。提交每项新候选前对比实际 SPV、defines、图边、owner 与旧实验；相同的执行身份直接引用已有结果。若新图使旧 shader 的输入/消费者变化，说明新的具体假设，不能只改标签再测。
- 不用更多清零删除、单次 submit、原有池化、robustness 开关或 API 改名替代本阶段布局和融合任务。无界 tile/WG/宏扫描不在范围内。

## 生成运行表和实际访问证明

交付每个候选的父 pass 集合→新 pass 集合映射，改变的资源/layout/ABI/dispatch/WG/shared 和实际 SPV 指纹。真实融合允许改变发数，NOP 仍算派发。已核当前 runner/profiler 的解析器固定要求 152 个逻辑 row 全覆盖，但实际 pass 数 np 可变；F1/F2/F3 的各条目标链都在同一逻辑 row 内，优先保留 row 语义并沿用原 binary，无需为了减派发改解析器或塞 NOP。现有解析限制包括 SG32、push 不超过 32 words、shared 不超过 49152 B，按新 ABI 显式规划。

若真实实现确需不同参数接口或 runner，仅在新阶段复制并作必要修改，不改父 binary；先以同一父 plan 核对新旧 runner 的必要数值和计时等价性。不要先放宽校验再决定图结构，也不引入通用加载器改造。

只核本次改变链的实际编译源、defines、SPV 访问、binding offset/range、debug/dump/history、alias 的 RAW/WAR/WAW 和跨帧寿命。旧 manifest 的 reads/writes 和已有 possible-extra-accesses 不能直接当完整访问证明。删除中间张量前枚举所有消费者；诊断用中间读出须与生产 SPV 区分，诊断时间不进收益。

保留 K 累加顺序、norm/den 树、epsilon、Q 缩放、概率 half 运算、blend 的 half mul/add 或 fma 边界、RGB/history 顺序、crop 和 padding。不能通过 FP32 norm 替代、晚 reciprocal、删 clamp、引入新容差来过门。

## 最小验收和计数器

先封 CPU 候选、源码 diff、图映射、编译指纹及 argv，再向原协调入口排 GPU。复用 ROOT/run/register-handoff-20261016/run_locked.ps1 与原 GPU.lock，使用全新的 RunLabel/输出目录，保持游戏独占与作业自然结束。工具入口、实际候选和派发映射在执行前绑定，防止旧绝对路径误绑；CPU 阶段不预填执行记录。

1. 对改变的计算或布局接口运行必要原 gold、逻辑坐标、padding/全分配门。未改的九个 C32 body 原 14 门和原尾 6 门不重跑；被改变的计算按实际范围补门。数值失败停止其性能验收，保留失败产物和差异。
2. 数值通过的候选运行完整新 graph 固定输入及真实 feedback 两帧，并核普通 30 次反馈末输出。沿用原数值身份：固定/frame0 为 1755e9c2fadba97f08cb5b02b7a4294cde3675379bdec75352287505f7e129d6，frame1 为 9c3e511e97a5879247bc2965792c96dd62928dddfd85a48bbf25af1e807d3536，30 次末输出为 2b63d4ba1967eebcda61698d538963f59bccaf6d690ef8168f1695a46c5d658d。
3. 普通整网使用同批父前→候选→父后，pool、warm1、reps30、feedback，关闭 perpass。由原始样本计算中位数和均值；差界为半父漂移 + max(两父 95% 均值采样半宽) + 候选半宽，半宽为 2.045×stdev/√30。两父对照均超过既定工程差界才认领明确收益；它不是中位数的正式置信区间。没有新增问题不重复已通过测量。
4. 另做一次受影响语义链的 perpass 归因。按映射对每次 replay 先求对应旧/新链的区间和，再求统计量；不要把逐 pass 中位数之和当整网中位数。区间包含清零、dispatch、屏障和插桩，不能拆出未经测量的纯 barrier 毫秒。
5. 对拟采信的单项或最终集成候选，按既有独立原生组采集 cold overview/slots/stalls/FP16-XMX 及真实 frame1 overview/slots，父前、候选、父后范围一致；只执行新票。本轮必须报 XMX、ALU1、ALU0、总停摆及 barrier/SBID 分项，保留原始逐发数据、GpuTime 权重、帧身份和漂移，不用 null 相等代替采集通过。
6. 有融合或布局新 SPV 时采其原生 scratch/shared/SG 和必要 ISA。GTPin 只补新核尚缺的动态 MOV/SEND/SYNC、地址/转换/交接或实际溢出证据，不要求未改 39 族重新全采。没有原生 GRF 数据时填未知，不能把插桩 GRF256 当原生分配。

shader 原生查询覆盖 dispatch 及其后计算屏障，不直接覆盖查询前的 fill/transfer 或其他 host/整帧间隙。派发变化后按语义链重建聚合；单项对比、完整整网和辅助 noise 工作分别列清，最终普通整网必须包括所有真实工作。GPU 时间加权百分比不构成互斥帧时分账，不能与指令数量比例混用。

对照注释目的设独立验收列：L1/L2 为实际布局接口及地址/运输代价；F1/F2 为真实中间物化和重复输入计算；F3 为 DS 回读/同步及完整链耗时。数值、资源目的、目标链、同批普通整网、硬件指标分别判 PASS/FAIL/不确定/未采集。不要把 AMD 不同硬件和精度的约 62% 当 Intel 整网阈值，也不预承诺 27ms 或 18ms。

若普通整网有收益而 XMX/ALU/停摆未改善，明确哪些注释目标达成、哪些仍 OPEN；不改写指标解释来过门。矩阵槽数不强制等于父的 979118080：辅助计算、边界重复 projection 等变化必须解释有用工作与实际工作，不能靠重复计算抬利用率。
