## 2. 提取链路实际位置（54 报告缺失）

| 组件 | 路径 | 作用 | 输入 → 输出 |
|---|---|---|---|
| C++ 提取器 | `src/amd-reference/windows/package/model-tools/dlssnr_extract_model.cpp` | 从 NVIDIA 模型中解出各层权重/表 | `nvngx_dlssnr.dll` → `inventory/weights/`、`unpacked*/` |
| 表生成 | 同目录 `gen_extract_tables.py` | 把 `descriptor.json`/`model-files.txt`/`.sha256` 编成 C++ 头 | 上述三个文件 → `dlssnr_extract_tables.hpp` |
| 构建 | 同目录 `build_extract_model.sh` | 编译上面的提取器 | — |
| Python 工具 | `src/amd-reference/linux/package/model-tools/`（`inspect_nr.py`、`pack_model.py`、`descriptor.json`、`model-files.txt`、`model-files.sha256`） | 检查模型结构、按 descriptor 打包 | 解出的权重 → 打包条目 |
| 我们的打包器 | `release/gen_assets.py` | 按内容哈希重命名 + 写 index + 重写 manifest 路径 | 扁平 blob 目录 → `assets/cold`、`assets/spv` |

**方向修正**：用户只需提供本地 `nvngx_dlssnr.dll`；工具负责提取、校验、生成资产。`ASSETS.md` 现在写的是"用户自行导出 blob"，必须改。

## 5. 哪些文件适合上 GitHub

**可公开**

- 自有源码：`source/bridge/**`、`source/vulkan/**`（含 `.comp`）。
- 控制面板：`panel/nr_control_panel.py`、`nr_panel.ini`、启动脚本。
- 提取工具：`tools/extract_model.py`（自有）+ `third_party/dlssnr_amd_model_tools/`（**需先确认许可**，见 P1-6）。
- 文档：`README.md`、`INSTALL.md`、`ASSETS.md`、`LICENSES.md`。
- 构建文件：两个 `CMakeLists.txt`。

**必须排除**

| 排除项 | 原因 |
|---|---|
| `assets/cold/*`（72 文件 / 325 MB）、`assets/spv/*` | 权重与派生 SPIR-V，不可再分发 |
| `nvngx_dlssnr.dll` 及其解出物 | NVIDIA 专有；用户自备 |
| OptiScaler（`dxgi.dll`）、`fakenvapi.dll`、`libxess*`、`nvngx_dlss*`、`ffx_*`、`sl.*` | 第三方可再分发件，只给链接 |
| `amd_fidelityfx_upscaler_dx12.dll`、`fsr-original.dll` | 第三方签名二进制，且来源与许可未核实 |
| `validation/`、`evidence/`、日志 | 内部过程数据，可能含本机绝对路径 |
