## 1. 判据总表（每条都能用文本匹配/计数直接判，不需要解码消息描述符）

| # | 观测量 | 父值 | 候选期望值 | 判据性质 | 不成立的解释 |
|---|---|---|---|---|---|
| **W1** | `store.slm` 出现次数 | 4（静态）/ 32（每线程动态） | **0** | 硬（文本存在性） | ≠0 ⇒ `sx` 暂存仍在 ⇒ **A 类：实现未落地** |
| **W2** | `load.slm` 出现次数 | 256 | **0** | 硬（文本存在性） | ≠0 ⇒ A 仍在从 shared 读 ⇒ **A 类** |
| **W3** | `sync.bar` / `signal barrier` / `fence.slm` | 1 / 1 / 1 | **0 / 0 / 0** | 硬（文本存在性） | 任一 ≠0 ⇒ barrier 仍在（IGC 自己加的也算）⇒ **A 类，不许写成"同步变少所以更快"** |
| **W4** | `dpas.8x8` 次数 | 64 | **64（精确相等）** | 硬（不变量） | ≠64 ⇒ 数学/K 序被改动 ⇒ **E 类**（先查数值门，不谈性能） |
| **W5** | scratch / spill | 0 | **0** | 硬 | >0 ⇒ 新增溢出 ⇒ **B 类**（先消溢出再谈收益） |
| **W6** | `send.gtwy` 总数 | 2（信号 + EOT） | **1（仅 EOT）** | 中（signal barrier 消失的直接后果） | =2 且 W3 已 0 ⇒ 多了一条非 barrier 的 gtwy ⇒ 查是否 scratch 通路 |

**只要 W1/W2/W3 任意一条非零，本卡就判 A（实现未落地），而不是"方法无效"。**

### 1.1 A 供料确实换源（这是"删掉中转"落地与否的第二层证据）

| # | 观测量 | 父 | 候选期望 | 说明 |
|---|---|---|---|---|
| **W7** | K 环内 A 读的 SFID | `send.slm`（描述符 `0x0210C500`，`load.slm.d32x8t.a32`） | `send.ugm`（`load.ugm.*`） | **通路必须变**。次数可能变（见下），通路不变而 W3 已 0 ⇒ A 被常量/垃圾替代 ⇒ 会先在 fixed 门炸掉 |
| **W8** | 每 k-step 的 A 读消息数 | 8 | 8（最可能）/ 2–32（可接受区间） | 256 B 连续块，IGC 可合法地重排成更少更宽的消息。**次数不是判据**，判据是 W7 + W4 |
| **W9** | 每 k-step 覆盖的 A 字节 | 8 行 × 32 B（跨 1 KiB 的行距） | 256 B 连续 | 若出现跨行的 8 条稀疏消息 ⇒ 与父同形，不构成"更差"，只是没利用连续性 |

### 1.2 不变量（这些数字**必须**与父相等；不等就是结构被动了）

| 不变量 | 值 | 为什么是最硬的门 |
|---|---|---|
| `dpas.8x8` | 64 | 每个 k-step 恰好 2 个 MulAdd，K 环 32 步全展开。DPAS 数量错 = 数学错 |
| 权重读 `load.ugm.d32x8` | 64（2/k-step） | B 双 bank（`base` 与 `base+16`）结构未动 |
| 末次 store `store.ugm.d32x64t` | 2 | side0/side1 各一次，直接写 `gy` |
| seed 块 `load.ugm.d16u32`（barrier 后） | 15 | seed 的 `input_value` + `weights` 读，父已有的寄存器直写路径 |
| `illegal` 结尾哨兵 | 1 | dump 完整性 |
| 两个累加器寄存器组 | 2 组（父为 `r62:f` 与 `r42:f`） | `acc0/acc1` 两条独立链；若被合成一组 ⇒ 数学被改 |

## 2. 判读流程（按合同 §8.5 的顺序：先落地，再数值，最后计时）

```
1. 取本卡 cand 臂的 ISA（F09 的 16 个 PASS 共用一个 pipeline）。
   ├─ 定位提示：baseline（dedup key 的 first-appearance 顺序）里 F09 = pipeline 17；
   │  本卡只换本组 SPV，ordinal 61 仍是首次出现位置 ⇒ pipeline 17 大概率不变；
   │  若变，按 ordinal 61 + name split16_b23_l1 重新定位，不要按文件名 hash 猜。
2. 文本判定 W1/W2/W3（store.slm / load.slm / sync.bar / signal barrier / fence.slm）
   ├─ 任一非零  → A 类：实现未落地。写"IGC/驱动仍保留 SLM 往返"，方法未证伪。
   │             下一处改动见 RESUME §5.1（先确认宏与分支，再考虑换 target-env/驱动侧）。
   └─ 全为 0    → 进 3。
3. 计数不变量 W4/W5 + §1.2 表
   ├─ dpas≠64 或权重读≠64 或 store≠2  → E 类：先定位首差 token/阶段，不要看计时。
   └─ 全部相等                        → 进 4。
4. scratch/spill（W5/W6）
   ├─ 出现 spill 或 gtwy 承载 scratch → B 类：新增副作用，先修溢出。
   └─ 干净                            → 进 5。
5. 数值门（fixed / fb2 两套 gold）
   ├─ 失败 → E 类，按 RESUME §4 的 E 分支逐条查（地址/grid/尾域/宏/gf-vs-gt）。
   └─ 通过 → 进 6。
6. 资源 + ordinary
   ├─ 整体显著优于 base（CI95 不含 0，且同批）→ C 类之外的"有净收益"，仍需注明只覆盖 16/232 PASS。
   ├─ 落地但整体不显著 → C 类（当前身份无净收益）或 D 类（INDISTINCT，CI 覆盖 0）。
   └─ 明确变慢 → B 类：最大副作用是 A 读 4× 放大（COST-LEDGER A1），
                 下一版针对它改（RESUME §5.2）。
```

## 3. 明确"不要当证据"的三件事

1. **plan 行里的 `shared=16384` 不是 SLM 分配**。`clock_runner.cpp` 只在解析与
   `shared > 49152` 断言里用它（3 处命中，无其它使用）；真正常驻的 shared 由 SPV 模块决定，
   候选的 Workgroup 字节数 = 0。若 native/resources 报表按 plan 回填 `shared_bytes`，
   那是**标签值**。→ 不要因为"报表里还是 16384"就判 A，也不要因此去改 plan（那是第二变量）。
2. **静态指令总数变化不是落地证据**（§1.3）。
3. **整体毫秒不能倒推机制**（合同 §8.5）。W1/W2/W3 为 0 才允许谈"删掉的往返"。
