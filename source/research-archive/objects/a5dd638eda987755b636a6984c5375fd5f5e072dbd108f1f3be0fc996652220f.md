## 0. What the three cards are, and what this card closed

The F3 family is the fused **body + 2× down-sample** kernel of each width. In the G3
control plan the three PASS are `f3c64_body_ds` (PASS 8), `f3c128_body_ds` (PASS 14)
and `f3c256_body_ds` (PASS 22). Each module contains **two different matrix stages**,
and they must not be confused:

| stage | what it is | operand A | operand B | where in the module |
|---|---|---|---|---|
| **WO** | the *front-end output projection* of the attention block that precedes the down-sample: `y = x·Wᵀ + residual` | `gT`, the attention context | the module's own weight pack (`pack`, binding 0) at the `p4.x` WO base | `nr_body_stage()` |
| **DS** | the *post-pool down-sample projection*: `d = mean·W_dsᵀ`, consumed from the pooled 2×2 tile | `nrf_mean`, the pooled tile | `nrf_w` (binding 8), the DS weight pack | `main()` |

The audit's 16 residual FP16 sites across the three modules split as follows, and this
card re-derived every one of them from the raw SPIR-V (not from the audit table):

| card | PASS | module | FP16 **WO** | FP16 **DS** | INT8 DS already |
|---|---|---|---|---|---|
| R09 | `f3c64_body_ds` | `C-producer.spv` | **4** | **0** | **2** (i32 K32) |
| R10 | `f3c128_body_ds` | `fused_c128_body_ds.spv` | **2** | **4** | 0 |
| R11 | `f3c256_body_ds` | `c2_S19_fused_c256_body_ds.spv` | **2** | **4** | 0 |
| | | | **8** | **8** | **2** |

So R09 is **not** "4 FP16 down-sample matrices": it is 4 FP16 **WO** matrices in front
of an **already INT8** DS. The GUIDE's R09 note ("DS 已 INT8, `nr_body_stage` 仍 4 处
FP16 MMA") is confirmed exactly, and R10/R11 are the mirror image (their DS is still
FP16 and their WO is 2 fragments instead of 4).

Delivered by this card:

* the **dispatch identity** of all three PASS against three different plans, including
  one real divergence (§2): R09's ledger pin is dispatched **only by G3**; the 232 FP16
  plan dispatches a different module for the same pass name;
* all **16 sites registered individually** (word offset / result id / function) and
  **classified WO vs post-pool DS from operand provenance**, agreeing 16/16 with
  `FULLNET-RESIDUAL-MMA-SITES.json` on word offset, result id and function;
* **parent replay byte-identical for all three modules** with the frozen toolchain,
  including the NoContraction-transfer step that the deployed R09/R11 SPVs actually
  went through;
* the **R09 arm implemented**: WO → INT8 (K32, i32 accumulator), the already-INT8 DS
  untouched, parent replay byte-exact, candidate `result=0`, word-level SPV diff fully
  attributed (`unexplained: []`), 2 new packs, a derived plan, and a segment-local
  arithmetic reference that answers the pool-value question;
* the **residual inventory re-enumerated on the new module type** (§7): R09 6 FP16 → 0;
  R10/R11 unchanged and named;
* named, quantified gaps for R10 and R11 (§9).

### 1.1 The per-family constants a WO/DS implementation must respect

Read off the G3 PASS lines and push words (`evidence/MODULE-IDENTITY.json`), because the
three families are **not** interchangeable:

| | R09 `f3c64_body_ds` | R10 `f3c128_body_ds` | R11 `f3c256_body_ds` |
|---|---|---|---|
| pack (b0) | `swin_8_weights` 107024 B | `swin_14_weights` 361232 B | `swin_22_weights` 1312032 B |
| WO base `p4.x` | 0 | 0 | 0 |
| K (context channels) | 64 | 128 | 256 |
| residual scale base `p4.z` | 12288 | 32768 | 98304 |
| WO FP16 tile formula | `(n/16)*1024 + (k/16)*256` | `(n/16)*2048 + (k/16)*256` | `n*256 + k` |
| DS weight buffer (b8) | `weights-C.i8.bin` **int8** 106496 B | `ioport_14_ioport_pack` **f16** 427008 B | `ioport_22_ioport_pack` **f16** 1574400 B |
| DS weight base `p6.y` | 53632 (with `p6.z` obase 0) | 180736 | 656128 |
| DS N (output channels) | **128** | **256** | **512** |
| pooled K | 64 | 128 | 256 |
| grid / shared | 42×25 / 9216 B | 22×13 / 10240 B | 11×7 / **45056 B** |

Two consequences that decide R10/R11's cost before any code is written:

* the DS packs of R10/R11 are **FP16** today. An INT8 K32 DS needs a **new** pack of
  256×128 = 32768 B (R10) and 512×256 = 131072 B (R11), plus per-output-channel scales;
  no existing file can be reused;
* R11's declared shared memory is already **45056 B of the 49152 B ceiling**. An int8
  K32 context tile for 64 tokens × 256 channels needs 16384 B on top of that. The way
  out is visible in the module itself: `shT[16384]` (32768 B, half) exists **only** to
  feed the WO A operand and the debug echo, so re-declaring it as the int8 staging tile
  *frees* 16 KiB instead of consuming it. That is a design note, not an implementation.

## 3. Closure item 2 — the implementation (R09, `f3c64_body_ds`)

### 3.1 The change, in full

`source/candidate/r09_f3c64_body_ds_wo_i8.comp` (parent
`source/parent/r09/fused_body_int8_ds.comp`, verbatim copy, sha `c4eddf97…05dc3`):

1. `+2` storage buffers: `gWo8` (int8, 4096 B) at binding **12**, `gWosc` (f32, 64
   entries) at binding **13**. No `#extension` is added — the parent already declares
   int8 arithmetic and 8-bit storage for its DS path;
2. `+3` shared declarations: `sT8[4096]` int8 (the staged context tile), `shMax[256]`
   f32, `shScale[2]` f32 → declared shared **9216 → 14344 B**;
3. the four FP16 `coopMatMulAdd` sites become four **INT8** sites: A `coopmat<int8,8,32,A>`,
   B `coopmat<int8,32,16,B>`, C `coopmat<int,8,16,Acc>`; the K loop drops from four K16
   steps to **two K32 steps**;
4. the FP16 WO tile stream (`pack[wo + (n/16)*1024 + ki*256]`, stride 16, column-major)
   is replaced by the INT8 stream (`gWo8[(n/16)*1024 + ki*512]`, stride 32,
   column-major), plus a per-output-channel f32 scale table;
5. an activation quantiser before the loop: pass 1 computes this workgroup's amax over
   its own 64×64 context tile (from the same `gT` half values the FP16 arm multiplies),
   a serial reduction plus two publication slots, pass 2 writes one code point per
   element into `sT8` in the measured I8A K32 layout; three workgroup barriers;
6. the epilogue per fragment: widen the **unchanged** seed, convert the int32
   accumulator to f32, `fsc = sWo[n] * sC`, `precise prod = acc * fsc`,
   `precise sum = prod + seed`, one narrow, then the **three unchanged stores**
   (debug echo, `imgout` with the original `c64_img_half_index` + OOB rule + stride 16,
   `nrf_pair` with the original `(sg*4+k)*128` stride-16 row-major layout).

identical M8COL8 address), and the whole DS / `emit_qx` / `main` body are the parent's
**text unchanged** — `pooling_tree_text_identical: true`,

## 9. Closure item 6 — unresolved blockers, named

1. **R10 `f3c128_body_ds` — enumerated, not implemented (6 sites: 2 WO + 4 DS).**
   The path the GUIDE names (output projection INT8 → keep the half pooling order →
   write INT8 where `nrf_mean` is formed → K32 DS → final output) needs, in this module's
   own terms: (a) an INT8 WO with `wo = 0`, K = 128, FP16 tile
   `(n/16)*2048 + (k/16)*256` → INT8 pack of 16384 B + 128 scales; (b) an INT8 writer at
   `nrf_mean`, which today is `shared float16_t nrf_mean[2048]` and receives the pooled
   half value **unquantised** — the pooled-after scale is the named missing piece (the
   C64 arm's `entry_sc[4]` has no C128 counterpart in this module's bindings); (c) a
   K32 DS pack of 256×128 = 32768 B with per-channel scales, replacing the FP16
   `ioport_14_ioport_pack` region at `whalf = 180736`; (d) the reader audit the GUIDE
   asks for: `nrf_stage[1024]` is written by each of the four fragments and read
   immediately by `nrf_write_group()` into `nrf_o` (binding 9, `block14_out`), so it
   cannot be deleted before the DS output is re-plumbed. Shared headroom is fine
   (10240 + ~8 KiB staging + ~1 KiB reduction ≈ 19.5 KiB of 49152).
2. **R11 `f3c256_body_ds` — enumerated, not implemented (6 sites: 2 WO + 4 DS).**
   Same path with K = 256, N = 512, `wo = 0`, `whalf = 656128`, DS pack 512×256 =
   131072 B, layout0 and the 32-channel grouping and the split16 entry format to be
   preserved. **The arithmetic obstacle is real and is the same one R07 recorded**: the
   module already declares `shT[16384]` = 32768 B and its whole shared budget is
   **45056 B of the 49152 B ceiling**, so a 64×256 int8 context tile (16384 B) does not
   fit as an *addition*. The visible way out — not decided, not implemented here — is to
   re-declare `shT` itself as the int8 staging tile, since `shT` exists only for the WO
   A operand (and the debug echo); that *frees* 16 KiB. The GUIDE's warning stands:
   the module's `qX` production is **not** evidence that either matrix stage is INT8 —
   this card's enumeration shows both are FP16.
3. **The 232 FP16 arm's `f3c64_body_ds` is a different module and is not closed.**
   `f3-c64-fused-half-patch-v1/fused_c64_body_ds.spv` (33048 B, `ccb6e0b9…`) has
   **6** FP16 sites — 4 WO (word 5106/5127/5228/5249) **and 2 FP16 DS**
   (word 2524/2663), shared 12288. Closing the G3 arm says nothing about this one; it
   needs a WO+DS card of its own, and the missing piece is exactly the DS INT8 path that
   the G3 module already has (its `weights-C.i8.bin` + M8COL8 `nrf_mean` writer are the
   template).
4. **No block-8 capture, so the deployed arm's numeric reference is unmeasured.**
   The oracle's frame is block 6. The block-8 numeric reference needs the
   `r09-cand-mean-capture` diagnostic job (§ `run/r09-r11-f3ds/jobs.json`), which uses
   `--dump-intermediates` and therefore changes residency — it can produce the capture
   but cannot itself be a production gate.
5. **No GPU slot.** `NATIVE`, `GATE`, `ORDINARY`, `QUALITY` are all un-run. The 12 job
   definitions (6 gate + 6 ordinary) are `LISTED_NOT_RUN`; the only equality this card
   asserts is byte equality between two runs of the *same* candidate plan. No tolerance
   between candidate and parent is invented here.
6. **Micro-residuals, reported not hidden.** (a) The NoContraction count rises 10 → 24;
   §4 P5 gives the role-level accounting and shows the parent's 6 float-arithmetic
   decorations are all preserved while the 4 stray ones are a transfer artefact that the
   probe proves inert. (b) The candidate's `OpLoad`/`OpStore` counts rise by 63/44 —
   glslang scalarises the cooperative-matrix epilogue into per-element function locals;
   reported as counts, not derived, because the magnitude follows the compiler's
   materialisation, not the source. (c) `OpTypeCooperativeMatrixKHR` falls by 2 with
   **no new cooperative-matrix type added**, which is the cleanest single line of
   evidence that this edit reuses the measured I8B/I8A/I8C combination rather than
   inventing a new fragment shape.
