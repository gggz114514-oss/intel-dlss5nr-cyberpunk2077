本卡禁止 GPU：以下全部是**预测与判据**，不是"已证明落到 native"。GPU 采集由主代理串行执行（GPU-REQUEST.json）。

  父 ISA 统计（来自 `f08-register-chain-20261027/NATIVE-COST.json`）：Instruction Count 4669、Basic Block 219、Loop 1、DPAS 站点 132、send 站点 534、mov 站点 1035、scratch 0、Workgroup Memory 2048。

## 1. 落地判据（最硬的一条）

候选只改了 4 个索引常量。若 native 真的按新映射生成，ISA 前段的整数常量必须是：

| 语义 | 父（应消失） | 候选（应出现） |
|---|---|---|
| token = WGID.x × ? | ×16 | **×32** |
| sg 选择 tile（`sg % ?`） | `and 1` | **`and 3`** |
| tile 在 WG 内的行偏移 | `sg*8` | `sg*8`（不变） |
| g = WGID.y × ? | ×4 | **×2** |
| sg 选择 group（`sg / ?`） | `shr 1` | **`shr 2`** |

判据：
- **落地** = 上述 5 个常量在 l0 kernel 里全部呈现候选值，且 `and 1 / shr 1 / ×16 / ×4` 只可能残留在与 token/group 无关的地址计算里（例如 `dbg` 调试分支的 `e/16`、`e%16`，那段是 dead code，允许保留）。
- **未落地（A 类）** = 仍看到 `and 1`/`shr 1`/`×16`/`×4` 驱动 token/group；或派发记录仍是 grid (66,2,1)（说明 plan 未生效）。
- **编译器自行改写（需记账）** = 出现新的强度削减/重新结合（例如把 ×32 变成 shl 5、把 `(x*32+…)/16` 变成 `x*2+…`）。这属于合法响应，但要逐条记录，不能默认当作"预期内"。

## 3. 派发面判据

- grid 必须是 **(33, 4, 1)**，WG 数 132（与父 132 相同）。若 capture 头里仍显示 66×2 或 WG 数变化 → 说明 plan 行没被替换或改错行。
- 每 PASS 的 subgroup 数应为 1056；有效 lane 全满（无尾块，因此不应出现"多余 WG / 半空 WG"）。

## 4. 不可观察项（必须写清，不许用 native 冒充）

- **cache 命中/权重驻留**：本工具集没有 cache 计数器。gtpin mode0 给的是 ISA/基本块，"全密度屏障计时"有 70–100× 放大反例，zprof 只给 GpuTime。因此"每 WG 权重集 512 KiB→256 KiB 是否真的降低了缺失"**无法由 native 证明**，只能由两臂整体计时判断。
- **WG→core 分配**：无法从 ISA 观察；"8 个 SG 同 core"只由每 WG 2048 B workgroup memory 的分配语义推出（假设，不是测量）。
- **并发 WG 窗口**：未知；无法回答"33 个 WG 的 y 切片是否把并发足迹压在 2 个 slab 内"。

## 5. 若看不到预期的处置

1. 先分诊为 **A（实现未落地）**，检查 plan 的 16 行是否都换成了本卡 `candidate.spv` 且 grid 为 (33,4,1)（`BUILD.json:plan` 已给逐行 old→new，可直接比对）。
2. 若常量正确但 structure 变了（指令数/块数/scratch 变化）→ 记为**编译器响应**，按 B 类列增量账，再决定是否要第二版（例如用 §6 的 t16/tr 写法把整除/取余在源码里消掉）。
3. 若常量正确、结构不变、整体计时 CI 跨 0 → **D（INDISTINCT）**，按合同同族成包，不得挑显著样本；下一处具名改动见 RESUME。

## 6. 已知的第二写法（本卡未采用，留作 A 类问题的兜底）

如果 IGC 没有把 `token/16`、`token%16` 折叠成 `2u+((sg>>1)&1)`、`(sg&1)*8` 而多出整数指令，可以把源码改写成显式 tile 形式：

```
uint t16 = gl_WorkGroupID.x*2u + (sg>>1);   // 16-token 块号
uint tr  = (sg&1u)*8u;                      // 块内行偏移
uint token = t16*16u + tr;
```

`tiled(token,0,512) = t16*8192`、`tiled(token,c,512) = (t16*(512/16)+c/16)*256 + tr*16 + c%16`，与现写法逐元素等价，可省掉对 `token` 的除法/取余。本卡**没有**这样做，因为当前 SPIR-V 证据显示指令数与父完全相同（1375/1375，6 处立即数），无需为 0 收益引入额外源码改动；若 native 出现整数指令增加，这是第一处要改的代码。
