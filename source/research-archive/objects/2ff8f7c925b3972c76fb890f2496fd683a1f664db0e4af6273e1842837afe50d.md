# Pure diagnosis: measurement controls before another optimization

No shader or production plan is modified. Baseline is f20-score-owner; the existing exact f20-norm-compact-pairs is an immutable diagnostic comparison, not a new optimization or a retiming campaign for adoption.

## Questions this batch can discriminate

1. Does a private runner with selected timing disabled preserve output and whole-network behavior relative to the existing runner?
2. Does adding only two F20 boundary timestamps measurably change whole-network time under this protocol?
3. With identical boundary placement, does compact-pairs change the F20 interval consistently, and how much of whole-network variability is outside that interval?

It cannot measure internal ALU/send/stall time, identify a unique GPU clock/temperature cause, or turn three inconclusive blocks into proof of equivalence.

## Runner and controls

Private source copies the existing runner. Only optional `--interval-pass230` timestamp writes,query count/readback,indexed reporting and argument validation change. Existing plan parsing,pooling,buffer initialization,feedback copies,dispatch order,barriers and shaders are untouched. Off mode records the same GPU commands as the original runner. Source diff is retained.

Selected mode writes BOTTOM_OF_PIPE immediately before pass230's first-use-clear/bind/dispatch sequence and after its existing post-dispatch barrier. This is a bounded dispatch interval, including clear/barrier effects. It is not a pure XMX interval. Whole-network timestamps remain, giving four timestamps/frame instead of two. It avoids the old235-timestamp full-network per-pass mode and all shader/GTPin instrumentation.

Arms O=old runner baseline/off, N=new runner baseline/off, S=new runner baseline/selected, C=new runner compact-pairs/selected. Three predetermined orders: O,N,S,C; C,S,N,O; N,O,C,S. Each job warm1/reps30/feedback. All360 samples retained. Controls are O−N and N−S; candidate comparison S−C. Confidence intervals use three block differences, not360 independent trials. A CI crossing zero is not an equivalence test or proof of negligible perturbation. No optimized candidate is adopted from this profiled comparison.

## Remaining dependency, without claiming exposed wait

The first score MMA needs BOTH normalized Q and normalized K. Q retention removes Q memory transport, but does not remove raw Q/K norm inputs, the norm coefficient dependency, or the normalized-K workgroup publication. K is consumed across subgroups. Consequently shortening Q's path alone cannot advance score before the other K path is ready. This is a source-level dependency constraint, not proof that K is late at runtime.
