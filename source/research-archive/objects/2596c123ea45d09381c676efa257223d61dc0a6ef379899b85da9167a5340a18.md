## 2. 激活量化域：为什么是这些尺度（本卡最关键的论证）

`ioport_block70_1` 是**图像传输前沿**：它的 `imgin` 是本帧的上游图像，`imgout` 是图像型 half 输出，
中间的 `Q/K/V/P/Ctx` 全部是核内动态量。**没有任何标定数据可以支撑一个 per-tensor 常数**，
所以本卡**不引入任何标定常数**：每个动态操作数的 scale 都是**该次 MMA 真正消费的那个 tile 的
amax/127**，在核内用 subgroup/workgroup 归约算出。这样定义有三条硬理由：

1. **域正确**：int8 码的域恰好等于该操作数的张量域，`|code| ≤ 127` 由构造保证，
   不存在"用一个别处的尺度去压当前张量"的越界/饱和风险。
2. **不需要标定**：没有捕获、没有激活统计也能上；因此不会把"SINGLE_FRAME_DIAGNOSTIC"伪装成标定。
3. **一致性条件可证明**（这是 attention 段真正的坑）：

| 操作数 | 尺度粒度 | 一致性要求与满足方式 |
|---|---|---|
| X（expand A） | 每 8-token 组，组内 8×32 | expand 的输出列只乘 `sWe[n]·sX`；`sX` 在该组 32 个 K 上恒定，符合"dequant 因子必须在累加 K 上恒定" |
| E（contract A） | 每 8-token 组，**整个 8×128** | K=128 走 4 个 K32 块，**同一 scale**（不是每块一个），否则就得分块反量化，与父的单次窄化不一致 |
| Y（QKV A） | 每 8-token 组，8×32 | 3 个不同 subgroup 读同一组，故码在**组**上构建一次（workgroup barrier 发布），不是每 subgroup 各建一份 |
| Q（score A） | 每 8-token 组，8×32 | 每个 query 行一组因子，**行内**恒定；softmax 是逐行的，跨行不同 scale 无害 |
| K（score B） | **整个工作组 tile 一个标量**（64 key × 32 dim） | 必需：stage 7 把 64 个 key 的 `exp()` 相加，若 2 个 key-tile 用不同 scale，分母就不可比。故 K 用**一个** workgroup 标量 |
| P（PV A） | 每 8-token 组，8×64 | K=64 走 2 个 K32 块但**同一 scale**（同理，不许分块反量化） |
| V（PV B） | **整个 tile 一个标量**（64 key × 32 ch） | V 是 QKV 的 half 输出，PV 里再量化一次；输出列只需一个标量因子 |
| Ctx（投影 A） | 每 8-token 组，8×32 | R21 原样（每 subgroup 自己的 8×32） |

权重侧是**静态、对称、逐输出通道**：`s[n] = amax_k|W[k,n]|/127`，`q = clamp(roundEven(W/s), ±127)`。
反量化折进 epilogue：`out = float(acc_int32) · (sW[n] · sA_tile)`（一次乘一个因子，再与父的 FP32 seed 相加），
**每个 stage 仍只窄化一次**，与父的"单次窄化"合同相同。

**没有被量化域改动的东西**（刻意保留）：stage 5/5b 的 half 归一化与 `scalar0`、
stage 6 之后的 half `nr_exp_h`、stage 7 的 half 64-key 行归约与 reciprocal、
两个 FP32 seed（`H(X·rs)`、`H(Y·ars)`）、所有 half shared tile 与 half 输出、
`dbg` 全部转储区域与地址、32 word PUSH、grid、local size。

**没有被保留的 FP16 矩阵**：`mma_operand_audit.py` 对候选模块的 12 条全部判 `i8/i8/i32`
（读 A/B/C 定义指令的分量类型与 signedness，**不从结果类型推断**）；也没有任何标量 float 点积顶替矩阵乘
（每条乘加都是 `OpCooperativeMatrixMulAddKHR`）。

## 6. 连接成本（次数推导，不写毫秒）

**新增**（每工作组 8 subgroup）：
- 码点：X 4×256、E 4×(every lane 8 codes × 4 chunks)、Y 256、Q 2×256、K 2048、P 2×256、V 2048、
  Ctx 256 ⇒ 每组每 stage 约 256–2048 次 `mul + roundEven + clamp + f32→i8`；全部**每元素一次**，
  没有重复量化（同一 tile 只量化一次并立即被消费）。
- 归约：subgroup amax 9 次（每次 2 个 subgroup barrier 对）、workgroup amax 2 次（K/V，各 2 个
  `barrier()` + lane0 的 256 次比较）。
- 共享声明：29184 → **42568 B**（+8192 `shK8`/`shV8` 共 4096、`shC8` 已在 R21 段计入、
  +`shGrp[8]`/`shKV[2]` 40 B；逐变量见 `evidence/SPV-DIFF.json.shared_detail`）。
  **声明 ≠ native 分配。**
- barrier 增量（静态）：`OpControlBarrier` +24、`OpMemoryBarrier` +19（`SPV-DIFF.json` 直方图）。
- descriptor：b5/b6 由 4 B 占位改绑新 BUFFER（不新增 binding，nbind 仍 8）。
- `OpFConvert` +16（`MAT_H`/`I8F` 的窄化/展开）、`OpConvertSToF` +12、`OpConvertFToS` +1、
  `OpExtInst` +25（abs/max/roundEven/clamp）。

**删除**：每段每 tile 的 K16 循环脚手架（父 expand 的 `k0/16` 除法与 push 重载等）；
每工作组 MMA 指令 64 → 32。**未**度量 DRAM 字节、LDS bank、occupancy。

**owner/活区**：`shC8` 在 6 个 stage 间按寿命复用（X→E→Y→Q→P→Ctx，互不重叠，每段之间都有
subgroup 或 workgroup barrier 退役上一次读）；`shK8`/`shV8` 是 workgroup 级只读发布；
`shArena` 的 Q/K/V/Ctx 语义与地址完全不动。

  （`sX/invX`、`sE/invE` 来自该 PASS 自己的 656 B scale 表 `fsc[0..4)` 与 `fsc[4..164)`）；
  **剩余 65 条 = QKV 24 + score 16 + PV 16 + output 8 + lift 1**。
- 剩余 64 条（QKV/QK/PV/output）与 block70 的对应段**同形**，本卡已证明该形状可闭合；
  但 F1 的 `Y`（contract 输出，含 residual seed）**没有 scale 槽**：656 B 表已被
  `sX/invX/sE/invE + 128 expand + 32 contract` 用满，**必须新增第三个 scale BUFFER**
  （F1 现有 bind 已到 b9，新增 b10 需要新 BUFFER + POLICY）——这是接线工作，本卡未做。
- `lift`（`nrf_lift`，1 条，K=16；父 word 45131 / result 7567，R01 候选 word 44790）：K=16 必须补零到 K=32，
  且它的输出**同时**喂 int8 码点与 FP16 残差 seed（R01 的 F1-B1…B3）。
- **R01 的首差链**（`ATTENTION-CHAIN-CPU-PROOF.json` + `candidates/r01-f1/`）给的是探针点：
  首差 `E[23][0]`、根位置 `X[23][19]`、5 个量化边界码（±1）、
  **修正 5 个码后 E/Y 0/8192、0/2048 逐位闭合**。这条链正好说明：
  F1 的 expand/contract INT8 在"码正确"时是逐位正确的，而**门打不开的原因是量化器输入
  与 dump 出的 half 差 ≤1 half ULP**（`c32_f1_i8.comp` 在窄化点之后就量化，dump 存的是窄化前）。
  → 任何新的 F1 INT8 段**必须先按 R01 的 M1 把量化器真正吃到的码 dump 出来**，
  否则新段同样无法零容差闭合。本卡按此判断**不动 F1**，避免制造第二个"原因不明"的段。

**7.1.2 `f2c32_block66_fused`（65 = 1 projection + 24 QKV + 16 QK + 16 PV + 8 output）**

- FFN（expand 16 + contract 4）**已经是 INT8**（父自己的 `nr_i8_*`）。
- 余下 64 条在 `nr_body_stage()`（与 F1 共享的 `register_handoff.glsl`/`c32_i8_common.glsl` 家族），
  与 block70 的 4 段同构但用 **register handoff**（`yb0/yb1`、`qb0/qb1`、`pb`、`tb0/tb1`）而不是 shared tile，
  所以本卡在 block70 上验证的 shC8 方案**不能直接搬**：需要为 handoff 寄存器版本设计
  A 侧码的发布方式（subgroup 内可以直接用 shared 暂存 8×32，但 `tb0/tb1` 的 Ctx 已经是寄存器，
  要落地到 I8A 需要一次 shared 往返）。
- projection（1 条）：`x65` 是**跨 tile gather**，且 blend 在投影**之后**加 `skip·skip_gain`，
  所以 blend 输出才是唯一可以建立 INT8 身份的点（R20 的具名阻塞）。
- 缺 `Y` 的 `invY` 标定（block66 不在 R02 的 6 个块里）——但本卡的方案不需要标定
  （自标定 amax），所以这一条**不再是阻塞**；真正的阻塞是 handoff 形态 + projection 的 qX 身份。

### 7.2 其它具名缺口

1. **无 GPU**：固定门/fb2/30 帧、ordinary、画质全部未跑（无时段）。`数值通过`/`质量通过` 均未取得。
2. **native**：`shaderInt8` + `StorageBuffer8BitAccess` 在**本 PASS 的 pipeline** 上是否启用只能在
   pipeline 创建时看到（7 个已部署 PASS 用过这两个特性，但那是别的 pipeline）。
   tile 布局（`k*32+m` / `n*32+k`、stride 32、LCOL）在 host 侧由 pack 往返 + R21 交叉校验确认，
   **设备侧映射只能由门证明**。
3. **block70 的 `Ctx`/`O` dump 从未捕获**（本卡不需要它，因为用了完整 PASS 模型）；
   若下一卡要做"逐坐标码级首差"，需要 `plan-b70-i8-diag.txt`（本卡已生成，`p0.z=1` 只对 ordinal 285）
   跑一次。
4. **scale 资格**：权重 scale 是静态量化（本卡生成器可复跑，rel_L2 ≤ 0.74 %）；
   激活 scale 是**核内自标定**，不依赖任何单帧诊断表 —— 这是本卡相对旧 C 卡的一个明确改进，
   但仍**不是**"标定通过"，只是"不需要标定"。
5. **I8A tile 的 4× 共享浪费**（1024 B 存 256 个码）是继承布局（R21 已记录），本卡沿用未改；
   一个 stride-8 变体是 stage-2 候选，需要自己的 native 证明。
