AMD 参考：`src/amd-reference`（源码快照，无 Git 身份，按快照对待；本地与

（f20-score-owner / kv-tile / f01-residual / f2-direct candidate.comp）。

既有结论（f20-score-owner/AMD-LAYOUT-COMPARISON.md）继续成立：AMD feature×token +

## C01（F20 K 提前完成与 Q 就地消费）
- AMD fswin_body.glsl 约 1864-1875 行：`S^T = K . Q^T`，累加器行是 **key** token，
  注释明确 "the softmax denominator a within-lane sum: one shuffle, no memory"。
  AMD 的 QKV 累加器方向使 K 无需跨 lane 发布，K 的"完成"天然在 lane 内。
- NR_HWAVES（token 拆 wave）时 AMD 在 score 前有 `#if !NR_HWAVES barrier()` 的反面：
  HWAVES 才需要同步（fswin_body.glsl 1860 行附近）；其 K 发布经 lds_k（1820 行
  NR_STORE_ACC_COL）。
- Intel F20：Q/K/V 同一 j 循环产出（stage 4），K norm（threads 64-127）需要全部 SG 的
  K 落地 → post-QKV 屏障不可避免。依赖图证明：K-early 重排不减少任何一条边，V/Q 生产
  与 K norm 的"重叠"只能靠 IGC 在 SG 2-3 指令流内调度（无原生关系证据），且 handoff0/1
  （contract 输出）寿命在 K,V,Q 任何顺序下都覆盖整个 stage 4。**结论：AMD 的 K-lane 内
  完成来自其片段方向，Intel 无对应机制；重排被依赖图阻断（详见 STATUS C01）。**

## C02（F20 生产者内寄存器 norm）
- AMD fswin_body.glsl 约 1624-1660 行："A column of the accumulator is one token, so the
  L2 norm is a within-lane sum over the head's NR_DF fragments plus one shuffle: no LDS,
  no barrier."——AMD norm=lane 内和 + 1 次 shuffleXor(16)，无 LDS 无屏障。
- NR_NORM_F32=1 变体（1670-1690 行）：f32 平方/归约 + "Four independent partial sums"
  依赖链管理；注释明确 f32 和与 shipping f16 归约 **不是同一函数**（溢出行为不同），
  不得移植——与本线"保持原 half 树"约束一致。
- NR_NORM_LATE_SHUFFLE 注释（1695-1710 行）：8 行先寄存器归约再 1 次跨 lane 交换
  "is not the same summation order - check the gold before believing it is free"——AMD 自己
  也警告改变归约次序需逐位验证。
- Intel：token 行横跨 lane（row=2c+(lane>>4)），不可能 lane 内归约。本轮 pair 变体
  （2 lane/行、XOR1 交换 16 个平方）把 AMD "lane 内 + 1 shuffle" 逼近为 "2 lane + 2 次交换"
  且保序；c02b 变体完全复用 Intel 标量树。两者均死于同一收缩/残余问题（见 RESULTS C02）。
- **可迁移机制：归约就地化、跨 lane 交换次数最小化、依赖链拆分；不可迁移：lane 内
  归约本身（方向性差异）。**

## C03（body/F01/F2 norm→scale→矩阵输入整链）
- AMD 1705-1710 行：`packFloat2x16, not packHalf2x16(vec2(...))`——"the value is already an
  f16vec2 and the shuffle only needs its 32 bits in another lane, not a widen and a narrow"
  ——系数传输避免窄化/加宽，与本线 full_norm 的 packFloat2x16 用法一致。
- AMD QK_SCALE_FAST（fswin_t.comp 1067-1086 行）展示系数合并的舍入陷阱：
  `nq * hscale` 折叠成单常数会"drop a rounding step"——本线保持 Q 的
  norm→half→headscale→half 次序，未做代数合并，与 AMD 注释一致。
- Intel body/F01/F2：n 在寄存器内直接服务原片段缩放（q00[c]*n.x），无重复窄化/打包/
  交换/解包——映射检查未发现可删交接（详见 STATUS C03）。

## C04（P→den→归一化→PV 行级流水）
- AMD fswin_body.glsl 1875-1885 行：NR_HWAVES "One query fragment at a time"——
  "the logits, the exponentials and the denominator of one query block are born and die
  inside it"，仅 pb[NR_MF][NR_JF] 跨迭代——**AMD 的行级流水存在于 query-fragment 粒度，
  且其累加器行=key 使 den 是 lane 内和（1 shuffle）**。
- Intel：P 片段（NRH_CH 8×16）一个片段覆盖全部 8 个 token 行（行=2c+(lane>>4)），
  den 必须等最后一个 key 块到达；且源码已按块增量累加 den（4 次 XOR8 后再做树）。
  片段粒度使"一组行先走"必须重新聚集成完整 tile，聚集成本未证可行（详见 STATUS C04）。

## C05（QK/PV 的 K/V 消费者布局与复用）
- AMD NR_K_REGS=1（fswin_body.glsl 1818-1824 行）："The ColumnMajor store was the
  transpose; the component copy is the same transpose with no memory behind it"——单 wave
  全窗时 K 留寄存器；NR_V_REGS 同理（"One wave owns the window: V never leaves registers"）。
  AMD 自己的 NR_K_REGS 检查（fswin_t.comp 704-705 行）：NR_MF<NR_JF 即多 wave 时
  K_REGS 编译即报错——**AMD 也只在单 wave 拥有全窗时免 LDS**。
- Intel body（4 SG）/F20（8 SG）：K/V 消费者跨 SG，必须共享。布局已是生产者直写消费者
  形态：body K 以 LCOL 存储（B-ready），V LROW；F20 stage-4 LROW 存 K、score LCOL 读
  （K^T）。消费者普查：每个 K/V tile 每 SG 恰好读一次（body score 8 tile×1、PV 8 tile×1；
  F20 score 8+Q2、PV 8），无重复小载入可删（详见 STATUS C05）。

## C06（FFN expand→激活→contract 并行与生命周期）
- AMD NR_STREAM_C32（fswin_body.glsl 825-850 行）："Consume each hidden fragment
  immediately. Keep the contraction's FP32 accumulators instead of all eight quantized
  hidden fragments. Every contraction still visits hidden fragments in ascending order."
  ——流式消费+保留 contract 累加器，与 body/F01/F2 现状同构。
- ffwd3_t.comp 有流式 Q0→Q2 实现，但 pipelines 未为 C32 启用 NR_STREAM_MLP（既有
  AMD-LAYOUT-COMPARISON 已核）。
- F20 的 FFN 为分阶段形式；此前 f20-peer8-dualweight、f20-ffn-fouracc-rebase 已按该方向
  施工：fouracc ordinary mean −0.104765 ms，95% CI [−0.274851,+0.065322]，INDISTINCT
  （f20-ffn-fouracc-rebase/ORDINARY-REVIEW.json）。**不重复同身份施工。**

## C07（F01/F2 残差与入口/出口长寿命数据）
- AMD NR_NATIVE_RESIDUAL / stream_contract（fswin_body.glsl 831-849 行）：残差 seed
  `x*nr_residual_scale(off)` 直接并入 contract 累加器——AMD 方向使其无长寿命片段。
- Intel F01 的 shResidual：F01-SPILL-PROOF.md 实证（f01-direct native 695dadb2cdd25729，
  溢出载荷 y11[1..3]，448B/SG scratch；f01-residual native 8d2c4e54aecd5a55 scratch=0，
  代价 1024B store+1024B load/WG）。F2 无 shResidual 且零 scratch，证明同核可以寄存器
  常驻——差异在入口机械（nrf_prepare_B 的 values[16] f32 暂存等）造成的分配器峰值。
  本轮未施工（见 STATUS C07 的寿命账）。

## C08（SLM 发布与退休屏障合并）
- AMD：`#if !NR_HWAVES barrier()`（1860 行）——单 wave 时 K/V 发布屏障整体不存在；
  NR_HEADS>1 时 head 间一道屏障（2207 行附近 "The next head reuses lds_k and lds_v"）。
- Intel F20 正常路径 13 道屏障逐边核对：post-QKV（WAR：stage-3 contract 读 A 区
  [0,8192) 与 stage-4 QKV 写 [0,6144) 重叠，必须保留）、post-norm→scale（可合并，C02
  尝试的一部分）、post-scale→score（c02c 实测删除后帧不变——在合并相位语境下冗余），
  其余为 debug 分支内。**逐边证明见 STATUS C08 表。**

## C09（八子组并行与 owner 全链安排）
- AMD plain C32：NR_FWAVES=1 单 wave 全窗（注释 561-580 行明确其代价与 wave 数关系；
  NR_FWAVES=2 时每 wave 拥有 32/64 token，NR_K_REGS 语义随之受限）。
- Intel F20 8 SG：本轮普查各阶段有效并行——stage 0 fold 256 线程全参与；stage 1/3/4/6/8/9
  全 SG；**stage 5 norm 仅 threads 0-127（SG 0-3），SG 4-7 空转**——这是全链唯一低于
  满并行的阶段，C02 候选正是要把该阶段摊到 8 SG。score-owner 基线已完成 score/den/PV
  的完整 query owner 统一（PROOF.json 4096 元素逐项枚举）。
