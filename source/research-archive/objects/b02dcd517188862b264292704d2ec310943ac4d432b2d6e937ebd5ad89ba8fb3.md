## 0. 为什么是做这一条（不重复已测搬家）

| 既有实现 | 机制 | 结果 | 本卡 |
|---|---|---|---|
| `f04-middle-consumer-tile-20261027` | mLocal 改 COL8 tile（发布 32 条 + 读 128 条 SLM → 4 + 16） | INDISTINCT，−0.0633 ms | 不重复 |
| `f04-own-middle-feed-20261027` | 自有 2 个 K 片段寄存器直交 | INDISTINCT，−0.0389 ms | 不重复 |
| `f04-family-package-20261027` + ablation | 权重精确重排 + 33 份独立权重缓冲 | SLOWER_95；退化归因到**分配**本身（0.2486 ms） | 不重复 |
| `n03-f04-middle`（C128 同变换） | hidden 块 32→64，A 读 4×→2× | **−620 指令、send −32、mov −337，整体 −0.023 ms INDISTINCT** | 本卡 = 该变换在 C256 上 |

C128 的结论是：**native 大幅落地但整体不可检出**。C256 的收益面是它的 2 倍（A 读 128→64 条/SG），
所以本卡的价值不在“单宽度可测”，而在于“同族成包”（C128+C256+C64）时能凑出可检出的量。

## 1. 映射：每个 (lane, component) 代表哪个 (token, channel)，消费者要什么

### 1.1 几何（父与候选完全相同）
- WG = 256 线程 = 8 个 simd32 子组（`local_size_x=256`）；`shared float16_t mLocal[4096]` = 8 KiB。
- 窗口 token `t`：`q=t>>4, s=t&15`；`tx = 2wx+shift_x+(q&1)`，`ty = 2wy+shift_y+(q>>1)`
  （`nb05_swin_c256_common.glsl:37-46`）。`t0 = 16·gl_WorkGroupID.z` → **一个 WG 恰好覆盖一个像素 q 的 16 个 slot**
  （s=0..15），即 16 个 token。
- `g = sg % 8` → M 通道 `32g..32g+31`（2 个 16 宽 tile `cg0=32g, cg1=cg0+16`）；
  `pair = sg / 8 = 0`（只有 8 个 SG）→ **8 个 SG 覆盖全部 256 个 M 通道，token 集合相同**。
- `MAT_A` 8×16 half（8 token × 16 K），`MAT_B` 16×16 half，`MAT_C` 8×16 f32，`MAT_H` 8×16 half。
- 每 SG 的 A 行组：`slA = 0`（token t0+0..7，s=0..7）、`slB = 8`（token t0+8..15，s=8..15）。

### 1.2 三段 matmul 的元素域（父与候选相同，本卡不动）
| 段 | A | B | 输出 | K |
|---|---|---|---|---|
| expand | imgin[8 token][16 in_ch]，ki=0..15 → 256 in_ch | `pack` 的 W_expand tile：`we + ((128g+h)/16)·4096 + ki·256` | 8 token × 16 hidden，每 SG 8 个 hidden tile（其 g 专属的 128 hidden 块） | 256 |
| middle | 激活后的 hidden CH（`c64_ch_to_a`） | `wm + cg·128 + h0 + 16t`，stride 128 | 8 token × 16 M 通道 | 128 hidden |
| contract | `mLocal` 的 [8 token][16 M 通道] | `wc + (cg/16)·4096 + ki·256` | Y | 256 M 通道 |

### 1.3 mLocal 生产/消费映射（本卡不改，穷举证明在 PROOF.json）
| 项 | 值 |
|---|---|
| 元素域 | [16 token][256 M 通道] = 4096 |
| 写者唯一性 | `sg = c // 32`；4096/4096 元素恰好 1 个写者，无重复写、无漏写 |
| 消费者 | contract 阶段：每 SG 每 ki 读 2 个 8×16 tile（16 ki × 2 = 32 tile/SG = 8 KiB/SG） |
| 消费多重度 | 每个元素被 **8 个 SG 全读**（C256 的 K = 256 M 通道，所有通道 owner 都要全 K）→ 64 KiB/WG |
| 尾块 | 16 行 = 2×8、M/SG = 32 = 2×16、contract K = 256 = 16×16 → **无残块** |

### 1.4 expand 的 A 输入（本卡唯一改动点）
| 项 | 父 | 候选 |
|---|---|---|
| 元素 | (8 token, 16 in_ch)，地址 `xA + ki·256` / `xB + ki·256` | 同 |
| 唯一地址数 | 32（2 token 组 × 16 ki） | 32 |
| 访问次数/SG | `hb 4 × ki 16 × 2 组` = **128**（每条 256 B = 32 KiB） | `hb 2 × ki 16 × 2` = **64**（16 KiB） |
| 重复度 | 4× | 2× |
| 被访问集合 | 完全相同的 32 个地址 | 同（PROOF.json `same_visited_set=true`） |

**native 侧独立证据**（链头 f10 采集 `CS_asm95c51e16…`，sha `2470b4cc…`，只读）：
`load.ugm.d32x64t.a32.bss` 共 **132** = barrier 前 **128** + barrier 后 **4**（= contract 的 4 个残差 seed）。
128 与源码推导 `4 hb × 16 ki × 2 组` **逐条相等**（PROOF.json `equals_source_derived=true`），
所以“4× 重复读”确实落到 native，不是源码错觉。

### 1.5 候选改动的映射等式（逐条）
- hidden tile 编号：父 `(8g + 2·hb + T')·…`（hb∈0..3, T'∈0..1）；候选 `(8g + 4·hb + T)·…`（hb∈0..1, T∈0..3）。
  两者都覆盖 `8g + 0..7` 且按 hidden 升序消费 → **middle 的 K 序列 0,16,32,48,64,80,96,112 逐项相同**。
- `wb` 只算一次（每 64 宽块一次 `/16`），4 个 tile 用 `wb + 0/4096/8192/12288 + ki·256`，
  与父的 `we + ((128g+h0+16t)/16)·4096 + ki·256` **代数等价**（h0 是 16 的倍数，除法无截断）。
- expand 累加器：父每 32-hidden 块 4 个（2 token 组 × 2 hidden tile）；候选每 64-hidden 块 8 个。块末都做 act+窄化+middle。
  每个输出元素的 K 累加仍 `ki=0..15` 升序，一条不差。
- act（`c256_act_h`）仍作用在同一 `MAT_H` 窄化点，参数、顺序、每元素 1 次不变。

**逻辑字节 ≠ DRAM 字节**：省下的 16 KiB/SG 是 L1/L2 层请求；同一 4 KiB 在极短窗口内被读 4 次（候选 2 次），
大概率命中 L1，**不宣称 DRAM 流量减少**。
**片段字节 ≠ 实际 GRF**：+32 GRF 是逻辑记账，物理分配由 IGC 决定，必须由 native 的 scratch/占用率确认。

## 6. 整体是否更快：本卡要测什么、用什么臂、怎么归因

- **臂**：`base` = 当前接受链头 `accepted/pkg-vit-16pass-20261027`（`5844990…`）；
  `cand` = `cards/n03b-f04-c256/plan.txt`（`660e8c10…`，**只换 15 个 C256 F04 PASS**，其余 3495 行逐字相同）。
- **门**：fixed（gold `1755e9c2…`）、fb2（末帧 gold `9c3e511e…`）、resources（zprof GpuTime）、native（§5 表）。
- **ordinary**：warm1 / reps30 / feedback，6 组交替独立进程对，全部 360 样本保留，t(df=5) 于对均值差，报 95% 区间；
  不删峰、不补跑、不追显著。交替顺序在启动前固定（GPU-REQUEST.json）。
- **归因边界**：232 个 PASS 里只有 15 个改变；每个 PASS 只删掉 844 条 send 中的 64 条（7.6%），
  且这 64 条是 256 B 的 L1 命中读。C128 同变换（32 条/SG）实测 −0.023 ms、CI95[−0.066, +0.019]，
  按被删消息数线性外推，本卡量级 ≈ **−0.05 ms**，仍低于 6 对检出下限（约 ±0.10 ms）。
  因此：**即使机制完全落地也大概率 INDISTINCT（D）**；D 不等于零收益，也不构成方向禁令。
  若出现 −0.2 ms 级变化，必须先排除分配/绑定差异（本卡 plan 的 buffer 数、pool 字节、PASS 行参数与链头逐字一致，
  可用 `PLAN-DIFF.json` 与 `CPU_PLAN_OK 152 rows, 232 passes, 502 buffers` 核对）。
- 单链归因：本卡只做“A 输入重复读 4→2”这一条，不掺权重/发布/contract 的混合包。

## 7. 未决项与下一处具体改动

1. **C64（7 PASS，ordinal 6/9/12/15/217/220/223）**：`c64/candidate.comp:64-75` 同结构，`ki<4`（K=64），
   A 读 4×4×2 = 32 条 → 16 条（−16 条/SG，最小）；累加器 4→8 与 C256 相同，可复用本卡实现套路。
2. **成包**：CARD 说明“若 C256 落地且 scratch=0，主代理会把 C128(C256) 与 C64 同变换成包测一次”。
   三宽度合计 −112 条 A 读/SG（C128 −32、C256 −64、C64 −16），是单卡之外唯一可能越过检出下限的形态。
3. **同族真正更大的空间（需新卡）**：C256 的 expand 权重每 SG 读 128 条 512 B（64 KiB），
   `pair=0` 让 8 个 SG 读**互不相同**的隐藏块，但 contract 的 WC 与 middle 的 Wm 存在跨 SG 重复；
   再进一步需要改 owner/几何（每 SG 更多 token 或 channel 合并），会动 WG 映射与权重读取总量，必须独立成卡。
4. **seed 与 expand A 的重复**：contract 的 4 个 seed tile 正是 expand 在 `ki=2g/2g+1` 上读过的同一批输入
   （同 token、同 16 通道）。保留可删 4 条 UGM/SG，但要把 4 个 half 片段跨整个 middle 段存活（+8 GRF/lane），
   与已测过的“长寿命片段”副作用同类 → 只在 A 复用版通过后再考虑。
