## 1. 物理块：父 = 一个 16384 half 的 staging 数组，且是**模块里唯一的 Workgroup 对象**

```glsl
shared float16_t shT[16384];                 // 16384 half = 32768 B，唯一的 shared 声明
for (uint e = t_local; e < 16384u; e += 256u)
    shT[e] = gT[w * 16384u + e];             // 整块拷贝，identity map
barrier();                                   // 唯一的 publish
if (debug) { for (...) dbg[425984u + e] = shT[e]; barrier(); }
```

| 项 | 值 | 依据 |
|---|---|---|
| 声明长度 | 16384 half = **32768 B** | 源码 + `build/lifetime.json.parent.declared_halves` |
| 模块 `Workgroup` | **1 个变量，32768 B**（无第二个 shared 对象） | `parent-rebuild.spv` 的 `storage_bytes()` |
| 元素语义 | `gT` 瓦片 `[64 token][256 channel]`，行距 **256 half = 512 B**，w 瓦片基址 `w*16384` | 源码 |
| 生产者 | 全部 256 线程，每线程 64 half（`e = t + 256i`，i<64） | 源码 |
| 主消费者 | `coopMatLoad(a, shT, m0*256 + k0, 256u, LROW)`：`MAT_A` = fp16 8×16，行主序、stride 256 | 源码 + `c256_common.glsl` |
| debug 消费者 | `dbg[425984 + e] = shT[e]`（`pc.p1.w != 0` 才走），读全 16384 half | 源码 |

## 2. 生产者：一次全量拷贝，逐地址**分区**（穷举，不是抽样）

`build/lifetime.json.parent.producers`（`_lifetime.py` 逐 half 枚举）：

| 检查 | 结果 |
|---|---|
| 写地址并集 | `{0 … 16383}`，**= 整个 tile**（`write_is_partition_of_tile = true`） |
| 每地址写次数 | 直方图 `{1: 16384}` —— 每个 half **恰好写一次** |
| 每线程写量 | 恒为 64 half（`halves_per_thread = [64]`） |
| 映射 | `shT[e] = gT[w*16384 + e]`：**恒等**（无置换、无缩放、无类型转换） |

⇒ 生产者侧没有第二个写者、没有第二轮覆盖，也没有任何 half 被写两次。

## 3. 消费者：1024 个 A 片段，并集 = 全 tile，每 half 被 **8 个 SG 各读一次**

`MAT_A` 8×16 行主序、stride 256 ⇒ 一个片段 = `{m0*256 + k0 + r*256 + c}`，128 个不重复 half。
`m0 = (sg/8u + 1u*j) * 8u`，而 `sg = gl_SubgroupID ∈ [0,7]` ⇒ **`sg/8 == 0` ⇒ `m0 = 8j`，与 SG 无关**。
即：8 个 SG 用 N 维分工（`n0 = (sg%8)*32`，8×32 = 256 覆盖全 channel），**A 操作数完全相同**。

| 检查 | 结果 | 依据 |
|---|---|---|
| 片段数 | `8 j × 16 ki` = 128/SG，× 8 SG = **1024** | `consumers.fragments_total` |
| 读地址并集 | `{0 … 16383}`，= 整个 tile（`read_union_is_whole_tile = true`） | 穷举 |
| 未读 half | **0**（`unread_halves = 0`） | 穷举 |
| 每地址读次数 | 直方图 `{8: 16384}` —— 每个 half 被 **8 个 SG 各读一次** | `read_multiplicity` |
| per-j 块 | `j` 的 64 个片段并集 = `[2048j, 2048j+2048)`，**恰是第 j 个 2048-half 块**（8/8 `is_block=true`） | `per_j_blocks` |
| debug echo | 读全 16384 half（debug=1 才走） | `echo` |

**关键结构事实**：第 j 块（row 8j…8j+7，全部 256 channel = 2048 half）**只在第 j 次迭代被读**，
之后永不复活；但因为它与其它 7 块在同一道 barrier 里一次性发布，**它在 barrier 时刻是活的**。

## 4. phase × 读写表（正常执行路径；debug 只作注）

| # | phase | `shT` | 说明 |
|---|---|---|---|
| P1 | 拷贝，`i = 0…63`（`e = t + 256i`） | **W** 16384 half（分区） | 全部 256 线程，一次扫完；行序 0→63 |
| P2 | `barrier()`（publish） | **—** | **1 道**，全 WG |
| P3.0…P3.7 | `j = 0…7`：`ki = 0…15` 各一次 `coopMatLoad(a)` | **R** 2048 half/次（全 8 SG 各读同一片段） | K 序（`ki` 0→15）与 DPAS 顺序不变 |
| P4 | debug echo（`pc.p1.w != 0`）+ `barrier()` | R 16384 half | 生产路径不执行 |

**活得时间线（源码顺序）**：

```
shT  [P1 W ───────────────────]  ← 一次写满 16384 half
                              [P2 barrier] ← 峰值点：全部 16384 half 已发布且都还没被读
                                   [P3.0 R 块0][P3.1 R 块1]…[P3.7 R 块7]
                                   块 j 的寿命 = [它被写的那一刻, 第 j 次迭代结束]
                                                 ↑ 但 barrier 把 8 块全部钉在同一时刻活
```

* `build/lifetime.json.parent.liveness.peak_simultaneously_live_halves = 16384`
  ⇒ **同时活值峰值 = 16384 half = 32768 B**。
* 声明值 = 32768 B，峰值 = 32768 B ⇒ **结构性 slack = 0 B**（`slack_halves = 0`，`slack_bytes = 0`）。
* RAW：写者 1 个 lane → 读者 8 个 SG。逐地址对：同 owner 512 对、跨 owner **130560** 对，
  全部由那一道 publish barrier 关闭（`hazards.RAW_stage_to_A_read.closed_by`）。
* WAR/WAW：**0**——只有一轮拷贝，没有第二轮覆盖。

## 5. 判定：本组 **没有 n37 那种 slack**（C 分支成立）

n37 的 F10 能压 20480→16384，是因为"最后一个 staging 窗口在交接时仍可读"把 arena 顶到
`8192 + 12288`，而**活值峰值只有 16384**。本组不是这个形状：

* 峰值 16384 half **等于**声明 16384 half，差 0；
* 每个 half 都被写一次、被读 8 次，**没有未读区、没有已死窗口、没有可退役平面**；
* 消费者里也不存在"某平面先死、另一平面后写"的窗口（只有一个数组、一次性发布）。

**下界**：发布粒度是"整块 + 一道 barrier"，barrier 时刻全部 16384 half 都在活着
⇒ 任何保持"整块一次发布"的设计都要 ≥ 16384 half = 32768 B。
要再小只有两条路，**都不是本卡能做的**：

1. **改发布粒度 = 分段**：段 0 发布 → 算段 0 时发布段 1 …… 每段退役。n06c 已按 4 段（16 token = 8 KiB）
   实测：staging 消息 18→66、总 send 1597→1642、动态 barrier 1→4、**−0.024617 ms**（6/6 同向变慢）。
   **本卡不重做分段**（也不做 2 段/8 段：段越细消息越碎、barrier 越多，n06c 的结论只会更差）。
2. **改 ownership = token tile**：让每个 SG 只拥有自己那 8 行（M 维分工），才能让"它的 A"与别人的 A 异步。
   但这会把权重读从 256 条变成 2048 条（每个 SG 要全部 8 个 N 块的权重），且 WG 的输出 tile 形状/写入
   全部要重排 —— 属于卡片禁止的"改 token tile"，本卡不做。

## 6. 但这个数组**根本不必存在**：32768 B 是"可删"，不是"可回收 slack"

`shT` 不是一份"活值"，而是 `gT` 的一份**逐字节副本**。三个条件同时成立
（`build/lifetime.json.deletable`）：

| 条件 | 证据 |
|---|---|
| 值等价 | `shT[e] == gT[w*16384 + e]` 对全部 e（恒等映射，无变换） |
| 源只读 | `gT` 在本 shader 里**从不被写**（唯一出现是拷贝读与 `coopMatLoad`） |
| 消费者可改写 | A 读的偏移在 gT 里是同一套：`m0*256 + k0` → `w*16384 + m0*256 + k0`；debug echo 同理 |

⇒ 把 A 操作数直接从 `gT` 读，**每个 (lane, component) 拿到的 half 逐位相同**，DPAS 的输入不变、顺序不变
⇒ 输出逐位不变。于是：

* **Workgroup 字节 32768 → 0**（已编译核对：候选模块**没有任何 Workgroup 变量**）；
* 同时删掉：整块拷贝（每线程 64 half 全局读 + 64 half SLM 写）、**publish barrier 1 道**、
  staging 的 16 条 SLM store 与约 18 条宽 UGM load。

**这不是"回收 slack"，而是"删掉一个纯副本生产者"**（L36 的话：先看峰值；峰值等于声明值时，
下一步不是找窗口，而是问"这份数据为什么要在 SLM 里"）。同一网络里 **F05 C256 已经在这么做**：
它的 A 操作数就是 `coopMatLoad(a, gY, (w*64+m0)*256 + k0, 256u, LROW)`（直读全局），
其 native 里 `load.ugm.d32x8t.a32.bss` 512 条、**没有** `load.slm.d32x8t`——本卡只是把 F06 C256 对齐到同一形态。

代价（如实入账，`COST-LEDGER.json`）：A 读从 SLM 变全局，**消息条数完全不变**（1024 条 d32x8t，
8 个 SG 读同一片段这一点父本来就有），但每条的数据来源从 SLM 变成 L1/L2；逻辑读字节 1×32 KiB → 8×32 KiB/WG
（同一批地址，预期 L1 吸收 7/8）。

## 8. 已排除的替代（写下来防重复）

1. **分段（n06c 的 4 段，或 2 段 / 8 段）**：已实测 −0.0246 ms、消息 18→66、barrier 1→4。不做，也不再重测。
2. **保留一半 staging（8192 half = 16384 B）**：能正好落在 4 驻留档，但要保住"半个 tile 的拷贝 +
   再拆一次 A 读的两套偏移"，而 §6 说明整块都可以删——留一半只多付拷贝与代码，**严格被 §6 支配**，不做。
3. **改 M 维 ownership（每 SG 自己的 8 行）**：权重读 ×8（256→2048 条/WG），属于改 token tile + 抬消息，不做。
4. **把 `gT` 瓦片按 A 片段重排（n06d 的 A tile 布局）**：已实测 −0.0025 ms（D 类），且仍要 32 KiB。不做。
5. **`shT` 缩小到 8192 B（8 驻留档）**：只有"删一部分"才有意义，而删一半已被 (2) 排除、全删已在 §6。

## 9. 一页结论

* **时间线**：`shT` = 一整套 16384 half 的 `gT` 副本；256 线程一次写满（每线程 64 half，恒等映射），
  1 道 barrier 发布，然后 8 个 SG 各自把整个 tile 读一遍（1024 个 8×16 片段，每 half 读 8 次）。
* **活值峰值 = 16384 half = 32768 B = 声明值 ⇒ 结构性 slack = 0 B**（C 分支：本组没有 n37 那种窗口）。
* **可回收/可删 = 32768 B**：数组是纯副本，源 `gT` 只读、消费者只有 A 读与 debug echo
  ⇒ A 直读 `gT`，Workgroup **32768 → 0 B**，值逐位不变。
* **驻留**：2 → **≥4**（0 B 让 SLM 不再约束；16384 B 档在同形状上实测就是 4）。
* **不重做 n06c 的分段**；不换 ownership；不改 grid、不改数学、不改 K 序、不抬活值。
