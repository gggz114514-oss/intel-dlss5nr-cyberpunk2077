------------------------------------------------------------------ 2. 做了什么
F07 C256（44 KiB 的 shader）的 DS 输出片段原来走
    coopMatStore(→nrf_pair[sg*256+128]) → publish subgroupBarrier →
    每元素标量读 nrf_pair → 每元素 nrf_ds_at → 16-bit global 存 → retire subgroupBarrier
共 8 次（2 轮 × 4 个 16 通道组）。本卡把这条往返删掉，改成一次 8×16 的
coopMatStore 直落消费者 io_at layout 0：

    if (!half_ok) return;
    coopMatStore(h, nrf_o,
                 obase + nrf_ds_at(uint(px0i), uint(py0i), group*16u, OW, OH, N, 0u),
                 16u, gl_CooperativeMatrixLayoutRowMajor);

能这么做的**唯一**理由是 C256 这个形状的 tile 对齐（不是普通手法）：
px0 = 4*wx（恒 %4==0）、py0 = 4*wy-2+2*sy（%4 ∈ {0,2}）→ 片段的 8 个行光栅
token 是 t = tbase+m，tbase%16 ∈ {0,8}，即**同一个 16-token supertile 内连续
8 个 token**；io_at layout 0 对固定 16 通道组正是行距 16 halves 的连续 256-half
块 = 行主 8×16 累加器存储。基址直接用 io_at 自己（c=group*16，c%16==0），
不是第二套地址代数。C64/C128 的 F07-D 之所以只能逐元素 scatter，是因为
它们的 px0 = 4*wx-2 不对齐——这一点在 SOURCE-DIFF.patch 与 ANALYSIS §0 里写明。
