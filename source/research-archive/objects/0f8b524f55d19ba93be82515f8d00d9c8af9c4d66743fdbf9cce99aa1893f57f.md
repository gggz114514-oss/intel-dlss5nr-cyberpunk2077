# F20 Q producer-to-score handoff

Parent is the current exact `f20-score-owner`, not the old P03. No prior gain is removed, and no plan is deployed. This is one controlled attempt following the user's request to make matrix results directly consumable by the next matrix.

## Scope and mapping

The QKV producer and score query consumer already own the same8 query rows per subgroup. Intel half-accumulator and A fragment coordinates match: row=`8*sg+2*d+lane/16`, feature=`16*half+lane%16`. The builder enumerates all2048 elements and verifies unique ownership. Copy the two half Q output fragments into score A components; no Q transpose or subgroup shuffle is introduced.

Produce K, V, then Q, rather than Q, K, V. These projections are independent outputs. Each still accumulates K0 then K16 and narrows once. Weight tile count and eight-subgroup parallelism are unchanged. The ordering tries to delay Q's birth until K/V projection accumulators retire. Compiler register allocation remains subject to native validation.

## Exact norm boundary retained

This does not remove the entire Q norm staging path. The original norm tree still reads the Q publication, because replacing that tree previously changed driver contraction and exact outputs. Keep its source and NoContraction policy unchanged. It returns the same norm coefficient through shNorm. The retained Q A fragments receive `H(Q*n)` then `H(result*headscale)` with separate NoContraction, then score consumes them directly. All original cross-subgroup publication barriers remain.

Compared with the parent, source-level removed traffic per workgroup is Q scale read4096B + Q normalized write4096B + score Q read4096B =12288B. Raw Q publication4096B and norm Q reads4096B remain. This is logical shared-memory traffic, not measured DRAM bandwidth.

Q payload16B/lane is retained across norm/K scaling. It can overlap norm temporaries. It must not be described as free or as a measured physical GRF count. During final Q conversion, the float accumulator pair and half outputs can coexist; K/V projections are scheduled earlier. No additional persistent raw32-value norm cache is introduced. Debug Q is emitted from normalized fragments.

## CPU and native evidence

Compilation, SPIR-V validation, plan CPU check and exact2048-element owner enumeration pass. Eight intended NoContraction sites: fold3, K scale1, Q scale2, bias2. No scalar-half norm NoContraction was added. Den/PV/output source remains identical to the previous consumer-scale candidate and the parent's arithmetic.

Fixed and fb2 gates are byte-identical to gold. Native has64 DPAS,511 SLM sends,252 UGM sends,13 barriers,1404 MOV,4282 total static instructions, and no scratch instructions. Versus the previous Q-consumer-only candidate it removes16 SLM sends and39 instructions; MOV,UGM,DPAS and barrier counts are unchanged. Versus the actual score-owner parent, total instructions still increase4209→4282 and MOV1356→1404. This proves a changed feed path, not a speedup.

All native totals include debug and alternative control flow. They cannot isolate time, physical GRF allocation or occupancy. GPU ordinary timing and driver resources are recorded separately. Performance acceptance uses one batch of three alternating parent/candidate process pairs,30 samples per process, no removal of samples,95% t interval over process-pair mean differences. No same-identity repeats to chase significance.
