## 1. Q/K 尺度沿点积 K 维可分离的条件

### 1.1 精确性条件（数学，不是近似）

设一行 query 与一列 key 的点积

```
score[t,j] = Σ_{d=0..D-1} Q[t,d] · K[j,d]        D = head_dim = 32（每族都恰好是一个 K32）
```

把两侧分别量化成 int8 码并各用一个标量反量化：

```
Q̂[t,d] = sQ(t) · q[t,d],      K̂[j,d] = sK(j) · k[j,d],      q,k ∈ [-127,127] ∩ Z
Σ_d Q̂ K̂ = sQ · sK · Σ_d q k = sQ · sK · acc        （acc = int32）
```

**只要 sQ 在 d 上恒定、sK 在 d 上恒定，这个等式就是精确的**，acc 与浮点参考只差量化误差，
不存在 rank-1 近似。反之，若 sQ 随 d 变化（逐维/per-channel），则 Σ_d sQ(d) q k ≠ sQ·acc，
必须先折进权重或按 K 分组分别累加——这是施工书第 7 节的红线。

因此"动态→静态"的门槛不是"沿 K 可分离"（现有每 WG 一个标量已经满足），而是：
**能不能在不量产的前提下把 sQ/sK 从"每次 dispatch 现算"换成"读一个常数"。**

### 1.2 为什么可以静态化：分辨率论证

动态尺度唯一的收益是分辨率。定义

```
res = median_窗口( per-window absmax ) / ( per-head static absmax )
```

`res` 越接近 1，动态尺度就越没用。实测（ViT，3 帧 × 8 block × 32 head）：

```
Q: res = 0.890 .. 0.938      K: res = 0.903 .. 0.940      V: res = 0.754 .. 0.880
```

Q/K 的 `res` 高达 0.89~0.94，原因是**归一化把幅值钉死了**：

* ViT：producer 对每行做 L2 归一后乘每 head 静态标量 `scales[h]`，所以 **‖Q 行‖ = 5.65625·scales[h] 恒定**
  （实测 Q 行范数 / scales[h] = 5.1849 = 5.65625×11/12，其中 11/12 是 dump 里 24 行零 token 的比例）。
  `max|Q|` 只是"固定范数向量在 64×32=2048 个样本里的最大分量"这个次序统计量，窗口之间几乎不变。
* 所有 5 个族的 K 都是 L2 归一（ViT/C64/C128/C256/split16 同合同），所以 `|K| ≤ 1` 是**硬上界**，
  连标定都不需要：`sK = 1/127` 永不饱和。
* V 不归一，所以 `res` 掉到 0.75~0.88，静态化代价相应变大（+17%）。

**这就是第一替换点选 Q/K 而不是 V/P 的原因**：Q/K 的动态范围是结构性的常数，V/P 的不是。

### 1.3 静态 head scale 的标定

```
s*_h(family, block, head) = headroom · max_{w ∈ 标定帧, 窗口} |X_h(w)| / 127
```

标定流程与超参（实测敏感性，ViT，24 个 (frame, block) 平均）：

| headroom | sQK context relL2 | 相对 headroom=1.0 |
|---|---|---|
| 1.00 | 0.00581 | 1.00 |
| 1.25 | 0.00663 | 1.14 |
| 1.50 | 0.00755 | 1.30 |
| 先验界（Q 用行范数、K 用 1.0） | 0.00799 | 1.37 |

跨帧稳定性：同一套 F1(34189) 标定值直接用在 F2(41444)/F3(43654)，
`sQK` 分别是 0.00364/0.00374/0.00361（block31）等，**帧间差 <3%**。所以 headroom 取 1.0~1.15 足够；
不建议为了"保险"取 1.5（多花 30% 误差）。若不想标定，Q 用行范数界、K 用 1/127 的纯先验版也可用（+37%），
这是无数据兜底方案。

> 注意：headroom=1.0 时标定帧内不饱和（clip_frac = 0.000000，实测）；
> 未标定的新场景有饱和风险，这是必须由 GPU/整网验证覆盖的部分。

## 2. P 的非负 0..127 限制

### 2.1 合同差异

* **Swin（c64/c128/c256/split16 l2）**：P 在 PV 之前**先归一化**（`P := half(P*inv)`，`inv = 1/max(ΣP, 2^-14)`），
  所以 `P ∈ [0,1]`，`Σ_{64 keys} P = 1`，每行最大码恰好 127（`pmx*(127/pmx)=127`，永不饱和）。
* **ViT**：P **不归一**进 PV，整段 5 个 64-key chunk 之后才做一次 `1/max(den, 6.198883056640625e-05)`。
  实测 `P ∈ [0.004028, 1.6406]`，且 **1.6406 就是 `vit_exp` 近似本身的上饱和值**（每 head、每帧都一样），
  即参考 P 已经贴着 exp 近似的天花板。

### 2.2 为什么 sP 不能静态（实测，两个合同都测了）

| 变体 | context relL2（均值，24 组合） | 相对动态 | 码饱和率 |
|---|---|---|---|
| 动态 per-query sP（现状） | 0.00538 | 1.00 | 0 |
| ViT：静态 sP = 1/127 | 0.12524 | 23.3× | **2.89%** |
| ViT：静态 sP = 每 head 标定 pmax | 0.02557 | 4.75× | 0 |
| Swin 代理：静态 sP = 1/127 | 0.03489 | 6.7× | 0 |

行最大值的分布（决定一切）：

```
ViT 未归一 P    ：逐行 max ∈ [0.0840, 1.641]，行中位数 1.125..1.530
Swin 代理归一 P ：逐行 max ∈ [0.0156, 0.8605]，行中位数 0.122..0.198
```

跨行 60:1 的行最大值跨度意味着：单个码尺度要么让尖锐行饱和（1/127 对 ViT 直接饱和 2.89% 的码），
要么让平坦行只剩 0~2 个码（Swin 代理：平坦行 P=1/64，码 = round(127/64) = 2，量化台阶就是 P 本身的 25%）。
**这是数据的性质，不是实现细节**，所以 sP 保持 per-query / per-(query,chunk) 动态是数学结论，
不是"暂时没做"。要真静下来，必须改 P 的表示（例如按 den 推导的第二 P 尺度、或非线性 P 码 + 配套反量化），
那是重新设计而不是换 scale——列入 S10/S11 的后续设计项，本轮不做。

### 2.3 0..127 而不是 -127..127

P ≥ 0 是硬约束。保持对称 S8 时只用到 0..127 这 127 个正码（码 0 是"零"），**不能宣称 256 级**，
也不能在用 `roundEven(P/sP) ∈ [0,127]` 之后再声称无损。施工书第 7/9 节：
不得非线性编码后仍直接线性 MMA。

## 3. U8×S8：真实支持证据缺失，本轮禁止引入

**已有证据（唯一一条，且是 SINT8）**：
`vit_qkv_common.glsl:53` 注释与 `MMA-RESIDUAL.json` 的编译探针记录
`B580 INT8 tuple (queried: M8/N16/K32 SINT8xSINT8 -> SINT32)`。
本会话用 opcode census 复核了 6 个 attention SPV，全部用 `int8_t`（signed）操作数，
没有任何 `OpTypeInt 8 0`（无符号）矩阵操作数的痕迹。

**要引入 U8×S8 必须先有的证据（本轮都没有）**：

1. 一段编译探针：`coopmat<uint8_t,…>` 或 `coopmat<int8_t,…>` 与 `uint8` A/B 组合能通过 glslang 并
   在 B580 上映射到同一 `OpCooperativeMatrixMulAddKHR` 指令（不是软件回退）。
2. 一条数值探针：证明该指令的组合语义是 `u8 × s8 → s32` 的直乘，而不是把无符号字节当有符号重新解释。
3. 零点补偿的完整实现：
   `Σ_d (p_d - zp_P)(v_d - zp_V) = Σ p_d v_d - zp_V Σ p_d - zp_P Σ v_d + D·zp_P·zp_V`，
   也就是每个输出元素需要 **两个额外的秩 1 归约**（`Σp`、`Σv`）加一个常数项。三者都必须进 epilogue，
   并且 padding 码、bias、残差都要跟着改。做不到就不是"U8×S8"，只是把 signed 字节重新贴标签——
   施工书明确禁止。

**判决**：本轮与下一轮都用 SINT8 对称、RNE、`clamp[-127,127]`，不改 zero point。U8 只作为具名第二候选记录，
不进入代码路径。

## 4. 目标函数：必须覆盖 score → exp → P，不能只最小化 score L2

### 4.1 为什么 score L2 是错的

`vit_exp`/`c256_exp_h` 都是**有限动态范围的近似**：`vit_exp` 先把分数映射到
`v = clamp(0.08953857421875·z + 1.708984375, 1.439453125, 1.9775390625)`，
再取半精度位域 `(h & 0x3ff) << 4`，于是 `|z| > ~3` 之后**完全饱和**（输出恒为 1.9775 或 1.4394 对应的位型）。
本会话实测：block31 的 score 范围是 `[-5.92, 4.55]`，block33 的 head6 到 `[-14.98, 17.05]`，
**大部分分数落在饱和区**。对这些元素再降低 score 误差对 P 没有任何影响；
反过来，最小值附近 1 ulp 的 score 变化就能改变整个码值。
所以"最小化 score L2"会把标定预算浪费在看不见的地方。

### 4.2 实际使用的多目标

对每个 (family, block, head)，在标定窗口集合 W 上：

```
J1 = || P_cand - P_ref ||_2 / || P_ref ||_2                        # 概率域（去饱和后才有意义）
J2 = || den_cand - den_ref || / || den_ref ||                      # 归一化树（仅 Swin）
J3 = || inv_cand - inv_ref || / || inv_ref ||                      # 倒数（ViT 在 5 个 chunk 之后一次）
J4 = || ctx_cand - ctx_ref ||_2 / || ctx_ref ||_2                  # context（本文件所有表格用的就是它）
J5 = || T_cand - T_ref ||_2 / || T_ref ||_2                        # 半精度窄化后的最终 T（Swin 到此为止）
J6 = 码饱和率（clip_frac）                                          # 硬约束：> 0 直接否决
```

约束：`clip_frac == 0`（硬）；`J6` 一旦非零，标定值直接乘 1.25 重来。
选择规则：先满足硬约束，再最小化 `J4 + 0.5·J1`（context 是下游真正消费的量，P 域用来防止
"context 抵消但 P 已经变形"的假改善）。本会话表格为了可读只报 `J4`，但 `tools/vit-static-study.json`
里每个变体都同时存了 score/P/ctx 三个域的均值、p90、max。

## 5. CPU 可执行标定流程（本轮已对 ViT 跑通，其余四族待跑）

```
0. 身份：核 SPV sha256、plan sha256、dump 文件大小/帧号；任何一项对不上就停。
   （本轮：plan combo-34189 = 2b5481d5…，rows = eaab2cf7…，Vit QKV dump = 288×3072 fp16）

1. dump → Q/K/V：ViT 是 [token][3072] 行主序，前 1024 Q、中 1024 K、后 1024 V，每 32 维一个 head。
   用"行范数是否恒定"做布局证明：Q 行范数 = 5.65625·scales[h]、K 行范数 = 1.0 —— 对不上就是布局错。
   （本轮实测 5.1849/1.0000，与 11/12 零行比例一致 → 布局确认）

2. 建参考：按 kernel 的真实顺序复现 score→exp→den→inv→ctx→T（含 f16 窄化点、den 的 half 树、
   padding key 的 exp(0) 与 pad 减法、ViT 的 5 chunk 累加）。
   验收门槛：与 FP16 教师 T dump 的 relL2 ≈ f16 舍入量级（本轮 3.7e-4..4.4e-4，全部 8 个 block × 32 head）。
   不过门槛就不要往下做——错误参考会驱动错误的"修正"。

3. 复现现状动态 int8 路径（每 WG/每 chunk 各自 absmax），得到基线误差（本轮 0.00538）。

4. 逐变体替换成静态常数，重算 J1..J6；标定只许用标定帧，评估帧单独报。

5. headroom 搜索 {1.0, 1.05, 1.1, 1.25, 1.5} + 纯先验界；命中 clip_frac>0 的配置直接丢弃。

6. 只有在"评估帧 J4 增量 ≤ 基线 10%"时才允许进入 SPV 修改；否则记录负结果，不硬上。
```

对 c64/c128/c256/split16 缺 Q/K dump，流程的 1、2 步改成"从 `dump_swin_*_Y` + FP16 `WQKV` 权重重算 Q/K/V"，
并在第 2 步用 `dump_swin_*_T` 做同样的验收门槛（见 `JOBS.json` 的 J2/J3）。

## 6. 实现形状（供实现卡落地，本轮未改任何 SPV）

### 6.1 scale 放哪

| 族 | 现有 scale 载体 | 需要新增 | 字节 |
|---|---|---|---|
| c64 | `swin_N_aux`（per-head 前置标量在 `aux[p4.y+h]`） | sQ[2] sK[2] sV[2] | 24 B/block |
| c128 | 同上 | sQ[4] sK[4] sV[4] | 48 B/block |
| c256 | 同上（`scalar[h]`） | sQ[8] sK[8] sV[8] | 96 B/block |
| split16 l2 | `split16_bNN_aux` + `wsc[96h+n]` | sQ[16] sK[16] sV[16] | 192 B/block |
| ViT | `vit_blockNN_scales`（32 float，Q 前置标量）+ `ws[16]` | sQ[32] sK[32] sV[32] | 384 B/block |

**注意**（施工书第 11 节 / CONTRACT §2）：改 buffer 字节数必须同步所有引用旧全长的 `BIND`，
否则 runner 会截断或越界。ViT 的 `vit_blockNN_scales` 现在正好 128 B（32 float），
扩到 512 B 必须同时改 BUFFER 行和 bind 1 的 BIND 行。

### 6.2 kernel 侧改动（逐 site）

```glsl
// 现在（动态）
if(lid==0u) shQMax=0u;
atomicMax(shQMax, floatBitsToUint(abs(float(amq))));
const float sQ=(shQMax==0u)?1.0:(uintBitsToFloat(shQMax)*(1.0/127.0));

// 静态
const float sQ = aux[SCALE_Q_OFF + h];      // 每 head 一个常数，标定得到
```

连带影响：`atomicMax` 与逐元素 abs/比较可以整段删除（**少做**，不是多做），
但 `amax` 往往寄生在已有的 norm 遍历里，所以性能收益接近 0，必须实测，不能声称免费。
`sQinv`/`sVinv` 同理改成常量倒数（或直接存 inv 省一次除法）。

### 6.3 SPV 侧验证（无 GPU 也能做的部分）

* `tools/spv_census.py` 的 `OpAtomicUMax` 计数必须从
  c64/c128/c256 = 4 → 1（只留 sA 或全清）、split16/ViT = 3 → 0。
  这是**二进制级**的"没有运行时 amax"的证据，比读源码强。
* 编译命令沿用各候选的 argv（split16 必须带 `-DL2_INLINE_QT=1 -DL2_NO_T_WRITE=1`）。
* 计划侧按 dispatch ordinal 换 SPV，用共享 `planlib.py`，不要字符串全替换。

## 7. 风险与不得声称的事

1. `res=0.89` 是 ViT 一帧集的事实，**不能直接外推到 c64/c128/c256/split16**；它的可迁移理由是
   "K 已 L2 归一、Q 由归一后乘静态标量"这一纸面合同，属于结构性论证，不是测量。
2. 本轮所有数字都是**共同 FP16 输入下的局部 context 误差**，不是实际量化上游输入下的误差，
   更不是整网/画质结论。多层误差不能相加预测（施工书第 2 节）。
3. `cpu_study` 的参考模型只对 ViT 做过逐块逐 head 校验（3.7e-4..4.4e-4）。其它族的参考模型**尚未校验**。
4. `GPU_VERIFICATION=NOT_RUN`。最小 GPU 作业集见 `JOBS.json`。
5. 静态 sP 被否决是**数学原因**（行最大值 60:1 跨度），不是"这一轮没时间"。
   若要把它写进"全网纯静态完成"，必须先改 P 的表示并重新证明。
