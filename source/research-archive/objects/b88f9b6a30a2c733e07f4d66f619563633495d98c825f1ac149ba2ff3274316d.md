## 2. M23：完整命令流的合法整表（已有实现+数值门）

依据报告 37 §5 的两个缺陷与 M23 新增要求，v3 模型相对 v2 的具体变化：

1. **同 binding 读写不再折叠为只写**（§5.1）。每个 binding 记 (read,write)，`OpAtomic*` 记 R+W。用 r07 plan/receipt 复核：shader-only 约束 RAW **1562**，与报告 37 独立复算的 RAW 1562 一致。
2. **105 处固定清零进入覆盖模型**（§5.2）。每个 first-use clear 是同一字节空间里的一次真实 `fill` 写事件，其 `compute→transfer / transfer→compute` 屏障对按 Vulkan 依赖链算作**一个 full 同步点**；history 两处 copy 同理（feedback 帧首）。
3. **真实 pool 分配与 alias**。分配身份取实际 `VkDeviceMemory`（两个池：resident 213 buffer / transient 274 buffer，0 dedicated），窗口取 receipt 的 `memory_offset/allocated_bytes`；对一个池内 **6,905 对重叠窗口**逐对检查 POLICY 生存区间，**0 违规**；并把 runner 自己的 slot 分配算法独立重放，145 处偏移差异全部是同 firstPass 的并列 tie 顺序（`std::sort` 非稳定），receipt 为真值、以并列安全性检查代替顺序复现。
4. **字节段 hazard**。在每个池的地址空间按所有访问/清零端点切成 elementary segments，只在真实重叠字节上生成 RAW/WAR/WAW；**约束总数 4,216（RAW 1566 / WAR 1100 / WAW 1550）**，其中 837 条涉及清零、6 条涉及 history。
5. **合法整表**。模型导出：**266 个边界中 105 个可无侧车屏障**（该位置的 clear 已提供 full 依赖链；这正是报告 37 指出“不能宣称 266 条钉点=最小集”的量化后果）、**59 个可弱化为 `src=SHADER_WRITE → dst=SHADER_READ`**、102 个保持 full。表**由模型推导，不是删屏障碰 gold**；模型自检“全部依赖被覆盖”。

**数值门（新身份，GPU 实跑）**：`t4-m23v3-fixed-001` / `t4-m23v3-feedback2-001`，runner `0d87cb52…` + `--plan-sha256`（回执内 verified=true）+ 侧车 sha。四文件全部命中既有 gold：fixed `frame_out`=`1755e9c2…`；feedback2 `frame_0`=`1755e9c2…`、`frame_1`/`frame_out`=`9c3e511e…`；nan/inf=0；边界命名 266、defaulted 0、modes {full 102, none 105, write_read 59}。

**普通整网（同 exe、同 plan，只差侧车）**：parent_pre 30.6867 / candidate 30.6657 / parent_post 30.6533（median，ms）；mean 30.7004 / 30.6610 / 30.6750。双父判定：median 差 +0.0210 / −0.0124、B=0.1731；mean 差 +0.0394 / +0.0140、B=0.1691 → **均 UNCERTAIN**。即“去掉 105 条被清零覆盖的屏障 + 59 条弱化”在整网上没有可判定的净收益；与 R05 的 100-mask 结论一致，但本表的 105 条 none 是模型给出而非未证。

**对旧侧车的复核**：把 R05 的 `barrier-min-masks-r07.json` 放进同一 v3 模型 → **uncovered=0**（它保留了全部 266 边界），说明旧门结果与本模型不冲突；但它没有利用清零提供的同步，因此不是本表的替代。

## 3. M24：真实 CHAIN（shader+host+plan+门+反例）

**实现**（不是框架）：
- shader：`c32_chain.comp` = 现役 C32 body（c5_S02 源）逐字保留，只在 `main` 顶部插入发布/等待、底部插入释放/信号，push 追加 4 word `{chain_wait, chain_need, chain_sig, chain_epoch}`，新增 binding 5（coherent 计数缓冲）。等待为**有界轮询**（16 副本、`wgid&15` 选副本、64 次 SALU 退避、超时写 error word），信号为 device-scope release + WG barrier + 每副本 +1；epoch 由 host 每帧写入。
- host：T4 runner 的 `CHAIN` 指令去掉 producer 后的屏障；计数缓冲是 plan 里的真实 BUFFER（81,920 B、16 副本×256 word×5 链、由既有 first-use clear 每帧清零 → epoch=1 的等价形式）。
- plan：7 个 C32 发（1,2,3,4,261,262,263）用新 SPV、绑定 5、push 20 word；5 条链 `1→2, 2→3, 3→4, 261→262, 262→263`；侧车把这 5 个边界置 `none`，其余 261 个 full。
- 依赖合法性（CPU）：v3 模型对 M24 plan + 侧车给出 **33 条未覆盖约束，全部是 (a) 相邻两发的整块数据依赖、(b) 由 pool alias 产生的 WAR/WAW（如 block1_out 与 block3_out 共用 82,575,360 起窗口）、(c) 计数缓冲自身的 RAW/WAW**；这些正是“完成后才允许开始”的语义所覆盖的，没有其它跨发依赖被删。

**数值门**：`t4-m24chain-fixed-001` / `-feedback2-001` 四文件全部命中 gold；nan/inf=0；`chain_ctl.bin` 回读每个副本 = 生产者 WG 数（4032 / 4165 / 4080 / 4165 / 4080，四条副本逐一相同），**5 条链 error word 全 0**。这同时证明：发布次数精确、消费者确实等到完整计数、可见性（release/acquire）端到端成立、无超时。

**普通整网（慢批，已被紧批复核取代）**：parent_pre 30.7828 / candidate 31.3283 / parent_post 30.9007（median）；mean 30.9212 / 31.3122 / 30.9395 → **CLEAR_REGRESSION**（median 差 −0.5455 / −0.4276、B=0.2856；mean 差 −0.3910 / −0.3727、B=0.2358）。
**紧批复核（`t4-m24chain2-*-007`，同 runner 三臂紧邻）**：median 差 −0.3851 / −0.3272、B=0.1715；mean 差 −0.4004 / −0.3687、B=0.1584 → **CLEAR_REGRESSION**，幅度修正为 **−0.33…−0.39 ms**。父臂水平在此批为 30.34–30.40。

**对照实验（已归因，见报告 45）**：先用“同一 CHAIN plan + 保留全部屏障”做过对照，曾读得 median 30.4617、mean 30.4774、对两父 CLEAR_IMPROVEMENT（+0.3210/+0.4390）。**T5 质询后新增 5 臂紧批（父 a、仅布局、对照、父 b、父 c）证明该 +0.32/+0.44 不可复现、予以撤回**：三个同批父臂 median 30.4024/30.3376/30.3686（极差 0.0648），而较早那批父臂读到 30.78/30.90（会话内父图漂移最高 ~0.45 ms），对照 plan 本身稳定（30.4617→30.5752），故旧值是跨臂时钟状态漂移。紧批结论：
- 对照（链代码 + 全屏障）对两父 **CLEAR_REGRESSION**（median −0.1728/−0.2066、B=0.1654；mean −0.2048/−0.2216、B=0.1569）——**CHAIN 的原子/轮询/额外 binding 本身就要 ~0.2 ms**；
- 仅布局臂（父 plan + 同一计数缓冲与 POLICY、父 SPV、不绑定）与对照的池布局 **488/488、0 处偏移不同**，对两父 **UNCERTAIN**（median +0.1058/+0.0720、B=0.1740；mean +0.0247/+0.0079、B=0.1655）——**250 个 buffer 的位移不是先前“变快”的原因，也不构成收益**；
- 对照 vs 仅布局（同分配）**CLEAR_REGRESSION**（median −0.2786、mean −0.2295，B=0.1512）。
- 因此代价分解：链协议代码 ~−0.17…−0.21 ms（对父）/ −0.23…−0.28 ms（对同布局），再去掉 5 条屏障再叠 ~−0.12…−0.18 ms；后者来自**消费者 WG 提前驻留并轮询、挤占生产者发射槽位**。两项都为负，**不得互相抵消，也不改写成“硬件不适用”**。分配位移作为独立观察单列（见报告 45 §1）。

## 4. M25：真实多层 ready-only 持久 worker（PERSIST/DF）

**实现**：
- 把 4 个同层 C32 层（原 pass 1..4，同一现役核）合并成 **1 发**：`c32_persist.comp` 把 body 变成 device 函数，新增 worker 入口。**任务表**（16,393 条 × 24 word，静态文件）给出每任务的 16-word PC（权重/aux 偏移已按层 arena 基址静态偏置）、层号、生产者任务 id（≤4）与窗口坐标；**激活通过 pool view**（`VIEW`：把 runner 真实 transient pool 整体 alias 到 offset 0，5 个激活基址由 runner 用真实 `memory_offset/2` 写入 push），**零拷贝**；权重/aux 是 4 层 pack 的 64B 对齐拼接 arena（静态偏移）。
- 协议：`claim` 为每帧被既有 first-use clear 归零的独立 4B 缓冲（**跨帧正确**）；`done` 每任务一字，写 host 帧 epoch（`atomicMax` release），消费者 `atomicLoad` acquire 等 `>= epoch`；**ready-only**：只等“写它读的 tile 的那些生产者窗口”；超时有界并写 error word + 超时计数/最大任务号。
- **前进性论证**（不依赖 AMD 的乱序/顺序发射前提，也不依赖全部 worker 驻留）：claim 单调且按层优先，故被 claim 的任务其生产者一定更早被 claim、正在别的 worker 上运行；worker 不会放弃已 claim 的任务；生产者/消费者关系严格跨层（生成时对 16,393 条任务断言 `producer_id < layer_base`），所以等待图无环、根在无等待的第 0 层。**实证**：两帧共 32,786 次等待，**timeouts=0**，error=0，done 16,393/16,393。
- **资源实测**：每 WG 128 线程、8,204 B shared；worker 进出计数测得 **并发峰值 160 个 WG**、退出后 live=0。这解释性能：原 4 发每发 4,032 WG 本来就能跑满，持久化不能增加并行；256 个 worker 中只有 160 个能同时驻留，且任务领取/等待是串行的额外控制。

**数值门（最终身份）**：`t4-m25persist3-fixed-001`、`-feedback2-001` 四文件全部 gold（含 feedback 的 history 两处 copy），30 帧末输出 = `2b63d4ba…`；nan/inf=0。
**普通整网（同 runner）**：parent_pre 30.3302 / candidate 31.0164 / parent_post 30.2921（median）；mean 30.3219 / 31.0929 / 30.2826 → **CLEAR_REGRESSION**（median 差 −0.6862 / −0.7243、B=0.1843；mean 差 −0.7710 / −0.8103、B=0.1850）。即“4 发→1 发”的持久化在 B580 上净慢约 0.7 ms（≈2.4%），**不能采用**；但方法本身（多层 task DAG、ready-only 单调领取、去重/完成发布、跨帧 epoch、错误与退出、资源峰值）已真实实现并过数值门。

| 图 | 发数/buffer | 约束 | 清零 | history | 池重叠对/违规 | 全 full 表未覆盖 |
|---|---:|---:|---:|---:|---:|---:|
| M24 CHAIN | 267 / 488 | 4,230 | 110 | 2 | 6,905 / **0** | 0 |
| M25 PERSIST | 264 / 493 | 4,733 | 110 | 2 | 7,371 / **0** | 0 |

- M25 的 `VIEW` 在模型里按“整个 pool（227,049,536 B）的保守访问窗口”处理：因此持久化发与池内**每个** buffer 都有边界依赖 → 其前后边界必须 full，plan 正是全 full 表（263/263）。
- 五个激活 buffer 被钉在 pass 1 存活的 POLICY 使池分配器**不能**在持久化发内部复用它们的槽（否则层 3 写 skip4 会踩层 0 的输入）；这是 M25 能成立的必要 alias 条件，已由 0 违规验证。
- **范围声明**：持久化发**内部**的任务级 RAW/WAR/WAW 不由图级屏障模型表达，由设备协议（done/epoch + release/acquire）覆盖，其正确性由四文件 gold 与 0 超时证明；不把“图级 0 未覆盖”外推成“内部依赖已被图模型证明”。
- 清零与 history 仍是每帧真实成本（110 处清零事件 + 2 处 copy）；本轮的数值门包含它们，未用“有效域”删除任何 padding/初始化。

## 6. 完成/未完成边界

**未完成（如实 OPEN）**：

2. **M25 的其他层**：只覆盖 C32 四层（同级多层）；宽体 C64/C128/C256 的 PERSIST（AMD 36→6 发）未做，需各自 body/帧网格与寄存器预算适配。
3. **native 计数器**：本轮全部 NOT_COLLECTED（工具在，但新 SPV 的 XMX/ALU/SEND/停摆采集未执行），因此不认领任何独占时间/占用率/运输改善；M23 的 105 条 none 与 M25 的持久化都只有整网普通耗时。
4. **M23 的“最小集”仍未主张**：模型给的是“充分且由清零/history 支撑的整表”，不是“物理上不能更少”；未删的 102 个 full 边界是否有替代同步未证。
