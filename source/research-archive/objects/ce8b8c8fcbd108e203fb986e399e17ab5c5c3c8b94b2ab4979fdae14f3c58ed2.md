## 三、首个候选：F3-C32 保留父分窗，按半 tile 写出

新建独立版本，例如 candidates/amd-layout-fusion-resume-20261016/f3-c32-keep-anchor-half-tile-v1/。以父 pass7 的已接受 WG128 body 和旧失败候选的交接实现为参考，保留原 half 运算、NoContraction、K 累加顺序和 skip4 写回。不要重新做整窗单 SG body，不重排注意力窗口。

### 3.1 必须保持的实际配置

父 pass7 为 block4_swin_body_1，逻辑 row4；body SPV 为 ROOT/candidates/register-handoff-20261016/c32/local-fma-nc-wg128-v1/c32_register.spv。

| 项目 | 必须值 |
|---|---|
| local_size / subgroup | 128 / SG32，四个 subgroup |
| dispatch | 84×49×1，不能减成 84×48 |
| p0.x / p0.y | tiles_x=168 / shift_x=0 |
| p3.z / p3.w | tiles_y=96 / signed ty_bias=-1；word15 的无符号编码为 4294967295 |
| body tile owner | tx=2*wx+(sg&1)，ty=2*wy-1+(sg>>1) |
| 融合范围 | 父 pass7 body → pass8 mean+learned projection，2→1；当前全网 278→277 发 |
| 必须保留 | skip4 供 decoder 使用；block4_out；原 HISTORY/OUTPUT 语义 |

body 的一个 4×4 tile 内含四个独立 2×2 均值；每个均值的四个 body 像素属于同一个父 subgroup。需要分开写的是池化后完整 4×4 tile 的上下半块，均值自身不需要跨 workgroup 通信。

### 3.2 同时修 mean 的全局坐标与 store 起点

沿用现有 nrf_tile 到 nrf_mean[16*32] 的 slot 排列，保持局部四个 half 的加法树、乘 0.25 和 half 舍入。对窗口中的池化 slot 0..15，真实全局坐标为：

```text
px = 4*wx + (slot & 3)
py = 4*wy - 2 + (slot >> 2)       // 用有符号整数
```

mean 的有效性检查也使用上述 signed py 以及 OW/OH、valid_W/valid_H。无效 entry 写确定的零，所有需要的共享 entry 在 barrier 前均有 writer。不能只修 store 的 py0，却继续用旧 py 判定 mean 有效性。

保持当前 DS 通道和矩阵行分配：

```text
n0      = (sg >> 1)*32
rowbase = (sg & 1)*8
px0     = 4*wx
py0     = 4*wy - 2 + 2*(sg & 1)   // 用有符号整数
```

每个 subgroup 的两片 M8×N16 half 结果分别写 n0 和 n0+16；两次 coopMatStore 使用同一个真实 py0，经原 layout0 的 io_at/nrf_ds_at 地址函数写出，保留原 K=32、N=64 的投影运算顺序。一个 M8 对应四列两行，恰好是一个输出 tile 的连续半块：

| sg&1 | body 行 | 池化行 | 输出位置 |
|---|---|---|---|
| 0 | 2*wy-1 | 4*wy-2、4*wy-1 | tile(wx,wy-1) 的 slot8..15 |
| 1 | 2*wy | 4*wy、4*wy+1 | tile(wx,wy) 的 slot0..7 |

当前 OW=336、OH=192、valid_W=336、valid_H=192。写前证明并检查完整四列两行均在界内：px0>=0、px0+3<OW、py0>=0、py0+1<OH；必要的 valid extent 同时满足后，才转换无符号并计算地址。wy=0 的前半块和 wy=48 的后半块不写；其余半块各有唯一 writer。所有 subgroup lane 必须一致执行或跳过 cooperative store；不要新增绕过 workgroup barrier 的提前退出。

报告 16 的 CPU 整数坐标证据已确认：64512 个有效池化像素各有唯一 owner，32256 段 128-half store 区间恰覆盖 block4_out 的 4128768 个 half。复用该证据，不重跑旧审计脚本。它是当前尺寸的地址可行性证明，不是新 SPV 的数值证明。当前 C32 适配不需要跨 workgroup 等待，也不需要为了写完整 tile 改 body 锚点。

### 3.3 必交的最小实现证明

- 对实际生成的 PASS/PUSH/绑定做针对性断言，给出 parent→candidate 的语义映射。只改计划 JSON 而实际 PUSH 未改，不允许进 GPU。
- 核对新编译 SPV 实际使用的 shared 交接、地址单位、half 运算边界及保留的 skip4 写回；区分 layout 编号与输出 base offset。原 p5.y 被用作输出基址，不能只凭旧注释把它当 layout 字段。
- 用新候选真实执行的 handoff/DS 输出和受影响数值门验证交接。若定位确需读出 nrf_tile/mean，才加一个实际消费这些数据的诊断；原 A 不能代替验证。诊断 SPV 与生产 SPV 分开，诊断时间不计收益。
- 给出首尾半块守卫、writer/consumer、全分配 padding/clear 的证明。实际 workgroup/指令工作量按 84×49 重算，不能继承旧 84×48 候选的计数。
- 数值通过再进入性能和计数器验收；失败保存版本和差异，仅停止本候选性能臂。不要预填会通过或会加速。

### C256 固定接口

父 pass83 的实际 DS push 为 IW=84、IH=48、OW=44、OH=24、K=256、N=512、dst_layout=1（word9），valid_W=42、valid_H=24。原 DS dispatch=132×16×1，M8 是 raster token 顺序的八行，不是空间四列两行。

block22_out 分配 1179648 B，即 1152 个 512-channel FP16 token；其 44×24 视图仅有 1056 token。以下三类必须分别证明：

| 区域 | 范围 / 字节 | 合同 |
|---|---|---|
| 有效数据 | x<42、y<24；1008 token | 对应原计算，按相同逻辑坐标逐位比较。 |
| 视图内 padding | x=42、43；48 token | 按原 DS 的 mean 置零及 projection 路径处理并覆盖，不能跳过后留下旧值。 |
| 分配尾部 | 1056..1151；96 token，98304 B | 原视图没有 writer；保留所需首次清零及原消费者约定，不能当成融合后自然全覆盖。 |

layout1 为 raster_token16：空间 4×2 patch 不保证在该布局下连续，也不能复用 layout0 的半 tile store 起址推导。交付每片 M8 的 raster 行顺序、真实物理地址、跨行/边界行为、writer 和消费者证明；必要时采用有明确定义的 staging/scatter 或合法分段 store。

如果要把 block22_out 改为 layout0，必须另列为 L2 布局候选，同时修改 split16 b23 等全部实际消费者（含 residual）、验证字节置换和上述两类 padding，再单独测或明确标组合候选。不能悄悄改变 layout 后仍把收益全归 F3-C256。INT8 也不会自动修复错误坐标或未写 padding。
