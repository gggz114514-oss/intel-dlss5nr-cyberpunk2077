# n03b-f04-c256 — native 可观察点与判据（预测，不是“已证明”）

本卡**没有 GPU**：下面是“若实现落地，ISA 里必须出现的可观察变化”，以及“看不到就等于未实现”的判据。
所有“父”列数字来自只读采集
`fullnet-mechanism-transfer-20261026/f10-weight-return-separation-20261027/captures/native-f20-pixel-owner/ISA/CS_asm95c51e1663cef130_simd32_000000000000000d_12_orig.asm`
（sha256 `2470b4ccfed606085ae4a69d0a3f64deaadb1783a0ec6dde860ab0970d7b16e0`，即链头 C256 F04 的 native 身份；
`NATIVE-REVIEW.json` 把它记为 width 256 / ordinal 36 的 candidate，指令 6549、Basic Block 429、Scratch 0、WG Memory 8192）。
计数方法：`ISA.py` 的行解析 + 消息注释（`// wr:…, rd:…; <intent>[addr]`）分类，与 `PROOF.json/messages` 一致。

## 1. 必须看到的可观察变化（按重要性排序）

| # | 观察项（ISA 里的逐字形态） | 父（实测） | 预测候选 | 判据 |
|---|---|---|---|---|
| 1 | `load.ugm.d32x64t.a32.bss`（256 B A tile / seed，`rd:4`） | **132** = barrier 前 **128** + 后 **4** | **68** = 前 **64** + 后 **4** | 前段仍 128 → **A（实现未落地）**：IGC 把两个 hidden 块串行化了 |
| 2 | `Scratch Memory Size`（编译器元数据） | 0 | **0** | >0 → **B（副作用）**，按 CARD 立即回退 |
| 3 | `dpas.8x8 (16|M0)` 总数 | 352（expand 256 / middle 32 / contract 64） | **352** | 任一变化 → 数学被改，立即停（停止条件 1） |
| 4 | `load.ugm.d32x8.a32.bss`（512 B 权重 tile，`rd:8`） | **176** = 前 144（expand 128 + middle 16）+ 后 32 | **176** | 变化 → 权重读被改动，实现错误 |
| 5 | `store.slm.d32x8t.a32`（mLocal 发布） | 32（barrier 前） | **32** | 变化 → 误动发布 |
| 6 | `load.slm.d32x8t.a32`（contract A 读） | 256（barrier 后） | **256** | 变化 → 误动 contract A 读 |

| 8 | `load.ugm.d32x64t` 的 oob 谓词 `jmpi` | 134（其中 128 条属于 A 读） | **70** | 不降 → A 读没有真的减少 |
| 9 | `mov` 总数 | 2571 | **1900–2000** | 不降反升 → 散布/零填充被换成了别的搬运，或发生 spill/fill |
| 10 | `Instruction Count` / `Basic Block Count`（元数据） | 6549 / 429 | **5200–5450 / ≈365** | 大涨（>+150）→ 搬运或溢出代价 |
| 11 | `max_r`（最大寄存器号） | 127 | **127** | 文件已顶到 128 GRF 上限，不可能更低；若明显下降说明 acc 被拆小 |
| 12 | `Workgroup Memory Size` | 8192 | 8192 | 变化 → 计划/绑定错误 |

预测用的定量换算：C128 同变换实测（32 条 A 读被删）为 `Instruction Count −620 / mov −337 / sync −139 / send −32`，
即**每个被删 A 读 ≈ 19.4 指令 / 10.5 mov / 4.3 sync**；C256 删 64 条 → 期望
`Instruction Count −1100..−1350`、`mov −600..−700`、`sync −250..−300`。这是外推，不是测量。

## 2. 顺序证据（比计数更早暴露“假落地”）

1. **A 的返回区**：同一条 A `send.ugm` 之后应紧跟 8 条 expand DPAS（父是 4 条），期间不应插入下一 `ki` 的 A 读。
   若 A 的 `rd:4` 返回窗口被下一 ki 的读顶掉，说明 IGC 没有把这一条 A 复用到两个 hidden 块。
2. **权重装载次序**：`wh2/wh3` 的 send 应晚于 `wh0/wh1` 的 4 条 DPAS（源码顺序）。若 4 条权重 send 全被提到
   ki 头部，峰值多 2 个 `MAT_B`（+16 GRF），是 scratch 风险的主要来源；这属于 §4 已经入账的“瞬时权重 tile”。
3. **12 个累加器是否同时驻留**：expand 段应有 8 个不同的 DPAS 目的基址（父 4 个：r20/r28/r36/r44 的形态），
   且 4 个 middle 累加器跨整个隐藏循环活着。若只见 4 个 expand 目的基址，等价于“两个 hidden 块被串行化”，
   第 1 项计数会同时退回 128 → 判 **A**。

## 3. 分诊映射（先看 native，再看数值，最后看计时）

| native 形态 | 分诊 | 处置 |
|---|---|---|
| `load.ugm.d32x64t` 前段 128（或 132 总数不变） | **A 实现未落地** | 换表达：显式 8 个命名 acc + 手工分离两个 hidden 块的 DPAS 顺序，或把 A 片段显式复用到下一块；不是方法无效 |
| 前段 64 且 `Scratch = 0`，其余表项一致 | 落地 | 进入数值门 + ordinary |
| 前段 64 但 `Scratch > 0` | **B 有副作用** | 按 CARD 回退；记增量账（+32 GRF acc 是主因），针对活值修一版（例如成包时先做 C64） |
| `dpas/write` 计数或 `Workgroup Memory` 变化 | 实现错误 | 停，回到 §1 逐条对表 |
| fixed/fb2 首帧不符 | **E 数值失败** | 先查 act 的窄化点与 middle 的 hidden 步配对（本卡唯一的新增风险面） |

## 4. 不算 native 实现证据的东西

- SPIR-V 层的 `OpCooperativeMatrixLoadKHR` 计数变化（1746→2086 指令只是循环体变厚）。
- 编译日志、`plans` 的 PASS 数、`cpu_check`（这些是身份/绑定门，不是落地证据）。
- 端到端毫秒：**native 看不到第 1 项变化时，禁止用整体毫秒倒推“机制有效”**（合同 §8.5）。
