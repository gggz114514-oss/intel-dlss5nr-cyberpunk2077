## 1. 映射：生产者每个 (lane, component) 代表哪个 (token, channel/head/k)，消费者要求什么

本卡的改动只落在 **QKV 投影的六个权重（B）供料地址**上，因此下面把「本卡触及的 B 供料映射」写成可枚举表，
把「未触及但必须保持」的映射写成不变量（父身份已证，本卡逐条复核未变）。

### 1.1 该 PASS 的 owner 几何（源与 native 一致）

| 量 | 值 | 证据 |
|---|---|---|
| `local_size_x` | 256 = 8 SG × 32 lane | candidate.comp L63；native `(16|M0)`/`(32|M0)` 混合，QKV 段 exec 16 |
| head | `h = wgid.z*2 + sg/4`，每 WG 2 个 head | candidate.comp L142 |
| token owner | `m0q = (sg%4)*8 + row_phase*32`：4 个 SG × 8 token，两个 row_phase 覆盖 64 token | L155 |
| 每 head 输出通道 | 96 = Q(0..31) + K(32..63) + V(64..95) | pack 索引 `(96h+n)/16` |
| 六个累加器 | (Q,K,V) × (通道低半 0..15 / 高半 16..31) | accQ0/accQ1/accK0/accK1/accV0/accV1 |
| native 累加器实体 | r43,r51,r35,r59,r67,r75（row_phase0）/ r57,r49,r73,r33,r15,r89（row_phase1） | ISA-QKV-FEED.json `dpas[].acc` |
| K 步 | `k0 = 0,16,32,48`，每步 1 次 A 载入 + 6 次 B 载入 + 6 个 DPAS | L163–186；native 24 DPAS/相位 |

### 1.2 累加器 (lane, component) → (token, channel) 双向枚举

Intel CH 片段布局（源注释 L103 明确写出，并由 L231–249 的按分量归约使用）：

```
component ci ∈ 0..3 , lane L ∈ 0..31
row  = 2*ci + L/16      (0..7)   → token = m0q + row
col  = L%16             (0..15)  → channel = n0 + col
```

`(L, ci) → (row, col)` 是双射：`(L/16) ∈ {0,1}` 给出 8 个 row，`L%16` 给出 16 个 col，32×4 = 128 = 8×16。
覆盖性：每相位 4 个 SG × 8 token = 32 token，两相位 = 64 token，无漏无重；每累加器 16 个通道，
六个累加器 6×16 = 96 通道 = 该 head 的 Q/K/V 全部输出通道，无漏无重。

### 1.3 B（权重）供料映射 —— 本卡触及的唯一映射

父地址表达式（每个 load 站点各自求值一次）：

```
pack_index(h, n, k0) = wq + ( ((96h + n)/16) * 4 + k0/16 ) * 256
```

候选把它改成一次共享标量 + 常数偏移：

```
wq_row = wq + ((96h)/16) * 1024          // 每 WG 一次
wk     = wq_row + (k0/16) * 256          // 每 K 步一次（只提前一步，不外推到未来各步）
pack_index(h, n, k0) = wk + 1024*(n/16)  // n/16 ∈ {0,1,2,3,4,5}
```

整数恒等（不是近似，也不是"同帧"比较）：对任意 `h ≥ 0`、`n ∈ {0,16,32,48,64,80}`、`k0 ∈ {0,16,32,48}`：

```
((96h + n)/16)*4*256 = (6h + n/16)*1024 = 6144h + 1024*(n/16)
((96h)/16)*1024      = 6144h
(k0/16)*256          = 256*(k0/16)
⇒ 两侧逐项相等，且 96h 与 n 都是 16 的整数倍，除法无截断
```

逐 lane 的语义（由 d32x8 + LCOL + 地址步长共同定，native 侧可核）：

| (lane, half) | 读到的元素 | 含义 |
|---|---|---|
| lane `l ∈ 0..15`（exec `(16|M0)`） | `pack[pack_index + 16*l + j]`，16 halves | 输出通道 `n0 + l` 的全部 16 个 K 值（`K = k0 + j`） |
| 地址步长 | `lane * 32 B`（native `mul (16|M0) accX = rN.0 * 32`） | 16 lane × 32 B = 512 B = 16×16 half 片段 |
| 消费 | 恰好 1 条 DPAS（`dpas.8x8 ... rNN:hf`） | 24 次 send ↔ 24 条 DPAS，1:1（ISA-QKV-FEED.json bank_chains 每个 send 只有一个 reader） |

覆盖性：一个片段 = 16 通道 × 16 K = 256 元素；16 lane 各持 1 个通道的全部 16 个 K ⇒ 无漏读、无重复读；
六片段 × 4 K 步 = 96 通道 × 64 K = 6144 halves/head = pack 中该 head 的全部 24 个 tile（24×256），
与 `pack` 中相邻 head 的区间 `[6h*1024, 6h*1024+6144)` 不重叠。

**本卡没有改变任何上述映射**：改的只是同一整数由几个中间量相加得到。父与候选取到的 `pack_index` 逐 (h,n,k0) 相等，
所以 (lane,half) → 元素的对应、以及 DPAS 消费关系完全继承。

## 2. 删什么真实工作（只计正常执行路径）

### 2.1 SPIR-V（实测，非估计）

父 → 候选的整模块 opcode 差值（`build/spv-opcode-delta.json`，全函数对齐）：

| opcode | 差 | 归因 |
|---|---|---|
| `OpIMul` | **−33** | `((96h+n)/16)*4*256` 每站点重算 |
| `OpIAdd` | **−22** | 同上 |
| `OpUDiv` | **−22** | `(96h+n)/16` 与 `k0/16` 每站点重算 |
| `OpLoad` | **−20** | 每站点重新读入 `wq` 与中间标量（glslang 把 `const` 局部量落成变量 + 读回） |
| `OpConstant` | +1 | 新增的常数 |
| `OpName` | +2 | 新变量名（调试段，无运行成本） |
| `OpVariable` | +2 | `wq_row` / `wk` |
| `OpStore` | +2 | 上述两个变量各存一次/相位、步 |

逐站点被删的指令链（`build/spv-hunks.json`：15 个 hunk，其中 12 个是地址链删除，
每处恰好 9 条 = 2 `OpLoad` + 3 `OpIMul` + 2 `OpUDiv` + 2 `OpIAdd`；3 个是插入）：

```
- OpLoad, OpIMul, OpIAdd, OpUDiv, OpIMul, OpLoad, OpUDiv, OpIAdd, OpIMul
+ （该站点只余 1 个常数偏移）
插入：+2 OpVariable；+7（wq_row 一次）；+6（wk 每 K 步一次）
```

主函数 1787 → 1694 条（净 −93；−108 +15）。**没有任何浮点算子被删或新增**
（差值表里没有 `OpFMul/OpFAdd/OpExtInst`；NoContraction 80/80 逐条对齐，见 BUILD.json）。
另据 `spv_scan.py`：模块内 `OpTypeInt 64` 为 0 个、无 64-bit 转换或 64-bit 算术 —— 该核的地址全部是
32-bit 标量整数，所以省下的是纯标量整数指令，不存在"64-bit 地址折叠"的隐藏成本。

### 2.2 native（父，实测；候选为预测，见 NATIVE-PREDICTION.md）

父 native 的 QKV 两段共 **782 / 4229** 条静态指令（row_phase0 374、row_phase1 408），其中地址相关：

| 项 | 父计数 | 说明 |
|---|---|---|
| `add` | 205 | 含 16-wide 每 lane 地址向量 |
| `mul` | 49 | `mul (16|M0) accX = rN.0 * 32`，≈ 每个权重 send 一次 |
| `shl` | 21 | 标量基址 ×2（half→byte） |
| `or` | 14 | 标量地址位拼装 |
| `mov` | 189 | A 片段装配 + 地址向量低/高半重建 |
| `add3` | 4 | 标量基址 + 两个立即数 |

本卡要删的正是 49 个「每 send 重算的地址量」中的可共享部分；**但父 native 也说明它不会白送**：
`sync.nop` 在这些站点同样密集（QKV 两段 103 条），说明地址/返回区的等待是显式编排的。

### 2.3 不删什么（明确）

- 不删任何 send（48 权重 send 全保留，B 读取次数不变）。
- 不删/不改 A 窗口（每 K 步 1 次 A 载入、4 次/相位，位移不变）。
- 不删 SLM 往返、不删屏障（该 PASS 只有 1 条 `sync.bar`，未动）。
- 不删归一化、den 树、exp、PV、T 存储的任何指令。
- 不改 Q/K/V 源语句顺序（本卡不动 QKV 顺序，只动地址算术）。

## 3. 重叠：独立工作原来如何重叠，谁挡住谁

### 3.1 值级 RAW/WAR/WAW（每 K 步，单相位）

| 值 | 生产者 | 最后消费者 | 覆盖者（下一写者） | 冲突 | 父怎么处理 | 候选是否变 |
|---|---|---|---|---|---|---|
| A 片段（8×16 half, gY 行） | `load.ugm d32x8t` + 8-wide mov 装配 | 该步 6 条 DPAS | 下一步 A 载入 | WAR（新载入 vs 旧 DPAS 源读） | `$n.src` | 未变 |
| B 片段（8 GRF 返回区） | 权重 send | 恰好 1 条 DPAS | 同区内下一次 send | WAR | `$n.src`（例 r19: 0x0DC0→0x10A8→0x10C0） | 未变 |
| 累加器 | 步 s 的 DPAS | 步 s+1 的 DPAS（RAW 链 0→16→32→48） | 窄化/存储后的下一次投影 | RAW | 结构保证 | 未变 |
| **B 地址向量** | 整数 add/shl/mul | **一次 send** | 该 send 的返回区写入、或随后的 A 装配 mov | **WAR/WAW，跨整段** | 短寿命临时量，可与返回区同寄存器 | **改为跨一步共享的 `wk`** |

### 3.2 父 native 的实证：地址值与权重返回区同寄存器（这是本卡的核心证据）

`ISA-QKV-FEED.json`（对 `CS_asm6a22246177be2653..._0006_5_orig.asm` 的逐条解析）：

| 寄存器 | 作为 B 返回区（被哪条 send 写 / 哪条 DPAS 读） | 作为权重 send 的地址 payload | 判定 |
|---|---|---|---|
| r7 | send 0x1760 → DPAS 0x17F0 (acc r67) | 0x0DC0, 0x1560, 0x1690, 0x1F90, 0x2070 | 双角色 |
| r8 | send 0x1600 → DPAS 0x1740 (acc r35) | 0x0DD0 | 双角色 |
| r18 | send 0x1F90 → DPAS 0x2058 (acc r59) | 0x1D30 | 双角色 |
| r22 | 5 条 send（0x1690/0x17C0/0x1B60/0x1C20/0x2070），5 条 DPAS 读 | 0x14A0 | 双角色（最重） |
| r4,r5,r6,r10 | — | 其余 16 条 send | 纯地址 |

row_phase0：**8 个地址寄存器中 4 个同时是权重返回区**；24 条权重 send 只用 **12 个返回区**，
其中 r19 被 4 个片段复用、r27 被 3 个复用、r22 被 5 个复用。

紧耦合样例（r22，row_phase0）：

```
0x1400  add (16|M0) r22.0 = r121.12 + acc0.0      ← 造地址（16 lane 向量）
0x14A0  send.ugm  r23  r22  ... {$6}              ← 用 r22 作地址
0x1690  send.ugm  r22  r7   ... {$15}             ← r22 改作权重返回区
0x17A0  dpas.8x8  r59  ...  r22:hf                ← 读 r22
0x17C0  send.ugm  r22  r7   ... {$2}              ← 同一区再次返回（依赖上一 DPAS 源读）
0x1908  dpas.8x8  r75  ...  r22:hf
...
0x2070  send.ugm  r22  r7   ... {$8}
0x2110  dpas.8x8  r67  ...  r22:hf
```

r19 的三连串（k0 步只有 3 个返回区在飞）：

```
0x0DC0 send r19 {$7} → 0x10A8 dpas(Q0) → 0x10C0 send r19 {$11} → 0x1328 dpas(K0)
      → 0x1340 send r19 {$13} → 0x13F0 dpas(V0)
0x15E0 mov (8|M0) r19.8 = r15.0        ← r19 又被用作 A 片段装配的高半
0x1D30 send r19 {$0}  → 0x1F70 dpas
```

**结论（第 3 问）**：原来能重叠的独立工作 = ①同一 K 步里最多 3 个权重载入在飞（r19/r27/r34）；
②下一步的 A 载入；③上一步的 DPAS。挡住的不是「B 数据本身」，而是**地址向量必须落在一个刚刚被 DPAS 读过的返回区里**，
于是「上一条 DPAS 源读退休 → 才能造下一次地址 → 才能发下一次 send」这段链被并进同一个寄存器生命周期。
本卡把地址值改成跨整步存活，使「返回区写入」与「地址值存活」在同一寄存器上不可同时成立。

## 5. 是否真落到 native（预测 + 判据，不声称已实现）

见 `NATIVE-PREDICTION.md`。三条必须同时成立才算落地：

1. 48 条权重 send 的**地址 payload 寄存器集合**与「该相位的 B 返回区集合」交集从父的 4（r7,r8,r18,r22；row_phase1 为 r7,r15）
   降到 **≤ 1**。
2. QKV 两段的 `mul (16|M0)`（每 send 一次的 `*32`）从 49 降到 **≤ 12**，且 `add/shl/or` 合计下降 ≥ 20。
3. 结构不变式全部保持：权重 send 48、DPAS 80、`sync.bar` 1、scratch 0、SLM 计数不变、返回区复用串仍是「1 send : 1 DPAS」。

若 1、2 都不变而 3 成立 → **A 实现未落地**（不是方法无效）。
若 1 成立但 `mov`/`sync.nop` 明显增加（例：> +40）→ **B 有副作用**，按最大副作用修一版（见 RESUME 的下一处改动）。

## 6. 整体是否更快（本卡不能测，写清要测什么、怎么归因）

- 要测的整体量：全网 ordinary（fixed 门通过后）两臂 base/cand 的整网帧时差，6 组交替 × 30 reps、warm 1、feedback，
  以组均值差 + t(df5) 区间报告，30 帧同进程不当作 30 个独立样本。
- 臂：`base` = 基线 plan（本组仍是 0d83192b）；`cand` = 本卡 plan（本组 7b6da747）。只差本组 8 个 PASS。
- 归因上限：本组 PASS 是 232 个派发位置里的 8 个，QKV 权重供料链又只是该 PASS 的 782/4229 静态指令中的地址子集。
  即使 native 判据 1、2 成立，也只能说「该链的地址不再占用权重返回区」，**不得**把整网毫秒差按单链归因。
  单链可归因的部分只有：native 判据 1/2 的成立与否，以及 fixed/fb2 门的通过与否。
- 若整网 INDISTINCT：按合同记 D，不推广为方向禁令；若 native 判据不成立，优先记 A 并改写下一步骤。

## 7. 本卡不做什么（避免重跑）

不重跑：C128 四块 B 滚动、六权重族、四权重 rolling、A 返回分离、双 A、phase1 双 A、无边界 Q/K 交错、subgroup 单点/全边界。
本卡不是「增加 B 预取数」：B 读取次数不变。不是 Q/K/V 语句重排：QKV 顺序、K 累加序、舍入点、den 树全部未动。
