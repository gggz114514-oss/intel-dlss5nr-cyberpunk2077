# n13b-f13-contract — NATIVE-PREDICTION（第 5 问：可观察点 + 判据）

**本卡没有 GPU，以下全部是预测，不是“已证明”。**
对照物：父身份的捕获 `run/codex-fp16-continuation-20261021/C/ct01-f17-native-001/gtpin/ISA/CS_asm479f1bb119e3b522_simd32_0000000000000002_1_orig.asm`
（sha256 `a6d4bc55…`）与 `compile/native-capture.json`（`Instruction Count 3458 / Basic Block Count 30 / Loop Count 2 / Scratch 0 / Workgroup Memory 0`）。
契约 §8.7：旧批不是当前身份，下面的“父值”只作**同一 SPV 字节**的方向参照（本组 8 行在链上未被任何已采纳卡改过，`PASS-TIME-RANKING` 标 `changed:false`）。

---

## 0. 先说清这个机制的 native 可见性

本卡删的是**执行**，不是**代码**：受护循环一行未动，仍然编译进模块（非 16 对齐 live 的回退路径）。因此

* 静态消息数 / DPAS 数 / mov 数 **预期几乎不变**；
* 静态能证明的是两件事：(a) 编译进去的确实是候选（**立即数变了**）；(b) 按新行公式，本 plan 下**没有 SG 会半活**，6/8 的第三片 SG 会走早退（**可达性变了**）；
* 真正“省了多少”只能由 `resources`/`ordinary` 给，**不能用静态计数倒推毫秒**。

## 2. 机制的可达性表（本卡的“处理是否形成”用静态枚举判，不靠计数）

`live = pc.p0.x = 288`（8 个 PASS 的 PUSH 全同），`grid.x = 3`，每 WG 8 个 SG。
按候选公式 `mA = wg.x*128 + sg*16, mB = mA+8`：

| wg.x | sg=0 | sg=1 | sg=2 | sg=3 | sg=4 | sg=5 | sg=6 | sg=7 |
|---|---|---|---|---|---|---|---|---|
| 0 | 0/8 | 16/24 | 32/40 | 48/56 | 64/72 | 80/88 | 96/104 | 112/120 |
| 1 | 128/136 | 144/152 | 160/168 | 176/184 | 192/200 | 208/216 | 224/232 | 240/248 |
| **2** | **256/264 快** | **272/280 快** | 288/296 死 | 304/312 死 | 320/328 死 | 336/344 死 | 352/360 死 | 368/376 死 |

* 18 个完整对偶（快） = 288 行全部覆盖，**0 个半活对偶**（父：4 个半活 + 4 个全死）；
* 6 个全死对偶在 `main` 入口 `return`，**不再进 K 循环**（父：这 4 个 SG 各发 512 条 512 B 宽消息、0 条 DPAS）。

判据：只要 ISA 里 #1/#2 的立即数是新值，上表就是**编译期可判定的**——本 plan 下受护循环的入口条件 `mA<live && mB<live` 对 18 个对偶成立、对其余 6 个两条都不成立，不存在第三个分支。

## 3. 阈值与分诊（写死，避免事后解释）

| 判 | 条件 |
|---|---|
| **A 实现未落地** | #1 仍是 `3:w`，或 #2 仍是 `64:w`，或 #3/#4/#5 全部无变化（BB 仍 30 且 IC 仍 3458） |
| **B 实现有副作用** | #4 >40，或 #5 >3658，或 #6/#7/#8/#9 任一改变，或 #10 非 0，或 #12 上升，或 `resources` 的每派发 GpuTime **上升而 #5 确实下降**（原因候选：第三片 WG 自身延迟 17,474→20,072 条/SG，+14.9%，没被 6 个空闲 SG 的槽位吸收） |
| **C 无净收益** | A 未触发、gates 通过、`ordinary` INDISTINCT（含 CI 跨 0） |
| **D 未检出（成包）** | C 且单点估计在 ±0.05 ms 内 → 按 L8 与 n11 合成 16 PASS 包复判，**不重写机制** |
| **E 数值失败** | fixed/fb2 任一 gate 末帧 ≠ gold（`1755e9c2…` / `9c3e511e…`）或 ordinary 末帧 ≠ `2b63d4ba…` → 先查行公式/写域，再查 epilogue |

## 4. 期望的资源侧观测（`resources` 臂，`zprof --metrics GpuTime`）

* 每派发 GpuTime：**下降**（若纯发射受限，上限 −12.4% ≈ −0.0105 ms；实测 IPC≈0.49，预期远小于此）；
* 8 个 contract PASS 全族求和：`PASS-TIME-RANKING` 父值 0.677131 ms（fixed）/ 0.678070 ms（fb2）；
* L2 侧：宽消息 −98,560 条/派发（−48.1 MiB 同地址重复读），DRAM 预期不变（未测，入 `unknown`）；
* 占用：WG 数、线程数、SLM 均为 0 变化。

## 5. 明确不声称的部分

* 不声称“已经省了 12.4% 时间”：这是指令槽模型值（静态块尺寸 × 实测行程），不是测量；
* 不声称“删掉的 48 MiB 一定变成带宽收益”：L12，被并发隐藏的消息不付钱；
* 不声称第三片 WG 变快：它自身延迟 +14.9%，收益来自整派发少 1.64 M 指令槽与 6/8 SG 的槽位释放，这需要 `resources` + `ordinary` 共同判。
