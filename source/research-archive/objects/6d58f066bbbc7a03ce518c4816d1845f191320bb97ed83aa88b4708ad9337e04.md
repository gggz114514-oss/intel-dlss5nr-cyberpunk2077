# COST - ViT QK static (sQ/sK per head)

`GPU_VERIFICATION=NOT_RUN`. **No timing, no GPU counter and no dispatch latency was measured
in this card.** Everything below is a static, countable property of the artefacts, except the
one item explicitly marked *estimated*.

---

## 1. Memory and payload

| item | before | after | delta |
|---|---|---|---|
| `vit_blockNN_scales` buffer, per block | 128 B | 384 B | +256 B |
| same, 8 blocks | 1024 B | 3072 B | **+2048 B** total network payload |
| BIND range (binding 1), 6 passes x 8 blocks | 128 B | 384 B | range only; residency unchanged (`resident=1`) |
| attention SPV, bytes | 41324 | 39800 | **-1524 B (-3.7%)** |
| attention SPV, SPIR-V words | 10331 | 9950 | -381 words |
| workgroup shared memory (plan `shared` field) | 20492 | 20484 | **-8 B** (`shQMax`, `shKMax` removed) |
| plan lines | 5011 | 5011 | 64 lines changed, 0 added, 0 removed |

The 2 KiB payload increase is the only network-level memory cost; it is inside one block's
existing per-block scale file and does not add a descriptor, a binding, a push word or a
buffer count (both plans still declare the same number of buffers, so the plan header is
byte-identical).

## 2. Work removed from the kernel (per workgroup launch)

Counted from the source and confirmed by the opcode census (CONTRACT §6):

| operation | before | after | note |
|---|---|---|---|
| `OpAtomicUMax` (Q) | 1 / launch | 0 | the site this card closes |
| `OpAtomicUMax` (K) | 1 / 64-key chunk = 5 / launch | 0 | the site this card closes |
| `OpAtomicUMax` (V) | 5 / launch | 5 | unchanged, `sV` stays dynamic |
| total atomics | 11 / launch | 5 / launch | -6 |
| full traversal of the 2048-element Q tile for the absmax | 1 extra pass (2048 f16 loads + 2048 `FAbs`/`FMax`) | **0** | the dynamic `sQ` needed its own pass; the code pass now runs once |
| full traversal of the key/value tile for the absmax | rides the existing `sk`/`sv` fill pass | unchanged | the K absmax was *parasitic*, so removing it saves no memory traffic |
| workgroup barriers | 2 (Q reduction) + 1 (q8 publish) + 3 per chunk x 5 | 1 (q8 publish) + 3 per chunk x 5 | **-2 barriers per launch** |
| uniform scalar loads from binding 1 | 0 | 2 per invocation (`Scales[32+h]`, `Scales[64+h]`) | constant-cache, cost not measurable here |

So the honest split is: the **K side is compute-neutral** (its absmax was fused into an
existing pass; only an atomic and a barrier go away), while the **Q side really does remove a
full extra pass over the query tile**. Whether that shows up in a frame time is unknown - this
kernel is bandwidth/latency oriented and the pass was only 2048 f16 elements per workgroup.
No speed-up is claimed.

## 3. Risk surface added

| risk | mitigation in this candidate |
|---|---|
| a mis-sized BIND range -> the shader reads outside the descriptor | all 48 BIND rows are set to the full new buffer size (384) in the same edit; `planlib.validate()` and an explicit post-check assert `offset+bytes <= buffer.bytes` for every row |
| a pack slot left at 0 -> division by zero / inf codes | the shader keeps a `>0 ? : 1.0` fallback and the pack builder asserts all 64 constants per block are `> 0` |
| a constant buffer placed in the pooled-transient path -> never uploaded | verified: all 8 tables are `POLICY <idx> 1 <first> <last> 0`; asserted by the builder, not edited (CONTRACT §4.3) |
| `shared` field drifting out of sync with the module | recomputed from the disassembly; the same code path reproduces the deployed value 20492, so 20484 is cross-checked |
| a stale 128 B file being uploaded against a 384 B BUFFER row | the runner rejects a size mismatch (`cold input size mismatch`), and each pack's first 128 B are proven byte-identical to the deployed file |
| calibration leaking from eval frames | packs are built from F1 only; F2/F3 are used only to measure |

## 4. Deployment cost

* Not deployable as-is: the plan binds absolute paths inside this card's work area, and the
  candidate has not been through a GPU numeric gate, let alone a quality run.
* A productionisation would need: the 8 packs moved into a named pack directory with a
  manifest, the SPV placed in a candidate `spv/` dir, and the plan's 64 changed lines applied
  to whichever plan is the current integration head (not to 34189, which is a measurement plan).
* Rollback is one line: point the 8 PASS rows back at `r12r15_vit_attention_qk8_pv8.spv`,
  revert the 8 BUFFER rows to 128 B and the deployed file, and the 48 BIND rows follow the
  buffer size. No shader edit, no weights edit, no game file.
