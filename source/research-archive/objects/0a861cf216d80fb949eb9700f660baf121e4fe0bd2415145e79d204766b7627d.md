## 4. R14 写域三条（问题 4）

### 4.1 写域 589824 B — 成立（CPU_STRUCT）

`b30_l4_int8.comp`：`gh_store`（18–23 行）地址 `gh[(Py*pc.p7.x+Px)*1024u+c]`，`p7.x=24`；`token_at(s)=WorkGroupID.x*16+s`（17 行）；每次 lane、每 side 4 次 store（48–51 行）；dispatch 18×8×1（PASS 行与 `B30-L4-CONTRACT.json` 一致）。

- `tile=t/16∈[0,18)`，`slot=t%16`；`Px=(tile%6)*4+slot%4∈[0,24)`，`Py=(tile/6)*4+slot/4∈[0,12)`。
- `t↔(Py,Px)` 是双射 ⇒ 288 个位置各写一次、无遗漏；288×1024×2 B = **589824 B**，最大 half 索引 294911（最大字节偏移 589823）。
- store 覆盖：lane 的 `rp=lv>>4∈{0,1}` 与 `h[0..3]` 组合覆盖 `m0..m0+7` 全部 8 行，`c=base+16*side+(lv&15)` 覆盖 32 列/side ×2 side；8 个 y-group ×128 = 1024 通道；18 WG ×16 = 288 token。全域恰好一次。
- 与 capture 一致：参考重算 294912 个 half，**neq 0（max_ulp 0）**。

### 4.2 24 个 padding token 是「写出的值」— 成立（CPU_STRUCT）

- 写出来源：`b30_l3_int8.comp` 29–38 行显式清零 **pool** 的 `Px=22,23`（`pid<24`→`Px=22+pid%2, Py=pid/2`，24 位置 ×512 通道 = **12288**），同时写 `gp=half(0)` 与 `qp=int8(0)`。
- l4 照常读这些位置（26–29 行 staging 覆盖全 16 token；tile 遍历覆盖 `Px=22,23`），算术链 `q=0 → int32 acc=0（精确） → f=0*scale=+0 → half(+0)`，**没有跳过分支**。
- capture 证据：24×1024 = **24576 个 half 全为 0x0000**（nonzero 0），`pool` 与 `qpool` 的 padding 也都为 0。
- 因此它们**是 l4 写出的 +0 值**，不是 POLICY clear 的结果；若删掉 l3 的清零，l4 会把陈旧 pool 值写真进 ViT 入口（值仍被写，但不再是 0），这正是 `B30-VIT-INPUT-CONTRACT` 警告的失效方式。

### 4.3 尾部 196608 B 未被写、未被读 — 成立（CPU_STRUCT + descriptor 范围）

- 未写：最大 half 索引 294911 < 294912 ⇒ 字节 [589824, 786432)（= **196608 B / 96 个 raster 位置**）永不写。capture 里该尾部 **nonzero = 0**（与 POLICY clear 一致）。
- 未读：消费者 `vit_block31_ffn_expand` 的 binding 2 是 `block30_out`，**range = 589824 B**（G3 与合并 plan 均如此）；其源码 `vit_nb04_mpair.glsl:53` 读 `x[pc.p5.x+t*1024u+col]`，`t<288`（push p0.x=288）、`col<1024` ⇒ 最大索引 294911。两条独立边界同时封住尾部。
- 清理合同保留：合并 plan 中 `POLICY 343 0 118 121 1`（clear=1，窗口随插入位移），ViT 侧 range 仍 589824。

## 7. 未解决阻碍与未验证项

1. **执行 SPV 身份未封印**：需要 runner 在 `port_network_receipt.json` 落每个 PASS 的模块 sha256；否则任何「历史通过」都无法绑定到具体字节。

7. `NATIVE`（GRF/scratch/SLM 实分配）未知；声明 shared 下降不等于 native 分配下降。
