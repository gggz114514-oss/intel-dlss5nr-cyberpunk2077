# C32 整条生产消费链：实现、首差修复与 GPU 结果

## 结论

保留的父基线是 `c32-owner-layout-20261025/plan.txt`，其中已有 C32 FFN owner 改造和 F20-linear。新候选 `norm-contract/plan.txt` 将七个 C32 位置的整条链改为 token-major，fixed 与双帧反馈逐位通过，native 无新增 scratch send。相对该组合，3个进程对×30样本的无插桩端到端计时平均节省 **0.375311ms/帧**，95% CI **[0.115092,0.635530]ms**，三对全正，约1.73%。

旧组合、旧权重、F20模块和已验证收益均原样保留。新方案独立落盘，未部署到游戏或稳定包。历史不同批次收益不得简单相加当作实测组合收益。

## 统一的完整范围

每个工作组128线程，四个SG32，每SG负责16个query/token和全部32个feature。

| 阶段 | 生产/消费布局与 owner |
|---|---|
| FFN | 沿用已验证的 token-major expand→contract；CH→A直接组件交接 |
| Y→QKV | Y保留token×feature，作为A直接输入；QKV权重按16×16位转置后作为B |
| norm | Q/K保持自然CH owner；跨feature lanes复现原加法树和feature31的FMA边界 |
| K发布 | shared K以feature×key存储，QK的B按这一布局读取；跨SG仍需一次barrier |
| V发布 | shared V以key×feature存储，供PV的B读取 |
| QK | query×feature的Q直接作A；输出query×key，不再先join Q |
| exp/den/P | 保留half exp和64-key的特殊加法树；归一化P保持query×key |
| PV | P的CH直接作A，V作B，Ctx输出query×feature |
| 输出投影 | Ctx直接作A，转置权重作B；Y同坐标半精度乘残差尺度后先宽化为累加种子 |
| 输出 | 直接写回既有tiled image ABI，无最终转置或额外输出缓冲 |

这样不仅删除了FFN出口转置，也删除了Y→QKV、Q→QK、P→PV和Ctx→输出投影的join。残差没有在末端补回转置。

七份新权重仅在原C32-owner权重上进一步位转置QKV的3072half和输出投影的1024half，每个16×16块按uint16搬移，不重新量化、不改值。其余字节检查不变。各buffer仅被目标PASS消费；绑定、PUSH、网格、资源数及F20均不变。总矩阵乘仍为128：FFN64、QKV24、QK16、PV16、输出8。

## 舍入和首差闭环

build.py以符号节点验证原norm的有序树和den的有序树。den不是普通平衡树：先分别对k与k+8配对，按四个16-key块从half零开始顺序累加，再按2、4、1的lane位归约；源级节点顺序已复现。所有输出累加器保留原K16块次序；H(Y*残差尺度)在首个输出MMA之前宽化。

第一版整链数值门失败，未运行性能测试。单WG诊断证明X、E、Y、rawQ、rawK逐位相同，首差为4个nq和2个nk。增加诊断写出没有改变原Qnorm/Knorm差异。进一步导出norm总和，CPU逐位模型得到：

- 父版的128个Q/K总和全部匹配“仅feature31平方进入单舍入FMA”的模型。
- 失败候选的128个总和全部匹配“所有高半区平方进入FMA”的模型。
- 普通平方、分支、加法已有precise约束，但新SPV缺少父版在两个显式FMA上的NoContraction装饰，编译器扩大了融合范围。

修复只向full_norm的两个FMA结果添加NoContraction，源码算术和布局不变。修复后fixed帧为1755e9c2…，fb2第二帧为9c3e511e…，全部逐字节匹配父gold。不是放宽数值阈值。`fix_norm_contract.py`可复现这两处SPV修复；原失败身份与所有诊断仍保留。

## 完整成本账：统一方向并非零成本

每SG原边界交换：出口transpose20、Y join8、Q join8、P join16、Ctx join8、norm1、den1，共62次packed shuffle。新候选删除前五项共60次；norm变32次、den变28次，共60次。**因此整链shuffle净减只有2次，而非删掉60次后忽略新的归约成本。**

新方案归约所有权还有重复计算：native rsqt从2增至16，inv从1增至8。它们属于真实执行路径。未来若继续减少这些成本，需要明确的query系数owner及分发证明，不能用不同的归约树替换。

| 资源/工作 | 当前组合 | 新整链 |
|---|---:|---:|
| DPAS位点 |128|128|
| 声明SLM |8192B|8192B|
| 源级跨SG barrier |1|1|
| packed shuffle/SG，源级调用展开 |62|60|
| native rsqt |2|16|
| native inv |1|8|
| native SLM send |153|421|
| native scratch send |0|0|

新的SLM send组成：384条load.slm.d32x8t、32条store.slm.d32x8t、4条store.slm.d32x4和1条fence。没有新增shared张量，但加载次数与指令粒度明显增加。QK当前两个8-query片段分别加载K的B块，逻辑K供料为8192B/SG，对比父版4096B/SG；PV的逻辑V供料仍为4096B/SG。以上是源级请求字节，不是DRAM带宽，也不是帧级实测等待时间。不能宣称这版在所有连接上都删工作。

新native `227a579a558b29e7` 的整文件静态指令6228条，包含调试分支，不能拿它当正常路径动态工作量。实测净收益包含这些新的归约、SLM供料、读写布局和调度响应，不能孤立归因给shuffle数量下降。后续最具名的可查项是配对query复用K块和SLM消费者瓦片布局，当前未擅自扩大验证范围或将它们宣称为已实现收益。

## 寄存器与生命周期

Y从FFN结果到末端残差保持half，32B/lane；没有提前将残差长期宽化为float。QKV各自的float投影累加器在窄化后退休。Q在score生成之后退休；K/V跨SG通过原大小的SLM发布。P仍需要覆盖原den全部64key，再按K16顺序被PV消费；不改变den次序，也未引入online softmax。Ctx窄化后直接作A；输出累加器仅在投影阶段存在。

矩阵值有效载荷上，PV阶段是P64B/lane、Ctx累加器64B/lane、Y32B/lane，再加短期供料和地址值。该源级账不能证明物理峰值。新native未出现scratch访问；实际GRF分配量与精确峰值未取得，因此只声称“没有观察到编译器新增scratch溢出”，不把最大寄存器编号当占用率。

## 执行纪律与证据

主审负责源码、映射/树证明、权重变换、诊断设计及独立回读，Luna只执行指定GPU作业，全部串行使用唯一锁。Luna报告两项执行器事故：norm probe的输出根一度指向DIAG目录，旧DIAG结果文件未丢，但旧锁证据被覆盖；本批证据已复制到独立NORM-PROBE-EXECUTION并如实登记。native诊断执行器另一次在GPU启动前因时间属性语法失败，自身无活跃GPU作业的遗留锁核查回收后修复；不计为GPU运行。两者均不隐藏，不改写为数值或性能结果。

最终候选与门/native/ordinary证据在norm-contract/。原失败身份、单WG诊断、rawQK/norm probe、sum probe、CPU模型分别保留在本目录下。当前GPU队列已结束，原C32＋F20组合仍可独立复用。
