## 0. 硬判据（写死，先看这一条）

> **判据 H0（落地/未落地）**
> 捕获 ISA 的 kernel attribute `Workgroup Memory` 必须从 **24576 B 变成 16384 B**，
> 且 `plan.txt` / `plan-c256.txt` 里被替换那几行的 `shared` 字段同步为 **16384**。
>
> * 两处都变 ⇒ 本卡的机制**落地**，再看数值/资源，最后才看毫秒。
> * **ISA 仍是 24576（或 32768 等旧值）⇒ 判 A 类"实现未落地"**，直接记 A，不许用整体毫秒倒推
>   "驻留机制有效"或"机制无效"。SPIR-V 字节下降只是必要条件，不是落地证据。
> * SPIR-V 已 16384 但 ISA 仍 24576 ⇒ 说明驱动/编译期没接受新声明（例如把 `qkv[8192]` 补齐到
>   某个分配粒度以外的量），同样记 A，并列出实际 attribute 值。
>
> 本卡已证的部分：SPIR-V `Workgroup` 求和 = **16384 B**（三组；`build/build.json.storage_bytes`），
> 声明 `qkv[12288] → qkv[8192]`，plan 字段 8+12+16 行 / 16 行两档均已同步（`build/plan.json`）。
> 未证的部分：驱动/ISA 侧的实际分配。

## 2. 资源/占用率可观察点（resources 臂）

* 16 个 C256 PASS 行的**实测占用率**应随 `Workgroup Memory = 16384` 上台阶；父值参考
  `evidence/OCCUPANCY-CANDIDATES.json`（24576 B 桶：`occ = 64.44%`）。
  **注意**：该桶是 36 行混合值，本卡第一档只动 C256，所以占用率应按 PASS 看，不按族看。
* **控制探针（可选但强烈建议）**：把 `qkv[8192]` 再填回 `qkv[24576]`（49152 B，数学不变，
  与本卡同源的参考探针做过三次），确认"新的驻留台阶确实存在"。若填充后**没有**变化，
  说明这条约束在本身份上不是 SLM（那就是寄存器/线程槽封顶），第一档的收益预期应归零。
* 反向判据：若 16384 B 下占用率**没有**上升，则驻留不是被 SLM 卡住的，本卡的钱花在了别处，
  必须在 RESUME 里把这一条写清楚，且不要给第二档派 GPU。
