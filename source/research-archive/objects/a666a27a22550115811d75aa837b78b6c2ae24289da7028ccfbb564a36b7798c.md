## 1. 映射：生产者每个 (lane,component) 代表哪个 (token,channel/k)，消费者要求什么

本核的 24 条贵操作只作用在两类量上，映射都能一一枚举：

**(a) 16 条 `math.rsqt` = Q/K 的 L2 范数。**
`full_norm(qlo,qhi,klo,khi)` 每次算 **一对** (q,k)：`q = qlo² + qhi²`、`k = klo² + khi²`，
各在 **16 lane** 内用 4 步 `xor` 树（8/4/2/1）求和，再 `inversesqrt(max(·, 6.2e-05))`。

| 调用 | 源行 | 实参（qlo,qhi,klo,khi） | lane 语义 | rsqt 站点 |
|---|---|---|---|---|
| 1 | 520 | `q00[0],q01[0],k00[0],k01[0]` | 第 0 个 component 的两个 half-channel | 2206(q) / 2220(k) |
| 2 | 525 | `[1]` | 第 1 个 component | 2298 / 2314 |
| 3 | 530 | `[2]` | 第 2 个 | 2391 / 2408 |
| 4 | 535 | `[3]` | 第 3 个 | 2486 / 2495 |
| 5 | 548 | `q10[0],q11[0],k10[0],k11[0]` | 第二组 token 行（`t0+8`）第 0 个 component | 2709 / 2794(?) |
| 6 | 553 | `[1]` | | 2794 / 2813 |
| 7 | 558 | `[2]` | | 2817 / 2892 |
| 8 | 563 | `[3]` | | 2910 / 2985 / 2994 |

- **覆盖**：每个 (token, head, component) 恰好一次；`col = gl_SubgroupInvocationID & 15`，
  16 个 lane 各持一个 token 的 partial sum，树后每 lane 拿到**同一个和**（全 16 lane 相同），
  再各自乘到自己的 q/k 上。
- **尾块**：`if(col==15u)` 用 `fma` 重算一次（lane 15 的舍入修正），不产生额外 rsqt。
- **消费者要求**：`q *= n.x * headscale`、`k *= n.y`（各 6 条 `mul`）。
  一一覆盖、无漏读、无重复写：见 `C-CONSUMERS.json`（每站恰好 1 个 narrow 消费者）。

**(b) 8 条 `math.inv` = softmax 分母的倒数。**
4 个分母组 × (`d.x`,`d.y`)。每组对 4 个 `p0x` 的同一分量做 4 步 `xor 8` + 3 步 `xor 2/4/1`，
得到 16 lane 相同的分母；`1/max(d, 6.103515625e-05)` 后乘回 8 个 `p` 分量。

尾块：无（`p` 的 4 个分量都在这 4 组里，覆盖完整）。

## 2. 删什么真实工作

**一条都没删**（本卡不删指令）。而且逐条判定「能不能删」：

| 候选删除 | 数量 | 判定 | 依据 |
|---|---|---|---|
| 16 条 rsqt 中的任一条 | — | **不可删** | 24 条贵操作 = 24 个不同 reaching definition（`REDUNDANCY-PROOF.md` §1） |
| 8 条 inv 中的任一条 | — | **不可删** | 同上；4 个分母 × 2 分量，输入互不相同 |
| 归约树（4+3 步 shuffle）换 `subgroupAdd` | 每站 7 步 | **禁止** | CONTRACT §3：norm/den 归约树不变 |
| `if(col==15u)` 的 `fma` 修正 | 每站 2 条 | **不可删** | lane 15 的舍入点 |
| debug 岛（1187 条） | 1187 | 不删 | `debug==0` 已整段不可达（CFG 实测），且 L17：dead code 不是帧成本 |

## 3. 重叠：独立工作原来如何重叠

| 块 | 生产者 | 最后消费者 | 覆盖者 | 边 |
|---|---|---|---|---|
| A: 8 棵 norm 树 | `mul` 平方（`q*q`） | rsqt 的 clamp（`sel (ge)`） | 无（直通） | 树→树：**无**（不同分量寄存器） |
| B: 4 个 norm apply | rsqt 结果 | `coopMatStore(k…)` / QK dpas | 无 | B→A：RAW（读 n.x/n.y） |
| C: 4 棵分母树 | `add` 重排 | `inv` 的 `max` | 无 | 树→树：无 |
| D: 4 个 den apply | inv | PV dpas | 无 | D→C：RAW |
| E: k/v store | apply 后 | barrier | 无 | E→B：RAW |
| F: `tc00/pv_early_b` | barrier 后 | 第一个 PV dpas | 无 | F→B0：RAW（只读 `p00` 的 apply 结果） |

父的重叠实况（ISA 实测）：每条 rsqt 与它自己的 apply 之间，IGC 只塞进了
**下一 component 的 4 条平方 `mul`**（如 2216–2219 夹在 2206 与 2220 之间），
所以 8 条 rsqt 里 8 条 `d_first ≤2`、`d_arith` 只有 3–8。

## 5. 是否真落到 native（预测 + 判据）

见 `NATIVE-PREDICTION.md`。三句话：
1. 卡面的「首消费者 ≤2→≥20」在 F02 **不可达**（首消费者是同表达式的 half 舍入，SPIR-V 实测父/候选都为 1）。
2. 替代判据是 `d_arith`（过舍入点后第一个 `mul`）：父 rsqt 3–187 / inv 5–10；
   候选在 SPIR-V 侧的请求是 4 棵树/4 棵分母树前置（每棵 85–130 条）。
3. 按主代理 L26（n32 实测源码顺序改不动 IGA 调度），**预期 A 类**；
   若 capture 里 `d_arith` 与父逐条相同，就是 L26 的第二次独立复现，不是本卡实现失误。
