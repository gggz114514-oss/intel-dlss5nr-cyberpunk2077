# LATENCY-AUDIT — n33-f02-latency（F02，kernel `7a38a17947f21ae6`，7 个 PASS）

**任务 A 的交付**：在当前身份的**可执行路径**上，把 F02 的 16 条 `math.rsqt` + 8 条 `math.inv`
的生产者→首消费者距离逐条定出来，给出改动前后可比的直方图，并列出它们周围**已存在但顺序写错**的
独立工作（含 RAW/WAR/WAW）。

结论先写：**距离审计与 `evidence/LATENCY-EXPOSURE.json` 逐条吻合**（≤2:16 / 3-10:7 / >10:1），
但本轮实测出一个**比卡面更硬的结构事实**——
本核每条贵操作的首消费者是**同一条表达式里的 half 舍入转换**，因此
「首消费者距离」在**任何纯语句重排下都不可能 >1**（SPIR-V 实测：父 1，候选 1）。
可被重排改变的是**过舍入点之后的第一个算术消费者**（父：rsqt 3–187、inv 5–10）。
⇒ 卡面的「≤2 → ≥20」判据对本核不成立，`REDUNDANCY-PROOF.md` 又把删除路线证伪，
本卡最终判 **BLOCKED**（§7）。

本文件所有数字由本目录脚本在**只读**证据上重算，CPU-only，无 GPU、无 plan 部署：

## 3. **卡面判据在本核的结构性上限**（本卡最重要的发现）

`full_norm` 的最后一行是

```glsl
return f16vec2(float16_t(inversesqrt(max(float(q),float(float16_t(0.000062))))),
               float16_t(inversesqrt(max(float(k),float(float16_t(0.000062))))));
```

`float16_t(...)` 就是 §2 里的 `mov :hf<-:f`。它和 `inversesqrt` 是**同一条表达式**，
所以在 IR 里 rsqt 的**第一个**消费者必然是那条转换：

| 口径 | 父 | 候选（纯语句重排后） |
|---|---|---|
| SPIR-V 展开流条数 | 13408 | 13420（+12：4 个 `d0=d` 拷贝与变量） |
| `rsqt` 条数 | 16 | **16** |
| `inv` 条数 | 8 | **8** |
| `float_NC` | 185 | **185** |
| rsqt→首消费者 | `[1]×16` | **`[1]×16`** |
| inv→首消费者 | `[1]×8` | **`[1]×8`** |
| rsqt 首末跨度 | 2366 | 2246 |

⇒ 只要不拆「开方 + 舍入」这条表达式，**任何重排都不可能把 `d_first` 抬到 20**。
这正是主代理 L26 在本核的机理侧解释：n32 在 F05 上量到 2–3 → 2–6，本核连 2 都不会有。

因此本卡把可动指标改为 **`d_arith`**（穿过舍入点之后的第一个算术消费者），
父值 rsqt 3–187 / inv 5–10，候选的 SPIR-V 侧规划值见 `NATIVE-PREDICTION.md`。

## 4. 可挪的独立工作清单（任务 A 的第二半）

两块贵操作所在区段都是**直通代码**（无分支、无 barrier 穿越），所以「独立」的判定就是纯 RAW：

| # | 工作块 | 规模（可执行指令） | 与 16 条 rsqt 的依赖 | 与 8 条 inv 的依赖 | 可挪? |
|---|---|---|---|---|---|
| A | `full_norm` 求和树 ×8（4 步 xor + 打包/解包 + c15 的 `mad` 修正） | 每棵 ≈ 85–95（实测调用间距 92/93/95/85/98/93，跨组边界 223 含 4 条 store） | **RAW 生产者**（树的末值是 rsqt 的源） | 无 | 只能作为「**别的 component** 的树」挪到某条 rsqt 与它的 apply 之间（互不相交） |
| B | 4 个 component 的 apply（`q*=n.x`、`*=headscale`、`k*=n.y`） | 每块 ≈ 10（2 条窄化 + 6 `mul`） | 消费者（RAW 于本组 rsqt） | 无 | 可挪到**其它**组 rsqt 之后 |
| C | softmax 分母树 ×4（4 步 `xor 8` + 3 步 `xor 2/4/1`） | 每棵 ≈ 130（实测 inv 间距 136/224/132） | 无 | **RAW 生产者** | 同上，作为别的组的填充 |
| D | softmax 8 个 `mul` 的 apply ×4 | 每块 8 条 `mul` | 无 | 消费者（RAW） | 可挪到别的组 inv 之后 |
| E | `coopMatStore` 到 `shK/shV`（k,v 各 4 条） | 每条约 3–4（含地址 `or`/`add`） | k 是消费者；**v 完全独立** | 无（再过 barrier 才读） | v 的 4 条 store 可任意后移 |
| F | `NRH_C tc00=0; coopMatLoad(pv_early_b,shV,0); dpas`（父已提前一块） | ≈ 10 | 只依赖 p00 的 **apply** | **无**（不依赖 inv） | 可挪到 8 条 inv 与它们的 apply 之间 |
| G | `oc00..oc11 = widen(y*scale)` 4 块 | 每块 ≈ 10 + 1 `send` | 无 | 无 | 可挪（会延长 4 个 `NRH_C` 的寿命，本卡未用） |

RAW/WAR/WAW（候选实际采用的方案）：

| 挪动 | 边 | 判定 |
|---|---|---|
| 4 棵 norm 树提前到 4 个 apply 之前 | apply→树：无；树→apply：RAW（apply 读树的结果） | 合法，只是把独立的树放进 rsqt 的影子里 |
| component [0]/[1] 树与 [2]/[3] 树互换先后 | 两组读写**不同分量**（`p00[0..1]` vs `p00[2..3]`） | 无 WAR/WAW |
| 4 棵分母树提前到 8 条 inv 之前 | inv→树：RAW | 合法 |
| `tc00/pv_early_b` 挪到 inv 与 apply 之间 | 只依赖 apply 后的 p00 ⇒ 仍在 apply0 之后 | 无新边 |
| `v` 的 4 条 store / `oc` 块 | 与任何 norm/inv 无依赖 | 本卡**没有**采用（保守） |

**每 lane 独立链数（L25 硬约束）**：父 ISA 上按 n32 同一套贪心 def-use 覆盖 + `[lo,hi]` 极大重叠
= **35 条链 / 同点最多 10 条**（`@0x8030`，正好在 rsqt2206 的 apply 区）。
候选按构造在 norm 区同时活 4 个 `f16vec2` 结果、softmax 区同时活 4 个 `d` + 4 个 `inv`
（父同点只活 1 个），**链数只升不降**；SPIR-V 侧 `float_NC` 185=185、rsqt/inv 条数不变。

## 5. 选中的重排（候选）

两块，都是**纯语句顺序**，表达式一字未改：

1. **norm 段**（源 519–538 / 547–566）：4 个 `full_norm(...)` 调用一起提到 4 个 apply 之前，
   每个 apply 仍包在自己的 `{}` 里，只把 `n` 换成 `n0..n3`。
2. **softmax 段**（源 710–827）：4 棵分母树一起提前、`d0..d3` 承接；4 个 `inv` 相邻算出；
   父里已有的 `tc00`/`pv_early_b` 块挪到 inv 与 apply 之间（它不依赖任何 inv）。

## 6. 六问里与「延迟」直接相关的三条

1. **重叠**：父把 8 棵树的 rsqt 各自压在自己的 apply 前（`d_first` 1–8），IGC 只塞进了
   「下一 components 的 4 条平方 `mul`」（例如 2216–2219 挤在 2206 与 2220 之间）；
   候选把 4 棵树/4 棵分母树整体前置，理论上给每条贵操作 85–130 条同区段独立指令。
2. **新增成本**：`d0=d` 式拷贝 4 条、`inv0..3` 变量 4 个、`n0..n3` 变量 4 个
   （SPIR-V +12 条展开指令，+16 条模块指令）；活值峰值：norm 区 +4 个 `f16vec2`、
   softmax 区 +8 个 `f16vec2`（≈ +12 dword）；ISA 侧**无法在本卡验证**。
3. **是否真落到 native**：见 `NATIVE-PREDICTION.md` 顶部判据——按 L26 预注册**预期不落地**。

## 7. 结论（分诊）

| 路线 | 判定 |
|---|---|
| 删除冗余副本 | **BLOCKED**：24 条贵操作 = 24 个不同值，0 冗余（`REDUNDANCY-PROOF.md`） |
| 纯语句重排隐藏延迟 | **BLOCKED**：卡面 `d_first ≤2→≥20` 在本核**结构上不可达**（§3，SPIR-V 父/候选都是 1）；退一步的 `d_arith` 也只是 SPIR-V 层面的「请求」，按 L26 预期被 IGA 调度吃掉 ⇒ A 类 |

**本卡不申请 GPU。** 候选全部构建身份（父字节复现逐字节、NC 185/185、SPV 通过校验、
plan 7 PASS + cpu_check 通过）留档为资产；`plan.txt` 明确标注**禁止派发**（见 `BUILD.json`）。
