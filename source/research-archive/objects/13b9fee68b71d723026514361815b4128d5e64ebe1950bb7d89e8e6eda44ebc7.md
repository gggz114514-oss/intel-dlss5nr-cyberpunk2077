### 3.3 计时口径（**必须遵守**）

`nr_stage_timing`（`prep/host/composite/tail/total`）是**桥内区间**，不是帧时间：

- `tail = 从 NR 结果就绪到游戏队列 retire 完成`，含**与下一帧重叠的异步等待**；
- 换更重的升频器后 `tail` 会变大，但吞吐可不变——34 FPS（≈29.4 ms/帧）与 `total≈31 ms` 并存就是这个原因；
- 性能判断只能用外部帧率或 PresentMon。

## 4. 分辨率限制（本次核心结论）

**锁在输出**，位置 `deferred_identity.cpp`：

```cpp
// 改前：output_desc.Width != 2560 || output_desc.Height != 1440
// 改后：output_desc.Width < 1280  || output_desc.Height < 720
```

另有一处 `frame.output_width/height` 原写死 2560×1440，已改为从真实输出描述符取值。

**输入 1280×720 不能"放开"**，它烘在计划里：

- `template_mapping[].patch.grid` 是字面量（如 `"85 49"`）；
- `size_overrides` 是字面量字节数（如 `swin_4_M = 8806400`）；
- 两个 pass 的 push 常量含 1280/720。

要支持其它输入尺寸（如 1080p 性能档的 960×540），必须用上游 planner 重生成计划并做数值验证（1–2 天/尺寸）。

现有三档天然命中 720p：1080p+质量（66.7%）、1440p+性能（50%）、2160p+超级性能（33.3%）。

## 9. 未决项与已知缺陷

1. **FSR4 水印（已解决）**：该水印由 `Fsr4EnableWatermark` 控制，但**有效取值是 `auto`（关）与 `true`（开），`false` 不生效**——曾设 `false` 时 OptiScaler 日志确认读到 `false` 却仍显示横幅。现值 `auto` 已确认无横幅。验证记录：为确认 FSR4 真在运行曾设 `true`，横幅显示 `MLSR UPSCALE V07-18 / XMX-DEV`。
2. **组件自报身份写死**：`nrb_vulkan_processor.cpp:151-152` 把 `build_id` 与 `manifest_sha256` 硬编码为 vk102 那次的值，加载任何计划都这么报。发布前应改为按实际 manifest 计算。
3. **面板后端与实况不一致**：`nr_panel.ini` 里 `backend = 102`，而启动挂载走编译期默认（small），`panel_state` 会显示 `102 / small -> 102 ok`。建议启动时以实际挂载结果回写。
4. **日志无轮转**：Cyberpunk 单次会话日志可达 9 MB，需手工归档。
5. **ini 写回风险**：游戏运行中修改 `OptiScaler.ini`，退出时可能被 OptiScaler 用内存值覆盖。**改配置前先确认游戏已退出**，改完复核文件内容。
