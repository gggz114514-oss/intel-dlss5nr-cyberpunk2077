# Candidate V1: D3D12 prepared/copy -> Vulkan GPU wait

Base: accepted optimized Full; network plan/assets/arithmetic unchanged. No Small optimization is included.

Order: game source list -> prepare dispatch -> prepared Signal -> input copies on the SAME frame.queue -> copy_fence Signal(value n) -> Vulkan submission waits on imported timeline(value n) at ALL_COMMANDS -> network -> existing output-ready signal -> D3D consumer wait -> composite/SR -> existing final retirement.

First frame still uses bridge CPU prepare wait because capability is false before successful Vulkan init/import. The explicit module-owned capability export is absent from original components. Switching processors forces identity resolution again; only matching context/device with a live imported semaphore can opt in. Motion CPU readback never bypasses prepared completion.

Lifetime: the original prior-network fence CPU wait remains before staging writes and copy allocator reuse. The existing copy fence completion check and slot fence check remain. The persistent import refers to the shared D3D fence, values strictly increase; its NT handle remains owned until shutdown. Semaphore is destroyed after existing per-slot completion waits. Output consumer retirement and resource lease proof remain mandatory. Private composite descriptors are used on bypass frames, an additional cost to measure.

Removed: prepared-event create/register/wait/close on qualified frames, and CPU copy-event registration/wait. Not removed: final consumer wait, prior-network reuse fence, validity/error checks, GPU dependency itself. This is not a fully asynchronous multi-frame pipeline.

Cost: one persistent imported timeline, one semaphore wait/value per Vulkan submit, capability query and private composite descriptor allocation. GPU waits can move displayed prep time into tail; only matched-scene total/end-to-end data can establish gain.

Spec: https://docs.vulkan.org/refpages/latest/refpages/source/VkD3D12FenceSubmitInfoKHR.html recommends timeline import with VkTimelineSemaphoreSubmitInfo for D3D12 fences.

Validation: component/frame recording CPU tests plus bridge tests; dedicated tests cover uninitialized capability, opt-in, motion readback, wrong device and replaced processor. GPU execution pending. Preserve full baseline and restore installation after a single controlled game run.
