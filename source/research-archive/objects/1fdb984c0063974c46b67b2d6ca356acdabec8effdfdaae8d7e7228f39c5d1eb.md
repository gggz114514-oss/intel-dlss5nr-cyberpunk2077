# n02c-f02-fb-bias — NATIVE-PREDICTION（第 5 问：可观察点与判据）

**本卡没有建候选，因此本文件里没有"已落地"的声称。** 它写的是：

1. 本卡定价所依赖的、**已经在这颗核的 ISA 里观察到的**事实（作为定价基线，可复核）；
2. 若后续卡实现"线性 SLM 缓存"（方案 N）或"真转置 SLM 缓存"（方案 T），
   native 里**必须**出现 / **绝不能**出现的可观察变化，以及"看不到就等于未实现"的判据。

采集口径：合同 §8.7 —— 以**该卡自己那一批**的 capture 为权威，旧批只作方向参考。
本卡的基线数字全部来自 `queue/n10-f10-next/native/captures/native-native-base/ISA/`
里 native hash `7a38a17947f21ae6` 的两个文件（同一 SPV 字节 `4c034a53…`）。

## 2. 若实现方案 N（线性 SLM 缓存）——应被立刻判"无效"

**预期（按实测的"条数 = 极大连续行段数"规则推）**

| 观察点 | 预期 |
|---|---|
| `load.ugm.d32x16t`（fb bias） | 64 → **0** |
| `load.slm.d32x16t`（新增，回读的逐行 gather） | 0 → **64**（一条都没省） |
| `store.slm`（填充） | +8 .. +16 |
| `load.ugm` 宽读（填充源） | +8（`d64x64t`）|
| `sync.bar` | 1 → **2** |
| shared | 8192 → **24576** |
| `dpas.8x8` | **128 不变** |
| 528 条交织 mov | **528 不变** |

**判据**：若 `load.slm` 回读确实是 64 条，则**总消息数上升**（209 → 225 左右），
该实现即使数值正确也应直接判负，**不进 ordinary 计时**。

## 3. 若实现方案 T（真转置 SLM 缓存）——唯一能省 gather 的形态

**预期**

| 观察点 | 预期 | 若看不到 |
|---|---|---|
| `load.ugm.d32x16t`（fb bias） | 64 → **0** | **A 类（未落地）**，不换写法重跑 |
| `store.slm` 散写（per-lane dword 128 B） | 0 → **32** | 若只出现 8 条 512 B 的"线性写"，说明转置没写进 SLM ⇒ 方案退化成 N |
| `load.slm.d64x64t`（或 512 B 形式）片段回读 | 0 → **8** | 若仍是 64 条 64 B，同上 |
| `send.ugm` | 570 → **554 ±**（−8 宽读 −64 gather +... 净 −16 总消息） | — |
| `send.slm` | 25 → **65 ±**（+32 散写 +8 回读 +fence） | — |
| `sync.bar` | 1 → **2**（或出现 subgroup 版同步，见下） | 若仍是 1 且无 fence ⇒ 可见性没保证 = 实现错误 |
| shared | 8192 → **24576** | 若仍 8192 ⇒ 复核足迹论证 |
| 最高寄存器 | **≤ 127** | >127 或 `scratch > 0` ⇒ B 类副作用，先修预算 |
| `dpas.8x8` | **128 不变** | 变化即实现错误 |
| 528 条交织 mov | **528 不变** | 变化即实现错误（动了 `NRH_B` 块读） |
| f32 bias 加 `add :f,:f,:f` | **32 不变** | 变化即数学变了 |
| 窄化 `mov …:hf ← …:f` | bias 部分 **64 不变** | 变化即舍入点变了 ⇒ E 类 |

**数值门**：`fixed` = `1755e9c2…`、`fb2` = `9c3e511e…`（合同 §8.1）。
两套 gold 都过才允许看计时；任一不过 ⇒ **E 类**，先定位首差（bias 元素映射是第一嫌疑人，
见 `PROOF.json.P1`：`row = 2*comp + (lane>>4)`、`col = lane & 15`）。

## 4. 若走"8×64 累加器宽读"（本卡 RESUME 推荐的下一条，需先做探针）

**第一步必须是探针，不是候选**：用 `if(debug)` 把 8×64 累加器片段的 16 个 component
逐 lane 落盘，和 `fb[]` 的已知值比对，**测出 8×64 的 lane map**。
判据：探针帧里 component `4*s + c` 必须等于 16 位精确保留的 `fb[pc.p2.w + (t0+8h+2c+(lane>>4))*64 + 16s + (lane&15)]`
（即 8×16 站点映射的自然延伸）。**测不到就不许写候选**（否则一定是 E 类）。

**探针落地后候选的预期**：`load.ugm.d32x16t` 64 → 0、新增 `load.ugm.d64x64t`
（2048 B 连续）**+8**（每 SG 2 个宽片段 × 4 条 512 B），`sync.bar` **仍 1**、
shared **仍 8192**、无散写、无新 ALU；净 −56 条消息/SG（执行路径 182 → 126，−30%）。
这才是本族唯一有量级的形态；它的两个前置（lane map、寄存器预算）就是本卡 §7 缺的第 1、3 条。
