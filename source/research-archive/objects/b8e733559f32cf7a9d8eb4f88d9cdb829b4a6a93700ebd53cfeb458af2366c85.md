### 1.3 每一条被移除的站点都有账（口径按 `local 128 = 4 SG` 修正）

`layout(local_size_x=128)` ⇒ 4 个 subgroup，**每个 subgroup 都执行 projection 和整段 body**。
"每 SG"与"每工作组"是两个口径，下表两列都给；MAC 用源矩阵形状（M·N·K）算，不用静态站点数推。

| 段 | 父静态 | 子静态 | 父动态 MMA / **每 SG** | 子动态 MMA / **每 SG** | MAC / **每 SG**（M·N·K） |
|---|---|---|---|---|---|
| projection | 1 | 1 | 4（K=64 走 4×K16） | 2（K=64 走 2×K32） | 8·16·64 = **8,192** |
| QKV | 24 | 12 | 24 | 12 | 12·8·16·32 = **49,152** |
| score | 16 | 8 | 16 | 8 | 8·8·16·32 = **32,768** |
| PV | 16 | 8 | 16 | 8 | 4·8·16·64 = **32,768** |
| output | 8 | 4 | 8 | 4 | 4·8·16·32 = **16,384** |
| **合计** | **65** | **33（新增）** | **68** | **34** | **139,264（父 = 子）** |
| **每工作组（×4 SG）** | 260 | 132 | **272** | **136** | **557,056（父 = 子）** |

**口径声明（三点，避免被读成性能结论）**
1. 68 → 34 是**每 SG** 的被替换段动态 MMA 数；4 个 SG 合计 **272 → 136 / 每工作组**。
2. 这里**不含**父已有的 FFN 段（expand 16 + contract 16 动态/每 SG）、不含 F1 的 lift、不含其余 286 个 PASS。
3. **不等于 native DPAS 指令数**：K32-int8 与 K16-fp16 在硬件上是否各自合并成不同条数只能由设备侧度量。
   本卡没有任何 native 或时间声明；静态站点 65 → 0、乘加总量 139,264/SG 不变，这是覆盖账，不是性能账。

## 3. 激活量化域：本卡最关键的论证

`f2c32_block66_fused` 的输入是 `block65_out`（半分辨率 64 通道）与 `skip4`，中间 `Q/K/V/P/Ctx`
全是核内动态量。**没有任何标定数据能支撑 per-tensor 常数**，所以本卡**不引入任何标定常数**：
每个动态操作数的 scale 都是"该次 MMA 真正消费的那个 tile 的 amax/127"，在核内用
subgroup shuffle-xor 归约（模块只启用 `GL_KHR_shader_subgroup_shuffle`，**没有** arithmetic 扩展，
所以不用 `subgroupMax`）算出。

**硬约束：一次反量化 ⇒ 累加 K 上因子必须恒定。** 逐段落地：

| 操作数 | 尺度粒度 | 为什么必须是这样 |
|---|---|---|
| x65（projection A） | 每 subgroup 一个标量（8 token × K=64） | 累加器跨整个 K=64 才反量化一次 |
| Wproj（projection B） | 每输出通道静态 | 只有一列因子 |
| Y（QKV B） | 每 subgroup 一个标量（32 feat × 16 tok） | QKV 的 K 就是 feat，跨 32 一次反量化 |
| Wq/Wk/Wv（QKV A） | 每输出通道静态 | 同上 |
| K（score A） | **整个 workgroup 一个标量**（64 key × 32 dim） | A 片段只有一段 K32，本身可以每片段一个；用 workgroup 标量是为了让 8 个 key 片段共享同一因子，减少跨片段可比性讨论（见下） |
| Q（score B） | 每 subgroup 一个标量（16 query × 32 dim） | 8 个 A 片段共用同一个 B |
| V（PV A） | **整个 workgroup 一个标量**（64 key × 32 ch） | PV 的累加跨 64 个 key；若两个 key 段用不同因子，单次反量化就不成立 |
| P（PV B） | 每 subgroup 一个标量（64 key × 16 tok） | 同上，与 sV 相乘后对 64 key 恒定 |
| Ctx（output B） | 每 subgroup 一个标量（32 ch × 16 tok） | 累加跨 32 通道一次反量化 |
| Wo（output A） | 每输出通道静态 | 同上 |

**统一条件**：`out = float(int32_acc) · (sW[ch] · sAct)`，每个 stage 仍只窄化一次，
与父的"单次窄化"合同相同。K 与 V 是 workgroup 发布量，所以它们的 amax 用
`shKV[8]` + 一次 `barrier()` 做 workgroup 归约（每 subgroup lane0 写，全组读）。

**被刻意保留、一个字节没动的东西**：int8 FFN（`fsc[0..164]` 656 B 表与 `c32_b66_weights.i8.bin`
逐字节相同）、`nr_act_h`、contract/projection 两个 half 残差 seed（`H(X·rs)`、`H(Y·ars)`）、
`nr_norm32_pair` 的 half 平方和树与 parity 分支、`scalar0`、`nr_exp_h2` 的位技巧、
64-key half 分母树与 `inv` 的 half 倒数、八条 debug 转储区与地址、32 word PUSH、grid、local size。

### 6.3 这个参考**不是**什么（硬边界，按复审收紧）

0. **本卡没有任何候选的 device 执行。** §6.1 的逐位相等证明的是**父算术与捕获之间的地址/数值合同**
   （x65 tile 寻址、投影权重 LCOL 布局、K=64 两段累加、skip 的 `nrf2_io_at0` 寻址、两路 gain、
   f32 累加 + 单次窄化）——**不是候选 GPU 实现**。候选 `f2_body_i8.spv` 从未在设备上运行。
1. **§6.1(B) 的 P 区逐位相等不能唯一证明 Q/K 路径正确。** 它只证明"在给定该 X 时父的
   score/exp/分母链与模型一致"。旧 dump 的 **Q、K 两区全为 0**（各 2048 half）、Y 区 absmax 478 而模型 42
   （≈11.4×）、Ctx 区 307.5 而模型 24.9 —— 这些差异至少还有四种未决解释：
   **身份**（buffer 是谁写的）、**覆盖**（多 WG/多 pass 写同一区）、**地址**（base 偏移）、**阶段**
   （写的是窄化前/后）。凭 P 一致**不能**排除这四条，因此 `Y / Q / K / Ctx / O` 五段**都不算被转储证实**。
2. 因此本卡**不主张** `数值通过`。要闭合它需要：一次**唯一 WG** 的干净诊断（见 §8.3 的施工单），
   把 codes / scale / int32 累加按具名阶段写出，再由 CPU 用**实际 codes** 做整数参考。
3. R 臂（float64、无 half 舍入）与 P 臂在 Y/Ctx/O 上几乎相同（差异 <0.02 %），
   说明这几段的偏差**不是** half 舍入能解释的；在 (A) 的投影+blend 段上 P 臂是**逐位**的，
   这两条合起来只说明"模型带着部署的 half 路径，且偏差来自转储归属"，不说明候选正确。
4. **46.34 dB 是 CPU 局部模型 SNR**，不是整网 PSNR、不是画质门、不是本臂合格判据。

## 7. 连接成本（次数推导，不写毫秒）

**新增（口径按实际执行路径校正）**
- **新增量化码点 = 16,384 / 每工作组**（不含父 FFN 已有的量化）：
  `4 SG × (x65 512 + Y 512 + Q 512 + P 1024 + Ctx 512) + K 2048 + V 2048`
  = 4×3,072 + 4,096 = **12,288 + 4,096 = 16,384**。
  父 FFN 每 SG 另有 X 512（父自身 expand 的 `nr_i8_put_x`）+ E 2048（contract 的 `nr_i8_put_e`），本卡不动，另计。
- **x65 是重复量化的**：`rh = sg2>>1` 选 A 的行块、`cg = sg2&1` 选输出通道，
  于是 (rh,cg) = (0,0)/(0,1)/(1,0)/(1,1)：**sg0 与 sg1 对同一 8 行 A 块各自做一次 amax + 量化**，
  sg2 与 sg3 同理。所以 2,048 个 x65 码点里只有 **1,024 个不同**。
  这是本卡**明确接受**的重复，理由：现在只做覆盖正确基线，改 A 共享或改 scale 粒度属于优化，不混进来。
- 归约：**7 次 `nr_i8_sgmax`**（projection A / Y / Q / K / V / P / Ctx），每次 **5 个 XOR 步骤**，
  每个执行 lane 都做（动态 35 步/lane）；K 与 V 另有 **2 次 workgroup 共享归约**（`shKV` + 1 个 `barrier()`）。
- barrier（静态）：`OpControlBarrier` 5 → **10**（+5）、`OpMemoryBarrier` 3 → **8**（+5）；
  静态计数不是动态次数，也不是时间。
- 附带成本（不隐瞒）：`OpConvertFToS` 2 → 8、`OpConvertSToF` 5 → 9、指令总数 8,868 → 9,815（+947）。
- 共享声明：**23,552 → 19,488 B（-4,064）**。逐变量：
  `shK` 4096→`shK8` 2048，`shV` 4096→`shV8` 2048，新增 `shKV[8]` 32；
  `sX8` 2048、`sE8` 8192、`nrf2_proj` 1024、`nrf2_blend` 4096 不变。
  `sE8` 在 contract 之后被复用为 Q8（2048 B）与 P8（4096 B），`sX8` 被复用为 Y8 与 Ctx8 —— 
  寿命互不重叠，每处切换前后都有 subgroup 或 workgroup barrier 退役上一次读。
  **声明 ≠ native 分配。**
- barrier 增量（静态）：`OpControlBarrier` +4（Y8 发布、K/V/Q 发布、P 发布、Ctx 发布）。
- descriptor：b9 / b10 两个**新** BUFFER（id 739 / 740），b0..b8 的 binding 与字节数一字不改。

**删除**：`shK`/`shV` 两个 half 共享 tile（各 4096 B）与其唯一的读者（score 的 LROW 半精度 A、PV 的半精度 A）；
每段每 tile 的 K16 脚手架；每工作组动态 MMA 指令 68 → 34。

## 14. 诊断施工单（唯一 WG + 具名阶段 codes/scale/int32）

### 14.1 为什么必须改 shader

`p3.y=1` 只把窗口固定成 (0,0)，**所有 84×48 个工作组照跑**，会并发写同一批地址；
现有 `dbg` 只有 50,176 B 且只装 FP16 阶段值，**新增 codes 挤不进那 507 个 half 的空隙**。
所以本卡建了**独立的诊断内核与独立 plan**，把判定权交给数据：

### 14.3 提交票（GPU 时段到位后按此顺序，不自行占设备）

1. 核 `plan-diag-f2.txt` / `plan-diag-f1.txt` 的 hash 与 SPV hash 一致；确认 pipeline 启用了
   `shaderInt8` + `StorageBuffer8BitAccess`（这两个特性在**本 PASS 的 pipeline** 上此前未证）。
2. 跑 `plan-diag-f2.txt`：**同一输入**上父（`c32_f2_i8.spv`）与候选各一次固定运行；
   收 `c32_f1_f2_diag_f2.bin`（163,840 B）+ `frame_out.bin` + `swin_66_debug`。
   先只读 `dg[0..11]` 确认 WG=(0,0) 且 payload 字数正确，再解析其余区。
3. 用实际 codes 做整数参考：`int32_ref = Σ code_A·code_B`（int64 后转 int32），
   与 `int32 QKV/S/PV/O` 区逐元素比对（判据：逐位相等）；再按 §14.2 的 scale 复算
   `dequant = int32 · (sW·sAct)` 与 FP16 阶段值比对。
   这一步同时给出 §6.3 里 Q/K/Ctx/O 四段的**独立**判据，不再依赖"P 一致"。
4. 同样的判据跑 `plan-diag-f1.txt`（这是 R01 M1 要求的"量化器真正吃到的码"）。
5. 两段都闭合后，才把 `plan-c32-f1-f2-cumulative.txt` 交 fixed / feedback 门重测；
   诊断运行本身**不进入累计臂**。
