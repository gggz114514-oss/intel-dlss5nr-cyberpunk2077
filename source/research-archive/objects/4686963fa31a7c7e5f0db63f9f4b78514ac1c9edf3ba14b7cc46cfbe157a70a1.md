## 2. 口径（重要，避免把派发数当矩阵数）

* **主键** = 0 基 dispatch ordinal + name + SPV SHA256。`PASS` 的分组号不唯一，逐行都按 ordinal 定位。
* **288 = 派发数，不是矩阵数**。288 个 dispatch 中：
  * **264** 个含 ≥1 个 INT8 cooperative-matrix 乘（S8×S8→S32）；
  * **22** 个是纯量化/生产者 kernel（`*_qx_producer`、`b30_qt_producer`），无矩阵乘，只有一次量化 epilogue（台账里记为 `QX quantiser epilogue` 伪边，单列，不计入矩阵边）；
  * **2** 个是纯 IO/blend/surface kernel（`ioport_block70_0` / `ioport_block70_2`），无矩阵、无量化 epilogue。
* **矩阵边（quantized matrix edge）404 条**，量化 epilogue 22 条，台账条目合计 **426**。融合 kernel 一次派发多条边（如 `c64_d1` = expand+mid 两条，attention = QKV+QK+PV 三条），所以边数 > 264 是正常的，反过来也不能用 288 冒充边数。
* **A/B 操作数 dtype**：全部矩阵边为 **S8**（`OpTypeInt 8 signed`，SPIR-V 类型证据），累加 **S32**（coopmat 累加器组件类型证据）。没有任何 U8 矩阵边；没有 FP16 矩阵边（见 §5）。
* **scale 分类**（逐边，取 A 侧=激活侧）：
  * `STATIC_REFINED`：本候选重建过该静态尺度包（资源级 diff 证明），并已被离线标定细化；
  * `STATIC_COARSE`：静态（绑定的是文件型尺度包，且该 kernel 的 SPIR-V 对该 binding 只有读、无写），但本轮未细化；
  * `DYNAMIC_RUNTIME`：kernel 内用当前张量求 amax 再除 127（有文档/源码/SPIR-V 证据）；
  * `FP16`：FP16 矩阵乘（本轮 0 条）；
  * `UNKNOWN`：证据不足，明确不声称已静态。

* **M/N/K**：只在有证据时填（C64 FFN 来自施工书 §2 的包布局 256×64 / 2×(32×128) / 64×64，与 28672 B 权重包一致；Swin attention 来自 `SCALE-CONTRACT.json` 的 geometry 与 `attn_*_wqkv_i8` 字节数）。**M（每次派发的 token 行数）依赖 grid，未推导 → null**。其余族 N/K 未证 → null。
* **producer/consumer**：用绑定图做 ordinal 邻接（`resource_adjacency`），并显式标注“不是已证明的读写方向”。

* 对 c32-equalized：16 个 SPV 变化 = 8×`c64_b*_qx_producer`（`c64_qx_producer.spv`→`c64-b6-equal-x-alpha1/candidate.spv`）+ 8×`block*_swin_body_2`（`c64_d2.spv`→`c64-b6-reconstruction/original-half.spv`）；8 个**仅绑定字节数变化**的是 8 个 `block*_swin_body_1`（`c64_b*_scales` 1856→2368 B，SPV 与父本同 SHA `99e602e893e3`）。

## 7. 未决项 / 最大未知

1. **C32 七块（1,2,3,4,67,68,69）仍是动态激活尺度**：这是当前候选“全网纯静态”最大的口子——7 个 dispatch 每帧在 kernel 内对 X/A/M/Y/Q/K 求 amax。它们占 F01→C64 之间的全部主干，且不在本轮 C64 细化范围内。要静态化必须为每个 block、每个 stage 给出离线 amax 上界并重标定（对应施工书 S01）。
2. **C256（16 block）与 split16（16 block）attention 的动态尺度**没有本族专用 SCALE-CONTRACT，只有同族推断；需要各补一份逐 head 的几何/粒度证明（否则替换静态时容易错配 granularity）。
3. **36 条 UNKNOWN 边**：C64 WO A 侧 7 条、C256 WO A 侧 15 条、DS 8 条（4 WO + 4 DS）、projection 4 条、F2/F20 各 1 条。WO 的 A 侧量化到底发生在 kernel 内还是由上游 attn kernel 附带，缺一份资源级证明（候选：`swin_*_weights` 107024 B 包内是否含 context 尺度）。
4. **融合 kernel 的边切分未证**（C32 七块、F2、F20/b70）：台账按 1 条融合边登记，边数被低估；若按真实 stage 展开，边总数会上升（估 +20~40），但**不影响**“动态位置至少 190”的下界。
