1. 父字节复现：用父源码原样 glslang 16.5.0 重编译 = 父 SPV 字节相同（两组不同 -I 目录各自相同）。BUILD.json:parent_rebuild。
2. candidate.spv sha256 = d699bc54b62573af52c3c70412730c30c9b09d943ac554cec9490724e985d267，过 spv_validate_cpu。
3. SPIR-V 结构：1375 条指令 / 5656 word，与父逐序号 opcode 全同；归一化（result-id 归一 + 常量代入）后仅 6 处不同：OpIMul 16->32、OpUMod 2->4、OpIMul 4->2、OpUDiv 2->4 + 两个 OpConstant 槽位交换值 1/4。float_NC_checked = 3（1 个 OpFMul + 2 个 GLSL.std.450 Fma；签名逐条相同；父子 NoContraction 集合都为空）。
4. 映射一一覆盖：1056 个 (tile, group) 对，两套映射都是双射（重复 0、缺失 0、多余 0）；写集 540672 half = 1056x512，两 mapping 集合**相等**、重复 0、等于全集；无尾块（1056%32=0、8%2=0，不需要 guard），最后一个 WG (32,3) 覆盖 tokens 1024..1055 完整。
5. plan：只替换本组 16 个 PASS 的 SPV 路径 + 这 16 行 grid `66 2 1`->`33 4 1`；与基线逐行 diff 仅 16 行；cpu_check = "CPU_PLAN_OK 152 rows, 232 passes, 502 buffers; no Vulkan loaded"。plan sha256 = 6dcb1e5cc897ea3bd7e979d8558f1f87395eb848e8c584edfc6c25f52bc1c402。

三、量化（逻辑字节，不是 DRAM）
每 PASS 权重请求量 132 MiB 不变、去重权重 1 MiB 不变、每 group slab 的 SG 请求 132 不变；
每 WG 去重权重 512 KiB -> 256 KiB（WG 内复用比 2.0 -> 4.0）；每 group slab 的 WG 回放 66 -> 33（WG,slab 关联 528 -> 264）；
代价：每 WG 去重输入 16 KiB -> 32 KiB，同 slab 并发流 2 -> 4，dispatch y 2 -> 4。

五、下一处具体代码改动（若 native 显示整数指令变多，A 类兜底）
把索引改写成显式 tile 形式以消掉 token 的除法/取余（与现写法逐元素等价）：
  uint t16 = gl_WorkGroupID.x*2u + (sg>>1);  uint tr = (sg&1u)*8u;  uint token = t16*16u + tr;
  tiled(token,0,512) -> t16*8192 ; tiled(token,c,512) -> (t16*32 + c/16)*256 + tr*16 + c%16
当前不采用：SPIR-V 已证指令数 1375/1375 相同，无需为 0 收益再加源码改动。
若整体计时显著变慢（B），第一条要改的是 locality 强度而不是网格：把每 WG 改成 8 tile x 1 group（grid (17,8)，WG 132->136，+4 WG、32 个 token 槽空闲、需要尾块 guard）——这是本卡刻意**没有**混进来的第二机制，必须单独首次修改、单独归因。
