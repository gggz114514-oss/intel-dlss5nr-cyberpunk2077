# ANALYSIS — n27-f07（F07 C256 A 片段 SLM 分块重排，D0）

六问逐条。所有计数来自只读 ISA（`COST-RAW.json`）与源码枚举（`COST-BREAKDOWN.md`）；
证明在 `PROOF.json`；native 判据在 `NATIVE-PREDICTION.md`。

---

## 1. 映射：生产者每个 (lane, component) 代表哪个 (token, channel/k)，消费者要什么

### 1.1 线程/所有权分解（C256，local_size_x = 256）

| 量 | 定义 | 取值 |
|---|---|---|
| `t_local` | `gl_LocalInvocationID.x` | 0..255 |
| `sg` | `t_local / 32` | 0..7（8 个 subgroup） |
| `lane` | `t_local % 32` | 0..31 |
| `w` | `wy * pc.p1.x + wx` | 0..76（grid 11×7） |
| `m0` | `(sg/8 + 1*j) * 8` | **= j*8**（sg/8 恒 0） |
| `n0` | `(sg%8) * 32` | 0,32,…,224（8 个互不重叠的 32 通道块） |

即：**subgroup `sg` 拥有「token 行 j*8..j*8+7」×「输出通道 sg*32..sg*32+31」**，
对 16 个 k 块（k = ki*16，ki = 0..15）全覆盖。8 个 subgroup 的通道块拼成 0..255，**一一覆盖、无重复写**。

### 1.2 A 片段（生产者 = shT 填充，消费者 = DPAS 的 A 操作数）

- 逻辑元素：`(row, k)`，`row = 0..63`（token 行，`q = row/16`、`s = row%16` 的 t 映射），`k = 0..255`（输入通道）。
- 片段索引：`jb = row/8`（0..7）、`kb = k/16`（0..15）→ 片段号 `fi = jb*16 + kb`（0..127），
  片段内 `r = row%8`、`c = k%16`。
- 候选映射（`PROOF.json.mapping.formula`）：
  `dst(row,k) = ((jb*16 + kb)*8 + r)*16 + c`，**在 [0,16384) 上是双射**（已穷举验证，16384/16384 个像，0 冲突）。
- 消费者：`coopMatLoad(MAT_A 8x16, LROW, base = fi*128, stride = 16 halfs)`。
  cooperative matrix 的 (lane, component) → (row, col) 映射与本卡池化段已实测的 CH 映射一致：
  `row = 2*ci + (lane>>4)`，`col = lane&15`（见父源码注释「Measured CH coordinates」）。
  因此 lane `l` 的 component `ci ∈ {0,1,2,3}` 读的是 `r = 2ci + (l>>4)`、`c = l&15`，
  地址 = `fi*128 + (2ci + (l>>4))*16 + (l&15)`。
- **一一覆盖**：8 个 subgroup × 16 个 ki × 128 元素 = 每 j 的 16384 元素；j 覆盖 0..7 ⇒ 每 WG 覆盖 64×256 = 16384 元素，
  每个元素被 8 个 subgroup 各读一次（同一份输入、不同输出通道），**无漏读、无重复写**。
- 尾块：grid 11×7×1 与 token 数 64 完全整除（64/8 = 8 个 j），`shT` 覆盖整行 16384 半，**无尾块**。

### 1.3 池化段（生产者 = DPAS 结果，消费者 = nrf_mean）

- `narrowed = MAT_H(acc)` 的元素 `ci` 落在 `row = 2ci + (lane>>4)`、`col = lane&15`；
  池化读 `nrf_pair[(sg*2 + (lane>>4))*128 + r0*16 + (lane&15)]`（`r0 = 2*dx`），
  写 `nrf_mean[(4*ly + lx)*K + kk]`，`ly = 2*(1-sy1) + dy`、`lx = 2*sx1 + dx`、`kk = (sg%8)*32 + (lane>>4)*16 + (lane&15)`。
  → 16 个 slot × 256 通道 = 4096 元素，8 个 subgroup 各写 32 通道 × 2 行 = **一一覆盖**。

### 1.4 DS 段

`nb0 = cb*8 + rnd*4`（`cb = sg>>1`，4 组 × 8 块 × 16 通道 = 512 通道位；实际 N 由 `pc.p5.w` 截断），
A 从 `nrf_mean[(rowbase + row)*K + k]` 读，`rowbase = (sy==0)?8:0`。本卡**不改**这一段。

## 2. 删什么真实工作（正常执行路径上的 send/mov/shuffle/转换/SLM 往返/屏障）

本卡的改动**只**在「A 片段读」这一条路径上：把 SLM 里的 A 分块从「8 行相隔 512 B」改成「8 行连续」，
从而让 8 条 32 B 的 uniform 消息合成 1 条 256 B 的 uniform 消息。

| # | 被删的工作 | 位置 | 静态条数 | 每 WG 动态 | 依据 |
|---|---|---|---|---|---|
| R1 | `load.slm.d32x8t@exec1`（A 片段 8 条/片段） | 主体 A 读 | 1024 → 128 | **8192 → 1024**（−7168） | ISA：`load.slm.d32x8t` 1040 条中 1024 条 = 128 片段 × 8 行 |
| R2 | 同上的 repack mov（每 8 条消息拼 8 个目的地） | 主体 A 读后 | 见 §4 | 未单独计价（归入 R1 的连带） | `repack_movs_from_send_dst` = 1134 |
| — | shT 填充（512 global load + 512 SLM store） | 填充 | 1+1 | **不变**（仍是 1024 条消息；每线程仍是 64 半，见 §4） | 父/子每线程都搬 64 半 |
| — | barrier | 填充后 | 1 | **不变** | 跨 subgroup 依赖仍在 |

**没有删除**：DPAS（264）、权重读（264 条 512 B）、gY seed、imgout/nrf_o 写、池化、DS 段、barrier 数量。
**不计入收益**：debug 分支（`if (pc.p1.w != 0)`，L17 明确不算）、编译器可能已折叠的源码冗余（L18）。

## 3. 重叠：独立工作原来如何重叠，A/B/acc/残差/norm-den 的生产者-最后消费者-覆盖者

| 缓冲/值 | 生产者 | 最后消费者 | 覆盖者 | 依赖 | 本卡是否改动 |
|---|---|---|---|---|---|
| `gT`（global） | 上游 PASS（ord 58） | shT 填充 | 无 | 跨 dispatch | 否 |
| **`shT`（SLM）** | 填充循环（全 WG 协作） | 主体 A 读 | 无（只读） | **填充→A 读：RAW（跨 warp，需 barrier，保留）** | **仅改元素落位，不改 RAW/barrier** |
| `pack`（权重） | 上游 | B 读（每个 DPAS） | 无 | 跨 dispatch | 否 |
| `gY`（seed） | 上游 | seed 读 | 无 | 跨 dispatch | 否 |
| `acc0..acc3`（DS 累加器） | DPAS | `MAT_H(acc)` | 每 k 步 WAW（累加） | 顺序不变 | 否 |
| `nrf_pair`（SLM） | 主体：`coopMatStore(narrowed)` | 池化读（同 subgroup 内跨 lane） | 下一 j 覆盖 | **写→读：RAW（需 subgroupBarrier，保留）；读→下轮写：WAR（第二个 subgroupBarrier，保留）** | 否 |
| `nrf_mean`（SLM） | 主体池化写（每 subgroup 写自己 32 通道） | DS 段 A 读（全部 8 subgroup） | 无 | **跨 subgroup RAW（`barrier()`，保留）** | 否 |
| `imgout` / `nrf_o`（global） | 主体 / DS scatter | 下游 PASS | 无 | 跨 dispatch | 否 |

本卡**不新增**任何跨阶段依赖：A 读仍然在 `barrier()` 之后、仍然在同一个 `ki` 循环体内、
仍然只有一份 `MAT_A a`（4 GRF）活值。**没有把原来重叠的东西串起来。**

## 4. 新增成本（全部入账）

| 项 | 变化 | 依据 |
|---|---|---|
| 重复权重/A 读取 | A 字节 **不变**（每片段 256 B，每 WG 256 KiB 逻辑 SLM 读）；权重读不变 | 映射是纯置换，字节数守恒 |
| 地址计算 | SPIR-V `OpIAdd` 145→154（+9）、`OpUDiv` 102→112（+10） | `PROOF.json.spv.arithmetic_opcode_delta` |
| 选择/分支 | 填充循环多了 4 次外层迭代的位运算（shift/and），`OpSelect` 12→17 | 同上 |
| shuffle | **0**（本卡不用 shuffle） | — |
| 复制 | 每线程仍搬 **64 半**（父 64 次 × 1 半；候选 4 块 × 16 半） | `PROOF.json.spv.staging_elements_per_thread = [64, 64]` |
| 同步 | **不变**（1 个 workgroup barrier + 33 个 subgroup barrier） | 源码结构未动 |
| 有效 lane | A 读仍是 exec=1 uniform（广播），有效 lane 语义不变；SLM 读消息从 8192→1024，**消息槽位减少 7168/WG** | ISA 静态计数 |
| WG 数 | 不变（77） | grid 未动 |
| 活值峰值 | **不变**：`MAT_A a` 仍是 4 GRF，`shT` 仍是 16384 半 | 源码 + SPIR-V Workgroup 变量数 [3,3] |
| 寄存器峰值 | 预期 **不变或更低**（`max_r` 父 126；本卡不新增长活值） | 预测，见 NATIVE-PREDICTION |
| 代码体积 | SPIR-V 1965→2073 指令（+5.5%）、7974→8393 words（+5.3%）；ISA 静态指令数**预测持平或下降**（少 896 条 send 站点、多几条地址运算） | `PROOF.json.spv` |
| scratch | 预期 0（不新增数组） | 预测 |
| **SLM store 银行冲突（新增风险）** | 填充的 SLM 写从「线性」变成「256 B 跨步」：连续 lane 写同一 bank 组 → 可能 32 路冲突。规模：512 条 store 消息/WG | 列入 `COST-LEDGER.added`；若 native 看到 fill 的 `store.slm` 条数/停顿上升 ⇒ B 类 |

**逻辑字节 ≠ DRAM 字节**：A 读的 256 KiB/WG 全部命中 SLM，不进 DRAM；本卡不改 DRAM 流量。
**片段字节 ≠ 实际 GRF**：A 片段 256 B = 8 GRF，与父完全相同（父是 8 × 1 GRF，子预期 1 × 8 GRF）。

## 5. 是否真落到 native（预测 + 判据，不声称已实现）

见 `NATIVE-PREDICTION.md`。摘要（主代理 2026-10-28 裁定口径）：

- **落地** = 出现 256 B 级消息（`load.slm.d32x64t` 或同族 `d32x16t`/`d64x64t` 的 uniform 形）**且**
  `load.slm.d32x8t@exec1` 从 **1040 明显下降**（目标 16，即只剩 DS 段的 16 条）。**不要求** `d32x8t` 消失。
- **不变量** = DPAS 264、`sync.bar` 1、WG mem 45056、scratch 0、`max_r ≤ 126`、`mov` 不显著上升。
- **A 类判据**：看不到更宽 opcode ⇒ 实现未落地，把「SLM A 分块行距」这条轴按 A 关闭（不是方向失败）。
- **B 类判据**：消息数降了但 `mov` 显著上升（repack 变大）⇒ 按净消息重新裁决。
- pipeline 映射**不变**（40 pipelines，ordinal 59 = pipeline 15），见 `PIPELINE-PREDICTION.json`。

## 6. 整体是否更快（本卡要测什么、用什么臂、如何归因）

- **不能测**（无 GPU）。本卡申请 ordinary 两臂 6 对交替（`base` = 链头 plan，`cand` = 本卡 plan），
  30 reps / warm 1 / feedback，门 fixed + fb2。
- **要测的整体量**：帧时间中位数差（ms）。归因只到「ordinal 59 这一个 PASS」：
  该 PASS 隔离时间 0.095 ms（占帧 0.52%），本卡删掉它 **−46% 的消息槽位**，
  按线性折算 ≈ **0.038 ms**（占帧 0.21%），刚过 L13 的 0.03 ms 批间漂移阈值。
- **必须一起看的对照**：L13 要求任何 <0.03 ms 的差在第二批复现；本卡的预测值贴阈值，
  所以**单批显著不算数，需要第二批平衡批复现**。若只得到 0.01–0.02 ms，按 L13 记 UNRESOLVED，不采纳。
- **不做**：不把三核的收益相加（L8）、不用整体毫秒倒推机制有效（CONTRACT 8.5）。

## 附：分诊预置

| 现象 | 分类 | 处置 |
|---|---|---|
| 没有 256 B 消息、`d32x8t` 仍 1040 | **A 实现未落地** | 记「SLM A 分块行距轴按 A 关闭」 |
| 有 256 B 消息，但 fill 的 store 消息变多/停顿上升，或 `mov` 显著上升 | **B 副作用** | 列增量账，针对 fill 的银行冲突修一版（改成 fragment-major 线程映射） |
| 消息降了、门通过、整体 <0.03 ms | **C/D** | 归因到形状/编译器/作用域，不推广成方向禁令 |
| 帧不一致 | **E 数值失败** | 先查映射（本卡映射已穷举证明双射，最可能是 debug 分支或 barrier 顺序） |
