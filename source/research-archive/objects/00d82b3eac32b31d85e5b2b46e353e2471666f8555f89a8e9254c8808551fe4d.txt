      (4 个 sg%2 相同的 subgroup 读同一批块, 24 KiB/WG 冗余), 被 128 GRF 上限挡死 (见 1 节 D5).

3. 本卡候选 (D0)
================================================================================
机制: 把 C256 的 T staging (shT, 32 KiB) 改成片段连续布局, 使 DPAS 的 A 片段
(8x16 半 = 256 B) 在 SLM 里成为一段连续 256 B, 从而把 8 条 32 B 的 exec=1 uniform 读
合成 1 条 256 B 的 uniform 读. 不是片段变宽 (片段仍 8x16), 是去掉行距 256 半的 stride.

映射: dst(row,k) = ((row/8*16 + k/16)*8 + row%8)*16 + k%16
(PROOF.json.mapping: 16384 元素双射; 128 片段 x 128 元素逐元素等价, 0 失配; 每片段连续 256 B).

改动面 (SOURCE-DIFF.patch, 3 处):
1. shT 填充循环: 线性 shT[e] = gT[w*16384+e] -> 按 16 半一块的置换拷贝 (每线程仍搬 64 半).
2. A 读: coopMatLoad(a, shT, m0*256+k0, 256, LROW) -> coopMatLoad(a, shT, ((m0>>3)*16+ki)*128, 16, LROW).
3. debug 分支: dbg[...] = shT[perm(e)] (语义与父一致; 门跑 debug=0).

构建三件套 (全过):
- 父字节复现: parent-rebuild.spv sha = c853148407be055e..., 与父逐字节相同
  (RECIPES.json 配方, raw 编译, 无 decoration 转移、无 NoContraction 补丁, header pin 315e7c34).
- candidate.spv sha = da0ee2d2f81bb1b2..., 33572 B, spv_validate_cpu.exe PASS.
- plan.txt sha = ea053b92ea8f0c44..., 167526 B, 建在链头
  accepted/restore-n10-f10-next-20261027/plan.txt (sha 719f100b...) 上, replaced == 1,
  cpu_check = CPU_PLAN_OK 152 rows, 232 passes, 502 buffers; no Vulkan loaded.
- float_NC_checked = 4 (NoContraction 4 个站点, 父子逐条一致: op129 x3 + op133 x1).
- 算术对齐: 浮点算术零变化; 算术 opcode delta 仅 OpIAdd +9 / OpUDiv +10 (索引置换).
- 资源: 3 个 Workgroup 变量不变 (WG mem 45056)、binding 集合不变、scratch 0.

4. 未决项 / 风险
================================================================================
1. U1 (决定成败): IGC 会不会把 8 条连续的 32 B uniform SLM 读合成 1 条 256 B?
   反证是 L20/n23 (连续化没换来更宽 opcode, 但那是 exec16 逐 lane gather 区);
   正证是本网络里 256 B/512 B 的 uniform 块读大量存在 (load.ugm.d32x64t x547、
   load.slm.d64x64t x64、load.slm.d32x64t x3), 且本核自己就在 exec=1 用 256 B 的
   store.slm.d32x64t. 判据写死: 看不到 256 B 级消息 => A 类, 把「SLM A 分块行距」轴按 A 关闭.
2. U2: 填充的 SLM 写从线性变成 256 B 跨步, 可能 32 路银行冲突 (512 条 store/WG 不变).
   若 native 看到 fill 的 store.slm 条数/停顿上升或 mov 显著上升 => B 类,
   修法: fill 改成 fragment-major 线程映射 (连续 lane 写连续 32 B).
3. U3: 预测 0.038 ms 只有 L13 阈值 1.3 倍 => 单批显著不算数, 必须第二批平衡批复现.
4. replaced == 1 而非卡面要求的 3: C64/C128 没有 SLM staging 可改; 造字节相同副本会改 SPV 路径,
   而 runner 的 pipeline key 是路径 (clock_runner.cpp:354), 会重排 pipeline 索引、破坏 native 映射.
   已按主代理 2026-10-28 裁定执行, 并记进 BUILD.json.scope.
