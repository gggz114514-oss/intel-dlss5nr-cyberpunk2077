## 1. Headline: what this 0.264 ms is actually spent on

5384 SASS instructions in 127 basic blocks. Two facts dominate:

```
always-run (77.7%)   4181 instr      uniform-guarded (22.3%)  1203 instr
dpas.8x8                129          (never executed when pc.p0.z == 0)
```

* **DPAS is 3.1 % of the code** (129 instructions, exactly one per
  `coopMatMulAdd` in the source — 129 in `candidate.comp`, 129 `dpas.8x8` in the
  ISA, so the matrix path is neither split nor lost).
* **Register movement + integer addressing is ~71 %**: 2486 `mov` (46.2 %),
  791 `add`, 364 `sel`, 253 `mul`, 176 `mad`, 118 `shl`, 49 `or`, 27 `and`,
  8 `macl`, 10 `bfn`, 12 `add3` ≈ 1828 non-mov integer/selector ops + 2486 movs.

For a 1 PSO / 129 DPAS kernel this is not a math-bound kernel, it is a
**lane-address + GRF-shuffle bound** kernel. That is where a legal win has to
come from.

**What each family is** (source → ISA, verified by count):

* 48 × `load.ugm.d64x64t` + 16 × `load.slm.d64x64t` = **the 64 `coopMatLoad(w, wb, …)`
  B-fragment loads of the weight blocks** (`NRH_B`, 16×16 f16) — 48 from UGM
  (weights) and 16 from SLM (the K/V tiles re-read as B in the attention step).
  This is the dominant message traffic of the kernel: 384 + 128 = 512 read units
  for weights vs 128 read units for everything else.
* 64 × `load.ugm.d32x8t` = the 48 `NRH_C` bias/`NRH_CH` operand loads plus the
  8 `coopMatLoad(bias, fb, …, 64u, LROW)` QK-bias reads.
* 64 × `load.ugm.d32x16t` = the strided `NRH_CH` scale/`dbg` window loads.
* 34 × `load.ugm.d16u32` = **per-lane 2-half gathers** (`d16u32` = 2×16-bit):
  8 × `sk[sa], sk[sa+1]` (the real skip input), 8 × `pw[pc.p5.z+ch]` skip gain,
  8 × `pw[pc.p5.z+pc.p5.y+ch]` projection gain, 8 × the stride-0 broadcast
  `coopMatLoad(scale, wb, …, 0u, LROW)` scale rows, +2 scalar.
* 43 SLM sends = the 9 `coopMatStore` to `shK[]`/`shV[]` plus the 8 per-lane
  `shK[ct*32+ch]` 2-half reads of `nr_blend_pair` and the 3 fences.
* **384 × `store.ugm.d32x8t` = the `dbg` debug-buffer stores** — 48 `if(debug)
  coopMatStore(...)` sites × 8 sends each. Every one of them sits inside a
  forward `(W&fN) jmpi` skip span, i.e. it is dead whenever `pc.p0.z == 0`.

## 4. DPAS

129 `dpas.8x8`, all always-run, all in the main latency chain. Per WG each
subgroup issues ~32.25 DPAS. The ISA shows no DPAS split/merge relative to the
source and no accumulator re-materialisation, i.e. **the matrix path is already
minimal** — the 0.264 ms cannot be moved by touching DPAS.

## 5. Address / modulo chain

Integer and selector ops in the always-run path (1393, = 33.3 % of 4181):
`add` 425, `sel` 364, `mul` 245, `mad` 176, `shl` 85, `or` 25, `and` 25,
`add3` 8, `macl` 8, `bfn` 10, `cmp` 9, `fbl` 1.

The single hottest address cluster is the **blend gather**, which runs **8 times
per lane** (8 literal call sites of `nr_blend_pair`, each inlined):

```glsl
uint nrf2_io_at0(uint px,uint py,uint c,uint W,uint C) {   // called 8x per lane
    uint t=((py/4u)*(W/4u)+px/4u)*16u+4u*(py%4u)+px%4u;    // 2 div + 2 mod
    return ((t/16u)*(C/16u)+c/16u)*256u+(t%16u)*16u+c%16u; // 2 div + 2 mod
}
```
with, per call site,
```glsl
uint sx=slot%4u, sy=slot/4u;                      // 8x
uint px=(2u*WGID.x+(sg&1))*4u+sx;                 // 8x
uint py=(2u*WGID.y+(sg>>1))*4u+sy;                // 8x
uint ct=(2u*(sg>>1)+(sy>>1))*4u+2u*(sg&1)+(sx>>1); // 8x
```

**The modulo/divide pairs are exactly redundant**: every call site passes
`slot = 2j + (lane>>4)`, `j = 0..7`, so `slot ∈ [0,16)` always, hence
`sy = slot/4 ∈ [0,4)`, `sx = slot%4 ∈ [0,4)`, and therefore
`px/4 == ax`, `py/4 == ay`, `px%4 == sx`, `py%4 == sy`, `t/16 == ay*(W/4)+ax`,
`t%16 == 4*sy+sx == slot` **for every reachable input**. The chain collapses
algebraically to

```
sa   = pc.p4.z + (ay*(W/4)+ax)*512 + (ch>>4)*256 + slot*16 + (ch&15)
shK# = 256*(sg>>1) + 64*(sg&1) + ch + 128*(j>=4) + 32*(j&1)
```
i.e. **one base per lane + compile-time constants per call site**. 6 div/mod, 3
`mul`, 2 `shl` per site × 8 sites ≈ 50–90 integer ops per lane are pure
recomputation of a value that differs only by a constant.

Note the precedent inside the same file: `nr_tok_base`/`nr_tok_addr` were
*already* converted to this exact form by an earlier card ("M01: … the four
addresses differ only by (c/16)*256 + c%16 in {0,8,256,264}"), and by a bitwise
`t>>4 / t&15`. The blend path was simply never converted. (`nr_tok_addr` itself
is now dead source: 1 definition, 0 call sites — glslang already drops it.)

## 6. Duplicate reads (measured, not estimated from lane width)

`nr_blend_pair` re-gathers, **per call site**, two values that are invariant
across all 8 call sites *within a lane*:

| value | index | gathers per lane |
|---|---|---:|
| `skip_gain` | `pw[pc.p5.z+ch], pw[…+ch+1]` | 8 (only 1 needed) |
| `proj_gain` | `pw[pc.p5.z+pc.p5.y+ch], pw[…+ch+1]` (guarded by `pc.p5.w==1u`) | 8 (only 1 needed) |

`ch = 2*(lane&15)` is loop-invariant, `pc.p5.*` are push constants. The ISA
confirms the duplicate: 34 `load.ugm.d16u32` gathers of which 16 are these two
values, and the capture shows them split 8 guarded / 8 speculative. So **14 of
34 per-lane gathers are re-reads of the same 4 bytes** (~41 % of the gather
traffic of the kernel, and 7 of them are unconditional).

## 7. Barriers, effective lanes, scratch, guarded-discard

**Barriers (all real, all needed):**
* `sync.bar` × 3 + `signal barrier` × 3 (`send.gtwy`) + `fence.slm.none.group` × 3
  = the 3 `barrier()` in the source (after the projection store, after the K/V
  SLM store, and the implicit end-of-kernel). `sync.allrd` × 6, `sync.allwr` × 5
  are the SLM producer/consumer fences; `sync.nop` × 184 are dependency
  scoreboard stalls, not barriers.
* SLM traffic: 2048 halves `shK` + 2048 halves `shV` per WG, written once
  (9 stores) and read 16 times as B fragments + 8 times as scalar pairs. The SLM
  round trip is *required* by the K/V cross-SG sharing the shader documents.

**Effective lanes.** 128 threads/WG, 4 subgroups, all 4 subgroups always active
(`if(sg<4u)` is statically true for `local_size_x=128`; the compiler kept the
compare but never a divergent path). Every lane of every subgroup executes the
same DPAS sequence. The only *data*-level discards are:
* `if(!tok_oob_u)` on the 4 final `coopMatStore(o*, imgout, …)` — a
  **subgroup-uniform** predicate (`subgroupBroadcastFirst`). Border WGs write
  nothing at all, but they still ran the full 129-DPAS pipeline. Grid 84×48 with
  `tiles_x`/`tiles_y` from push constants: the border rows/columns are a
  minority of the 4032 WGs, and the discarded work is only the store, not the
  arithmetic, so nothing is recoverable there without changing the math.
* `if(debug)` — 1203 instructions (22.3 %) that never execute in the measured
  captures. **This is I-cache/issue footprint, not execution.**

**Scratch.** `scratch_ops = 0`, `max_grf = 127` (the `r127.0` uses are the
5 header-mask instructions), 126 distinct GRFs. **No spills, no scratch traffic.**
The `r2.x` "2.x" region holds the payload-header block; no stack objects.

**Guarded-discarded summary.** 1203/5384 instructions are inside uniform-predicated
forward-skip spans, and 396 of the 604 UGM sends are in them (384 debug stores +
4 real imgout stores + 8 gathers). Removing them is *not* a speed mechanism —
they already cost no issue slots — but it does cut the hot code footprint by
22 % and is available as a separate, strictly-behaviour-preserving experiment
(it changes the `dbg` buffer contents only when the debug push constant is on).

## 8. What this does and does not say about 0.264 ms

* Not claimed: any DRAM byte number. The `d…t` block-load width is not
  re-derivable from the ISA text alone, so the ledger records **message counts
  and register units**, and bytes stay `unknown` (§CARD "禁止凭静态 32-lane
  公式算字节", L11).
* Claimed from the ISA: 3.1 % DPAS, 46 % `mov`, 33 % integer/selector, 8×
  duplicated address chain, 14 duplicated gathers, 0 scratch, 3 barriers,
  22 % dead-by-uniform-branch code.
* Therefore the only three mechanisms with real headroom are the three the CARD
  lists, in this order of provability: (1) the blend **address/modulo chain**,
  (2) the duplicated **gain gathers**, (3) the uniform-guarded **debug blocks**.
  (§CARD direction 2 "guarded *pixel/token* work" has no headroom: `oob` only
  discards the final store.)

## 9. Chosen mechanism (for the candidate in this card)

**Class 1 + 3 fused in one function: collapse the exact-redundant div/mod chain
and hoist the two lane-invariant gain gathers out of the 8 inlined call sites.**

* removes ~6 div/mod + ~5 `mul`/`shl` per call site × 8 sites (~50–90 integer
  ops/lane) and 14 of the 34 per-lane gathers;
* adds: 1 base computation per lane (already needed), 2 gathers per lane, 2
  `f16vec2` registers kept live across the 8 sites;
* touches **no** floating-point expression, no rounding point, no accumulation
  order, no barrier, no DPAS, no store;
* provable by exhaustive integer enumeration over the whole reachable domain
  (`slot ∈ [0,16)`, `ch ∈ {0,2,…,30}`, `j = 0..7`) plus the algebraic identity
  above — see `PROOF.json`.

Share of 0.264 ms that can plausibly move: the always-run address+mov budget is
~70 % of issue slots and the blend cluster is the only place in this kernel
where 8 identical chains exist, so a **0.5–2 % pass-level** change is the
honest expectation (≈0.001–0.005 ms on a 0.264 ms PASS); the value of the card
is that it is exact, single-PASS scoped and stacks with every other family.
