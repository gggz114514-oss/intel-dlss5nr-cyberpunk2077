# n10-f10-next · native 可观察点与判据（预测，不是已实现）

本卡没有 GPU。以下全部是**预测 + 判据**，用于主代理拿到 native 捕获后判定"实现是否落地"。
所有基线地址来自同身份/同代码 F10 PASS 的既有捕获（pipeline 18；`C-producer.asm`、`PARENT-QKV-FEED-NATIVE.txt`、
`INTEL-ROWS.json[62].native` 指向的整份 ISA）。**候选的 PC 会整体平移，不能用绝对地址判等，只能按形态与计数判。**

## 0. 基线（父）在被改区域的既有形态

| 观测 | 父（`6b7d2bd9…`）现值 | 出处 |
|---|---|---|
| 整 PASS `sync.bar` 配对数 | **5**：`0x0E40/0x0E50`、`0x1560/0x1570`、`0x2620/0x2630`、`0x2910/0x2920`、`0x6670/0x6680` | 同代码 ISA 捕获 |
| 每个 barrier 前的 SLM fence | 5 条 `send.slm … fence.slm.none.group`（`0x0E00/0x1520/0x25D8/0x28D0/0x6630`） | 同上 |
| kc 循环内 barrier | **2**：publish `0x0E40` 后紧跟内层 k 循环头 `L3744=0x0EA0`；retire `0x1560` 在循环尾（出口 `(W&~f3.0) jmpi L5408=0x1520` 之后） | `PARENT-QKV-FEED-NATIVE.txt` |
| staging 地址 | 每 slice 4 组 ~6–7 条 `or/shr/and/add/shl 8/bfn.0xFE`（`0x06B8/0x0728/0x07A8/0x0818`） | `C-producer.asm` |
| staging 消息 | 16 条 `send.slm … store.slm.d16u32.a32` + 16 条 `send.ugm … load.ugm.d16u32.a32.bss` | 同上 |

| 资源 | instruction 4613、shared 20480、scratch 0 | 同上 |

## 1. 预测（希望看到什么）

**P1（H2 落地主判据）** 整 PASS 的 `sync.bar` 配对数 **5 → 4**，且 kc 循环体内的 `sync.bar` **2 → 1**；
`send.gtwy … signal barrier` 与 `send.slm … fence.slm.none.group` 各少一条（都在循环体里）。
→ 期望形态：循环里只剩 staging 之后的那一对（fence → signal barrier → sync.bar），循环尾只剩 `abase` 取反 + 回边。

**P2（H1 落地主判据）** staging 段不再出现 4 组 `shl 8` + `bfn.0xFE` 的基址重建；
改为 4 个循环携带基址寄存器 + 每 slice 4 条 `add (…, 0x800)`（1024 half = 2048 B）。
→ 期望形态：4 个 base 在循环前算好（`bfn` 只出现一次每象限），循环体内每 slice 只有 `add …2048`。

**P3（同步总量）** 每 WG 的 QKV 阶段 barrier+fence 消息组 **16 → 8**（8 slice × 2 → 8 slice × 1）。
→ 动态计数需按 WG 数（grid 6×3×16 = 288 WG/派发）换算；不要用静态条数当动态次数。

**P4（B 资产不回退，硬判据）** 三条权重 UGM send 仍各自返回**三个互不重叠的 8-GRF 区**，且都**早于该 k-step 的首个 DPAS**；
每 k-step 每 SG 的权重读仍 **3 次**（无第 4 次、无重复地址）。
→ 这条是现役 0.422ms 的资产本身，本卡锁定不动。

**P5（A 片段形态不变）** 每个 A tile 仍是 **2 条向量 SLM 读 + halfword 重组**；每 k-step 仍 2 条 A 片段读；
两条 A 读的地址关系仍是 `abase + base + {0, 512}`。

**P6（arena 常量折叠）** `+0x2000` 应作为 SLM 地址立即数出现（例如 `[A+0x2000]` 形态），
**不应**新增 ~33 条独立地址 ALU。若 ISA 真的多出 ~33 条地址运算，则把 COST-LEDGER 的 "+33 OpIAdd" 从"预期折叠"升级为实测成本。

**P7（资源门）** scratch **0**、shared **20480**、instruction count ≈ **4613 ± 40**。
→ scratch > 0 立即按停止条件 2（新增溢出无法消除）处理，不进 ordinary。

**P8（数值无关性复核）** fixed / fb2 两门必须逐字节通过（预测 trivial 通过：本卡未改任何浮点语句与顺序）。

**P9（可选、只做记录）** 若 native 支持按 WG 统计 barrier 等待，记录 publish barrier 前后的 issue 间隙是否变化；
这只是诊断，不用来替代整体计时。

## 2. "若看不到就等于未实现"的具名判据

| 若看到 | 判定 |
|---|---|
| `sync.bar` 仍为 5 / 循环内仍为 2 | **H2 实现未落地**（判 A 类），不是"少一次同步没用" |
| 循环尾仍有 fence+barrier 对，且窗口 base 无 `0x2000/0` 交替迹象 | H2 未落地 |
| 循环体内仍有 4 组 `bfn.0xFE` 基址重建 | **H1 实现未落地**（编译器把递推折回去了），判 A 类 |
| 三条权重 send 中任一条落到首 DPAS 之后，或两块返回区重叠，或多出第 4 次权重读 | **牺牲已接受资产**（判 B 类，直接否，不看时间） |
| A 片段组装由 2 条向量读 + 重组变成别的形态（例如多了 shuffle/搬运） | 判 B 类，列增量账后再决定是否修一版 |
| scratch > 0 | 判 B 类；停止条件 2 |
| 上述 P1/P2/P4 全对，但 ordinary 仍平 | 判 **D INDISTINCT**（本卡作用域小），不写成方向禁令 |

## 3. 归因纪律

本卡只动 F10 的 A 供料链（地址 + 发布/退休），**不能**用整体收益反推"某条 barrier 值 X ms"。
若 P1 与 P2 同时落地，二者只能用一次具名消融（把 H1 或 H2 单独回退、重建 plan、重测同批）区分，
不允许只凭静态条数宣称其中任何一项的贡献。
