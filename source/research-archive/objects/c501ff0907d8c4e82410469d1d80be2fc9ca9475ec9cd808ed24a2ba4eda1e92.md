## 2. 合并语义（为什么必须是合一内核）

R08 的 producer 契约（`c128_d4_qx.comp`，已部署）：
`imgout` 写 half，**同一个** narrowed half 再量化成 token-major int8 qX 给下一块 FFN 的 body_1。
R07 的 WO 契约（`c128_d4_full_i8.comp`）：WO 矩阵换成 int8，反量化乘 `sC·sWo[n]` 后与 seed 相加。

两者对同一 PASS 的要求不冲突，只是都必须发生在**同一次窄化**上。本卡因此：

```
seed   = MAT_C( H(Y)[m0..][n0..] * pack[ars+n] )        // 与两个父一致（half 乘后加宽）
iacc   = Σ_k int8(A)[m][k] · int8(B)[n][k]              // K32 ×4，int32 精确
acc    = seed + MAT_C(iacc) · (wosc[n] · sC)            // 反量化只做一次
narrowed = MAT_H(acc)                                    // 全流程唯一一次窄化
imgout  ← narrowed                                       // 与父同址同 stride
qX      ← clamp(roundEven(half(narrowed) · invX), ±127)  // 量化器输入强制 half round-trip
```

`invX` 来自**目标块**的 scale 表 `sc[1]`（BIND 9），与 R08 一致：producer 绑的是下游块的缓冲，
不是自己的。BIND 10/11 才是自己的 WO 码表与逐输出通道尺度。

**half round-trip 不是装饰**：C256 的 v3 臂证明编译器会把未舍入的 FP32 累加器喂给 qX 量化器，
在 .5 边界产生 ±1 码。本卡用 `packHalf2x16`/`unpackHalf2x16` 把量化器输入钉死在 imgout 收到的那
个 half 上。本卡在真实抓取上量化了这件事：**若改用未舍入 FP32 累加器，0.26%（21,396 / 8,257,536）
的元素会得到不同的 int8 码**（合成 invX = 127/absmax 下测得，见 `evidence/INT8-REFERENCE.json`
的 `arm_stats_*.qx_code_diff_synthetic`）。这就是 R08 producer 可能同样存在的风险，已列为具名缺口。

| 60 | 0.006479 | 43.8 dB | 1.080% | 0 | 是 | 63 |
| 61 | 0.006530 | 43.7 dB | 1.038% | 0 | 是 | 100 |

结论：**pack 确实是那个矩阵**（rel_L2 0.65–0.71%），逐输出通道尺度 9/9 逐字节复现，
**码也 9/9 逐字节复现（0 个码不同）**。

> **本卡的一处自我更正（2026-10-24 深夜）**：本节初版写"shipped 量化器的 tie 处理无法用五种候选
> 算术逐字节复现（`f32_recip_mul` 最好，仍差 60–112 个码）"。那是**错的**——我漏试了密封形式本身：
> `code = roundEven( half( W · (1/sW) ) )`，即**乘积先舍入到 half，再做整数舍入**。加上这一步，
> 九份 pack 全部逐字节复现、残差 0；去掉这一步才出现 60–112 个 ±1（全部落在 |scaled| = 63.499996）。
> 这个更正来自 `r07-c128-cproducer` 卡（它用同一形式让十份 pack 全部复现），我独立复算确认后改的。
> 影响：参考仍然**直接解码 shipped codes**（这样参考与内核读的是同一份字节，不依赖任何重生成），
> 但"不可复现"这个说法撤回。

`evidence/WO-PACK-EVIDENCE.json` 现在同时记录 `recomputed_code_diff`（密封形式，全 0）与
`recomputed_code_diff_without_half_rounding`（旧形式，60–112），两条都在，方便复审对比。

## 5. 本臂整数参考（`evidence/INT8-REFERENCE.json`）

没有 GPU 时段，所以参考建在**已有真实抓取**上，先把模拟器钉到硬件输出，再用它判 INT8 臂：

- fixture：`candidates/amd-map-20261015/s1-output-complete/gpu-numeric/c128-full-b9-full/`
  （`T.bin` / `Y.bin` / `M.bin` / `image_out.bin`，252 窗口 × 8192 half，全部有限非零）
- push 常量：同 case 的 `c128_abi.bin` 196 B → `p0=(42,24,0,0)`、`p1=(21,12,0,0)`、`p4=(wo=0, rs=180488, ars=32768)`
- WO 码表：`candidates/r07-c128-wo-i8/packs/c128_b9_wo.i8.bin`（16896 B = 16384 码 + 128 f32 尺度）

| 比较 | 位相同率 | max abs | rel_L2 | SNR |
|---|---:|---:|---:|---:|
| **A 模拟器 vs GPU 抓取**（FP16 父算术） | **0.999927** | 0.0009766 | 6.0e-06 | 104.4 dB |
| **B INT8 vs FP16（同输入）** | 0.1482 | 0.01855 | **0.004093** | **47.76 dB** |
| C INT8 vs GPU 抓取 | 0.1482 | 0.01855 | 0.004093 | 47.76 dB |

A 行是锚：模拟器对真实硬件输出 99.9927% 逐位相同、其余差 1 ulp，说明父算术被复现，B 行的差异可以归给
量化而不是模拟误差。B 行 0.41% rel_L2 / 47.76 dB 与 C64 已封存的 WO 参考（0.489% / 46.2 dB）同量级。

量化器与整数范围：激活 absmax 1.335–2.475 → invC 51.3–95.1；饱和 0.0129%；INT32 累加 absmax **102,899**，
远低于 2³¹，且 int8×int8 乘积在 int32 里精确（`fits_int32: true`）。

**参考的边界**：这是 b9 的 D4 抓取，不是 blocks 11/12/13/56–60 各自的输入。它证明的是**机制**（同一份
内核算术、同一 tile 布局、同一量化点），不是这 8 个位置各自的数值。要逐位置闭合，需要一次
`--dump-intermediates` 或诊断 plan 抓取这 8 块的 T/Y。

## 5b. qX 边的所有权核对（`evidence/QX-EDGE-CHECK.txt`）

合一内核最容易被破坏的不是算术而是边：producer 与 consumer 可能对"哪个缓冲装 qX"产生分歧。
本卡对 8 条边逐条从**计划本身**核对（不看注释）：

| 边 | producer | consumer | 同资源 | 同字节 |
|---|---|---|---|---|
| block11_body_4 → block12_body_1 | `c128_d4_wo_qx` | `r08_d1_expand_qx` | 是 | 是 |
| block12 → block13 | 同 | 同 | 是 | 是 |
| block13 → block14 | 同 | 同 | 是 | 是 |
| block56 → block57 | 同 | 同 | 是 | 是 |
| block57 → block58 | 同 | 同 | 是 | 是 |
| block58 → block59 | 同 | 同 | 是 | 是 |
| block59 → block60 | 同 | 同 | 是 | 是 |
| block60 → block61 | 同 | 同 | 是 | 是 |

producer 的 BIND 8/9 与 consumer 的 BIND 2/1 指向**同一对资源**且字节数相同；每条 qX 缓冲
**单写单读**（无多写者/多读者）。这条检查是"融合没有把边接错"的直接证据，也是 R08 原卡
`EXIT-MAP.json` 关心的同一件事，只是换成了从计划侧复核。

## 6. 具名缺口（复审请按此判）

1. **无 GPU 门**：本会话没有 GPU 时段，8 个 PASS 没有跑过整网，也没有单帧 PSNR。合并后必须重测，
   不能把 R07 独立 9x 臂的 45.92 dB 当作本卡结果（不同组织、不同 PASS 集合）。
2. **逐位置输入参考缺失**：只有 b9 抓取。需要 blocks 11/12/13/56–60 的 T/Y 抓取才能做逐位置整数参考。
3. **R08 producer 的 qX 可能同样缺 half round-trip**：本卡量化了风险（0.26% 元素会换码），但没有改
   R08 的 `c128_d4_qx.comp`——它现在只服务 block61 之外……实际 v5 里 R08 producer 已全部被本卡替换，
   所以该风险在累计臂里已消除；单独跑 R08 卡的旧身份仍带此风险，登记为历史缺陷。
4. **POLICY 缺失是累计工具的缺陷**：`merge_cumulative_v*.py` 只复制 base 的 tail，v1–v4 因此丢了所有
   卡新增资源的 POLICY 行（v4 有 63 个）。本卡沿用默认（resident=1），未擅自补写；修复应作为一个独立的
   合并一致性改动，且需要 GPU 复核。
5. **scale 资格**：8 份 WO pack 的尺度是静态权重量化器（`amax_k|W|/127`），不是单帧诊断值，这一点
   优于 R08 的 FFN scale；但 qX 侧 `invX` 仍来自 R08 的 `c128_b{N}_sc` 表，那批是
   `SINGLE_FRAME_DIAGNOSTIC_NOT_CALIBRATION`，未按当前臂标定。
6. **未验证**：int8 `M8N16K32` 在本组织的 device 行为（B580 上 R07 的 9x 臂跑过 exit 0，但那是独立
   计划）；nbind=12 的 descriptor 布局；native SLM/scratch（9224 是 SPIR-V 静态声明量，不是 native 分配）。
