## 0. 一句话结论

F01 的 1.164 ms 里，**入口 gather 本身的消息量很小（73 条 / 9.3 KB 每 lane-program），真正贵的是给这 73 条消息算地址的整数运算**：
入口区 1491 条热指令中，**31 处内联的 32×32 取模序列（每处 4 条乘加 + 约 6 条修正）≈ 310 条，占入口区约 21%**，而 5 个双线性 tap 的 20 次角点读全都落在**被 clamp 死的区间**里 —— 这些取模在数学上是恒等的死算术。这是本卡选中的机制。

## 3. 消息构成与字节（热路径 306 条）

每消息载荷口径：per-lane 形式 `d32` = 4 B/lane × 32 lane = **128 B**；transposed 块形式 `d<w>x<N>t` = N × w/8 B（与驱动 `rd:` 计数按 64 B 粒度取整一致：`d64x64t` = 512 B = 一个 16×16 half B 片段，`d32x32t` = 128 B，`d32x16t` = 64 B，`d32x8t` = 32 B）。

| 消息 | 条数 | 单条字节 | 小计 | 归属 |
|---|---|---|---|---|
| `load.ugm.d64x64t` | 50 | 512 | 25 600 B | 权重/片段（lift 与 8 组 linear、QKV、out） |
| `load.ugm.d32x16t` | 64 | 64 | 4 096 B | 片段/权重（16×16 面内小块） |
| `load.ugm.d32x8t` | 65 | 32 | 2 080 B | 片段/权重 |
| **`load.ugm.d32`（标量 gather）** | **73** | **128** | **9 344 B** | **入口图像/历史/深度/运动** |
| `load.slm.d64x64t` | 16 | 512 | 8 192 B | SLM → A 片段（K/V/残差） |
| `load.slm.d32x64t` | 3 | 256 | 768 B | SLM 小读 |
| `store.slm.d32x64t` | 5 | 256 | 1 280 B | SLM 写（shK/shV） |
| `store.slm.d32x4` | 4 | 128 | 512 B | SLM 写（feature pack 32 B/lane） |
| `store.ugm.d32` | 8 | 128 | 1 024 B | imgout 输出 |
| `store.ugm.d32x64t` | 4 | 256 | 1 024 B | pooled 输出 |
| flat 标量（控制/噪声/小常量） | 5 | 4–128 | 264 B | prologue 控制向量、噪声、headscale |
| fence/barrier/EOT | 5 | 0 | 0 B | 同步 |

结论一：**消息字节的主项不是 gather，是权重/片段读（31.8 KB / 43.5 KB = 73%）**；
结论二：**node 数的主项在入口区**（77 send.ugm / 82 消息都在入口区，= 全核消息数的 27%），其中 73/77 是 4 字节标量读。

> 注意（合同 §4.4）：以上是**消息载荷**字节，不是 DRAM 字节。权重 30 KB/ lane-program × 4 SG × 16128 WG = 1.9 GB 的“请求字节”，实际由 L2 供给（权重总量只有几百 KB）；gather 同理。这里只用于说明“谁在发消息”，不用于推 DRAM 压力。

## 4. 入口区（`nrf_prepare_A`，索引 206–2066）：1491 条热指令 / 82 消息 / 10 284 B

### 4.1 gather 的构成（73 条标量 `load.ugm.d32`）

| 来源 | 每 lane 读 | 消息 | 说明 |
|---|---|---|---|
| 源图像 1 像素 RGB | 3 float | 3 | `nrf_rgba(pc.p4.z,…)`（`.rgb`，alpha 被编译器删掉） |
| 历史 5 tap × 4 角点 RGB | 5×4×3 = 60 float | **60** | `nrf_hist_linear` × 5，`nrf_rgba(pc.p6.y,…)` |
| 深度 1+4 | 5 float | 5 | `nrf_depth_at`，`pc.p6.w` |
| 运动向量 2 | 2 float | 2 | `nrf_motion_uv`，`pc.p6.z` |
| 冷噪声 3 | 3 float | 1 | `load.ugm.d32x32t`（一次 32 dword 转置读，非标量） |
| 控制 19 个 uniform | — | 1 | prologue `load.ugm.d32x32t.a64.ca.cc.flat`（见 §4.4） |

三个通道用**同一条地址寄存器 + 立即数 +0/+4/+8**：ISA 里 28 条 `[a0.0]`、23 条 `[A+0x4]`、22 条 `[A+0x8]`，**没有 `[A+0xC]`**（alpha 已删）。即“一个像素 = 1 次地址计算 + 3 条 4 字节消息”。

每 lane-program gather 请求字节 = 73 × 128 B = **9 344 B**；每 WG = 4 SG × 9 344 = 37 376 B；每派发 = 16128 × 37 376 = **602.9 MB**（请求侧）。

### 4.2 有效 lane：gather 的 32 条 lane 里只有 16 条是本职像素

证据：73 条标量读的 exec size **全部是 32**（`send.ugm (32|M0)`，无谓词），而源级由 `if(lane<16u)` 保护；lane→像素映射为

```
xl = 4*(q&1) + lane%4      yl = 4*(q>>1) + lane/4
px = WGID.x*8 + xl         py = WGID.y*8 + yl      (q = sg = 0..3)
```

lane 16..31 的 `lane/4 = 4..7`，于是：

* q=0 的 16..31 → (列 0–3, 行 4–7) = **q=2 的 0..15 正在用的同一批像素**
* q=1 的 16..31 → (列 4–7, 行 4–7) = **q=3 的 0..15 的像素**
* q=2/q=3 的 16..31 → 行 8–11 = **下一个 WG 的 SGs 0/1 的像素**

所以每个 WG 的 gather 请求字节里恰好 **50% 是别处已经在读的同一批地址**（去重因子 2.0；图像边界处 mirror 折叠会略微改变这一点，但不会降低消息数）。
→ 73 条消息里 32-lane 载荷只有 16 lane 有效，**gather 请求字节 602.9 MB 中 301.5 MB 是重复地址**。
这条属于“有效 lane”账，本卡**不做**（修它要改 lane→owner 映射，牵动 feature pack 的 shK 写入与 token 归属，超出本卡范围），列为下一处候选（见 RESUME）。

### 4.3 地址计算：入口区 1491 条里约 900 条是整数寻址

| 项 | 计数（入口区热） | 说明 |
|---|---|---|
| `mul (16|M0) acc` / `mul (16|M16) acc` / `macl (16|M0)` / `macl (16|M16)` | **31 / 31 / 31 / 31** | 每 4 条 = 1 次 32×32→64 乘；`i % period`（runtime period）就这么lower |
| 取模序列配套修正（`add`/`add3`/`cmp`/`sel`/`xor`/`jmpi`） | ≈6 / 处 ≈ 186 | 符号修正 + 反射选择 |
| `sel` | 151 | clamp + mirror 反射 + 分支归并 |
| `cmp` | 104 | 同上 |
| `add`/`add3` | 256 | 同上 + 地址加法 |
| `bit`（shl/shr/asr/and/xor/bfn） | 150 | `*4`、`*W*4`、`period=2*size`、符号扩展 |
| `mul (32|…)` 浮点乘 | 67（130 − 63 整数乘） | 双线性权重与除法 |
| `math.inv` + `mad` 补 Newton | 13 + 109 | `w2/wc`（float 除） |
| `rndd` / `frc` | 10 / 6 | `floor(q)` / `fract(q)`（5 tap + 5 次 hist_linear） |

`nrf_mirror` 每个轴 1 次取模；5 tap × 4 角点 = 20 次 `nrf_rgba` 调用 = **40 个轴取模**，加上源像素/深度(5)/运动 = 27 次调用 = 54 个轴取模。ISA 只看到 **31 处**，即 IGC 已对共享坐标做了一部分 CSE（例如 tap T1/T3/T5 的 y 都是 `pm.y`、T2/T3/T4 的 x 都是 `pm.x`）。

**关键事实**：这 20 次角点读的坐标在进 `nrf_rgba` 之前已经被 `clamp(ij(+1), 0, (W-1,H-1))` 压到像素区间内，而
`nrf_mirror(i,size) = i` 对一切 `0 ≤ i ≤ size-1` 成立（`period = 2·size > i` ⇒ `i%period == i`，`j<0` 分支死，`j<size` 取 `j`）。
也就是说 **31 处取模里最多 20 处（40 个轴 → 被 CSE 后的实际站点约 17–20 处）是恒等的死算术**。

### 4.4 交织 mov：275 条（入口区）

| 类型对 | 条数 | 来源 |
|---|---|---|
| `f ← ud` / `ud ← f` | 46 / 34 | IGC 在整型/浮点寄存器类之间搬运（`cr0` float-mode 切换配套），集中在 `mix`/`fract`/`floor` 与地址整数交错处 |
| `d ← d` / `d ← ?` | 25 / 20 | clamp/镜像的中间值 |
| **`hf ← f`** | **24** | f32→f16 舍入点（见 §4.5） |
| `f ← hf` | 12 | f16→f32 扩张（`centered`/`cn` 回写） |
| `hf ← hf` | 8 | pack 前的半精度搬运 |
| `ud←ud` / `ud←d` / `d←f` | 25 / 18 / 8 | 地址与描述符 |

### 4.5 FConvert / Quantize：24 个 `mov hf←f` 就是入口的全部舍入点

源级可数出 **19 个 f32→f16 转换点**：`sampled` 3、`hv`(history) 3、噪声 3、`ctl(6)` 1、`ctl(0..4)` 5、
`packed[5..7]` 的 4 个控制量（其中 `ctl(4)` 与常量 0 共用 1 个槽位）。
另有 **6 个 half→float→half 往返**：`packed[2..4]` 写的是 `float16_t(float(cn.x))` 这类形式，
而 `cn`/`hn` 本来就是 `float16_t`（widen 精确、narrow 回原值），所以是源码级可删的恒等往返。
ISA 实测入口 **`hf←f` 24 条 / `f←hf` 12 条**（多出的部分来自 pack 前后的寄存器类搬运），本卡一条都不动。
4 个 `packFloat2x16` 的位拼装：ISA 里是 `hf←f` 落位后再由 `store.slm.d32x4` 一次写 16 B/lane（2 条消息 32 B/lane），**没有逐 byte/逐 half 的窄写**——这一项已经是宽的。

### 4.6 scratch / SLM

* Scratch Memory Size = **0 B**（驱动统计 + 静态 `scratch` 文本 0 次 + 父卡 NATIVE-REVIEW `scratch: []` 三方一致）。
* SLM = **9216 B** = `shK[2048] + shV[2048] + shResidual[512]` half = 4608 × 2 B，与驱动统计逐字节相符。
* SLM 往返：入口 `store.slm.d32x4` ×2（写 feature）+ `load.slm.d32x64t` ×2（读回 A 片段）= 4 条；屏障 `fence.slm` + `signal barrier`。**入口的 SLM 往返不是成本主项**（占入口消息 5%）。

## 5. 成本归属：1.164 ms 怎么分

没有逐指令计数器，所以用两种口径互校，**只给量级**：

* 口径 A（指令份额，假设 issue-bound）：入口 1491 / 5667 = **26.3%**；其中地址/取模 ≈ 900 = 入口的 60%，= 全核的 **15.9%**（≈0.185 ms 上限）。
* 口径 B（消息份额）：入口 82 / 306 = **26.8%**，字节 10 284 / 43 460 = **23.7%**；gather 73 条 = 全部消息的 24%。

两个口径都指向“入口 ≈ 全核 1/4”，且入口内部**整数寻址 ≈ 60%**。这与该 kernel 的形态一致：每个 owner 像素要算 21 次镜像/夹取地址，但只产出 16 个 half。

派发级换算（供量级核对，不作预测）：16 128 WG × 4 SG × 5667 指令 = 3.66×10⁸ 次指令发射；1.164 ms × ≈2.67 GHz ≈ 3.1×10⁶ cycle × 160 EU ≈ 5.0×10⁸ 发射槽 → 静态/发射口径下**填充率约 0.73**，即这个 kernel 接近发射受限。**这是本卡认为“删指令”仍有空间、而“删消息”空间较小的依据。**

## 6. 选中机制与它在 1.164 ms 里的份额

**机制（一类）：入口 gather 的镜像/取模恒等删减 —— “地址计算”类。**

* 删什么：`nrf_hist_linear` 的 4 个角点读改为直接读已 clamp 的像素（新 `nrf_rgba_clamped`），20 次 `nrf_rgba` 调用不再走 `nrf_mirror`。
* 份额：这 20 次调用对应的取模站点（ISA 现 31 处，其中约 17–20 处消失）每处 4 条乘加 + 约 6 条修正 ≈ 10 条 → **预计 -170 ~ -200 条指令**（= 热路径 3.0–3.5%，入口区 11–13%）。加上被一并删除的反射 `sel/cmp` 与符号修正，上限约 -300 条（入口区的 20%）。
* 不改：地址顺序、加载顺序、`mix`/`fract`/`floor`/除法、任何浮点舍入点、任何消息地址与消息数（gather 仍是 73 条、仍 128 B/条）。
* 为什么不是另外两类：
  * **宽读**（3 条 4 B 标量 → 1 条 16 B 向量）：消息 73→33 条（-40），但字节 +33%，且要把 `f[]` 换成 `vec4[]` 视图（同 binding 别名 + 16 B 对齐假设，本卡无 GPU 无法验证对齐与是否真合并），收益按 §5 口径 A 只有 ~0.01 ms 量级。
  * **重复读共享**（F09 形态）：真正能拿的是 §4.2 的跨 SG 半重复（去重因子 2.0，301 MB），但要改 lane→owner 映射与 token 归属，属于重排整个 block 几何，本卡范围外。
  * **入口系数 owner 归约**（F14 形态）：入口的 uniform 量（19 个 ctl、`headscale`）已经被 IGC 用标量 `(1|M0)` 读+广播，没有可归约的重复计算。

## 7. 这份分解**没有**回答的（防止过度引用）

1. 没有 cycle/事件计数：不给“取模占多少 ns”，只给指令份额与消息份额。
2. 静态 ≠ 动态：1501 条调试指令已剔除，但循环/分支的实取次数仍未知（Loop Count = 0，全展开）。
3. 消息载荷 ≠ DRAM 字节：无 L2 miss 计数，权重 30 KB/lane-program 很可能全命中。
4. §4.2 的“重复地址”是**结构证明**（由 lane→像素映射推出），不是内存事务计数。

## 勘误（2026-10-27，由 n18b-f01-gather 的 ISA 实证）

本文 §4.2 的 **602.9 MB / 301.5 MB 重复**是按 32 lane 公式算出的**幽灵字节**。
实测：入口块整体是 IGC 的一条发散区域（`0x0340 cmp (lt)f0.0 lane,16` → `0x0390 (~f0.0) goto L19088`，
区域 (0x390,0x4A90) 含全部 73 条 `load.ugm.d32`），运行时活动掩码 = lanes 0..15，
每条 gather 载荷 **64 B 而不是 128 B** ⇒ **真实 gather 请求字节 = 301.40 MB，重复 = 0 B**。
证据与逐条证明见 `cards/n18b-f01-gather/{PROOF.json,tools/isa-mask-proof.json}`。
今后引用 F01 的 gather 压力请用 **301.4 MB（无重复）**，不要再用 602.9/301.5。
