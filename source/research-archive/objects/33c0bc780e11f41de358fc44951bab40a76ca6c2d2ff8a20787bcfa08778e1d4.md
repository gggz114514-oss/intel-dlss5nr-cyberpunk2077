# N17C F20 Q+Y — ANALYSIS (contract §4, six questions)

Card `n17c-f20-qy`, PASS ordinal 230, `s37_fold_body_r1a_v1`, grid (169, 97, 1), local 256,
8 subgroups of 32.  Candidate: **both intra-subgroup cooperative-matrix round trips of this
PASS are removed in one module** —

* **Q** (stage 4 → stage 6): the `H(Q)` pair stays in registers and becomes the stage-6 `A`
  fragments; the `shArena` Q-plane publication becomes debug-only.
* **Y** (stage 3 → stage 9): the `H(Y)` pair stays in registers and becomes the projection
  seed; the `shY` publication becomes debug-only.

This is one variable (the same mechanism, two instances), and it is the composite of the two
single-point cards that were each measured alone: `cards/n17-f20-body` (Q, +0.025685 ms
CI[−0.042,+0.094]) and `cards/n17b-f20-transport` (Y, −0.018101 ms CI[−0.041,+0.0045]).
Neither single point is separable from noise at 5 % of the message stream; 64 messages
(10.0 %) is the only size of this mechanism that can clear a frame-level detection, with an
upper bound of 1.367 ms × 10 % = **0.137 ms** against an ordinary CI half-width of 0.068 ms.

The change, in one table (per warp; parent from the captured ISA of kernel
`76902ef344609c8a`, candidate predicted):

## Q1. Mapping — what does each (lane, component) mean, and why are both handoffs the identity?

**Two tiles, two owners, one subgroup each.**

| object | logical index | writer | reader | owner |
|---|---|---|---|---|
| `half0` (stage 4, `region 0`) | token `t = 8*sg + r`, channel `c = 0..15` | SG `sg`, `m0 = sg*8` | stage 6 `ki=0` A operand | SG `sg` |
| `half1` (stage 4, `region 0`) | token `t = 8*sg + r`, channel `c = 16..31` | SG `sg`, `m0 = sg*8` | stage 6 `ki=1` A operand | SG `sg` |
| `yhalf0` (stage 3) | token `t = 8*sg + r`, channel `c = 0..15` | SG `sg`, `m0 = sg*8` | stage 9 seed 0 (`MAT_H * scale`) | SG `sg` |
| `yhalf1` (stage 3) | token `t = 8*sg + r`, channel `c = 16..31` | SG `sg`, `m0 = sg*8` | stage 9 seed 1 | SG `sg` |

Coverage per tile: 8 SG × 8 rows = 64 tokens, 2 fragments × 16 channels = 32 channels ⇒
**64 × 32 = 2048 halfs = the whole tile, every (t, c) written exactly once and read by the
consumer of the same subgroup**.  Two tiles ⇒ 4096 halfs, 4 fragments, 4 loads, 4 stores.

**Writer/reader index identity (the enumerable part).** In the parent both round trips are the
identity on the logical index by construction:

* Q: `coopMatStore(half0, shArena, region*2048 + m0*32, 32, LROW)` writes element `(r,c)` to
  `shArena[(8*sg + r)*32 + c]`; `coopMatLoad(score_q0, shArena, sg*8*32, 32, LROW)` reads
  element `(r,c)` from `shArena[(8*sg + r)*32 + c]` — the same address function (`m0 = sg*8`
  on both sides), and the same for `+16`.
* Y: `coopMatStore(half0, shY, m0*32, 32, LROW)` and the stage-9 seed
  `coopMatLoad(seed, shY, m0*32 + 0u, 32, LROW)` — again the same `m0 = sg*8`, the same
  stride 32 and the same row-major layout.

The candidate replaces each round trip with `fragment[d] = half[d]`.  The claim is therefore
only about the *fragment accessor*: `MAT_H[d]` and `MAT_A[d]` (Q) or `MAT_H[d]` and `MAT_H[d]`
(Y) denote the same element.  That is not a new assumption:

1. the SPIR-V types are identical except for `MatrixUse` — component f16, scope Subgroup,
   8 × 16, use 2 (accumulator-half) vs 0 (A), `same_except_use = true`
   (`build/spv-check.json → H_vs_A_type`); the Y handoff is `MAT_H → MAT_H`, i.e. the very same
   type;
2. **the accepted baseline already does this exact component-wise handoff twice** — stage 8
   (`MAT_A pa; pa[d] = p_cache[j][d]`) and, decisively, the stage 8 → 9 context handoff
   (`a[0..3] = ctx_half0[0..3]`, the S37-CONTEXT-A path at source lines 553-558) which is in the
   baseline and passes the fixed-frame gold;
3. the same accessor `fragment[d]`, `d = 0..3`, is used on both sides of each new handoff, so a
   different map cannot be introduced without also breaking stage 6 or stage 9.

The `(lane, component) → (t, c)` layout itself is IGC's DPAS operand layout and is *not*
re-derived here; it is the same function for the two sides because the types are the same
family, and this card does not need to name it (that is exactly why the round trip can be
deleted without a layout proof — see `COST-BREAKDOWN.md` §5.3 for the direction that *would*
need one).

**No duplicate writes, no dropped reads, no tail.**

| check | Q | Y |
|---|---|---|
| writes per element | 1 (capture guarded by `region == 0`, true for exactly one of the three unrolled iterations, `j = 2 − step`) | 1 (stage 3 runs once, no loop) |
| reads per element | 4 DPAS A-operand reads per fragment (2 `j` × 2 accumulators) — same count as the parent's 2 loads × 2 `j` | 1 (the seed multiply, then the accumulator carries it) |
| partial fragment / predicated lane | none: the tile is exactly 2 fragments × 8 SG | none |
| pixel-level tail | untouched (stage 0 `oob`, stage 11 `px<1280 && py<720`) | untouched |

`PROOF.json → P1_mapping` carries the same statement machine-checkably
(`elements_written_per_handoff = 256`, `duplicate_writes = 0`, `dropped_reads = 0`).

## Q2. What real work is deleted (normal path only)

Per warp, from the parent ISA (`build/isa-sites.json`); nothing here counts debug declarations,
and the 107 static debug-only messages are excluded because `p0.z = 0` branches around them.

| # | deleted work | count | where |
|---|---|---:|---|
| 1 | `send.slm load.slm.d32x8t` — stage-6 Q pair | **16 messages** | segment 7 of the parent capture (144 load messages = 18 transfers); the two removed records are identified by address in `build/spv-check.json → removed_loads` |
| 2 | `send.slm load.slm.d32x8t` — stage-9 Y seeds | **16 messages** | segment 10 (16 load messages = 2 transfers, i.e. the whole load budget of that segment) |
| 3 | `send.slm store.slm.d32x8t` — the two Q-plane stores, region 0 | **16 messages not issued** | segment 5 holds 48 store messages in three groups of 16; the base immediates of the three groups are `12320` (0x3020), `8192` (0x2000) and `4096` (0x1000), i.e. `shArena + 2*4096`, `+1*4096`, `+0` — the last group (`87D0..8950`) is the `j = 0` (Q) publication |
| 4 | `send.slm store.slm.d32x8t` — the two shY stores | **16 messages not issued** | segment 3 (16 store messages = 2 transfers, the whole store budget of the stage-3 segment) |
| 5 | address arithmetic for the four removed loads | −12 `OpIMul`, −6 `OpIAdd` | `build/spv-check.json → opcode_delta` |
| 6 | uniform SLM offset adds for the 32 removed messages | ≈16–24 `add (1|M0)` | 564 `add (1|M0)` over 701 messages (0.80/message) |
| 7 | register-slice landing pads for those messages | ≈10–16 `mov (N|M0)` | 297 slice movs over 464 fragment messages (0.64/message) |
| 8 | `sync.nop` scoreboard padding | ≤32 (not a criterion) | 353 `sync.nop` for 640 messages (0.55/message) |
| 9 | RAW/WAR dependency edges on the two planes | 3 | see Q3 |

Nothing else is deleted: **no DPAS, no norm/den reduction, no bias/exp, no epilogue, no
barrier, no weight read, no pixel-tail work**.  `OpCooperativeMatrixMulAddKHR` 16 → 16,
`OpCooperativeMatrixStoreKHR` 17 → 17 (static), `sync.bar` 12 → 12.

Runtime message accounting (per warp, `p0.z = 0`):

```
parent static sends            747
- debug-only static messages   107   (96 store.ugm.d32x8t + 11 store.ugm.d16u32)
= parent runtime messages      640
- removed load messages         32   (4 transfers × 8, statically gone)
- predicated store messages     32   (4 transfers × 8, still in the module, not issued)
= candidate runtime messages   576   (-10.0 %)
```

Per dispatch: 131 144 warps ⇒ 83 932 160 → **75 538 944** messages (−8 393 216).

**Why "not issued" is a statement about a predicate and not about hope.**  In SPIR-V the four
target stores are inside selections whose condition is the push-constant `debug` flag:

| store site | variable | condition (canonical, ID-free) | executes when |
|---|---|---|---|
| idx 8, 9 | `shY` | `('load', ('var','Function',None,23))` = `debug` | `p0.z != 0` |
| idx 10, 11 | `shArena` (stride 32) | `('op',166, (debug, ('op',171,(region, 0))))` = `debug \|\| region != 0` | `p0.z != 0` **or** `region != 0` |

`debug` is materialised once as `OpINotEqual(OpLoad %pc, 0)` on the push-constant block
(`build/spv-check.json → pushconstant_debug_flag`), so both predicates are workgroup-uniform;
with `p0.z = 0` they are uniformly false, and the whole region is branched around.  For the Q
pair the condition still admits `region != 0`, i.e. the K and V iterations keep publishing —
only the `region == 0` (Q) copy stops.  Counted on the module: the number of cooperative-matrix
stores *without* a debug dependency falls from 10 (parent) to 6 (candidate), exactly the four
target sites (`store_guard_classification.target_assertions.unguarded_delta = 4`).

## Q3. Overlap — what overlapped before, and what protects the feed now

The kernel is a 12-barrier sequence of owner blocks; the two deleted round trips are the only
intra-subgroup ones (`COST-BREAKDOWN.md` §5.2).  A = the fragment producer/consumer pair; every
block B that runs between producer and consumer; the acc groups, the norm/den producers and the
residual producer with their last consumers.

| plane | producer | last consumer | blocks in between | protection in the parent | protection now |
|---|---|---|---|---|---|
| Q (`shArena` region 0) | stage 4, last unrolled iteration (`step=2`, `j=0`) | stage 6 `ki = 0/1` A operands | stage-4 debug dump (`if (debug)`), 1 barrier | RAW through SLM + barrier | **register**: `score_q0/score_q1` |
| Y (`shY`) | stage 3 tail | stage 9 seed multiply (blocks K0 and K16) | stage-4 loop (all three regions), stage-4 debug dump, stage 6 (score/bias/exp, `p_cache`), the den reduction (`pv_inv`), stage 8 (context, `ctx_half0/1`), stage-8 debug dump | RAW through SLM + 5 barriers | **register**: `yhalf0/yhalf1` |
| stage-1 M (`shArena` A plane) | stage 1 | stage 3 `A` operand (8 K slices) | — | RAW through SLM + barrier | unchanged (**cross-SG**: 16 transfers) |
| K, V (`shArena` regions 1, 2) | stage 4 (`j=1`, `j=2`) | stage 6 (`K^T`), stage 8 (`V`) | stage-4 debug dump | RAW through SLM + barrier | unchanged (**cross-SG**: 16 + 16 transfers) |
| O (`shXP`) | stage 9 | pixel tail `boundary_project` | 1 barrier | RAW through SLM + barrier | unchanged (**cross-SG**: 2 transfers) |
| `p_cache` / `pv_inv` | stage 6 | stage 8 (`a[d] = p_cache[ki][d] * pv_inv`) | subgroup shuffles only | register (already) | unchanged |
| `ctx_half0/1` | stage 8 | stage 9 A operands | 1 debug barrier | register (already) | unchanged |
| `residual_out` | stage 11 | the frame | — | global store | unchanged |

Hazard table (per plane, parent → candidate):

| edge | parent | candidate |
|---|---|---|
| RAW stage4 Q-plane store → stage6 load | yes, 2×16 messages + barrier | **deleted** (value in registers) |
| RAW stage3 shY store → stage9 seed load | yes, 2×16 messages + 5 barriers | **deleted** (value in registers) |
| WAR stage-3 read of the `shArena` A plane vs the stage-4 Q-plane rewrite | yes (barrier at source line 336) | **deleted** on the normal path: the Q plane is never rewritten |
| WAR stage-4 read of Q vs anything later | none (no later writer) | none |
| WAW on either plane | none | none |
| new RAW/WAR/WAW | — | **none**: the retained values are single-assignment locals with exactly one definition and one (or four) uses |

The feed is protected by *not moving anything else*: the barriers stay (the cross-SG transports
still need them), the debug dumps stay (they read the shared planes, which are still written
under `debug`), and the three other intra-SG handoffs the module already performs in registers
(`p_cache → A`, `ctx_half → A`) are untouched.

| item | count | evidence |
|---|---|---|

| address arithmetic | **−18** (`OpIMul` −12, `OpIAdd` −6) | `opcode_delta` |
| component copies | **8** for Q (AccessChain/Load/AccessChain/Store per component), **0** for Y | `build/spv-diff.txt`; the Y side only renames the source of an existing copy |
| selections / predicates | **+4** (2 × `if (debug)` around the shY stores, `region == 0` around the Q capture, `debug \|\| region != 0` around the Q publication) | `OpSelectionMerge` 57 → 61, `OpBranchConditional` 89 → 93, `OpLogicalOr` 2 → 3, `OpIEqual` 17 → 18, `OpINotEqual` 5 → 6 |
| shuffles | **0** | the subgroup shuffles live in `full_norm` and the den reduction; both are outside the diff |
| synchronisation | **0 added** (`sync.bar` 12 → 12; `sync.allwr` may go 12 → 13 by IGC scoreboarding, as measured on the Y-only card) | `PROOF.json` P5 |
| effective lanes / WG count / bound coverage | **unchanged** (grid 169×97, 16 393 WGs, 131 144 warps, 98.4 % covered WGs, 89.3 % useful pixel slots) | `COST-BREAKDOWN.md` §4 |
| live-value peak | **+4 GRF net** at the stage-4 Q iteration (`handoff` 4 + `yhalf` 4 + `score_q` 4 = 12 vs parent 8), worst case **+8** if IGC declines to coalesce `score_q` onto the Q store payload | `PROOF.json` P3 |
| code size | SPIR-V **+51 words / +364 B**; static ISA **−101 instructions** (prediction) | `words 16924 → 16975` |
| register-file pressure | `scratch` must stay 0; `max_r` is already 127 (architectural max) so it cannot rise | native criteria N4 |

**The combined register budget, explicitly.**  The two retained pairs overlap (the Q window is a
strict sub-interval of the Y window), so the question is whether the four extra GRF add up twice:

* the Q pair is filled from the Q store payload that the parent already holds at exactly that
  point (`half0/half1`, 4 GRF, whose live range ends at the now-predicated store), so a
  coalescing allocator puts `score_q0/score_q1` on those registers — the Q half of the change is
  **0 net GRF at the peak**;
* the Y pair is the whole +4, and +4 GRF across stages 4/6/8 is exactly the delta the Y-only card
  measured with `scratch = 0`, `max_r = 127` (`cards/n17b-f20-transport/RESULTS.json`);
* the tightest point of the card is the interval **stage-4 Q iteration → stage-6 head**, because
  it also contains the stage-4 → stage-6 debug dump block (`dbg[10240+e] = NR_Q(...)`,
  `dbg[12288+e] = NR_K(...)`), whose temporaries could previously use the just-freed Q payload
  registers.  This is why `scratch = 0` — not any counting argument — is the decisive criterion,
  and why the fallback is to drop one half of the composite rather than to tune it.

## Q6. Is the whole thing faster? (what to measure, with which arm, how to attribute)

This card cannot measure.  The instrument and the attribution rule:

* **Primary arm: `ordinary`, two arms, 6 alternating process groups × 30 reps (warm 1,
  feedback)** — the only instrument that yields a CI on the whole frame; the paired
  per-group difference with a two-sided t 95 % interval on df = 5.  The quantity to test is
  whether the frame moves at all: the effect can be at most 1.367 ms × 10 % = **0.137 ms**
  against a CI half-width of **0.068 ms** on 17.8 ms, so this is the only size of this mechanism
  that can be resolved (5 % was not, twice).
* **Secondary arm: `resources` (per-PASS `GpuTime` of PASS 151 / ord 230)** — the only instrument
  that reports the dispatch in isolation, but it yields one sample per arm and the parent's own
  frame-to-frame spread on this PASS is 7.1 µs on 1.367 ms (0.52 %).  A 10 % message cut would be
  ≈20 × that spread, so this arm is the *most sensitive* one; it has no CI, so it corroborates and
  never decides alone.
* **Gates: `fixed` and `fb2`** must both reproduce the gold of the parent, because the arithmetic
  is claimed identical.  A frame difference is a numerics failure (class E), not a performance
  result.
* **Attribution rule (contract §8.5):** native first.  If N1/N2/N4 do not appear, the result is
  **A (implementation did not land)** and no millisecond number may be quoted.  If they appear and
  the CI still crosses zero, the direction is **D (INDISTINCT)** for the *intra-subgroup* class —
  the card's stop condition — and the next move is the cross-SG probe (48 transports = 384
  messages) or a different shape, **not** another variant of this one.
* **What single-PASS attribution may claim at most:** this PASS is 1.367 ms of the 18.16 ms
  isolated sum (7.5 %); even a complete deletion of its message stream would be ≈0.14 ms of the
  frame.  The two measured single points (Q +0.0257 ms, Y −0.0181 ms, same 32-message size,
  opposite signs) bound the per-32-message effect at |≤0.026| ms, i.e. ≤0.8 µs per message —
  the composite doubles the deleted stream, so anything below ≈0.055 ms is invisible to both
  instruments.  That is the honest ceiling of this card, and it is why the verdict is
  "D unless the composite clears the floor", not "the mechanism is worthless".
