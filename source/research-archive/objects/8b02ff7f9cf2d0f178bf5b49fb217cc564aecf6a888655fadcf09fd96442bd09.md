# NATIVE-PREDICTION — n31-f01-dpas-chain（F01 / ordinal 0）

**只写预测与判据，不声称已实现。** 本卡没有 GPU，也没有离线 IGA 编译器：父的 ISA 是实测的
（`queue/n29-f01-alu-chain/native/captures/native-native-cand/ISA/
CS_asma0888c5a3c6703a9_simd32_0000000000000001_0_orig.asm`，6403 条，链头身份），
候选的 ISA 只能按源码/SPV 差值预测。

口径：**region** = `0x4A90..0x16A30`（4996 条）；**live** = 去掉 37 个 `debug==0` 跳过区间后的
3927 条；**chain** = 从 24 个 live 写内存 send 反向切片的并集（1390 条）。

## 2. 为什么这些预测是「保守的」

* SPIR-V 侧已经实测：`OpSelect 61 → 1`、`OpIEqual 32 → 3`、`OpBitwiseAnd 45 → 16`、
  `OpVariable −29`、`OpLoad −149`、`OpStore −29`，**浮点 opcode 313 → 313 一条没变**
  （`tools/spv-delta.json`）。所以 ISA 不会「一点不动」，但也**不会**有除法/开方/加法的增减。
* ISA 与 SPV 的缩放不一定是 1:1：SPV 里一个 `OpSelect` 作用在 `f16vec2` 上，到 ISA 变成
  **每个分量一条 `sel`**（父实测 68 对 add × 2 = 136 条 sel，而 SPV 只有 60 个被删的 OpSelect）。
  因此第 1 条用区间（240 ± 8）而不是点值。
* `nr_pool_natural` 的 4 个调用点里，ISA 只检出 **3 组**（12 对）；第 4 组可能已被 IGC 折叠，
  那样总降幅会是 128 而不是 136 —— **这不是未落地**，要在 RESULTS 里如实写。
* `bool lower` 的 SPIR-V 变量流量（178 条）在父 ISA 里已经被 SSA 化，**不预期**任何 ISA 收益；
  把它算进收益是虚报。

## 3. 归因纪律

* 只有 PASS 0 的 SPV 变了（`BUILD.json` 的 `card_plan.diff_rows=[504]`，其余 231 个 PASS 字节相同）。
* **先看第 1/2/3 条（是否落地），再看金帧，最后才看毫秒**（合同 §8.5）。
  第 1 条看不到（仍 376）时不许用整帧毫秒倒推「机制有效」。
* 计数器归因只看 **PASS 0 的 `XVE_STALL_ALUWR`**（父 0.385039 ms）。若 ALUWR 不降而整体帧时降了，
  那是别的 PASS/别的机制，不能记在本卡头上。
* 本改动不删除法，所以**不预期**复现 n29 的 +0.080；<0.03 ms 按 L13 走第二批。
