# VK102 Format 10/26 支持与 tail 门修复

日期：2026-10-18（Asia/Tokyo）
状态：**Format 10 与 Format 26 均已在游戏内实际处理；tail 门误拒已修；包 rev6 已封存。周期性闪动的 90 秒验收尚未完成。**

## 1. 起因：游戏画质被重置，不是用户改设置

安装前 `UserSettings.pre-install.json` 与故障局对比，游戏把 **15 项画质从 High 重置为 Low/Off**，包括：

- `ColorPrecision` High → Medium
- `AmbientOcclusion` High → Off
- `Anisotropy` 16 → 1
- `LODPreset` High → Low
- `CascadedShadows*`、`ScreenSpaceReflections`、`Volumetric*` 等 High → Low/Off

恢复安装前快照后，`host_color_dxgi=10`、NR 恢复（789 帧、31.7 ms）。所以不是用户手动改设置，也不是 ASI 没换回来。

## 2. Format 26 复现与根因

用当时故障局的完整 Low/Medium 快照复现：

- `host_color_dxgi=26 output_dxgi=26 color_supported=1`
- `deferred_record_reject reason=4 (tail_unverified)` 连续 32 次
- `processed_frames=0`、`deferred_identity` 0 条

`same_list_tail` 实际为 `output_state:[4,8]`（UAV=8）；而 `tail_safe_for_deferred_identity` 硬编码要求 `output_after==192`（PSR=192）。Format 26 的 DLSS 输出留在 UAV，因此永远被判 unsafe，`tail_valid_samples` 永远不到 8，全部 `tail_unverified`。

另一个独立缺陷：`deferred_identity_tail_verified` 要求 `tail_valid_samples == 8`（精确等于）。第 9 个安全 tail 出现后会永久不满足，形成另一种 tail 锁死。

## 3. 修复（仅宿主 tail/观测，不改网络）

1. `nr_tail_probe.cpp`：`tail_safe_for_deferred_identity` 接受 `output_after == 192` **或 8**；两者分别是 RGBA16F 的 PSR tail 与 R11G11B10 的 UAV tail。
2. `deferred_identity.cpp`：`deferred_identity_tail_verified` 改为 `tail_samples >= 8 && tail_valid_samples >= 8`，不再是精确 8。
3. `asi.cpp`：首个真实 NGX 帧记录
   `host_color_dxgi=%u output_dxgi=%u color_supported=%d; supported=10(RGBA16F),26(R11G11B10)`。
4. `deferred_identity`：`record` 的 reject 增加宿主日志（前 32 次），格式
   `deferred_record_reject reason=%d detail=%llu detail2=%llu`；用于定位 `tail_unverified` / `source_state` / `hdr_missing`。

## 5. 闪动修复进展

旧桥 `docs/PERIODIC_FLASH_20261001.md` 的周期闪动根因是 **全局命令 age >64 → source_state 拒绝单帧 → 下一帧恢复**；v5 用 list-scoped source proof 修到 90 秒 1309 帧 fallback/skip/failure 增量 0。

本轮：

- 已修掉 tail 门的两个真实锁死点（`output_after` 只认 192、`valid == 8` 精确判断）。
- 短时 10/26 运行中，除启动期 8 次外没有周期性 `tail_unverified`；`deferred_record_reject` 日志可继续抓后续拒绝。
- **尚未启用** v5 的 `NRB_DLSS_COLOR_STATE_PROOF_V1` 路径；之前直接打开会让当前 nrvk 路径 0 帧（`record` 全拒），说明旧 v5 证明不能原样套用，需要按当前 nrvk/deferred 路径移植。
- 因此：tail 类闪动已有修复证据；source_state 类周期闪动仍需 90 秒/1309 帧级验收，不能宣称已彻底解决。

## 6. 显卡优先级

- 当前慢的主因是 NR/合成/尾段计算（`tail≈27–28 ms`）与显存/游戏负载，不是队列排队。
- 提高进程优先级只影响 CPU 调度；提高 D3D12 队列优先级或 Vulkan queue priority 可能改善被抢占时的调度，但不能减少 27 ms 的 GPU 工作，且 `GLOBAL_REALTIME` 有饿死游戏/显示的风险。
- 若要试，建议只试 `D3D12_COMMAND_QUEUE_PRIORITY_HIGH` / 进程 `HIGH_PRIORITY_CLASS`，逐项记录帧时；不作为默认。当前未改优先级。

## 8. 帧命令池（rev7）

`record` 的 `record_resources` 原来每帧新建 3 个 command allocator、3 个 command list、1 个 `color_copy` 和 1 个 completion fence。rev7 增加有界帧命令池：

- 每个 Pending 持有一个 `FrameCommands` 租约；consumer fence 完成后归还；
- 8 个槽上限，池内 allocator/list 已 Close，使用前 Reset；
- 3 个 allocator + 3 个 list 复用；
- `color_copy`、completion fence、HdrProxy 仍按帧创建，下一步再池化。

## 11. copy + HDR proxy 融合试验（否决）

尝试把 `CopyResource(color→color_copy)` 删除，让 HdrProxy prepare shader 同时写 `XeSSInput`（`cff8778e…`）。scene 3、Format 10、60 秒 PresentMon：

| 项 | rev10 | 融合版 |
|---|---:|---:|
| prep | 4.95 ms | **5.40 ms** |
| NR 段 | 34.98 ms | **35.42 ms** |
| PresentMon 中位 | 43.07 ms | **43.45 ms** |
| P95 | 43.99 ms | 44.20 ms |
| 帧数 | 1389 | 1368 |

结论：**无收益，略差**。`CopyResource` 是 copy engine 的廉价操作；把同样的全帧写塞进 prepare shader，增加了 UAV 写和 barrier，抵消了省掉的 copy。已回退源码到 rev10，游戏 ASI 恢复为已验收的 `c7b65f1f`；rev11 只是包内务重封（保留同一 bin），不引入融合。

## 12. prepared-wait bypass 试验（否决）

尝试在 nrvk 稳态跳过 prepared 的 CPU 等待，让 nrvk process 自己的 copy fence 承担同步（`9d89e621…`）。scene 3、Format 10、60 秒 PresentMon：

| 项 | rev10 | bypass |
|---|---:|---:|
| prep | 4.95 ms | **0.005 ms** |
| host | 1.16 ms | **6.55 ms** |
| composite submit | 0.04 ms | 0.31 ms |
| NR 段 | 34.98 ms | **35.40 ms** |
| PresentMon 中位 | 43.07 ms | **43.69 ms** |
| P95 | 43.99 ms | 44.54 ms |

结论：**没有收益**。`prep` 主要是从 NR 开始到 prepared fence 的队列等待（包含游戏 list 前缀），不是可删的桥接计算；跳过 CPU 等待只是把 5 ms 搬到 `host`，还多了 composite 提交开销。已回退源码，游戏 ASI 保持 `c7b65f1f`；rev12 为包内务重封。

## 13. 结论

`HDRPROXY_POOL_REV10_RETAINED_COPY_FUSION_AND_PREPARED_BYPASS_REJECTED`。

Format 10/26 都已实际处理；tail 误拒已修；周期闪动的 tail 类锁死已消除，但 source_state 类周期闪动仍需长时验收。显卡优先级不是当前瓶颈的主要解法。
