# NATIVE-PREDICTION.md — n05c-f05-mbatch 第 5 问的可观察点与判据

本卡**没有 GPU**：以下全部是**预测**，不是"已实现"。主代理按此在 native 捕获里逐条核对；
任何一条对不上，先按合同 §6 分诊，不许用整体毫秒倒推机制。

基础身份：父 SPV `20f4074f…`（pipeline 9，`simd32`），候选 `candidate.spv`（本卡，见 BUILD.json）。
参照的父 native 计数来自 `queue/n04b-f05-c128-feed/native/captures/native-native-base/`；
**新捕获才是权威**（同一 SPV 字节在不同批次/驱动的计数可能不同，旧数只作方向参照）。

## 1. 主判据：权重消息减半、A 行翻倍、DPAS 不动

| 观测项 | 父（参照） | 候选预测 | 判读 |
|---|---|---|---|
| `send.ugm load.ugm.d32x8.a32.bss[a0.2]`（QKV 权重 tile，`rd:8`，16-lane） | **96** | **48** | **N1：必须正好 48。** 仍是 96 → 实现未落地（A 类）；不是 48 也不是 96 → 先读 ISA 再判断 |
| `send.ugm load.ugm.d32x8t.a32.bss[a0.0]`（A 行，`rd:1`，1-lane） | **128** | **256** | **N2：必须正好 256。** 少 → 第二遍被合并/优化（要重新解释）；多 → 多读了 |
| `dpas.8x8` 总数 | **128** | **128** | **N3：必须相等。** 不等 = 数学被动了，直接停 |
| QKV 段 DPAS（前 96 条，acc ∈ {Q,K,V 组}） | 96 | 96 | 每 acc 的 K 序（ki=0..7）与条数都不许变 |
| `send.ugm` 总条数 | 518 | **598**（−48 +128） | 净 +80；与 N1/N2 自洽 |
| 其它消息类型（`load.slm`/`store.slm`/`store.ugm`/`fence`） | 见 n04b | **逐类相同** | 任何一类变了 = 实现走偏（本卡不该动它们） |
| 权重返回区宽度 | `rd:8` | `rd:8` | 不变 |
| A 行返回区宽度 | `rd:1` | `rd:1` | 不变 |

**"若看不到就等于未实现"的写法**：只要 N1 或 N2 不成立，本卡的机制在 native 就没形成处理，
记为 **A 类（实现未落地）**，不得写成"权重复用方向在 C128 无效"。

## 2. 寄存器 / 资源判据（预算的实证形态）

| 观测项 | 预测 | 判读 |
|---|---|---|
| `max_r` | 127（不变） | 变大不可能（128 封顶）；仍是 127 只说明高位用到了 |
| **scratch** | **0** | **scratch > 0 = spill = STOP**。这是 BUDGET.md §4 对 D2 估 102/128 的直接检验；也是 D1（12 acc）会先崩的地方 |
| QKV 段 DPAS 目标基址 | **8 个一组**（8 GRF/acc，两组 4 个 + 一组 4 个） | 只看到 6 组 → 8 acc 没形成 |
| shared / 绑定 / grid | 24,576 B / 8 / 与 plan 行一致 | 任一变化都要解释（本卡不该动） |
| 首 DPAS 地址 | 可能后移（V 遍/更长 prologue） | **如实记录，不作门** |
| `sync.allwr` 计数 | 不可预测（n05a 见过 44→19） | 记录，不单独归因 |
| 静态指令总数 | 上升（多一个展开的 V ki 循环，量级 +10~15%） | 记录，不作门 |

## 3. 分诊预登记（还没有结果，先写判据）

- **A（实现未落地）**：N1 仍是 96，或 N2 不是 256。
- **B（实现有副作用）**：N1/N2/N3 成立且 scratch > 0，或权重返回区活值推迟导致等待包/在途深度下降。
  第一修法：把 V 遍的 A 载入提前（不改 acc 数），或把 Q/K 遍的两块 B 改成"分槽返回"。
- **C（当前身份无净收益）**：N1/N2/N3 成立、门通过、6 组均值差显著为负/不显著 → 归因到
  "A 读翻倍抵消了权重减半"这一具名权衡（BUDGET.md §5.1 的三种度量背离），不推广成方向禁令。
- **D（INDISTINCT）**：6 组均值差 CI 跨 0 且 N1/N2 成立。
- **E（数值失败）**：先查首差 token/head/ki；本卡预期 bit-exact（K 序、舍入点、归约树都没动），
  若出现首差，优先查 m0a/m0b 的 store 地址配对与 K 的列主序偏移（1920+128 的边界）。

## 4. 若主代理要另行证伪/证实"D1 装不下"（独立实验，本卡不做）

只需一次 **native-only** 捕获（不需要计时、不需要门）12 acc 版本（把 QKV 段写成一遍 12 acc，
即 n05a 的 C256 形态直接搬到 C128），核对三件事：

1. `scratch`：> 0 即在分配器层证实预算结论（BUDGET.md §4 的 D1 判定成立）；
2. `max_r` 与 QKV 段 DPAS 目标基址是否变成 12 组（是否出现 4 GRF 间距的紧排）；
3. 权重消息是否 96 → 48、A 行是否仍 128（这是 D1 的机制预测）。

若 1 为 0（无 spill）且 2 显示紧排 → BUDGET.md §7 未决项 3 成立，D1 的预算要重算，
那时**应当**改为提交 D1（机制更纯：A 读不翻倍）。这条路径的前提是主代理愿意花一个 native 槽位。

## 5. 预期收益的量级（只作排序参考，不作承诺）

参照 n05a（C256，同机制，权重 192→96、A 不变）在 16 个 PASS 上 +0.521 ms。C128 的杠杆只有一半
（权重 96→48），而且**多付 128 条 A 行**，所以本卡**不承诺任何毫秒数**，也不与 n05a 的 0.521 ms
相加或相减（不同批次、不同 shader、不同副作用）。
